## A. Эстетика абстрактного искусства

<details><summary><b>Постановка задачи</b></summary>

Дано $n$ прямоугольных картин и выставочный зал длины $l$. Для каждой картины известны её ширина, высота и эстетическая оценка при поворотах на $0$, $90$, $180$ и $270$ градусов.

Требуется выбрать некоторое подмножество картин и ориентацию для каждой выбранной картины так, чтобы:

- сумма их ширин не превышала $l$;
- сумма эстетических оценок была не меньше $a$;
- максимальная высота выбранных картин была как можно меньше.

Разрешается не выбирать ни одной картины. Тогда суммарная оценка и максимальная высота считаются равными нулю.

Нужно вывести минимальную возможную максимальную высоту. Если выполнить требования невозможно, следует вывести $-1$.

</details>

<details><summary><b>Основная идея</b></summary>

Повороты на $0$ и $180$ градусов дают одинаковые размеры картины, поэтому среди них имеет смысл оставить ориентацию с большей оценкой. То же верно для поворотов на $90$ и $270$ градусов. Таким образом, у каждой картины остаются **два варианта размещения**.

Зафиксируем ограничение $H$ на высоту. Все варианты с высотой больше $H$ запрещены, а среди остальных требуется набрать оценку не меньше $a$, потратив не более $l$ единиц ширины. Получается задача о рюкзаке: для каждой картины разрешается отказаться от неё либо выбрать один из двух допустимых вариантов.

Если ответ существует при некотором $H$, он существует и при любой большей высоте. Это монотонное свойство позволяет применить **двоичный поиск по ответу**.

Одна проверка работает за $O(nl)$, поэтому общее время работы равно $O(nl\log(M))$, где $M$ — верхняя граница поиска по высоте. Память — $O(n+l)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Перебирать подмножества картин напрямую нельзя: для каждой картины есть несколько вариантов — не брать её либо выбрать одну из ориентаций. Число комбинаций растёт экспоненциально. Сначала сократим число вариантов, а затем отделим поиск минимальной высоты от проверки того, достижима ли нужная оценка.

Повороты на $0$ и $180$ градусов не меняют ширину и высоту картины. Если решено использовать такие размеры, ориентация с меньшей эстетической оценкой никогда не приносит пользы. Поэтому будем оставлять только оценку $\max(a_0,a_2)$.

После поворотов на $90$ и $270$ градусов ширина и высота меняются местами. Размеры в обоих случаях также совпадают, значит, для второго варианта оставим оценку $\max(a_1,a_3)$.

В результате каждая картина имеет не более двух существенных вариантов:

- исходные ширина и высота с лучшей оценкой среди поворотов на $0$ и $180$ градусов;
- переставленные местами ширина и высота с лучшей оценкой среди поворотов на $90$ и $270$ градусов.

Теперь зафиксируем некоторое значение $H$ и проверим, можно ли получить суммарную оценку не меньше $a$, если высота каждой выбранной картины не превосходит $H$.

Будем поддерживать массив, в котором $\text{curr}[x]$ — максимальная эстетическая оценка, достижимая после обработки некоторого префикса картин при суммарной ширине $x$. Недостижимые состояния получают значение $-\infty$.

До рассмотрения картин достижимо только состояние с нулевой шириной и нулевой оценкой:

- $\text{curr}[0]=0$;
- при $x>0$ значение $\text{curr}[x]$ равно $-\infty$.

При обработке очередной картины возможны три действия:

1. Не брать картину. Тогда все ранее достижимые состояния сохраняются.
2. Выбрать первый вариант, если его высота не больше $H$.
3. Выбрать второй вариант, если его высота не больше $H$.

Переходы выполняются из массива предыдущего слоя в новый массив. Это существенно: оба варианта одной картины переходят из состояний, полученных **до** её обработки. Поэтому одну картину нельзя случайно выбрать дважды или одновременно повесить в двух ориентациях.

Пусть выбранный вариант имеет ширину $w$ и оценку $c$. Из состояния ширины $x$ получаем состояние ширины $x+w$, а к накопленной оценке прибавляется $c$. Переход разрешён только при $x+w\le l$.

После обработки всех картин условие выполнимо тогда и только тогда, когда $\max_{0\le x\le l}\text{curr}[x]\ge a$. Отрицательные оценки не требуют особой обработки: картину всегда можно пропустить. По той же причине пустой набор остаётся допустимым. Если $a\le 0$, проверка успешна уже при $H=0$, поскольку пустой набор имеет оценку $0$.

Осталось найти минимальное подходящее $H$. Здесь действует монотонность: при увеличении $H$ ранее разрешённые варианты картин не исчезают, к ним могут лишь добавиться новые. Следовательно, если требуемую оценку удалось набрать при высоте $H$, то это возможно и при любой большей высоте.

Будем выполнять двоичный поиск по границе между неподходящими и подходящими значениями. Если проверка для середины успешна, продолжим поиск в левой половине; иначе перейдём в правую. В итоге получим минимальную допустимую максимальную высоту. Если подходящего значения нет, выводится $-1$.

**Корректность динамики** следует по индукции по числу обработанных картин. Изначально описан единственный возможный выбор — пустой набор. При добавлении очередной картины новый слой рассматривает все допустимые действия с ней: пропуск и выбор каждого разрешённого варианта. Других действий нет, а переходы из предыдущего слоя не позволяют использовать картину несколько раз. Значит, после последней картины учтены все допустимые наборы и ориентации, а для каждой суммарной ширины сохранена наибольшая оценка.

Одна проверка перебирает $n$ картин и до $l+1$ значений ширины для каждого из двух вариантов, поэтому требует $O(nl)$ времени. Двоичный поиск добавляет множитель $O(\log(M))$. Массив динамики занимает $O(l)$ памяти, а описание картин — $O(n)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
#define all(x) (x).begin(),(x).end()
#define int int64_t
const int inf = 1e18L;
void setmax(auto &x, const auto &y) { if (x < y) x = y; }
int32_t main() {
    int n, len, a; std::cin >> n >> len >> a;
    std::vector items(n, std::vector<std::tuple<int,int,int>>{}); // {width, height, cost}
    for (int i = 0; i < n; i++) {
        int w, h, a0, a1, a2, a3;
        std::cin >> w >> h >> a0 >> a1 >> a2 >> a3;
        items[i].emplace_back(w, h, std::max(a0, a2));
        items[i].emplace_back(h, w, std::max(a1, a3));
    }
    // sum W <= len
    // max H <= answ
    // sum cost >= a
    auto check = [&](int maxH){
        // можно ли, взяв только картины высотой <= maxH, добиться суммарной стоимости >= a,
        // используя длину l? dp[l] = max total cost
        std::vector<int> curr(1+len, -inf);
        curr[0] = 0;
        for (int i = 0; i < n; i++) {
            auto next = curr;
            const auto &[w1, h1, a1] = items[i][0];
            const auto &[w2, h2, a2] = items[i][1];
            if (h1 <= maxH)
                for (int was = len-w1; was >= 0; was--)
                    setmax(next[was+w1], curr[was] + a1);
            if (h2 <= maxH)
                for (int was = len-w2; was >= 0; was--)
                    setmax(next[was+w2], curr[was] + a2);
            curr.swap(next);
        }
        return *std::max_element(all(curr)) >= a;
    };
    // бинарный поиск по ответу - максимальной высоте картины
    int low = -1, high = 1e5;
    while (high - low > 1) {
        int mid = (low + high) / 2;
        if (check(mid)) high = mid;
        else low = mid;
    }
    if (high >= 1e4) std::cout << "-1\n";
    else std::cout << high << "\n";
    return 0;
}
```

</details>

```cpp
items[i].emplace_back(w, h, std::max(a0, a2));
items[i].emplace_back(h, w, std::max(a1, a3));
```

Для каждой картины сохраняются два существенных варианта. Первый соответствует поворотам на $0$ и $180$ градусов: размеры остаются равными $(w,h)$, а из двух оценок выбирается большая. Второй соответствует поворотам на $90$ и $270$ градусов: ширина и высота меняются местами, а оценка также выбирается максимальная.

```cpp
std::vector<int> curr(1+len, -inf);
curr[0] = 0;
```

Индекс массива обозначает использованную ширину. Значение `-inf` отмечает недостижимое состояние, а `curr[0] = 0` описывает пустой набор картин. Большое отрицательное значение позволяет применять обычный максимум без отдельной проверки достижимости каждого состояния.

```cpp
for (int i = 0; i < n; i++) {
    auto next = curr;
    const auto &[w1, h1, a1] = items[i][0];
    const auto &[w2, h2, a2] = items[i][1];
    if (h1 <= maxH)
        for (int was = len-w1; was >= 0; was--)
            setmax(next[was+w1], curr[was] + a1);
    if (h2 <= maxH)
        for (int was = len-w2; was >= 0; was--)
            setmax(next[was+w2], curr[was] + a2);
    curr.swap(next);
}
```

Копирование `curr` в `next` сохраняет вариант, при котором текущая картина не выбирается. Переходы для обеих ориентаций читают значения только из `curr`, то есть из слоя до обработки картины. Благодаря этому нельзя взять одну картину дважды.

Проверки `h1 <= maxH` и `h2 <= maxH` отбрасывают варианты, нарушающие ограничение по высоте. Верхняя граница цикла `len-w1` или `len-w2` гарантирует, что новая суммарная ширина не превысит длину зала.

```cpp
return *std::max_element(all(curr)) >= a;
```

Не требуется использовать всю длину зала. Поэтому рассматривается максимум среди состояний для всех суммарных ширин от $0$ до `len`. Проверка успешна, если хотя бы одно из них набирает оценку не меньше `a`.

```cpp
int low = -1, high = 1e5;
while (high - low > 1) {
    int mid = (low + high) / 2;
    if (check(mid)) high = mid;
    else low = mid;
}
```

Двоичный поиск опирается на монотонность `check`: увеличение допустимой высоты может только добавить новые варианты ориентаций. При успешной проверке правая граница переносится в `mid`, поскольку минимальный ответ не больше этого значения. При неуспешной проверке переносится левая граница.

<details><summary><b>Разбор сложных фрагментов кода на Python</b></summary>

Повороты с одинаковыми размерами объединяются в один вариант. Для исходных размеров выбирается большая оценка среди поворотов на $0$ и $180$ градусов, а для переставленных размеров — среди поворотов на $90$ и $270$ градусов.

Копия `curr` содержит все состояния, в которых текущая картина пропущена. Оба варианта ориентации добавляются из старого массива `curr` в новый массив `next`. Поэтому выбор одного варианта не может стать основой для выбора второго варианта той же картины.

Диапазон заканчивается на `len-w1` или `len-w2`, так что индекс нового состояния не выходит за допустимую длину зала. Если ширина картины больше `len`, соответствующий диапазон пуст и переходов не возникает.

```python
return max(curr) >= a
```

Картины могут занимать любую суммарную ширину, не превосходящую `len`. Максимум по всему массиву находит лучший результат среди всех таких ширин.

```python
low, high = -1, 10**5
while high - low > 1:
    mid = (low + high) // 2
    if check(mid): high = mid
    else: low = mid
```

Функция `check` монотонна по `maxH`: после увеличения предельной высоты ни один разрешённый вариант не становится запрещённым. Поэтому при успешной проверке поиск продолжается слева, а при неуспешной — справа. После завершения цикла `high` содержит найденную границу.

## B. Basic Bounding Boxes

<details><summary><b>Постановка задачи</b></summary>

Полимино из $n$ клеток — это связное по сторонам множество клеток квадратной сетки. Два полимино считаются эквивалентными, если одно из них можно получить из другого с помощью переносов, поворотов на угол, кратный $90^\circ$, и отражений.

**Базовая ограничивающая рамка** полимино — квадрат минимального размера со сторонами на линиях сетки, содержащий всё полимино. Через $f(n,k)$ обозначается количество классов эквивалентности полимино из $n$ клеток, для которых сторона такой рамки равна $k$.

По заданному $n$, где $1\le n\le 10^{18}$, требуется найти количество положительных целых $k$, удовлетворяющих условию $f(n,k)=1$.

</details>

<details><summary><b>Основная идея</b></summary>

Если ограничивающая рамка имеет сторону $k$, то обязательно выполняется

$k\le n\le k^2$.

На границах этого диапазона полимино определяется однозначно:

- при $n=k$ получается полоса длины $k$;
- при $n=k^2$ получается заполненный квадрат $k\times k$.

Во всех промежуточных случаях существует хотя бы два неэквивалентных полимино, кроме пары $n=3$, $k=2$: три клетки в квадрате $2\times2$ образуют единственное свободное полимино в форме буквы `L`.

Следовательно:

- при $n=1$ ответ равен $1$;
- при $n=3$ ответ равен $2$;
- во всех остальных случаях полоса всегда даёт один подходящий размер рамки, а полный квадрат добавляет ещё один, если $n$ — точный квадрат.

Итоговая формула имеет вид: $1+[n\text{ является точным квадратом}]$, за исключением двух особых случаев.

Алгоритм работает за **$O(1)$ по времени** и использует **$O(1)$ дополнительной памяти**.

</details>

<details><summary><b>Детальный разбор</b></summary>

Перебирать полимино напрямую невозможно: уже для сравнительно небольшого числа клеток их количество стремительно растёт, тогда как $n$ достигает $10^{18}$. Поэтому важно не считать сами полимино, а выяснить, **когда полимино с заданной стороной рамки может быть единственным**.

Пусть минимальный прямоугольник, содержащий полимино, имеет ширину $w$ и высоту $h$. Тогда сторона его базовой квадратной рамки равна $\max(w,h)$. Предположим без ограничения общности, что она равна $k$ за счёт ширины.

Чтобы полимино занимало $k$ столбцов, в каждом из них должна находиться хотя бы одна клетка. Значит, $n\ge k$. С другой стороны, все клетки помещаются в квадрат $k\times k$, откуда $n\le k^2$. Итак, необходимое условие существования имеет вид

$k\le n\le k^2$.

Если это условие не выполнено, то $f(n,k)=0$, поэтому такие значения $k$ нас не интересуют.

Рассмотрим сначала границы полученного диапазона.

При **$n=k$** в каждом из $k$ столбцов находится по одной клетке. Чтобы соседние столбцы оставались связными по сторонам, все клетки должны лежать в одной строке. Получается полоса длины $k$. С точностью до разрешённых преобразований она единственна, поэтому

$f(k,k)=1$.

Значит, для любого $n$ значение $k=n$ обязательно входит в ответ.

При **$n=k^2$** полимино занимает все клетки ограничивающего квадрата $k\times k$. Иначе в нём было бы меньше $k^2$ клеток. Следовательно, полимино является заполненным квадратом и также определяется однозначно:

$f(k^2,k)=1$.

Так появляется второе подходящее значение $k$, если $n$ — точный квадрат.

Осталось понять, могут ли встречаться другие единственные полимино. Рассмотрим внутреннюю часть диапазона:

$k<n<k^2$.

Для $k\ge3$ покажем, что при любом таком $n$ можно построить не менее двух неэквивалентных полимино. Представим число клеток в виде

$n=qk+r,\qquad 0\le r<k$.

Поскольку $k<n<k^2$, выполняется $1\le q\le k-1$.

В качестве первого полимино возьмём $q$ полностью заполненных строк длины $k$. Если $r>0$, добавим под ними непрерывный отрезок из $r$ клеток. Полимино связано и содержит полную строку длины $k$, поэтому сторона его рамки равна $k$.

Теперь разберём возможные остатки.

- **Если $r\ge2$**, клетки последней строки можно разделить на две группы, оставив между ними пропуск. Обе группы соприкасаются с заполненной строкой, поэтому связность сохраняется. У первого полимино все $r$ клеток последней строки образуют один отрезок, а у второго — два. У второго полимино на одно соседство клеток меньше, а его периметр на $2$ больше. Следовательно, эти полимино неэквивалентны.

- **Если $r=1$**, единственную дополнительную клетку можно прикрепить либо под угловой клеткой прямоугольника, либо под неугловой клеткой его стороны. При $q=1$ первое полимино является ломаной без разветвления, а во втором появляется клетка с тремя соседями. При $q\ge2$ в первом случае степень угловой клетки меняется с $2$ на $3$, а во втором степень граничной неугловой клетки меняется с $3$ на $4$. Наборы степеней клеток различаются, поэтому совместить эти полимино поворотами и отражениями нельзя.

- **Если $r=0$**, первое полимино является прямоугольником $k\times q$. У второго удалим угловую клетку и добавим клетку снаружи под неугловой клеткой нижней стороны. Связность сохраняется, а высота не превосходит $q+1\le k$. Удаление угловой клетки не меняет периметр: исчезают две внешние стороны, но открываются две внутренние. Новая клетка, прикреплённая одной стороной, увеличивает периметр на $2$. Поэтому полученные полимино неэквивалентны.

Таким образом, при $k\ge3$ во всей внутренней части диапазона выполняется $f(n,k)\ne1$.

Для $k=2$ между $k$ и $k^2$ находится только $n=3$. Любое связное полимино из трёх клеток, помещающееся в квадрат $2\times2$, получается удалением одного угла этого квадрата. Все четыре варианта эквивалентны, поэтому

$f(3,2)=1$.

Кроме того, при $n=3$ значение $k=3$ соответствует прямой полосе. Отсюда ответ для $n=3$ равен $2$.

При $n=1$ полоса и заполненный квадрат совпадают: это одна клетка с рамкой стороны $1$. Поэтому два общих случая дают одно и то же значение $k$, а ответ равен $1$.

Во всех остальных случаях ответ складывается из:

- одного значения $k=n$, соответствующего полосе;
- ещё одного значения, если $n$ является точным квадратом.

Для проверки точного квадрата достаточно вычислить целую часть квадратного корня и проверить, равен ли её квадрат числу $n$.

**Асимптотика по времени — $O(1)$, по памяти — $O(1)$.**

</details>

## C. Вычисление изменяющихся коэффициентов

<details><summary><b>Постановка задачи</b></summary>

Дан многочлен степени $n$ с целыми коэффициентами, причём старший коэффициент отличен от нуля. Выписываются все коэффициенты исходного многочлена и каждого из его производных вплоть до производной порядка $n$. Нулевые коэффициенты также учитываются.

Требуется найти **наименьшее** и **наибольшее** среди всех выписанных чисел. Для каждого из них нужно вывести неотрицательный остаток от деления на $998244353$: сначала для минимума, затем для максимума.

</details>

<details><summary><b>Основная идея</b></summary>

Коэффициент $a_i$ при $x^i$ после $k$ дифференцирований превращается в $a_i\cdot i!/(i-k)!$. Все множители положительны и по мере дифференцирования не уменьшаются. Поэтому для одного исходного коэффициента крайние значения достигаются либо в исходном многочлене, либо после последнего возможного дифференцирования:

- при $a_i>0$ минимум равен $a_i$, а максимум — $a_i\cdot i!$;
- при $a_i<0$ минимум равен $a_i\cdot i!$, а максимум — $a_i$;
- нулевой коэффициент всегда остаётся нулём.

Надо научиться сравнивать числа $a_i\cdot i!$: сами факториалы не помещаются ни в один стандартный целочисленный тип. Будем сравнивать два таких произведения после сокращения меньшего факториала. Отношение факториалов вычисляется только пока оно меньше $2\cdot 10^{18}$; после достижения этой границы исход сравнения уже определяется знаками и ограничением $|a_i|\le 10^{18}$.

Положительные и неположительные коэффициенты сортируются по значениям $a_i\cdot i!$. После выбора нужных элементов их значения вычисляются по модулю $998244353$.

Асимптотика по времени — **$O(n\log(n))$**, по памяти — **$O(n)$**.

</details>

<details><summary><b>Детальный разбор</b></summary>

Запишем многочлен в виде $\sum_{i=0}^{n}a_i x^i$. В производной порядка $k$, где $0\le k\le i$, слагаемое $a_i x^i$ даёт коэффициент $a_i\cdot i!/(i-k)!$ при степени $i-k$.

Важно, что коэффициенты от разных исходных степеней здесь не складываются. После фиксированного числа дифференцирований исходная степень $i$ переходит в степень $i-k$, поэтому каждому выписанному коэффициенту соответствует единственный коэффициент исходного многочлена.

Для фиксированного $i$ получаем последовательность множителей:

$1,\ i,\ i(i-1),\ldots,\ i!$.

Все они положительны и не убывают. Значит, промежуточные производные не могут дать новое крайнее значение:

- если $a_i$ положителен, наименьшее значение в этой последовательности равно $a_i$, а наибольшее — $a_i\cdot i!$;
- если $a_i$ отрицателен, умножение на больший положительный множитель делает число меньше, поэтому минимум равен $a_i\cdot i!$, а максимум — $a_i$;
- если $a_i=0$, во всех производных от этого слагаемого также получается ноль.

Таким образом, среди всех выписанных чисел нас интересуют лишь исходные коэффициенты и значения $a_i\cdot i!$.

Теперь разберём минимум. Если есть отрицательные коэффициенты, минимум находится среди произведений $a_i\cdot i!$ для них. Если отрицательных нет, но присутствует ноль, ответ равен нулю. Если же все коэффициенты положительны, достаточно выбрать наименьший исходный коэффициент. В реализации нули объединены с отрицательными коэффициентами в одну группу: это не меняет результата, поскольку любой отрицательный элемент меньше нуля, а при отсутствии отрицательных ноль сам становится минимумом.

Для максимума рассуждение симметрично. Если есть положительные коэффициенты, максимум находится среди $a_i\cdot i!$. Если положительных коэффициентов нет, наибольшее значение следует выбирать среди исходных коэффициентов: им может оказаться либо ноль, либо отрицательное число, ближайшее к нулю.

Остаётся научиться сравнивать произведения $a_i\cdot i!$ и $a_j\cdot j!$. Сравнения проводятся только внутри одной группы знаков.

Пусть $i\le j$. Сократим обе части на положительное число $i!$. Тогда

$a_i\cdot i!<a_j\cdot j!$

эквивалентно

$a_i<a_j\cdot(i+1)(i+2)\ldots j$.

При $i>j$ аналогично получаем сравнение

$a_i\cdot(j+1)(j+2)\ldots i<a_j$.

Отношение факториалов всё ещё может быть огромным. Однако вычислять его полностью не требуется. Обозначим границу через $B=2\cdot 10^{18}$. Модули исходных коэффициентов не превышают $10^{18}$. Поэтому, как только произведение последовательных множителей достигает $B$, исход сравнения становится известен:

- для положительных коэффициентов число, умноженное на такой коэффициент, заведомо превосходит другой исходный коэффициент;
- для отрицательных коэффициентов его модуль также становится заведомо больше, а само число — меньше;
- ноль остаётся нулём при любом множителе.

Для каждого индекса $i$ заранее сохраним пары, содержащие индекс $j$ и произведение $(i+1)(i+2)\ldots j$, пока оно меньше $B$. Такие списки имеют небольшой размер: из-за быстрого роста произведения в них находится не более нескольких десятков элементов. Если нужного $j$ в списке нет, вместо настоящего отношения факториалов достаточно использовать $B$.

После этого положительные и неположительные коэффициенты будем сортировать по величине $a_i\cdot i!$. Первый элемент отсортированной группы даёт минимум, последний — максимум. При этом само огромное значение вычислять не нужно: после выбора индекса факториал считается сразу по модулю $998244353$.

**Почему рассмотрены все варианты?** Каждый выписанный коэффициент принадлежит последовательности, порождённой некоторым исходным $a_i$. Крайнее значение любой такой последовательности находится на одном из её концов. Алгоритм рассматривает нужный конец для каждого знака, а затем выбирает глобальный минимум и максимум. Следовательно, ни один возможный кандидат на ответ не пропущен.

Предварительные списки отношений факториалов занимают $O(n)$ памяти при заданном ограничении на коэффициенты. Сортировка двух групп требует суммарно $O(n\log(n))$ сравнений, а вычисление факториалов по модулю — $O(n)$. Итого время работы равно $O(n\log(n))$, объём памяти — $O(n)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
#define all(x) (x).begin(),(x).end()
#define isz(x) (int)(x).size()
#define int int64_t
using i128 = __int128;
const int NMAX = 100100;
int32_t main() {
    int n; std::cin >> n;
    std::vector<int> a(n+1);
    for (auto &it : a) std::cin >> it;
    std::reverse(all(a));
    // сравнивать нужно a[i] * i! против a[j] * j!, причём a[i] и a[j] должны быть одного знака
    std::vector<std::pair<int, int>> pos, neg;
    for (int i = 0; i < isz(a); i++)
        if (a[i] > 0) pos.emplace_back(a[i], i);
        else neg.emplace_back(a[i], i);
    // теперь будем сортировать в порядке возрастания
    // a[i] * i! < a[j] * j!. Случаи:
    // 1. Если i >= j, то a[i] * (i!/j!) < a[j]
    // 2. Если i < j, то a[i] < a[j] * (j! / i!)
    // отношение a[i] / a[j] может быть порядка 10^{18}, поэтому нужно предварительно подсчитать
    // для каждого факториала с какими другими факториалами отношение не превысит 10^{18}
    std::vector adj(NMAX+1, std::vector<std::pair<int, __int128>>{});
    const int inf = 2e18L;
    for (int i = 0; i <= NMAX; i++) {
        // fact[j] / fact[i] = (i+1) * (i+2) * ... * j <= 10^{18}
        int j = i;
        __int128 prod = 1;
        adj[i] = {{i, 1}};
        while (prod * (j+1) < inf) {
            prod *= (++j);
            adj[i].emplace_back(j, prod);
        }
    }
    // теперь можем начать сортировать:
    auto cmp = [&](const auto &lhs, const auto &rhs) {
        auto [ai, i] = lhs;
        auto [aj, j] = rhs;
        if (i <= j) {
            // a[i] < a[j] * (j!/i!)
            int coeff = inf;
            auto it = std::lower_bound(all(adj[i]), std::make_pair(j, i128{}));
            if (it != adj[i].end()) coeff = it->second;
            return a[i] < __int128(a[j]) * coeff;
        } else {
            // a[i] * (i! / j!) < a[j]
            int coeff = inf;
            auto it = std::lower_bound(all(adj[j]), std::make_pair(i, i128{}));
            if (it != adj[j].end()) coeff = it->second;
            return __int128(a[i]) * coeff < a[j];
        }
    };
    std::sort(all(pos), cmp);
    std::sort(all(neg), cmp);
    const int mod = 998244353;
    std::vector<int> fact(n+1, 1);
    for (int i = 2; i <= n; i++)
        fact[i] = (fact[i-1] * i) % mod;
    // сначала минимум
    if (!neg.empty()) {
        auto [aj, j] = neg.front();
        auto se = (aj % mod * fact[j] % mod + mod) % mod;
        std::cout << se << '\n';
    } else {
        int answ = inf;
        for (auto &[ai, _] : pos)
            answ = std::min(answ, ai);
        std::cout << answ % mod << '\n';
    }
    // теперь максимум
    if (!pos.empty()) {
        auto [ai, i] = pos.back();
        auto fi = (ai % mod * fact[i] % mod + mod) % mod;
        std::cout << fi << '\n';
    } else {
        int answ = -inf;
        for (auto &[ai, _] : neg)
            answ = std::max(answ, ai);
        std::cout << (answ % mod + mod) % mod << '\n';
    }
    return 0;
}
```

</details>

```python
    se = (aj % mod * fact[j] % mod + mod) % mod

# теперь максимум

    print(fi)
else:

    print((answ % mod + mod) % mod)
```

```cpp
    std::vector adj(NMAX+1, std::vector<std::pair<int, __int128>>{});
    const int inf = 2e18L;
    for (int i = 0; i <= NMAX; i++) {
        // fact[j] / fact[i] = (i+1) * (i+2) * ... * j <= 10^{18}
        int j = i;
        __int128 prod = 1;
        adj[i] = {{i, 1}};
        while (prod * (j+1) < inf) {
            prod *= (++j);
            adj[i].emplace_back(j, prod);
        }
    }
```

В `adj[i]` сохраняются отношения $j!/i!$ для последовательных $j\ge i$, пока произведение меньше `inf`. Первый элемент `(i, 1)` соответствует отношению $i!/i!=1$.

Тип `__int128` нужен не для хранения факториалов целиком, а для безопасного умножения возле границы $2\cdot 10^{18}$. Списки получаются короткими, поскольку произведение последовательных целых чисел растёт очень быстро.

```cpp
    auto cmp = [&](const auto &lhs, const auto &rhs) {
        auto [ai, i] = lhs;
        auto [aj, j] = rhs;
        if (i <= j) {
            // a[i] < a[j] * (j!/i!)
            int coeff = inf;
            auto it = std::lower_bound(all(adj[i]), std::make_pair(j, i128{}));
            if (it != adj[i].end()) coeff = it->second;
            return a[i] < __int128(a[j]) * coeff;
        } else {
            // a[i] * (i! / j!) < a[j]
            int coeff = inf;
            auto it = std::lower_bound(all(adj[j]), std::make_pair(i, i128{}));
            if (it != adj[j].end()) coeff = it->second;
            return __int128(a[i]) * coeff < a[j];
        }
    };
```

Компаратор упорядочивает пары по значениям $a_i\cdot i!$, не вычисляя факториалы.

При `i <= j` обе части сравнения делятся на $i!$, поэтому проверяется `a[i] < a[j] * (j! / i!)`. Если точное отношение сохранено в `adj[i]`, оно извлекается двоичным поиском. В противном случае отношение не меньше `inf`, и этого порогового значения уже достаточно для правильного сравнения.

Ветка `i > j` действует симметрично: после сокращения $j!$ множитель $i!/j!$ переносится к `a[i]`. Приведение к `__int128` предотвращает переполнение при итоговом умножении.

```cpp
    std::sort(all(pos), cmp);
    std::sort(all(neg), cmp);
```

Обе группы сортируются по значениям $a_i\cdot i!$. В `neg` первый элемент соответствует наименьшему произведению, а в `pos` последний — наибольшему.

```cpp

        std::cout << se << '\n';

        int answ = inf;
        for (auto &[ai, _] : pos)
            answ = std::min(answ, ai);
        std::cout << answ % mod << '\n';

```

Если группа `neg` непуста, минимум определяется первым произведением $a_j\cdot j!$. Массив `fact` хранит факториалы уже по модулю.

Если неположительных коэффициентов нет, все исходные коэффициенты положительны. Их значения при дифференцировании не уменьшаются, поэтому минимум выбирается среди самих `ai`.

```cpp

```

При наличии положительных коэффициентов максимум задаёт последний элемент `pos`, то есть наибольшее произведение $a_i\cdot i!$.

Если положительных коэффициентов нет, дифференцирование не увеличивает ни одно отрицательное значение. Поэтому максимум ищется среди исходных коэффициентов. Прибавление `mod` перед последним взятием остатка переводит отрицательный остаток C++ в неотрицательный.

```python
def cmp(lhs, rhs):
    ai, i = lhs
    aj, j = rhs
    if i <= j:
        # a[i] < a[j] * (j!/i!)
        coeff = inf
        it = bisect_left(adj[i], (j, 0))
        if it != len(adj[i]): coeff = adj[i][it][1]
        x, y = a[i], a[j] * coeff
    else:
        # a[i] * (i! / j!) < a[j]
        coeff = inf
        it = bisect_left(adj[j], (i, 0))
        if it != len(adj[j]): coeff = adj[j][it][1]
        x, y = a[i] * coeff, a[j]
    return (x > y) - (x < y)
```

Функция сравнивает $a_i\cdot i!$ и $a_j\cdot j!$ после сокращения меньшего факториала.

## H. Hidden Hallway Hacking

<details><summary><b>Постановка задачи</b></summary>

Для каждого набора дано $n$ жетонов, на которых записаны целые числа $a_1,a_2,\ldots,a_n$.

Требуется выбрать **непустое подмножество жетонов** максимального размера $k$ так, чтобы сумма записанных на них чисел не делилась на $k$.

Если ни одного подходящего подмножества не существует, нужно вывести $-1$.

Выполняются ограничения:

- $1\le n\le 3\cdot10^5$;
- $-10^{18}\le a_i\le10^{18}$;
- сумма значений $n$ по всем наборам не превосходит $3\cdot10^5$.

</details>

<details><summary><b>Основная идея</b></summary>

Будем перебирать количество удалённых жетонов $i$ в порядке возрастания. Тогда останется $k=n-i$ жетонов, и первый подходящий вариант сразу даст максимальный ответ.

Обозначим сумму всех чисел через $S$, а сумму удалённых — через $D$. Условие принимает вид $S-D\not\equiv0\pmod k$.

Для фиксированного $k$ достаточно рассмотреть остатки всех чисел по модулю $k$:

- если встречаются хотя бы два разных остатка, можно выбрать $i$ удаляемых жетонов так, чтобы получить требуемое неравенство;
- если все остатки равны $r$, сумма любых $i$ удалённых чисел сравнима с $ir$ по модулю $k$. Поэтому вариант подходит тогда и только тогда, когда $S-ir\not\equiv0\pmod k$.

Проверять требуется не более **29 удалений**. Если ни один из этих вариантов не подошёл, ограничения на значения чисел и свойства НОК последовательных модулей гарантируют, что решения нет.

Время работы — $O(30n)$ на один набор, дополнительная память — $O(n)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Нужно сохранить как можно больше жетонов. Значит, имеет смысл начинать с исходного набора, а затем постепенно увеличивать количество удалений.

Пусть удаляется $i$ жетонов, а остаётся $k=n-i$. Обозначим через $S$ сумму всех чисел, через $D$ — сумму удалённых. Сумма оставшихся чисел равна $S-D$, поэтому нас интересует условие

$S-D\not\equiv0\pmod k$.

При $i=0$ выбора нет: остаются все жетоны. Если $S$ не делится на $n$, ответ сразу равен $n$.

Теперь зафиксируем положительное $i<n$. Перебирать все подмножества из $i$ удаляемых жетонов нельзя: их количество может быть огромным. Однако значение $D$ важно лишь по модулю $k$, поэтому посмотрим на остатки чисел при делении на $k$.

**Если встречаются хотя бы два разных остатка**, подходящий набор удаляемых жетонов существует. Докажем это от противного. Предположим, что суммы всех подмножеств размера $i$ имеют один остаток. Возьмём два любых элемента $x$ и $y$. Поскольку $1\le i<n$, можно выбрать подмножество размера $i$, которое содержит $x$, но не содержит $y$. Заменим в нём $x$ на $y$. Остаток суммы, согласно предположению, не изменится, откуда следует $x\equiv y\pmod k$.

Такое рассуждение применимо к любой паре элементов, а значит, все числа должны иметь одинаковые остатки. Получили противоречие. Следовательно, суммы подмножеств размера $i$ принимают хотя бы два различных значения по модулю $k$. Среди них найдётся значение, отличное от $S\bmod k$, а соответствующий набор удалённых жетонов даст $S-D\not\equiv0\pmod k$.

Остаётся случай, когда **все числа имеют один остаток** $r$ по модулю $k$. Тогда для любого выбора $i$ удаляемых жетонов выполняется

$D\equiv ir\pmod k$.

Выбор конкретных жетонов уже ни на что не влияет. Решение для данного $i$ существует тогда и только тогда, когда

$S-ir\not\equiv0\pmod k$.

Таким образом, для каждого количества удалений нам потребуется узнать лишь две вещи:

- сколько различных остатков встречается по модулю $k$;
- чему равен единственный остаток, если он один.

Перебирать $i$ будем в порядке $0,1,2,\ldots$. Поэтому первое найденное значение $k=n-i$ является максимальным возможным ответом.

Осталось объяснить, **почему достаточно проверить только $i<30$**.

Предположим, что варианты с $i=1,2,\ldots,29$ не подошли. Тогда для каждого модуля

$n-1,n-2,\ldots,n-29$

все числа имеют одинаковые остатки. Следовательно, разность любых двух чисел делится на

$L=\text{НОК}(n-1,n-2,\ldots,n-29)$.

Здесь используется следующее числовое свойство:

- при $n\ge44$ выполняется $L>2\cdot10^{18}$;
- для $n\ge61$ это, в частности, следует из оценки $L\ge(n-29)\binom{n-1}{28}$;
- оставшийся конечный диапазон $44\le n\le60$ проверяется разложением этих последовательных чисел на простые множители; минимальное значение НОК в нём уже не меньше $9419588158802421600$.

При этом $|a_x-a_y|\le2\cdot10^{18}$. Единственная разность такого размера, делящаяся на $L>2\cdot10^{18}$, равна нулю. Значит, **все исходные числа равны**. Сумма любых $k$ выбранных чисел тогда равна $ka$ и делится на $k$, поэтому решения нет.

Если $n\le30$, цикл рассматривает все возможные положительные размеры оставшегося набора.

Пусть теперь $31\le n\le43$. Непроверенными могут остаться только размеры $k\le n-30\le13$. Каждый такой $k$ делит хотя бы одно из 29 последовательных чисел $n-29,\ldots,n-1$, а потому делит и их НОК $L$. Разности всех исходных чисел делятся на $L$, следовательно, все числа имеют одинаковый остаток по модулю любого непроверенного $k$. Сумма любых $k$ выбранных чисел сравнима с $kr$, то есть делится на $k$. Для этих размеров решения также нет.

Итак, если ответ существует, он обнаруживается после не более чем 29 удалений. Каждый такой шаг просматривает все $n$ чисел и очищает массив счётчиков длины $n$. Поэтому время работы равно $O(30n)$, а память — $O(n)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
#define all(x) (x).begin(),(x).end()
#define isz(x) (int)(x).size()
#define int int64_t
// для надёжности, функция взятия остатка:
auto remainder(auto a, auto mod) {
    auto result = a % mod;
    if (result < 0) result += mod;
    return result;
}
void solve() {
    int n; std::cin >> n;
    std::vector<int> a(n);
    for (auto &it : a) std::cin >> it;
    // 0 удалений невозможно: S = 0 (mod n)
    // 1 удаление невозможно: S - a[i] = 0 (mod n-1) для любого i => a[i] = S (mod n-1) =>
    // остатки всех элементов равны одному и тому же числу.
    // Похоже, что мы можем добиться неравенства нулю только тогда, когда у нас будет как
    // минимум два различных остатка. Иначе -1
    auto S = std::accumulate(all(a), __int128(0));
    if (remainder(S, n) != 0) { std::cout << n << "\n"; return; }
    std::vector<int> cnt(n);
    for (int i = 1; i < std::min<int>(30, n); i++) { // сколько элементов удаляем
        std::fill(all(cnt), 0);
        for (auto it : a)
            cnt[remainder(it, (n-i))]++;
        int fi = 0;
        while (fi < isz(cnt) && cnt[fi] == 0) fi++;
        int se = fi+1;
        while (se < isz(cnt) && cnt[se] == 0) se++;
        if (se == isz(cnt)) {
            // только один уникальный остаток: пробуем вычесть его из S ровно i раз
            if (remainder((S - i * fi), (n-i)) != 0) {
                std::cout << n-i << "\n";
                return;
            }
        } else {
            // даже проверять не нужно, всегда можем
            std::cout << n-i << "\n";
            return;
        }
    }
    std::cout << "-1\n";
}
int32_t main() {
    int tt = 1; std::cin >> tt;
    while (tt --> 0) solve();
    return 0;
}
```

## J. Jiaozi, Jam, Juice

<details><summary><b>Постановка задачи</b></summary>

Даны $n$ товаров. У товара $i$ есть цена $a_i<c$ и один из трёх типов: основное блюдо **M**, закуска **S** или напиток **D**.

Каждый товар из списка разрешается купить не более одного раза. Покупка оформляется одним из двух способов:

- товар оплачивается отдельно за $a_i$;
- за $c$ покупается непустой набор, содержащий не более одного товара каждого типа.

Если для такого набора недостаёт товаров, их разрешается добавить извне. В ответе учитываются только товары из исходного списка.

Требуется найти **максимальное количество исходных товаров**, которое можно купить, потратив не более $s$.

</details>

<details><summary><b>Основная идея</b></summary>

Будем перебирать количество использованных акций. Пусть оплачено $k$ акций. Тогда в них помещается не более $k$ товаров каждого типа.

При фиксированном $k$ в акции выгодно отправить самые дорогие товары каждого типа: более дешёвые останутся для покупки по отдельности. После этого за оставшийся бюджет будем покупать самые дешёвые из оставшихся товаров.

Количество акций будем увеличивать на один. На каждом шаге в новую акцию попадает самый дорогой оставшийся товар каждого непустого типа. Два дерева отрезков поддерживают среди товаров, ещё не включённых в акции:

- сумму цен на префиксе общего отсортированного списка;
- количество товаров на этом префиксе.

Максимальный доступный по бюджету префикс будем находить двоичным поиском.

Асимптотика по времени — $O(n\log^2(n))$, по памяти — $O(n)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Главная трудность: один и тот же товар можно оплатить либо отдельно, либо в составе акции. Если независимо выбирать способ покупки для каждого товара, число вариантов становится слишком большим. Поэтому сначала отделим вопрос **о количестве акций** от вопроса **о покупке оставшихся товаров**.

Пусть используются $k$ акций. В каждой из них находится не более одного товара каждого типа, поэтому среди акционных товаров присутствует не более:

- $k$ основных блюд;
- $k$ закусок;
- $k$ напитков.

Рассмотрим товары какого-либо одного типа. Предположим, что более дешёвый товар включён в акцию, а более дорогой оставлен для отдельной покупки. Если поменять их местами, допустимость акций сохранится: тип товара не изменился. При этом среди товаров, оплачиваемых отдельно, дорогой товар заменится дешёвым. Значит, суммарные расходы не увеличатся.

Следовательно, при фиксированном $k$ в акции должны входить **самые дорогие товары каждого типа**. Для типа, представленного $m$ товарами, будут выбраны $\min(k,m)$ самых дорогих.

Кроме того, свободное место соответствующего типа в уже оплаченной акции нет смысла оставлять пустым, пока существует невыбранный товар этого типа. Его добавление не меняет стоимость акции, зато увеличивает число купленных товаров. Поэтому для очередной акции будем брать самый дорогой оставшийся товар каждого непустого типа.

Такой способ выбора согласуется с ограничениями акции: на одном шаге берётся не более одного товара каждого типа. Пока хотя бы один из трёх списков не пуст, очередная акция содержит хотя бы один исходный товар.

После оплаты $k$ акций остаётся бюджет $s-kc$. За него можно покупать товары по отдельности. Если требуется купить некоторое количество товаров, наименьшую сумму дают самые дешёвые из оставшихся. Значит, среди оставшихся товаров нас интересует самый длинный префикс в порядке возрастания цены, сумма которого не превосходит текущий бюджет.

Пересобирать список после каждой акции слишком долго. Вместо этого один раз отсортируем все товары по парам $(a_i,i)$. Исходный индекс различает товары с одинаковой ценой, поэтому у каждого товара есть своя позиция.

Над этим порядком будем поддерживать два дерева отрезков:

- `segTreeSum` хранит сумму цен товаров, ещё не включённых в акции;
- `segTreeCnt` хранит количество таких товаров.

Когда товар переходит в акцию, его цена вычитается из первого дерева, а единица — из второго. Позиция остаётся в общем порядке, но её вклад становится нулевым.

Для текущего количества акций будем искать последнюю позицию, до которой сумма активных товаров не превосходит оставшийся бюджет. Здесь возникает нужная для двоичного поиска монотонность: цены неотрицательны, поэтому сумма на префиксе не уменьшается при расширении префикса. Если некоторый префикс слишком дорог, любой более длинный префикс также не подходит.

После двоичного поиска дерево количеств сообщает, сколько не удалённых товаров находится в найденном префиксе. К этому числу прибавляется количество товаров, уже оплаченных акциями.

Случай без акций обработаем отдельно: все товары ещё доступны, поэтому достаточно пройти по общему отсортированному списку и взять самый длинный префикс, укладывающийся в исходный бюджет.

Осталось обосновать, что перебор не пропускает оптимальный ответ.

- Для каждого допустимого числа акций рассматривается лучший выбор акционных товаров: обмен дешёвого акционного товара на более дорогой товар того же типа не ухудшает результат.
- После выбора акционных товаров рассматривается лучшее множество для отдельной покупки: при заданном количестве товаров минимальную цену имеет префикс отсортированного списка.
- Если денег уже не хватает на следующую акцию, большее их количество также недоступно.
- Если все товары перешли в акции, дальнейшие акции не могут увеличить ответ.

Таким образом, для каждого существенного количества акций вычисляется наибольшее достижимое число покупок, а максимум среди этих значений и есть ответ.

Сортировка занимает $O(n\log(n))$. Каждый товар добавляется в деревья и удаляется из них не более одного раза, на что требуется $O(n\log(n))$. Для каждого количества акций выполняется двоичный поиск из $O(\log(n))$ запросов, причём один запрос к дереву работает за $O(\log(n))$. Итоговая асимптотика по времени — $O(n\log^2(n))$, по памяти — $O(n)$.

</details>

```cpp
#include <bits/extc++.h>
#define all(x) (x).begin(),(x).end()
#define isz(x) (int)(x).size()
#define int int64_t
using pii = std::pair<int,int>;
int lowpos(const auto &v, const auto &x) {
    return int(std::lower_bound(all(v), x) - v.begin());
}
struct SegTree {
    std::vector<int> data;
    SegTree(int n) : data(4*n, 0) { }
    void add(int p, int x) {
        add(0, 0, isz(data)/4, p, x);
    }
    int sum(int l, int r) const {
        return sum(0, 0, isz(data)/4, l, r+1);
    }
    int operator()(int l, int r) const {
        return sum(l, r);
    }
    void add(int v, int tl, int tr, int p, int x) {
        if (p < tl || p >= tr) return;
        if (tl + 1 == tr) {
            data[v] += x;
            return;
        }
        int tm = (tl + tr) / 2;
        add(2*v+1, tl, tm, p, x);
        add(2*v+2, tm, tr, p, x);
        data[v] = data[2*v+1] + data[2*v+2];
    }
    int sum(int v, int tl, int tr, int ql, int qr) const {
        if (qr <= tl || ql >= tr) return 0;
        if (ql <= tl && tr <= qr) return data[v];
        int tm = (tl + tr) / 2;
        return sum(2*v+1, tl, tm, ql, qr) + sum(2*v+2, tm, tr, ql, qr);
    }
};

    // читаем входные данные:
    int n, s, c; std::cin >> n >> s >> c;

    std::vector<pii> fi, se, th, coords;

        else if (b[i] == 'S') se.emplace_back(a[i], i);
        else { assert(b[i] == 'D'); th.emplace_back(a[i], i); }
        coords.emplace_back(a[i], i);

    // сортируем:
    std::sort(all(coords));
    std::sort(all(fi));
    std::sort(all(se));
    std::sort(all(th));

    SegTree segTreeSum(isz(coords));
    SegTree segTreeCnt(isz(coords));
    auto insert = [&](auto x) { // вставка товара
        const int ix = lowpos(coords, x);
        segTreeSum.add(ix, +x.first);
        segTreeCnt.add(ix, +1);
    };

        const int ix = lowpos(coords, x);
        segTreeSum.add(ix, -x.first);
        segTreeCnt.add(ix, -1);
    };

    for (const auto &it : coords) insert(it);
    // теперь перебираем все варианты для фиксированного количества акций "три по c"
    // если мы использовали акцию 0 раз, то мы берём k самых дешёвых товаров суммой <= s
    // если мы использовали акцию 1 раз, то нам выгодно купить самый дорогой товар каждого
    // типа, удалить их из дерева отрезков как доступные для покупки, а затем снова купить
    // k самых дешёвых товаров суммой <= s. Так перебираем все варианты и находим лучший
    int answ = 0, best = 0, pref = 0;
    for (const auto &[x, _] : coords)
        if (pref+x <= s) pref += x, best++;
        else break;
    // применяем акцию, пока можем, и считаем лучший вариант для заданного количества акций:
    while ((isz(fi) || isz(se) || isz(th)) && s >= c) {
        // удаляем три самых дорогих товара: включаем их в акцию
        if (isz(fi)) {
            auto item = fi.back();
            fi.pop_back();
            answ++;
            remove(item);
        }
        if (isz(se)) {
            auto item = se.back();
            se.pop_back();
            answ++;
            remove(item);
        }
        if (isz(th)) {
            auto item = th.back();
            th.pop_back();
            answ++;
            remove(item);
        }
        s -= c;
        // теперь бинарным поиском находим, какое максимальное количество товаров можем купить
        // за оставшиеся деньги по одному:
        int low = -1, high = n;
        while (high - low > 1) {
            int mid = (low + high) / 2;
            if (segTreeSum(0, mid) > s) high = mid;
            else low = mid;
        }
        // low - крайний элемент, для которого sum(0, low) <= S
        best = std::max(best, answ + segTreeCnt(0, low));
    }
    std::cout << best << std::endl;
}
```

```python
        segTreeSum.add(ix, -x[0])
        segTreeCnt.add(ix, -1)
    # сперва вставляем туда все элементы:
    for it in coords: insert(it)
    # теперь перебираем все варианты для фиксированного количества акций "три по c"
    # если мы использовали акцию 0 раз, то мы берём k самых дешёвых товаров суммой <= s
    # если мы использовали акцию 1 раз, то нам выгодно купить самый дорогой товар каждого
    # типа, удалить их из дерева отрезков как доступные для покупки, а затем снова купить
    # k самых дешёвых товаров суммой <= s. Так перебираем все варианты и находим лучший
    answ, best, pref = 0, 0, 0
    for x, _ in coords:
        if pref+x <= s: pref += x; best += 1
        else: break

    while (len(fi) or len(se) or len(th)) and s >= c:
        # удаляем три самых дорогих товара: включаем их в акцию
        if len(fi):
            item = fi.pop()
            answ += 1
            remove(item)
        if len(se):
            item = se.pop()
            answ += 1
            remove(item)
        if len(th):
            item = th.pop()
            answ += 1
            remove(item)
        s -= c
        # теперь бинарным поиском находим, какое максимальное количество товаров можем купить
        # за оставшиеся деньги по одному:
        low, high = -1, n
        while high - low > 1:
            mid = (low + high) // 2
            if segTreeSum.sum(0, mid) > s: high = mid
            else: low = mid
        # low - крайний элемент, для которого sum(0, low) <= S
        best = max(best, answ + segTreeCnt.sum(0, low))
    print(best)
```
