## 6. Бинарный поиск по ответу

Вот мы и добрались до **бинарного поиска по ответу**. В первой главе кандидатами были индексы отсортированного массива. Теперь кандидат – сама величина, которую требует найти задача. Массива с готовыми ответами перед нами нет, но мы умеем спросить для любого кандидата: подходит он или нет?

> [!TIP]
> Прежде чем писать бинарный поиск по ответу, ответьте на три вопроса:
>
> - Что является ответом и в каком диапазоне эта величина лежит?
> - Монотонна ли проверка кандидата?
> - Можно ли быстро проверить, подходит ли фиксированный кандидат?
>
> Если на все три вопроса есть ответ, задачу часто можно решить бинарным поиском.

**Рассмотрим задачу**. Есть $n$ $(1 \le n \le 10^{18})$ единичных квадратов. Разрешается взять некоторые из них и сложить в квадрат со стороной $k$. Требуется найти максимальное целое $k$.

**Решение**. Задача сама подсказывает пространство ответов: искать нужно сторону $k$. Для квадрата $k \times k$ потребуется ровно $k^2$ единичных квадратов.

Проверка кандидата получается короткой:

$$
\text{check}(k) = (k^2 \le n).
$$

> [!IMPORTANT]
> Проверка **монотонна**. Если квадрат со стороной $k$ можно собрать, то квадрат со стороной $k-1$ получится автоматически после удаления одной строки и одного столбца.
>
> Если квадрата со стороной $k$ собрать нельзя, то квадрат со стороной $k+1$ тем более собрать не получится.
>
> Для корректности достаточно доказать одну из этих двух сторон монотонности. Вторая здесь нужна только для полноты картины.

Подходящие значения находятся слева, поэтому ищем последний плюс. В коде `low` будет подходящим значением, а `high` – неподходящим.

<details>
<summary><strong>C++: максимальная сторона квадрата</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Читаем число доступных единичных квадратов.
    int64_t n; cin >> n;
    // low подходит, high не подходит. При такой high квадрат mid помещается в int64_t.
    int64_t low = 1, high = 2'000'000'000LL;
    while (high - low > 1) {
        int64_t mid = (low + high) / 2;
        if (mid * mid <= n) low = mid;
        else high = mid;
    }
    cout << low << '\n';
}
```

</details>

<details>
<summary><strong>Python3: максимальная сторона квадрата</strong></summary>

```python
# Читаем число доступных единичных квадратов.
n = int(input())
# low подходит, high не подходит.
low, high = 1, 2_000_000_000
while high - low > 1:
    mid = (low + high) // 2
    if mid * mid <= n: low = mid
    else: high = mid
print(low)
```

</details>


Проверка работает за $O(1)$, а длина пространства ответов не больше $2 \cdot 10^9$. Поэтому поиск требует $O(\log(10^9))$ времени и $O(1)$ дополнительной памяти.

## 7. Как задать границы и выбрать типы данных?

Если мы подумаем, то из условия задачи следует, что ответ ограничен числом $10^9$. Но это не значит, что верхняя граница полуинтервала обязана равняться $10^9 + 1$ в вашем коде.

> [!IMPORTANT]
> Для поиска последнего подходящего значения верхняя граница не обязана быть минимальной неподходящей.

Здесь `low = 1` подходит, потому что $n$ натурально. Любое число больше $10^9$ не подходит. Например, можно взять `high = 1'111'111'111LL`. В рабочей версии выбрано `2'000'000'000LL`: это простая граница с запасом.

> [!WARNING]
> Граница «с запасом» остаётся допустимой только после доказательства, что она не подходит. Если `high` подходит, бинарный поиск может завершиться с неверным ответом.

> [!TIP]
> Если проверка уже доказана, но при отправке получается `Wrong Answer`, проверьте границы. В частности, можно временно увеличить `high` в два раза и повторно проверить её неподходящесть.
>
> Это быстрый способ проверить гипотезу о слишком маленьком диапазоне, но не замена доказательству.

Ещё один практический совет: **не жадничайте с типами**. В задачах на поиск ответа границы, середина и промежуточные произведения быстро становятся больше обычного `int`.

> [!TIP]
> Для целых границ и вычислений сразу выбирайте `int64_t`, если ограничения допускают большие числа.
>
> - `low + high` не переполнится при наших границах.
> - Середина всегда меньше `high`, поэтому произведение `mid * mid` меньше $4 \cdot 10^{18}$ и также помещается в `int64_t`.
> - При необходимости верхнюю границу можно увеличить, не переписывая весь код под другой тип.

Выражения приведения к 64-битному типу вроде `mid * 1LL * mid` выглядят круто, но не помогают сдать правильное решение без багов раньше конкурентов.

## 8. Почему не `sqrt`?

Математически ответ равен $\lfloor\sqrt{n}\rfloor$. Кажется, что можно вычислить `sqrt(n)`, отбросить дробную часть и закончить задачу без бинарного поиска. Проблема в том, что обычный `sqrt` работает с `double` и может округлить значение вверх.

В GCC есть специальный вариант `sqrtl`, который возвращает `long double`. При данных ограничениях выражение `(int64_t)sqrtl(n)` даёт правильный ответ, но опирается на точность `long double` в конкретном компиляторе.

Пусть $p = 999\,999\,999$. Для $n = p^2 - 1$ верный ответ равен $p - 1 = 999\,999\,998$. Однако на обычных реализациях с числами IEEE 754 следующий код печатает $999\,999\,999$.

<details>
<summary><strong>C++: ненадёжный вариант с sqrt</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Демонстрация: преобразование результата sqrt может дать неверный целый корень.
    int64_t n; cin >> n;
    cout << (int64_t)sqrt(n) << '\n';
}
```

</details>

<details>
<summary><strong>Python3: ненадёжный вариант с sqrt</strong></summary>

```python
import math
# Демонстрация: преобразование результата sqrt может дать неверный целый корень.
n = int(input())
print(int(math.sqrt(n)))
```

</details>

Полные демонстрационные программы: [C++](examples/example-02.cpp) и [Python3](examples/example-02.py).

<details>
<summary><strong>Контрпример</strong></summary>

```text

Неверный вывод варианта с sqrt

Правильный ответ

```

</details>

> [!CAUTION]
> Преобразование `sqrt(n)` к целому типу не является надёжным способом получить целый квадратный корень.
>
> В GCC при данных ограничениях можно использовать `(int64_t)sqrtl(n)`, но этот приём зависит от точности `long double`.
> 
> Бинарный поиск работает только с целыми числами и не зависит от этой особенности компилятора.

Можно оставить обычный `sqrt`, но считать его результат только начальным кандидатом. Сначала увеличиваем $k$, пока следующий кандидат подходит, затем уменьшаем $k$, пока текущий кандидат не подходит. После этих двух проверок выполнено $k^2 \le n < (k + 1)^2$, поэтому $k = \lfloor\sqrt{n}\rfloor$.

> [!TIP]
> После вычисления приближённого ответа проверяйте его тем же целочисленным предикатом, который определяет правильный ответ.

В C++ этот приём выглядит так:

```cpp
int64_t k = sqrt(n);
while ((k + 1) * (k + 1) <= n) k++;
while (k * k > n) k--;
cout << k << '\n';
```

В Python проверки те же:

```python
k = int(math.sqrt(n))
while (k + 1) * (k + 1) <= n: k += 1
while k * k > n: k -= 1
print(k)
```

При данных ограничениях `sqrt` с `double` промахивается не более чем на единицу, поэтому выполнится не больше одной итерации одного из циклов. Целочисленная проверка всё равно нужна: именно она превращает приближённый результат в точный.

## 9. Последовательность квадратов

**Рассмотрим задачу**. Есть $n$ $(1 \le n \le 10^{18})$ единичных квадратов. Сначала собираем квадрат $1 \times 1$ и кладём его на стол. Затем из оставшихся квадратов собираем квадрат $2 \times 2$ и кладём справа от первого. Продолжаем со сторонами $3$, $4$ и так далее, пока квадратов хватает. Требуется найти число полных квадратов на столе.

**Решение с формулой**. На шаге $i$ расходуется $i^2$ единичных квадратов. Чтобы выложить первые $k$ квадратов, потребуется

$$
S(k) = 1^2 + 2^2 + \dots + k^2 = \frac{k(k + 1)(2k + 1)}{6}.
$$

Например, при $n = 100$ первые шесть квадратов потребуют $1 + 4 + 9 + 16 + 25 + 36 = 91$ клетку, а седьмой увеличит расход до $140$. Ответ равен $6$.

Подходит кандидат $k$, для которого $S(k) \le n$. Предикат монотонен: если на первые $k$ квадратов хватает клеток, то хватит и на первые $k - 1$. Поэтому снова ищем последний плюс.

<details>
<summary><strong>C++: бинарный поиск с формулой суммы квадратов</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
int64_t sumSquares(int64_t k) {
    return k * (k + 1) * (2 * k + 1) / 6;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Ищем последнее k, для которого хватает квадратов на все фигуры от 1 до k.
    int64_t n; cin >> n;
    int64_t low = 0, high = 1'500'000;
    while (high - low > 1) {
        int64_t mid = (low + high) / 2;
        if (sumSquares(mid) <= n) low = mid;
        else high = mid;
    }
    cout << low << '\n';
}
```

</details>

<details>
<summary><strong>Python3: бинарный поиск с формулой суммы квадратов</strong></summary>

```python
def sum_squares(k):
    return k * (k + 1) * (2 * k + 1) // 6

    mid = (low + high) // 2
    if sum_squares(mid) <= n: low = mid
    else: high = mid
print(low)
```

</details>

Проверка занимает $O(1)$, поиск – $O(\log(\sqrt[3]{n}))$, а дополнительная память – $O(1)$.

**Решение без формулы**. Можно не помнить сумму квадратов. Заведём `sums`, где `sums[k]` – расход на первые $k$ квадратов. Начинаем с `sums[0] = 0` и добавляем $k^2$, пока следующее значение не превысит $10^{18}$. Массив строго возрастает, поэтому `upper_bound` в C++ и `bisect_right` в Python найдут первое значение больше $n$. Его предыдущий индекс и будет ответом.

> [!TIP]
> Префиксные суммы строятся один раз. Если в задаче много запросов с разными $n$, одну и ту же таблицу можно использовать для всех них.

<details>
<summary><strong>C++: префиксные суммы без формулы</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Храним все возможные расходы, не превосходящие ограничение на n.
    vector<int64_t> sums = {0};
    for (int64_t k = 1; sums.back() + k * k <= 1'000'000'000'000'000'000LL; k++)
        sums.push_back(sums.back() + k * k);
    // Отвечаем на запрос последним расходом, не превосходящим n.
    int64_t n; cin >> n;
    cout << upper_bound(sums.begin(), sums.end(), n) - sums.begin() - 1 << '\n';
}
```

</details>

<details>
<summary><strong>Python3: префиксные суммы без формулы</strong></summary>

```python
from bisect import bisect_right
# Храним все возможные расходы, не превосходящие ограничение на n.
sums = [0]
k = 1
while sums[-1] + k * k <= 10 ** 18:
    sums.append(sums[-1] + k * k)
    k += 1
# Отвечаем на запрос последним расходом, не превосходящим n.
n = int(input())
print(bisect_right(sums, n) - 1)
```

</details>

Полные программы: [C++](examples/example-04.cpp) и [Python3](examples/example-04.py).

Предподсчёт создаёт $1\,442\,249$ положительных значений и занимает $O(k)$ времени и памяти. После него один запрос обрабатывается за $O(\log(k))$. Для одного $n$ вариант с формулой легче и быстрее, а для многих запросов предподсчёт остаётся удобной альтернативой.

**Почему не кубическое уравнение**. Если подставить формулу в равенство $S(k) = n$, получится

$$
2k^3 + 3k^2 + k - 6n = 0.
$$

Все три корня можно записать непосредственно через $n$:

$$
\begin{aligned}
k_1 &= \frac{\sqrt[3]{12n + \sqrt{144n^2 - \frac{1}{27}}} + \sqrt[3]{12n - \sqrt{144n^2 - \frac{1}{27}}} - 1}{2}, \\
k_2 &= \frac{\frac{-1 + i\sqrt{3}}{2}\sqrt[3]{12n + \sqrt{144n^2 - \frac{1}{27}}} + \frac{-1 - i\sqrt{3}}{2}\sqrt[3]{12n - \sqrt{144n^2 - \frac{1}{27}}} - 1}{2}, \\
k_3 &= \frac{\frac{-1 - i\sqrt{3}}{2}\sqrt[3]{12n + \sqrt{144n^2 - \frac{1}{27}}} + \frac{-1 + i\sqrt{3}}{2}\sqrt[3]{12n - \sqrt{144n^2 - \frac{1}{27}}} - 1}{2}.
\end{aligned}
$$

> [!NOTE]
> При $n \ge 1$ первый корень вещественный, а второй и третий образуют комплексно-сопряжённую пару. Математический ответ задачи равен целой части первого корня.

<details>
<summary><strong>Вывод через формулы Кардано</strong></summary>

Сделаем замену $t = 2k + 1$. Тогда

$\frac{t^3 - t}{4} = 6n, \qquad t^3 - t - 24n = 0$.

Это пониженное кубическое уравнение. Обозначим

$D = 144n^2 - \frac{1}{27}, \qquad u = \sqrt[3]{12n + \sqrt{D}}, \qquad v = \sqrt[3]{12n - \sqrt{D}}$.

Пусть $\omega = \frac{-1 + i\sqrt{3}}{2}$, где $\omega^3 = 1$ и $\omega \ne 1$. По формуле Кардано получаем

$k_1 = \frac{u + v - 1}{2}$.

$k_2 = \frac{\omega u + \omega^2 v - 1}{2}$.

$k_3 = \frac{\omega^2 u + \omega v - 1}{2}$.

</details>

Формула даёт точное выражение, но для программы его всё равно нужно привести к целому и исправить циклами с проверкой $S(k) \le n$. Такая реализация длиннее бинарного поиска, зависит от вычислений с вещественными числами и требует целочисленной проверки в конце.

> [!WARNING]
> Простой `cbrt(n)` задаёт лишь порядок ответа, а не близкое значение самого $k$. При $n = 10^{18}$ оно равно $10^6$, тогда как правильный ответ равен $1\,442\,249$. Цикл, который увеличивает такой кандидат на единицу, выполнит более $400\,000$ шагов. На версии задачи с несколькими тестами это не заменяет бинарный поиск.

В следующей главе мы сохраним тот же подход, но проверка перестанет быть одной формулой. Сам цикл бинарного поиска останется коротким, а главной частью решения станет `check`.
