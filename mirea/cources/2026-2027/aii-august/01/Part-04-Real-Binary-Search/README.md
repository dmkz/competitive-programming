## 13. Вещественный бинарный поиск по ответу

В предыдущих главах кандидат был целым числом. Как только между `low` и `high` не оставалось целого значения, поиск завершался. Для вещественных чисел соседних значений нет: между $2$ и $2{,}000001$ лежит бесконечно много кандидатов.

Значит, в задачах с вещественным ответом мы не находим число в точности. Мы поддерживаем отрезок, в котором лежит ответ, и сужаем его до заранее выбранной точности. Сама идея из прошлой главы не меняется: `check(x)` отвечает, подходит ли кандидат $x$, а бинарный поиск сохраняет подходящую левую и неподходящую правую границы.

```cpp
using ld = long double;
ld low = ..., high = ...;
for (int iter = 0; iter < 100; iter++) {
    ld mid = (low + high) / 2;
    if (check(mid)) low = mid;
    else high = mid;
}
cout << fixed << setprecision(10) << low << '\n';
```

> [!IMPORTANT]
> После каждой итерации `low` остаётся подходящим, а `high` – неподходящим. Поэтому печатаем `low`: это гарантированно допустимое приближение ответа снизу.

За один шаг расстояние между границами уменьшается вдвое. Если исходная ширина отрезка равна $r$, то после $t$ шагов она равна

$$
\frac{r}{2^t}.
$$

Чтобы получить абсолютную погрешность не больше $\varepsilon$, достаточно выбрать

$$
t \ge \left\lceil \log_2\left(\frac{r}{\varepsilon}\right) \right\rceil.
$$

На практике часто выполняют $100$ итераций. При начальной ширине не больше $10^9 + 1$ математическая ширина интервала после них меньше $10^{-20}$. Это намного точнее обычного требования $10^{-6}$, а фиксированное число шагов избавляет от ненадёжного сравнения вещественных чисел в условии остановки.

> [!TIP]
> Сначала оцените начальную ширину отрезка и требуемую точность, затем выберите число итераций с запасом. Не ждите, что `mid` когда-либо совпадёт с точным ответом.

Посмотрим, как такой поиск работает в задаче.

## 14. Нарезка отрезков

**Рассмотрим задачу**. Даны $n$ $(1 \le n \le 2 \cdot 10^5)$ отрезков целой длины $a_i$ $(1 \le a_i \le 10^9)$ и число $m$ $(1 \le m \le 10^9)$. Каждый отрезок разрешается разрезать на части одной и той же одинаковой вещественной длины $x$, остатки выбрасываются. Требуется найти наибольшую длину $x$, из которой получится не меньше $m$ частей.

**Решение.** Пусть `check(x)` проверяет длину одной части $x$. Из отрезка длины $a_i$ можно получить $\left\lfloor a_i / x \right\rfloor$ полных частей. Значит, суммарное число частей равно

$$
P(x) = \sum_{i=1}^{n} \left\lfloor \frac{a_i}{x} \right\rfloor.
$$

Кандидат подходит, если $P(x) \ge m$.

Проверка на **монотонность**. При увеличении $x$ каждое слагаемое в этой сумме не возрастает. Поэтому если длина $x$ подходит, то любая меньшая положительная длина тоже подходит. Подходящие значения стоят слева, неподходящие справа, и снова можно искать границу между `+` и `-`.

Разберём отрезки $[5, 8, 3]$ и $m = 7$.

| длина части $x$ | части из 5 | части из 8 | части из 3 | всего | `check(x)` |
| ---: | ---: | ---: | ---: | ---: | --- |
| 3 | 1 | 2 | 1 | 4 | - |
| 2,5 | 2 | 3 | 1 | 6 | - |
| 2 | 2 | 4 | 1 | 7 | + |
| 1,5 | 3 | 5 | 2 | 10 | + |

Граница находится в точке $2$. В отличие от целого поиска, алгоритм не должен увидеть именно это число. Достаточно сделать интервал между границами существенно меньше разрешённой ошибки.

> [!NOTE]
> В этой задаче требуется **хотя бы** $m$ частей, а не ровно $m$. При меньшей длине частей может получиться больше, и это только подтверждает, что кандидат подходит.

## 15. Границы, проверка и точность

Для левой границы берём `low = 0`. Это служебная подходящая граница, но `check(0)` вызывать нельзя: в ней было бы деление на ноль. В первом и всех следующих шагах `mid` строго больше нуля, поэтому проверка получает только допустимые длины.

Правая граница `high = max(a) + 1` точно не подходит. Самый длинный исходный отрезок короче `high`, поэтому не даст даже одной части такой длины. Итак, перед началом поиска ответ лежит между `low` и `high`.

В `check` последовательно суммируем число частей. Полная сумма может быть гораздо больше $m$, но большего нам знать не нужно. Как только частей стало хотя бы $m$, возвращаем `true`. В C++ это заодно защищает счётчик от переполнения: если число частей от очередного отрезка уже достаточно, функция завершится до преобразования его к `int64_t`.

> [!WARNING]
> Не заменяйте досрочную проверку строкой `pieces += length / x`. Для очень маленького $x$ значение может не поместиться в целочисленный счётчик, хотя ответ `true` уже известен.

После $100$ делений пополам печатаем `low` с десятью знаками после запятой. В C++ для вычислений выбран `long double` с обычным олимпиадным сокращением `ld`, в Python обычный `float` уже даёт достаточную точность для этой задачи.

<details>
<summary><strong>C++: нарезка отрезков</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
using ld = long double;
bool check(const auto& a, int64_t m, ld x) {
    int64_t pieces = 0;
    for (auto it : a) {
        ld count = it / x;
        if (count >= m - pieces) return true;
        pieces += (int64_t)count;
    }
    return false;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Ищем наибольшую длину, из которой получится хотя бы m отрезков.
    int n; int64_t m; cin >> n >> m;
    vector<int64_t> a(n);
    for (auto& it : a) cin >> it;
    ld low = 0, high = *max_element(a.begin(), a.end()) + 1;
    for (int iter = 0; iter < 100; iter++) {
        ld mid = (low + high) / 2;
        if (check(a, m, mid)) low = mid;
        else high = mid;
    }
    cout << fixed << setprecision(10) << low << '\n';
}
```

</details>

<details>
<summary><strong>Python3: нарезка отрезков</strong></summary>

```python
def check(a, m, x):
    pieces = 0
    for length in a:
        count = length / x
        if count >= m - pieces: return True
        pieces += int(count)
    return False
# Ищем наибольшую длину, из которой получится хотя бы m отрезков.
n, m = map(int, input().split())
a = list(map(int, input().split()))
low, high = 0.0, max(a) + 1.0
for iter in range(100):
    mid = (low + high) / 2
    if check(a, m, mid): low = mid
    else: high = mid
print(f'{low:.10f}')
```

</details>
