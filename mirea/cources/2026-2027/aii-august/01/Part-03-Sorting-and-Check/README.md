## 10. Проверка кандидата в отдельной функции

В прошлой главе проверка кандидата была короткой формулой. Но в задачах поинтереснее для фиксированного ответа нужно сначала построить план: выбрать элементы, сопоставить пары, посчитать цену этого плана. Если писать всё внутри цикла бинарного поиска, сам поиск теряется среди деталей задачи.

Поэтому <u>вынесем проверку кандидата в функцию `check`</u>. Она получает только кандидат `x` и отвечает на один вопрос: может ли `x` быть ответом. Все остальные данные уже прочитаны и при необходимости подготовлены до бинарного поиска.

```cpp
bool check(int64_t x) {
    // Проверяем, может ли x быть ответом на задачу?
    ...
}
while (high - low > 1) {
    int64_t mid = (low + high) / 2;
    if (check(mid)) low = mid;
    else high = mid;
}
cout << low << endl;
```

Здесь, как и раньше, `low` подходит, а `high` не подходит. Цикл ничего не знает о смысле кандидата. Он лишь находит последний плюс в монотонной последовательности значений `check`.

> [!IMPORTANT]
> У `check(x)` должен быть точный смысл. Для задачи на максимум она обычно отвечает «можно получить **хотя бы** `x`». Тогда из `check(x) = true` автоматически следует `check(x - 1) = true`, и бинарный поиск ищет последнюю подходящую границу.

Разделение полезно по трём причинам. Во-первых, внешний цикл больше не меняется от задачи к задаче. Во-вторых, доказательство корректности распадается на две независимые части: мы доказываем точность `check` и её монотонность. В-третьих, проверку легко отладить отдельно: подставить конкретный `x`, вручную построить план и сравнить его цену с тем, что посчитала функция.

> [!TIP]
> Сначала напишите и проверьте `check` для нескольких значений кандидата, а уже затем оборачивайте её бинарным поиском. Если функция ошибается для фиксированного `x`, смена границ `low` и `high` этого не исправит.

В следующих двух задачах цикл будет одинаковым. Изменится только содержимое `check`: сначала она выберет выгодные элементы одного массива, затем составит выгодные пары в игре.

## 11. Сколько чисел можно поднять до порога?

**Рассмотрим задачу**. Даны $n$ $(1 \le n \le 2 \cdot 10^5)$ чисел $a_i$ $(0 \le a_i \le 10^9)$, запас $k$ $(0 \le k \le 10^{18})$ единичных увеличений и порог $x$ $(1 \le x \le 10^9)$. За одно увеличение разрешается прибавить $1$ к любому числу. Требуется найти наибольшее количество чисел, которые можно сделать больше либо равными $x$.

**Решение**. Пусть кандидат `mid` означает, что мы хотим подготовить хотя бы `mid` чисел. Тогда `check(mid)` должна вернуть `true` тогда и только тогда, когда минимальная цена такой подготовки не превосходит $k$.

**Предикат монотонен**. Если удалось поднять `mid` чисел, можно оставить только `mid - 1` из них и получить меньший результат. Поэтому последовательность проверок имеет вид `+ + ... + - - ... -`, а бинарный поиск действительно найдёт максимум.

Остаётся найти **минимальную цену**, с помощью которой мы достигнем ответ `>= mid`. Сначала отсортируем массив. Для подготовки выгодно выбрать `mid` наибольших чисел и увеличивать только их.

<details>
<summary><strong>Почему выбираем самые большие числа?</strong></summary>

Пусть выбрано число $a_p$, а большее $a_q$ осталось вне выбора. Если заменить $a_p$ на $a_q$, нужное число увеличений не вырастет: $\max(0, x - a_q) \le \max(0, x - a_p)$.

Повторяя такой обмен, получаем первые `mid` чисел массива, отсортированного по убыванию.

</details>

Для каждого из них нужно доплатить недостачу до $x$, если она есть. Минимальная цена равна

$$
C(\text{mid}) = \sum_{i=0}^{\text{mid}-1} \max(0, x - a_i).
$$

Значит, `check(mid)` вычисляет эту сумму и сравнивает её с $k$. Как только накопленная цена стала больше $k$, функция сразу возвращает `false`: точное значение суммы уже не влияет на ответ.

Разберём массив $a = [1, 2, 8, 9]$, порог $x = 10$ и запас $k = 3$.

| `mid` | выбранные числа | минимальная цена | `check(mid)` |
| ---: | --- | ---: | --- |
| 0 | нет | 0 | + |
| 1 | 9 | 1 | + |
| 2 | 8, 9 | 3 | + |
| 3 | 2, 8, 9 | 11 | - |
| 4 | 1, 2, 8, 9 | 20 | - |

Последний плюс находится при `mid = 2`, это и есть ответ.

> [!IMPORTANT]
> В `check` не нужно искать какой-нибудь допустимый набор элементов. Нужен набор с **минимальной** ценой. Только после этого сравнение с $k$ честно отвечает на вопрос, достижим ли кандидат.

Полная программа повторяет общий шаблон. Сортировка по убыванию выполняется один раз до поиска, а `check` проходит по выбранному префиксу массива.

<details>
<summary><strong>C++: сколько чисел можно поднять до x</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
bool check(const auto& a, int64_t x, int64_t k, int mid) {
    // Считаем цену подготовки mid наибольших чисел.
    int64_t need = 0;
    for (int i = 0; i < mid; i++) {
        need += max(0LL, x - a[i]);
        if (need > k) return false;
    }
    return true;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Читаем числа, запас увеличений и порог.
    int n; int64_t k, x;
    cin >> n >> k >> x;
    vector<int64_t> a(n);
    for (auto& it : a) cin >> it;
    // Сортируем по убыванию, чтобы улучшать первые элементы.
    sort(a.rbegin(), a.rend());
    // Ищем наибольшее достижимое количество подготовленных чисел.
    int low = 0, high = n + 1;
    while (high - low > 1) {
        int mid = (low + high) / 2;
        if (check(a, x, k, mid)) low = mid;
        else high = mid;
    }
    // Выводим максимальное количество.
    cout << low << '\n';
}
```

</details>

## 12. Игра с двумя мультимножествами

Теперь усложним проверку. Есть два игрока и два мультимножества чисел. До игры мы можем увеличить свои числа, а затем начать играть. Каждый раунд состоит из шагов:
1. Соперник выбирает число из своего мультимножества и кладёт его на стол;
2. Мы выбираем число из нашего мультимножества и кладём его на стол.

Если наше число больше либо равно числу соперника, мы получаем очко. Требуется максимизировать число очков.

Это излюбленный баян соревнований по спортивному программированию (Яндекс Алгоритм, РуКод, ICPC, т.д.). Внешне задача похожа на игру, но после того как известны оба мультимножества, надо не моделировать ходы, а составить выгодные пары.

**Формально** даны $n$ $(1 \le n \le 2 \cdot 10^5)$ чисел $a_i$ $(0 \le a_i \le 10^9)$, $n$ чисел $b_i$ $(0 \le b_i \le 10^9)$ и запас $k$ $(0 \le k \le 10^{18})$ единичных увеличений для чисел первого игрока. Соперник выкладывает число из $b$, затем первый игрок отвечает числом из $a$. До начала игры разрешается потратить не более $k$ увеличений на числа из $a$. Найдите наибольшее число очков первого игрока.

**Решение**. Фиксируем `mid`: хотим получить хотя бы `mid` побед.

Проверим **монотонность**. Если есть план на `mid` очков, достаточно оставить в нём любые `mid - 1` запланированных побед. При этом на остальных парах иногда тоже получится победить без вложений, но лишнее очко не мешает предикату «хотя бы `mid`».

Сортируем оба мультимножества.

> [!IMPORTANT]
> После сортировки по возрастанию берём суффикс `a[n - mid] ... a[n - 1]` из `mid` максимальных наших чисел и префикс `b[0] ... b[mid - 1]` из `mid` минимальных чисел соперника.
>
> Сопоставляем их последовательно: `a[n - mid]` ставим против `b[0]`, затем `a[n - mid + 1]` против `b[1]` и так далее.
>
> Остальные числа можно сопоставить как угодно, не беспокоясь о результате: они не важны для плана получить хотя бы `mid` очков.

<details>
<summary><strong>Почему этот план имеет минимальную цену?</strong></summary>

Выбор первых обосновывается тем же обменом, что и в предыдущей задаче: большее своё число не дороже поднять до любой цели. Выбор вторых тоже обосновывается обменом: если мы готовы победить большее число соперника, то тем же своим числом победим меньшее не дороже.

Почему сопоставляем именно в этом порядке? Пусть два своих числа $p \le q$, а два числа соперника $r \le s$. В последовательном варианте получаются пары $p$ с $r$ и $q$ с $s$. Если они перекрещены, то есть $p$ поставлено против $s$, а $q$ против $r$, поменяем числа соперника местами. Большая цель $s$ достаётся не меньшему числу $q$, поэтому суммарная недостача не растёт. Повторяя такой обмен, приходим к последовательному сопоставлению суффикса `a` и префикса `b`.

</details>

Таким образом, минимальная цена `mid` запланированных побед равна

$$
C(\text{mid}) = \sum_{i=0}^{\text{mid}-1} \max(0, b_i - a_{n-\text{mid}+i}).
$$

Здесь слагаемое с `i = 0` – цена пары `b[0]` и `a[n - mid]`, а слагаемое с `i = mid - 1` – цена пары `b[mid - 1]` и `a[n - 1]`. Именно эту сумму считает `check(mid)`: она последовательно бьёт префикс `b` суффиксом `a`. В ней появились два решения, которых не было в первой задаче: какие числа выбрать с обеих сторон и как составить пары. А цикл бинарного поиска остался прежним.

Разберём $a = [1, 2, 8, 9]$, $b = [3, 7, 10, 12]$ и $k = 3$. Для `mid = 3` план выглядит так:

| роль пары | число соперника | наше число | цена увеличений |
| --- | ---: | ---: | ---: |
| не планируем очко | 12 | 1 | 0 |
| планируем очко | 3 | 2 | 1 |
| планируем очко | 7 | 8 | 0 |
| планируем очко | 10 | 9 | 1 |

Цена равна $2$, поэтому `check(3)` возвращает `true`. Для `mid = 4` придётся поднять все свои числа. Цена станет $2 + 5 + 2 + 3 = 12$, она больше $k$. Ответ равен $3$.

> [!WARNING]
> Стоимость пары равна `max(0, b[i] - a[j])`, а не просто `b[i] - a[j]`. Уже выигранная пара не возвращает увеличения в запас, её цена равна нулю.

<details>
<summary><strong>C++: максимальное число побед</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
bool check(const auto& a, const auto& b, int64_t k, int mid) {
    // Считаем цену mid запланированных побед.
    int64_t need = 0;
    int firstWin = a.size() - mid;
    for (int i = 0; i < mid; i++) {
        need += max(0LL, b[i] - a[firstWin + i]);
        if (need > k) return false;
    }
    return true;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Читаем оба мультимножества и запас увеличений.
    int n; int64_t k; cin >> n >> k;
    vector<int64_t> a(n), b(n);
    for (auto& it : a) cin >> it;
    for (auto& it : b) cin >> it;
    // Сортируем, чтобы сопоставлять малые и большие значения по ролям.
    sort(a.begin(), a.end());
    sort(b.begin(), b.end());
    // Ищем наибольшее достижимое количество побед.
    int low = 0, high = n + 1;
    while (high - low > 1) {
        int mid = (low + high) / 2;
        if (check(a, b, k, mid)) low = mid;
        else high = mid;
    }
    // Выводим максимальное количество побед.
    cout << low << '\n';
}
```

</details>
