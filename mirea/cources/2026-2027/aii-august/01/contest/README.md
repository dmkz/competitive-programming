# Разбор задач

## A. Шахматная доска

<details>
<summary>Текстовый разбор</summary>

Пусть сторона будущей доски равна $x$. Всего на ней $x^2$ клеток. Цвета чередуются, а левая нижняя клетка чёрная, поэтому чёрных клеток ровно $\left\lceil \frac{x^2}{2} \right\rceil$.

Можно получить ту же величину без вещественных чисел. Из $x^2$ клеток сначала отнесём к белым $\left\lfloor x^2/2 \right\rfloor$ клеток, а остальные будут чёрными.

Теперь в бинарном поиске будем спрашивать «хватит ли $n$ чёрных клеток на сторону `side`?». Ответом будет проверка $\left\lceil \frac{\text{side}^2}{2} \right\rceil \le n$.

Если клеток хватает на сторону `side`, то их хватит и на любую меньшую сторону. Значит, выполняется монотонность, и можно искать последнюю подходящую сторону бинарным поиском.

**Выбор границ поиска**. В коде `low` всегда хранит подходящую сторону, а `high` — неподходящую. Сторона $0$ подходит всегда, поэтому `low = 0`. Для $n \le 10^{18}$ ответ меньше $2 \cdot 10^9$: доска со стороной $2 \cdot 10^9$ требует $2 \cdot 10^{18}$ чёрных клеток, которых по условию нет. Поэтому `high = 2e9` точно неподходящая граница. Кроме того, квадрат этой границы равен $4 \cdot 10^{18}$ и ещё помещается в `long long`.

**Асимптотика** одного набора: $O(\log n)$ по времени и $O(1)$ дополнительной памяти.

</details>

<details>
<summary>Решение на C++ (<code>A.cpp</code>)</summary>

```cpp
// Решим задачу бинарным поиском по стороне квадрата. Если мы знаем сторону, то знаем и
// площадь. В квадрате чёрных и белых клеток примерно поровну. Для нечётной длины чёрных
// клеток на 1 больше, чем белых, поэтому, если k - сторона квадрата, то точная формула
// для количества чёрных клеток равна (k^2+1)/2. Условие того, что сторона нам подходит:
// (k^2+1)/2 <= n. Ищем ответ на полуинтервале [0, 2*10^9).
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
// Функция проверки: можем ли мы получить квадрат со стороной side?
bool check(ll side, ll n) {
	// чёрных и белых квадратов примерно поровну, около половины:
	ll square = side * side;
	ll white = square / 2;
	ll black = square - white;
	return black <= n;
}
void solve() {
	ll n; cin >> n;
	ll low = 0, high = 2e9L;
	while (high - low > 1) {
		ll mid = (low + high) / 2;
		if (check(mid, n)) low = mid;
		else high = mid;
	}
	cout << low << '\n';
}
main() {
	int tt; cin >> tt;
	while (tt --> 0) solve();
}
```

<details>
<summary>Разбор решения на C++</summary>

Вычисление числа чёрных клеток записано так:

```cpp
ll square = side * side;
ll white = square / 2;
ll black = square - white;
```

При чётном `square` белых и чёрных клеток поровну. При нечётном целочисленное деление отдаёт белым меньшую половину, а оставшаяся клетка становится чёрной. Поэтому выражение работает для обеих чётностей стороны и не использует округление вещественных чисел.

Инвариант бинарного поиска поддерживает эта ветка:

```cpp
if (check(mid, n)) low = mid;
else high = mid;
```

При истинной проверке `mid` может стать новой лучшей стороной, поэтому он заменяет `low`. При ложной проверке все стороны от `mid` и выше тоже не подходят, поэтому `high` можно сдвинуть в `mid`. Когда разность границ равна $1$, поиск останавливается.

## B. Принтеры

<details>
<summary>Текстовый разбор</summary>

Смоделировать печать по секундам нельзя: времена и ответ могут быть очень большими. Вместо этого зафиксируем момент времени $t$ и научимся отвечать, успели ли принтеры вместе напечатать хотя бы $k$ страниц за время $t$.

Рассмотрим принтер $i$. До момента $d_i$ он разогревается и не печатает ничего. После разогрева его $j$-я страница готова в момент $d_i + j \cdot p_i$.

Чтобы эта страница была готова к моменту $t$, нужно $d_i + j \cdot p_i \le t$, то есть $j \le \left\lfloor \frac{t-d_i}{p_i} \right\rfloor$.

Количество не может быть отрицательным и не может превосходить запас листов $c_i$. Поэтому вклад одного принтера равен $\min\left(c_i, \max\left(0, \left\lfloor \frac{t-d_i}{p_i} \right\rfloor\right)\right)$.

Сложим вклады всех принтеров. Если сумма не меньше $k$, момент $t$ подходит. При увеличении $t$ ни один принтер не теряет уже напечатанные страницы, значит проверка **монотонна**: ложные времена идут сначала, а истинные — после них.

**Выбор границ**. Ищем первый истинный момент. `low = 0` можно считать неподходящей границей: за нулевое время нельзя получить требуемое положительное число страниц. Верхняя граница `4e18` подходит с большим запасом. Даже один принтер заканчивает свой запас не позже $d_i+c_i p_i \le 10^9+10^9\cdot10^9 < 4\cdot10^{18}$, а по условию суммарного запаса достаточно.

В конце `high` — минимальное подходящее время.

**Асимптотика** одного набора: $O(n \log(4\cdot10^{18}))$ по времени и $O(n)$ памяти.

</details>

<details>
<summary>Решение на C++ (<code>B.cpp</code>)</summary>

```cpp
// Будем делать бинарный поиск по ответу - по времени, необходимому для печати k страниц.
// Если мы зафиксируем время t, то сможем для одного принтера посчитать, сколько страниц он
// напечатает. Сначала принтер разогревается d[i] секунд, потом на печать каждой страницы
// уходит p[i] секунд. Следовательно, j-я страница будет напечатана в момент времени
// d[i] + j * p[i]. Чтобы посчитать, сколько страниц напечатает принтер, нужно найти
// индекс максимальной страницы, которую принтер успеет напечатать, то есть, максимальное
// значение j, удовлетворяющее условию: d[i] + j * p[i] <= t ==> j <= (t - d[i]) / p[i].
// Естественные ограничения из условия задачи: 0 <= j <= c[i].
// Итоговая формула: min(c[i], max(0, (t - d[i]) / p[i]).
// Зная формулу, для фиксированного момента времени для каждого принтера сможем посчитать,
// сколько страниц он напечатает, и использовать это в проверке ответа.
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
void solve() {
	int n, k; cin >> n >> k;
	vector<int> d(n), p(n), c(n);
	for (int i = 0; i < n; i++)
		cin >> d[i] >> p[i] >> c[i];
	// будем делать бинарный поиск по времени
	// функция проверки, подходит ли заданное время:
	auto check = [&](ll t) {
		ll want = k;
		for (int i = 0; i < n; i++) {
			// d[i] - разогрев, затем каждая страница печатается каждые p[i] секунд
			// если cnt - количество страниц, то d[i] + p[i] * cnt <= t =>
			// cnt <= (t - d[i]) / p[i]. Из условия задачи: 0 <= cnt <= c[i].
			ll cnt = max<ll>(0, (t - d[i]) / p[i]);
			want -= min<ll>(c[i], cnt);
			if (want <= 0)
				return true;
		}
		return false;
	};
	ll low = 0, high = 4e18L;
	while (high - low > 1) {
		ll mid = (low + high) / 2;
		if (check(mid)) high = mid;
		else low = mid;
	}
	cout << high << "\n";
}
main() {
	int tt; cin >> tt;
	while (tt --> 0) solve();
}
```

После обработки части принтеров `want` показывает, сколько страниц ещё нужно получить. ## C. Витрины коллекции

<details>
<summary>Текстовый разбор</summary>

В ответе требуется минимизировать максимальную сложность витрины. Попробуем зафиксировать число $x$: разрешим каждой витрине иметь не более $x$ различных идентификаторов и спросим, удастся ли разложить все экспонаты максимум по $k$ витринам.

При фиксированном $x$ идём слева направо и собираем текущую витрину. Идентификаторы в ней храним в множестве. Если следующий идентификатор уже есть, его можно добавить без увеличения сложности. Если его нет и после добавления различных идентификаторов стало хотя бы $x+1$, текущая витрина обязана закончиться перед этим экспонатом: перенести в новую витрину какой-либо более ранний экспонат нельзя, ведь порядок фиксирован.

Получается **жадная проверка**. Она делает каждую витрину максимально длинной. Любое другое допустимое разбиение заканчивает первую витрину не правее жадной, затем то же верно для второй и так далее. Значит, жадный алгоритм использует минимальное возможное число витрин при данном $x$.

**Монотонность**. Если $x$ подходит, то подойдёт и любое большее ограничение: уже найденное разбиение останется допустимым. Следовательно, ищем первый истинный `x` бинарным поиском.

**Выбор границ**. Нижняя граница `low = 0` ложная, ведь в каждой непустой витрине есть хотя бы один идентификатор. Верхняя граница `high = n + 1` истинная: в одном фрагменте не бывает больше $n$ различных идентификаторов. Можно было бы взять и `n`, но `n + 1` также является заведомо истинной границей и сохраняет удобный инвариант.

Асимптотика проверки — $O(n\log(n))$ из-за операций со `set`, всего решения — $O(n(\log(n))^2)$ по времени и $O(n)$ по памяти.

</details>

<details>
<summary>Решение на C++ (<code>C.cpp</code>)</summary>

```cpp
// Нам разрешается использовать не более k витрин, поэтому давайте сделаем бинарный поиск по
// максимальной сложности одной витрины. Зафиксировав mid - максимальную сложность, мы будем
// жадно набирать витрины до тех пор, пока сложность каждой не достигнет mid. Для этого
// поддерживаем множество уникальных идентификаторов для каждой витрины в std::set<int> и
// создаём новую витрину, когда после очередной вставки размер множества превысит mid.
// Если нам удалось собрать <= k витрин, то ответ mid подходит, иначе - нет.
#include <bits/stdc++.h>
using namespace std;
void solve() {
	// читаем входные данные
	int n, k; cin >> n >> k;
	vector<int> a(n);
	for (int i = 0; i < n; i++)
		cin >> a[i];
	// бинарный поиск по сложности коллекции:
	int low = 0, high = n+1;
	while (high - low > 1) {
		int mid = (low + high) / 2;
		// посчитаем минимальное количество витрин, каждая из которых сложностью <= mid
		set<int> indexes;
		int answer = 1;
		for (int i = 0; i < n; i++) {
			// пытаемся вставить i-е число в set:
			indexes.insert(a[i]);
			// если витрина превысила лимит, то создаём новую витрину, состоящую из a[i]:
			if (indexes.size() > mid) {
				indexes = {a[i]};
				answer++;
			}
		}
		// проверяем условие бинарного поиска:
		if (answer <= k) high = mid;
		else low = mid;
	}
	cout << high << '\n';
}
main() {
	int tt; cin >> tt;
	while (tt --> 0) solve();
}
```

```python
			if len(indexes) > mid:
				indexes = {a[i]}
				answer += 1
		# проверяем условие бинарного поиска:
		if answer <= k:
			high = mid
		else:
			low = mid
	print(high)

	solve()
	tt -= 1
```

<summary>Разбор решения на C++</summary>

Переполнение лимита обрабатывается так:

```cpp
indexes.insert(a[i]);
if (indexes.size() > mid) {
	indexes = {a[i]};
	answer++;
}
```

Перед условием в `indexes` находятся идентификаторы текущей витрины вместе с `a[i]`. Если их стало слишком много, нельзя оставить `a[i]` в прежней витрине. Присваивание `{a[i]}` не теряет экспонат: оно начинает новую витрину, первым и пока единственным элементом которой становится именно `a[i]`.

Истинность проверки задаёт фрагмент:

```cpp
if (answer <= k) high = mid;
else low = mid;
```

Переменная `answer` содержит минимальное число витрин, необходимое при ограничении `mid`. Поэтому `answer <= k` означает, что ограничение достаточно. Так как требуется минимальное достаточное значение, истинная середина сдвигает правую границу `high`.

<details>
<summary>Разбор решения на Python3</summary>

Текущая витрина представлена множеством:

```python
indexes.add(a[i])

```

Множество хранит каждый идентификатор только один раз, поэтому `len(indexes)` в точности равно сложности текущей витрины. Если новый идентификатор не увеличил размер, переносить экспонат не нужно. Если размер превысил `mid`, текущий экспонат становится началом следующей витрины, а число витрин увеличивается.

Границы имеют разные роли:

```python
low = 0
high = n + 1
```

При `low = 0` ни одну непустую витрину создать нельзя, поэтому это ложная граница. При `high = n + 1` все экспонаты точно можно положить в одну витрину: в ней не может оказаться более `n` различных идентификаторов. Это позволяет искать минимальный истинный ответ.

## D. Полосы экрана

<details>
<summary>Текстовый разбор</summary>

Здесь тоже удобно зафиксировать ответ: пусть ширина экрана равна $w$. Тогда нужно только проверить, удаётся ли расположить прямоугольники не более чем в $k$ строках.

Заполняем текущую строку слева направо. Пока очередной прямоугольник помещается, добавляем его в строку. Если после добавления сумма ширин стала больше $w$, этот прямоугольник обязан начать следующую строку: в текущую он не помещается, а переставлять прямоугольники условие запрещает. Так получается максимально заполненная текущая строка, затем — следующая, и так далее.

Этот жадный процесс использует минимальное число строк для заданной ширины. Действительно, первая строка содержит самый длинный допустимый префикс. Любое другое разбиение должно закончить её не правее. После этого тот же аргумент применим к оставшемуся суффиксу.

**Монотонность**. Если ширина $w$ подходит, то любая большая ширина тоже подойдёт: прежнее разбиение никуда не исчезает. Значит, ищем минимальную подходящую ширину бинарным поиском.

**Выбор границ**. `low = 0` не подходит, так как все прямоугольники имеют положительную ширину. `high = 10^{18}` подходит: даже сумма всех ширин не превосходит $300000\cdot10^9=3\cdot10^{14}$, а значит все прямоугольники можно уложить в одну строку такой ширины.

Асимптотика одного набора: $O(n\log(10^{18}))$ по времени и $O(n)$ памяти.

</details>

<details>
<summary>Решение на C++ (<code>D.cpp</code>)</summary>

```cpp
// Сделаем бинарный поиск по ширине окна. Пусть мы зафиксировали w - текущую ширину окна.
// Нужно проверить, хватит ли нам k строк, чтобы нарисовать все прямоугольники в окне.
// Для этого будем формировать строки одну за другой. Прямоугольник кладём сначала в последнюю
// строку, но если после этого мы вылезли за границу области, то переносим его на следующую
// строку. Если в итоге получилось <= k строк, то у нас всё получилось.
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
// Функция проверки, можно ли нарисовать n прямоугольников на поле k x w:
bool check(int n, const auto &a, int k, ll w) {
	ll sum = 0;   // sum - сумма длин в последней строке
	int answ = 1; // количество занятых строк
	for (int i = 0; i < n; i++) {
		if (a[i] > w) // быстрый выход, если строка слишком узкая:
			return false;
		// рисуем в текущей строке:
		sum += a[i];
		// если не влезло, то рисуем в следующей:
		if (sum > w) {
			answ++;
			sum = a[i];
		}
	}
	return answ <= k;
}
void solve() {
	// читаем входные данные:
	int n, k; cin >> n >> k;
	vector<int> a(n);
	for (int i = 0; i < n; i++)
		cin >> a[i];
	// запускаем бинарный поиск по длине строки:
	ll low = 0, high = 1e18L;
	while (high - low > 1) {
		ll mid = (low + high) / 2;
		if (check(n, a, k, mid)) high = mid;
		else low = mid;
	}
	cout << high << '\n';
}
main() {
	int tt; cin >> tt;
	while (tt --> 0) solve();
}
```

## E. Вкусняшки перед лекцией

<details>
<summary>Текстовый разбор</summary>

Пусть выбрана скорость $x$. Сладость $i$ вообще можно съесть, только когда $x>v_i$. Тогда на неё уйдёт $\frac{d_i}{x-v_i}$ единиц времени. Нужно найти непрерывный фрагмент ровно из $k$ сладостей, для которого все $k$ выражений определены, а их сумма не превосходит $t$.

Для фиксированного $x$ можно пройти по массиву и искать такой фрагмент скользящим окном.

**Монотонность**. При увеличении скорости время на каждой уже доступной сладости только уменьшается, а недоступные сладости могут стать доступными. Поэтому если скорость подходит, то подходит и любая большая скорость. Это снова монотонный предикат, но ответ вещественный.

**Первое решение**. В контесте показаны два варианта одной идеи. `E-dangerous.cpp` заменяет недоступную сладость числом `inf` и поддерживает сумму всего скользящего окна. Такой приём выглядит коротким, но для вещественных чисел опасен. При сдвиге окна программа многократно выполняет операции вида `s += inf` и `s -= inf`. После накопления большой суммы вычитание близких огромных значений теряет младшие разряды: небольшая настоящая сумма времён может исказиться. В `long double` точность выше, и именно с ним данный способ решения прошёл тесты. В обычном `double`, который использует Python, аналогичный вариант получает Wrong Answer.

Кроме того, число, изображающее бесконечность, должно быть строго больше допустимого времени. В опасном варианте `inf = 10^{12}` совпадает с максимальным возможным $t$, поэтому такой подход требует особенно аккуратной работы с границами.

**Второй способ**. `E-safe.cpp` делает проверку иначе. Встречая сладость с $x\le v_i$, он разрезает массив. В каждом получившемся сегменте лежат только доступные сладости, поэтому окно длины $k$ внутри сегмента автоматически не пересекает недоступную сладость. Скользящее окно складывает только реальные конечные времена и никогда не прибавляет и не вычитает искусственную бесконечность. Поэтому вычисления устойчивее, и для них достаточно `double`. Такой же вариант работает в Python.

**Выбор границ**. Нижняя граница `low = 0` не подходит: все $v_i$ неотрицательны, значит при нулевой скорости ни одна сладость не доступна. Верхняя граница `high = 10^{12}+10` подходит с большим запасом. Она больше любого $v_i$, а сумма времён даже для $300000$ сладостей не превышает $300000\cdot\frac{1000}{10^{12}+10-10^6}<1$, тогда как $t\ge1$. Значит, любой фрагмент длины $k$ при такой скорости можно съесть вовремя.

**Оценка на число итераций**. После $60$ итераций длина начального интервала уменьшается до $\frac{10^{12}+10}{2^{60}}<10^{-6}$.

Этой абсолютной погрешности достаточно для чекера с абсолютной или относительной погрешностью $10^{-6}$. В опасном варианте $200$ итераций избыточны: они не исправляют потерю точности при операциях с `inf`.

**Асимптотика** одной проверки безопасного варианта — $O(n)$, потому что каждый элемент попадает ровно в один сегмент и в одно скользящее окно. Всё решение работает за $O(60n)$ времени и использует $O(n)$ памяти.

</details>

<details>
<summary>Решение на C++ (<code>E-dangerous.cpp</code>)</summary>

```cpp
// Сделаем бинарный поиск по величине x - скорости поедания сладостей. Для каждой сладости
// посчитаем время, необходимое для её поедания. Если x > v[i], то время равно:
// d[i] / (x - v[i]). Иначе мы никогда не закончим есть сладость и время равно бесконечности.
// В полученном массиве найдём подотрезок длины k минимальной суммы (с минимальным суммарным
// временем). Если его сумма <= t, то данная скорость подходит, иначе - нет.
// Чтобы не заморачиваться с минимальным отрезком, данное решение проверяет каждый отрезок
// длины k и находит первый из них с суммой <= t. Так тоже можно.
// В качестве бесконечности можно взять 10^{12} - максимальное t в условии задачи.
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
using ld = long double;
const ld inf = 1e12L;
void solve() {
	// читаем входные данные:
	int n, k; ll t; cin >> n >> k >> t;
	vector<int> d(n), v(n);
	for (int i = 0; i < n; i++)
		cin >> d[i];
	for (int i = 0; i < n; i++)
		cin >> v[i];
	// делаем бинарный поиск по скорости поедания
	// функция проверки выбранной скорости x:
	auto check = [&](ld x) {
		// для каждой сладости посчитаем время, необходимое для её
		// поедания на фиксированной скорости x:
		vector<ld> needTime(n);
		for (int i = 0; i < n; i++)
			needTime[i] = (x <= v[i] ? inf : d[i] / (x - v[i]));
		// можно применить метод скользящего окна
		ld s = 0; // сумма в текущем окне длины k
		for (int i = 0; i < k; i++)
			s += needTime[i];
		// проверяем первое окно:
		if (s <= t)
			return true;
		// перебираем все окна и проверяем каждое:
		for (int i = k; i < n; i++) {
			// добавляем новый элемент справа:
			s += needTime[i];
			// удаляем крайний элемент слева:
			s -= needTime[i - k];
			// проверяем текущее окно:
			if (s <= t)
				return true;
		}
		return false;
	};
	// запускаем бинарный поиск на полуинтервале (0, inf]:
	ld low = 0, high = inf;
	for (int iter = 0; iter < 200; iter++) {
		ld mid = (low + high) / 2;
		if (check(mid)) high = mid;
		else low = mid;
	}
	// выводим ответ:
	cout << setprecision(10) << fixed << high << "\n";
}
main() {
	int tt; cin >> tt;
	while (tt --> 0) solve();
}
```

<details>
<summary>Разбор решения <code>E-dangerous.cpp</code></summary>

Недоступная сладость заменяется специальным числом:

```cpp
needTime[i] = (x <= v[i] ? inf : d[i] / (x - v[i]));
```

Такое представление позволяет одним условием `s <= t` отсеять окно с недоступной сладостью, если `inf` действительно больше `t`. Но `inf` не является математической бесконечностью: это обычное конечное вещественное число. При максимальном `t = 10^{12}` значение `inf = 10^{12}` уже не строго больше лимита, поэтому этот приём нельзя бездумно переносить даже с точки зрения логики.

Потеря точности возникает в скользящем окне:

```cpp
s += needTime[i];
s -= needTime[i - k];
```

Если в окне встречаются недоступные сладости, `s` становится очень большой суммой с несколькими слагаемыми `inf`. Когда такая сладость покидает окно, из большой накопленной величины вычитается почти равная ей величина. В числах с плавающей точкой младшие разряды реальной суммы времён могли уже потеряться, поэтому итог после вычитания не обязан совпасть с суммой оставшихся конечных слагаемых. `long double` уменьшает эту ошибку по сравнению с `double`, но сам приём не делает устойчивым.

Число итераций выбрано здесь так:

```cpp
for (int iter = 0; iter < 200; iter++) {
	ld mid = (low + high) / 2;
	if (check(mid)) high = mid;
	else low = mid;
}
```

Интервал уже после $60$ делений имеет длину меньше $10^{-6}$. Последующие итерации не дают полезной точности для ответа чекера и не возвращают биты, потерянные в `s += inf` и `s -= inf`.

<details>
<summary>Решение на C++ (<code>E-safe.cpp</code>)</summary>

```cpp
// Сделаем бинарный поиск по величине x - скорости поедания сладостей. Для каждой сладости
// посчитаем время, необходимое для её поедания. Если x > v[i], то время равно:
// d[i] / (x - v[i]). Иначе мы никогда не закончим есть сладость и время равно бесконечности.
// В полученном массиве найдём подотрезок длины k минимальной суммы (с минимальным суммарным
// временем). Если его сумма <= t, то данная скорость подходит, иначе - нет.
// Чтобы не заморачиваться с минимальным отрезком, данное решение проверяет каждый отрезок
// длины k и находит первый из них с суммой <= t. Так тоже можно.
// Отличие безопасного решения "E-safe.cpp" от опасного "E-dangerous.cpp" в том, что мы
// добавляем разрезание исходного массива на подотрезки, на которых нет бесконечностей.
#include <bits/stdc++.h>
#include <cassert>
#define isz(x) (int)(x).size()
using namespace std;
using ll = long long;
using ld = double;
// вспомогательная функция, которая проверяет, есть ли в массиве "a" подотрезок длины "k" с
// суммой <= t?
bool checkWindowSumK(const auto &a, int k, ld t) {
	if (k > (int)a.size())
		return false;
	// считаем и проверяем сумму в первом подотрезке длины k:
	ld s = 0;
	for (int i = 0; i < k; i++)
		s += a[i];
	if (s <= t)
		return true;
	// двигаем окно длины k вправо, считая и проверяя каждое:
	for (int i = k; i < (int)a.size(); i++) {
		s += a[i];
		s -= a[i-k];
		if (s <= t)
			return true;
	}
	return false;
}
void solve() {
	// читаем входные данные:
	int n, k; ll t; cin >> n >> k >> t;
	vector<int> d(n), v(n);
	for (int i = 0; i < n; i++)
		cin >> d[i];
	for (int i = 0; i < n; i++)
		cin >> v[i];
	// делаем бинарный поиск по скорости поедания
	// функция проверки выбранной скорости x:
	auto check = [&](ld x) {
		// для каждой сладости посчитаем время, необходимое для её поедания на фиксированной
		// скорости x. Отрезку ответа запрещено содержать сладости с x <= v[i], поэтому мы
		// разрежем исходный вектор на множество подходящих векторов:
		vector<vector<ld>> segments(1);
		for (int i = 0; i < n; i++) {
			if (x <= v[i]) {
				segments.push_back({});
				continue;
			}
			segments.back().push_back(d[i] / (x - v[i]));
		}
		// для каждого вектора решаем задачу отдельно:
		for (const auto &ss : segments)
			if (checkWindowSumK(ss, k, (ld)t))
				return true;
		return false;

		ld mid = (low + high) / 2;
		if (check(mid)) high = mid;
		else low = mid;
	}

	cout << setprecision(10) << fixed << high << "\n";
```

<summary>Разбор решения <code>E-safe.cpp</code></summary>

Сегменты строятся следующим циклом:

```cpp
vector<vector<ld>> segments(1);
for (int i = 0; i < n; i++) {
	if (x <= v[i]) {
		segments.push_back({});
		continue;
	}
	segments.back().push_back(d[i] / (x - v[i]));
}
```

Каждая недоступная сладость обязана разорвать возможный отрезок ответа. Поэтому при `x <= v[i]` она не добавляется ни в один сегмент, а следующий доступный элемент начнёт новый сегмент. Важно выполнять `push_back({})` для каждой недоступной сладости, в том числе первой в массиве и следующей после другой недоступной: иначе программа могла бы попытаться вычислить время с неположительным знаменателем.

Проверка короткого сегмента находится в начале хелпера:

```cpp
if (k > (int)a.size())
	return false;
```

Фрагмент ответа обязан иметь ровно $k$ элементов. Если в данном сегменте их меньше, запускать скользящее окно нельзя, но другой сегмент всё ещё может подойти.

Скользящее окно работает только с конечными временами:

```cpp
for (int i = k; i < (int)a.size(); i++) {
	s += a[i];
	s -= a[i-k];
	if (s <= t)
		return true;
}
```

При переходе к следующему окну добавляется один новый доступный элемент и удаляется один старый доступный элемент. Благодаря разрезанию здесь нет искусственного `inf`, поэтому не возникает вычитания огромных почти равных сумм. `double` даёт точность, достаточную для $60$ итераций и требуемой погрешности ответа.

<summary>Решение на Python3 (<code>E-safe.py</code>)</summary>

```python
# Сделаем бинарный поиск по величине x - скорости поедания сладостей. Для каждой сладости
# посчитаем время, необходимое для её поедания. Если x > v[i], то время равно:
# d[i] / (x - v[i]). Иначе мы никогда не закончим есть сладость и время равно бесконечности.
# В полученном массиве найдём подотрезок длины k минимальной суммы (с минимальным суммарным
# временем). Если его сумма <= t, то данная скорость подходит, иначе - нет.
# Чтобы не заморачиваться с минимальным отрезком, данное решение проверяет каждый отрезок
# длины k и находит первый из них с суммой <= t. Так тоже можно.
# Отличие безопасного решения "E-safe.cpp" от опасного "E-dangerous.cpp" в том, что мы
# добавляем разрезание исходного массива на подотрезки, на которых нет бесконечностей.
# вспомогательная функция, которая проверяет, есть ли в массиве "a" подотрезок длины "k" с
# суммой <= t?
def checkWindowSumK(a, k, t):
	if k > len(a):
		return False
	# считаем и проверяем сумму в первом подотрезке длины k:
	s = 0
	for i in range(k):
		s += a[i]
	if s <= t:
		return True
	# двигаем окно длины k вправо, считая и проверяя каждое:
	for i in range(k, len(a)):
		s += a[i]
		s -= a[i-k]
		if s <= t:
			return True
	return False
def solve():
	# читаем входные данные:
	n, k, t = map(int, input().split())
	d = list(map(int, input().split()))
	v = list(map(int, input().split()))
	# делаем бинарный поиск по скорости поедания
	# функция проверки выбранной скорости x:
	def check(x):
		# для каждой сладости посчитаем время, необходимое для её поедания на фиксированной
		# скорости x. Отрезку ответа запрещено содержать сладости с x <= v[i], поэтому мы
		# разрежем исходный вектор на множество подходящих векторов:
		segments = [[]]
		for i in range(n):
			if x <= v[i]:
				segments.append([])
				continue
			segments[-1].append(d[i] / (x - v[i]))
		# для каждого вектора решаем задачу отдельно:
		for ss in segments:
			if checkWindowSumK(ss, k, t):
				return True
		return False
	# запускаем бинарный поиск на полуинтервале (0, inf]:
	low, high = 0, 1e12+10
	for iter in range(60):
		mid = (low + high) / 2
		if check(mid): high = mid
		else: low = mid
	# выводим ответ:
	print(f"{high:.10f}")
tt = int(input())
while tt > 0:
	solve()
	tt -= 1
```

<summary>Разбор решения на Python3</summary>

Доступные сладости собираются в сегменты:

```python
segments = [[]]
for i in range(n):
	if x <= v[i]:
		segments.append([])
		continue
	segments[-1].append(d[i] / (x - v[i]))
```

Для недоступной сладости деление не выполняется. Вместо этого создаётся новый пустой сегмент. Поэтому каждый список в `segments` содержит последовательный фрагмент только из тех сладостей, которые можно съесть при скорости `x`; никакое окно внутри него не пересекает запрещённый элемент.

Хелпер отдельно отбрасывает короткий сегмент:

```python
if k > len(a):
	return False
```

Если элементов меньше, чем требуется взять подряд, подходящего фрагмента в этом сегменте быть не может. Проверка завершает работу только с текущим сегментом, а внешний цикл продолжит просмотр остальных.

Вещественный бинарный поиск обновляет границы так:

```python
for iter in range(60):
	mid = (low + high) / 2
	if check(mid): high = mid
	else: low = mid
```

`low` остаётся скоростью, для которой допустимый фрагмент не найден, а `high` — скоростью, для которой он уже есть. Здесь нет искусственной бесконечности в суммах окна, поэтому обычные числа `float` Python не теряют точность из-за компенсации `inf` большими слагаемыми. После $60$ делений ширина интервала меньше $10^{-6}$, и печатается его правая граница `high`.
