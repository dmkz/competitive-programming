## A. Сбалансированный выбор

<details><summary><b>Идея</b></summary>

Для подходящего подмножества важны не сами значения элементов, а только их чётность. Поэтому достаточно разделить массив на две группы:

- `nOdd` нечётных элементов;
- `nEven` чётных элементов.

Пусть в подмножество выбрано ровно $k$ нечётных чисел. Чтобы подмножество было сбалансированным, чётных чисел также должно быть ровно $k$.

Выбрать нечётные элементы можно $C(nOdd,k)$ способами, а чётные — $C(nEven,k)$ способами. Эти выборы независимы, поэтому для фиксированного $k$ получаем:

$C(nOdd,k) \cdot C(nEven,k)$

Значение $k$ может изменяться от $0$ до $\min(nOdd,nEven)$. Следовательно, искомый ответ равен:

$\displaystyle \sum_{k=0}^{\min(nOdd,nEven)} C(nOdd,k) \cdot C(nEven,k)$

Случай $k=0$ соответствует пустому подмножеству, поэтому отдельно учитывать его не требуется.

Перебирать сами подмножества нельзя: их количество может достигать $2^n$. Полученная формула позволяет вместо этого перебрать только возможное число элементов каждой чётности.

В решениях сначала подсчитываются размеры двух групп.

#### C++

```cpp
    int nOdd{}, nEven{};
    for (int i = 0; i < n; i++) {
        int ai; cin >> ai;
        if (ai % 2 == 1) nOdd++;
        else nEven++;
    }
```

#### Python

```python
    nOdd, nEven = 0, 0
    for ai in map(int, input().split()):
        if ai % 2 == 1:
            nOdd += 1
        else:
            nEven += 1
```

</details>

<details><summary><b>Наблюдения</b></summary>

Для каждого значения $k$ нужно быстро вычислить два биномиальных коэффициента. Если каждый раз находить их с помощью отдельных произведений, суммарное время окажется слишком большим.

Максимальное значение $n$ равно $200000$, поэтому можно один раз заранее вычислить факториалы и обратные факториалы для всех необходимых значений. После этого каждый коэффициент $C(n,k)$ будет находиться за $O(1)$.

Такой предподсчёт общий для всех наборов данных: он не зависит от содержимого конкретного массива и выполняется до обработки тестов.

</details>

<details><summary><b>Предподсчёт биномиальных коэффициентов</b></summary>

Биномиальный коэффициент выражается через факториалы:

$C(n,k)=\dfrac{n!}{k!(n-k)!}$

При вычислениях по модулю деление заменяется умножением на обратные элементы. Поэтому решения хранят:

- `fact[i]` — значение $i!$ по модулю;
- `ifact[i]` — число, обратное к $i!$ по модулю.

Модуль $10^9+7$ является простым. По малой теореме Ферма обратное к ненулевому числу $x$ можно найти как $x^{mod-2}$. В C++ это возведение в степень выполняется бинарным алгоритмом.

#### C++

```cpp
// Быстрое возведение в степень:
int binpow(int a, int n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
```

В Python та же операция выполняется встроенной функцией `pow`.

Сначала последовательно вычисляются все факториалы. Затем находится обратный последний факториал, а остальные обратные факториалы восстанавливаются справа налево:

$ifact[i]=(i+1)\cdot ifact[i+1]$

Действительно, если $ifact[i+1]=1/(i+1)!$, то после умножения на $i+1$ получается $1/i!$.

#### C++

```cpp
// Факториалы и обратные к ним:
const int NMAX = 200200;
int fact[NMAX], ifact[NMAX];
void precalc() {
    fact[0] = 1;
    for (int i = 1; i < NMAX; i++)
        fact[i] = int(fact[i-1] * 1LL * i % mod);
    ifact[NMAX-1] = binpow(fact[NMAX-1], mod-2);
    for (int i = NMAX-2; i >= 0; i--)
        ifact[i] = int((i+1LL) * ifact[i+1] % mod);
}
```

#### Python

```python
# Факториалы и обратные к ним:
NMAX = 200200
fact, ifact = [0] * NMAX, [0] * NMAX
def precalc():
    fact[0] = 1
    for i in range(1, NMAX):
        fact[i] = fact[i - 1] * i % mod
    ifact[NMAX - 1] = pow(fact[NMAX - 1], mod - 2, mod)
    for i in range(NMAX - 2, -1, -1):
        ifact[i] = (i + 1) * ifact[i + 1] % mod
```

Предподсчёт вызывается один раз до чтения и обработки отдельных наборов данных.

#### C++

```cpp
    precalc(); // вызов предподсчёта факториалов и обратных к ним
```

#### Python

```python
precalc() # вызов предподсчёта факториалов и обратных к ним
```

</details>

<details><summary><b>Вычисление биномиального коэффициента</b></summary>

После предподсчёта используется формула:

$C(n,k)=fact[n]\cdot ifact[k]\cdot ifact[n-k]\pmod {mod}$

Если параметры не задают корректный выбор, функция возвращает ноль.

#### C++

```cpp
// Биномиальный коэффициент:
int C(int n, int k) {
    if (n < 0 || k < 0 || k > n)
        return 0;
    return int(fact[n] * 1LL * ifact[k] % mod * ifact[n-k] % mod);
}
```

#### Python

```python
# Биномиальный коэффициент:
def C(n, k):
    if n < 0 or k < 0 or k > n:
        return 0
    return fact[n] * ifact[k] % mod * ifact[n - k] % mod
```

</details>

<details><summary><b>Подсчёт подходящих подмножеств</b></summary>

Остаётся перебрать общее количество $k$ выбранных элементов каждой чётности. Верхняя граница равна $\min(nOdd,nEven)$, поскольку нельзя выбрать больше элементов, чем содержится в одной из групп.

Для каждого $k$ к ответу добавляется произведение двух биномиальных коэффициентов.

#### C++

```cpp
    int answ = 0;
    for (int k = 0; k <= std::min(nOdd, nEven); k++)
        answ = int((answ + C(nOdd, k) * 1LL * C(nEven, k)) % mod);
```

#### Python

```python
    answ = 0
    for k in range(min(nOdd, nEven) + 1):
        answ = (answ + C(nOdd, k) * C(nEven, k)) % mod
```

Все слагаемые сразу прибавляются по модулю $10^9+7$.

</details>

<details><summary><b>Пример</b></summary>

Рассмотрим массив `[1, 2, 3, 4]`. В нём два нечётных и два чётных элемента.

Возможны три значения $k$:

- $k=0$: выбирается пустое подмножество, способов $C(2,0)C(2,0)=1$;
- $k=1$: выбирается один нечётный и один чётный элемент, способов $C(2,1)C(2,1)=4$;
- $k=2$: выбираются все четыре элемента, способов $C(2,2)C(2,2)=1$.

Итого получается $1+4+1=6$ подходящих подмножеств.

</details>

<details><summary><b>Ответ</b></summary>

После завершения перебора в `answ` находится сумма числа способов для всех допустимых значений $k$. Она и выводится как ответ для текущего набора данных.

#### C++

```cpp
    cout << answ << "\n";
```

#### Python

```python
    print(answ)
```

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что алгоритм выводит точное количество подходящих подмножеств.

Рассмотрим произвольное подходящее подмножество. Пусть оно содержит $k$ нечётных элементов. По условию число чётных элементов в нём также равно $k$. Значит, это подмножество учитывается в слагаемом $C(nOdd,k)C(nEven,k)$.

Обратно, каждый вариант, посчитанный этим произведением, содержит ровно $k$ нечётных и ровно $k$ чётных элементов, поэтому является подходящим.

Одно подмножество не может учитываться при разных значениях $k$, поскольку количество выбранных нечётных элементов определяется однозначно. Перебор от $0$ до $\min(nOdd,nEven)$ охватывает все возможные значения этого количества.

Следовательно, алгоритм считает каждое подходящее подмножество ровно один раз, а вычисленная сумма является правильным ответом.

</details>

<details><summary><b>Сложность</b></summary>

Предподсчёт факториалов и обратных факториалов выполняется за $O(NMAX+\log mod)$ времени и использует $O(NMAX)$ памяти.

Для одного набора данных подсчёт чётных и нечётных элементов занимает $O(n)$. Перебор значений $k$ также требует не более $O(n)$ итераций, причём каждый биномиальный коэффициент вычисляется за $O(1)$. Поэтому один тест обрабатывается за $O(n)$ времени и $O(1)$ дополнительной памяти.

С учётом ограничения $\sum n \le 200000$ решение укладывается в заданные ограничения.

</details>

<details><summary><b>Реализация на C++</b></summary>

#### C++

```cpp
#include <bits/stdc++.h>
using namespace std;
const int mod = (int)1e9+7;
// Быстрое возведение в степень:
int binpow(int a, int n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
// Факториалы и обратные к ним:
const int NMAX = 200200;
int fact[NMAX], ifact[NMAX];
void precalc() {
    fact[0] = 1;
    for (int i = 1; i < NMAX; i++)
        fact[i] = int(fact[i-1] * 1LL * i % mod);
    ifact[NMAX-1] = binpow(fact[NMAX-1], mod-2);
    for (int i = NMAX-2; i >= 0; i--)
        ifact[i] = int((i+1LL) * ifact[i+1] % mod);
}
// Биномиальный коэффициент:
int C(int n, int k) {
    if (n < 0 || k < 0 || k > n)
        return 0;
    return int(fact[n] * 1LL * ifact[k] % mod * ifact[n-k] % mod);
}
// Решение:
void solve() {
    int n; cin >> n;
    int nOdd{}, nEven{};
    for (int i = 0; i < n; i++) {
        int ai; cin >> ai;
        if (ai % 2 == 1) nOdd++;
        else nEven++;
    }
    int answ = 0;
    for (int k = 0; k <= std::min(nOdd, nEven); k++)
        answ = int((answ + C(nOdd, k) * 1LL * C(nEven, k)) % mod);
    cout << answ << "\n";
}
main() {
    precalc(); // вызов предподсчёта факториалов и обратных к ним
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

## B. Ладьи на шахматной доске

<details><summary><b>Идея</b></summary>

После $i$-го вмешательства на доске уже стоят $i$ ладей. Они занимают попарно различные строки и попарно различные столбцы, поэтому ни одна пара среди них не бьёт друг друга. Остаётся разместить ещё $n-i$ ладей.

Напрямую считать расстановки, в которых существует атакующая пара, неудобно: такая пара может находиться в строке или столбце, а в одной расстановке может быть сразу несколько атакующих пар. Из-за этого обычный подсчёт по принципу включений-исключений получился бы сложным.

Проще посчитать дополнение:

1. найти количество всех способов поставить оставшиеся ладьи в свободные клетки;
2. вычесть количество способов, при которых никакие две из всех $n$ ладей не бьют друг друга.

После $i$ вмешательств свободны $n^2-i$ клеток. Ладьи неразличимы, поэтому для произвольной расстановки достаточно выбрать множество из $n-i$ свободных клеток. Всего таких вариантов:

$C(n^2-i,n-i)$

Осталось определить число полностью неатакующих расстановок. Уже поставленные ладьи занимают $i$ различных строк и $i$ различных столбцов. Чтобы после добавления остальных ладей атакующих пар не появилось, в каждой из оставшихся $n-i$ строк и в каждом из оставшихся $n-i$ столбцов должна находиться ровно одна ладья.

Для каждой свободной строки можно выбрать свободный столбец, причём все выбранные столбцы должны быть различны. Это означает, что нужно построить взаимно однозначное соответствие между оставшимися строками и столбцами. Число таких соответствий равно:

$(n-i)!$

Следовательно, ответ после $i$-го вмешательства равен:

$C(n^2-i,n-i)-(n-i)!$

Все вычисления выполняются по модулю $10^9+7$.

</details>

<details><summary><b>Наблюдения</b></summary>

Конкретные координаты уже поставленных ладей не влияют на ответ. Важно только их количество и тот факт, что их строки и столбцы не повторяются.

Действительно, после $i$ вмешательств при любых допустимых координатах:

- занято ровно $i$ клеток;
- использовано ровно $i$ строк;
- использовано ровно $i$ столбцов;
- остаётся ровно $n-i$ свободных строк и $n-i$ свободных столбцов.

Поэтому массивы координат нужно прочитать, но в дальнейшей формуле их значения не используются.

#### C++

```cpp
    vector<int> r(q), c(q);
    for (auto &it : r) cin >> it;
    for (auto &it : c) cin >> it;
```

#### Python

```python
    r, c = list(map(int, input().split())), list(map(int, input().split()))
```

</details>

<details><summary><b>Предподсчёт биномиальных коэффициентов</b></summary>

Для каждого вмешательства требуется вычислить биномиальный коэффициент $C(n^2-i,n-i)$. Поскольку $n$ может достигать $1000$, верхний аргумент коэффициента может быть порядка $10^6$.

Чтобы получать каждый коэффициент за $O(1)$, заранее вычисляются:

- `fact[x]` — значение $x!$ по модулю;
- `ifact[x]` — число, обратное к $x!$ по модулю.

Модуль $10^9+7$ является простым, поэтому по малой теореме Ферма обратный элемент к ненулевому $x$ равен $x^{mod-2}$ по модулю. В C++ это значение находится бинарным возведением в степень.

#### C++

```cpp
// Быстрое возведение в степень:
int binpow(int a, int n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
```

В Python для той же операции используется встроенная функция `pow`.

Сначала вычисляются все факториалы. Затем находится обратный элемент для последнего факториала, после чего остальные обратные факториалы восстанавливаются справа налево.

#### C++

```cpp
// Факториалы и обратные к ним:
const int NMAX = 1 << 20;
int fact[NMAX], ifact[NMAX];
void precalc() {
    fact[0] = 1;
    for (int i = 1; i < NMAX; i++)
        fact[i] = int(fact[i-1] * 1LL * i % mod);
    ifact[NMAX-1] = binpow(fact[NMAX-1], mod-2);
    for (int i = NMAX-2; i >= 0; i--)
        ifact[i] = int((i+1LL) * ifact[i+1] % mod);
}
```

#### Python

```python
# Факториалы и обратные к ним:

```

Размер `NMAX = 2^{20}` больше $10^6$, поэтому массивы содержат все факториалы, которые могут потребоваться при $n \le 1000$.

Предподсчёт выполняется один раз перед обработкой всех наборов данных.

<details><summary><b>Ответ после вмешательства</b></summary>

После вмешательства с номером $i$ уже занято $i$ клеток и осталось поставить $n-i$ ладей.

Общее количество расстановок равно $C(n^2-i,n-i)$, а количество расстановок без атакующих пар равно $(n-i)!$. Поэтому из первого значения вычитается второе.

При вычислении по модулю перед взятием остатка добавляется `mod`, чтобы результат вычитания оставался неотрицательным.

#### C++

```cpp
    for (int i = 1; i <= q; i++)
        cout << (C(n * n - i, n - i) - fact[n - i] + mod) % mod << ' ';
    cout << '\n';
```

#### Python

```python
    for i in range(1, q + 1):
        print((C(n * n - i, n - i) - fact[n - i] + mod) % mod, end=' ')
    print()
```

</details>

<details><summary><b>Пример</b></summary>

Рассмотрим доску $3 \times 3$ и два вмешательства.

После первого вмешательства уже стоит одна ладья, поэтому остаётся поставить ещё две:

- свободны $9-1=8$ клеток;
- выбрать две клетки можно $C(8,2)=28$ способами;
- для полной неатакующей расстановки две оставшиеся строки нужно сопоставить двум оставшимся столбцам, что можно сделать $2!=2$ способами.

Следовательно, ответ равен:

$28-2=26$

После второго вмешательства стоят две не бьющие друг друга ладьи. Остаётся поставить одну ладью:

- свободны $9-2=7$ клеток;
- всего существует $C(7,1)=7$ вариантов;
- только одна клетка лежит одновременно в оставшейся строке и оставшемся столбце, поэтому неатакующая расстановка единственна.

Ответ равен:

$7-1!=6$

Получаем значения `26 6`, как в примере.

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что после каждого вмешательства алгоритм выводит количество расстановок, содержащих хотя бы одну атакующую пару ладей.

Зафиксируем номер вмешательства $i$. На доске уже находятся $i$ ладей, занимающих различные строки и столбцы. Остаётся поставить $n-i$ неразличимых ладей.

### Количество всех расстановок

Из $n^2$ клеток заняты ровно $i$, поэтому свободны $n^2-i$ клеток. Каждая расстановка оставшихся неразличимых ладей однозначно определяется множеством из $n-i$ выбранных свободных клеток. Следовательно, всего существует $C(n^2-i,n-i)$ расстановок.

### Количество расстановок без атакующих пар

В неатакующей расстановке из $n$ ладей каждая строка и каждый столбец должны содержать ровно одну ладью. Уже поставленные $i$ ладей занимают $i$ различных строк и $i$ различных столбцов, поэтому оставшиеся ладьи должны занять все остальные $n-i$ строк и все остальные $n-i$ столбцов.

Зафиксируем порядок оставшихся строк. Для первой из них можно выбрать любой из $n-i$ свободных столбцов, для второй — любой из $n-i-1$ ещё не использованных столбцов и так далее. Таким образом, число неатакующих дополнений равно $(n-i)!$.

Каждая полученная перестановка действительно задаёт допустимую расстановку: все новые ладьи находятся в различных строках и столбцах, а также не используют строки и столбцы уже стоящих ладей. Обратно, любая неатакующая расстановка задаёт ровно одну такую перестановку.

### Вычитание дополнения

Все расстановки делятся на два непересекающихся типа:

- содержащие хотя бы одну атакующую пару;
- не содержащие ни одной атакующей пары.

Поэтому число расстановок первого типа равно:

$C(n^2-i,n-i)-(n-i)!$

Именно это значение вычисляет алгоритм. Следовательно, ответ после каждого вмешательства корректен.

</details>

<details><summary><b>Сложность</b></summary>

Предподсчёт факториалов и обратных факториалов выполняется один раз за $O(NMAX+\log mod)$ времени и использует $O(NMAX)$ памяти.

Для каждого набора данных:

- чтение координат занимает $O(q)$ времени;
- вычисление и вывод всех ответов также занимают $O(q)$ времени;
- массивы координат используют $O(q)$ дополнительной памяти.

Каждый биномиальный коэффициент после предподсчёта вычисляется за $O(1)$. Поэтому обработка одного набора данных занимает $O(q)$ времени и $O(q)$ дополнительной памяти.

С учётом ограничений $\sum q \le 200000$ и $n \le 1000$ решение укладывается в заданные ограничения.

</details>

<details><summary><b>Реализация на C++</b></summary>

#### C++

```cpp
#include <bits/stdc++.h>
using namespace std;
const int mod = (int)1e9+7;
// Быстрое возведение в степень:
int binpow(int a, int n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
// Факториалы и обратные к ним:
const int NMAX = 1 << 20;
int fact[NMAX], ifact[NMAX];
void precalc() {
    fact[0] = 1;
    for (int i = 1; i < NMAX; i++)
        fact[i] = int(fact[i-1] * 1LL * i % mod);
    ifact[NMAX-1] = binpow(fact[NMAX-1], mod-2);
    for (int i = NMAX-2; i >= 0; i--)
        ifact[i] = int((i+1LL) * ifact[i+1] % mod);
}
// Биномиальный коэффициент:
int C(int n, int k) {
    if (n < 0 || k < 0 || k > n)
        return 0;
    return int(fact[n] * 1LL * ifact[k] % mod * ifact[n-k] % mod);
}
// Решение:
void solve() {
    int n, q; cin >> n >> q;
    vector<int> r(q), c(q);
    for (auto &it : r) cin >> it;
    for (auto &it : c) cin >> it;
    for (int i = 1; i <= q; i++)
        cout << (C(n * n - i, n - i) - fact[n - i] + mod) % mod << ' ';
    cout << '\n';
}
main() {
    precalc(); // вызов предподсчёта факториалов и обратных к ним
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

## C. Не трогай, это на Новый Год!

<details><summary><b>Идея</b></summary>

Каждый стол однозначно задаётся количеством салатов каждого типа. Если сейчас в холодильнике присутствуют $m$ типов, то для запроса `? k` требуется посчитать количество наборов неотрицательных чисел:

$x_1+x_2+\ldots+x_m=k$

Здесь $x_i$ — количество салатов $i$-го присутствующего типа, поставленных на стол.

Важно понять, почему фактическое количество салатов каждого типа не ограничивает выбор. Все изменения количества измеряются миллионами салатов. Если некоторый тип присутствует в холодильнике, салатов этого типа имеется не менее одного миллиона. При этом $k \le 10^6$, поэтому даже если поставить на стол все $k$ салатов одного присутствующего типа, их всё равно хватит.

Следовательно, для ответа важен только факт присутствия типа:

- если его количество положительно, можно взять от $0$ до $k$ салатов этого типа;
- если количество стало нулевым, использовать этот тип нельзя.

Число неотрицательных решений уравнения $x_1+\ldots+x_m=k$ находится методом шаров и перегородок. Представим $k$ одинаковых салатов и $m-1$ перегородку, разделяющую их между типами. Всего имеется $k+m-1$ позиций, из которых достаточно выбрать позиции для $k$ салатов:

$C(m+k-1,k)$

Таким образом, нужно поддерживать количества салатов по типам и знать текущее число типов с положительным количеством.

</details>

<details><summary><b>Предподсчёт биномиальных коэффициентов</b></summary>

Каждый запрос ответа требует вычислить $C(m+k-1,k)$. Чтобы находить биномиальные коэффициенты за $O(1)$, заранее вычисляются:

- `fact[i]` — значение $i!$ по модулю;
- `ifact[i]` — число, обратное к $i!$ по модулю.

Максимальный верхний аргумент коэффициента не превосходит:

$d+k-1 \le 200000+10^6-1$

Поэтому размера `NMAX = 2^{21}` достаточно для всех необходимых значений.

Модуль $10^9+7$ является простым. По малой теореме Ферма обратное к ненулевому числу $x$ можно найти как $x^{mod-2}$. В C++ это возведение в степень выполняется бинарным алгоритмом.

#### C++

```cpp
// Быстрое возведение в степень:
int binpow(int a, int n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
```

В Python для этой операции используется встроенная функция `pow`.

Сначала вычисляются факториалы. Затем находится обратный элемент для последнего факториала, после чего остальные обратные факториалы восстанавливаются справа налево по формуле:

$ifact[i]=(i+1)\cdot ifact[i+1]$

#### C++

<details><summary><b>Пример</b></summary>

Изначально в примере присутствуют типы `1` и `4`, поэтому $m=2$.

Для запроса `? 2` требуется решить уравнение:

$x_1+x_2=2$

Его неотрицательные решения:

- $(2,0)$ — стол `{1,1}`;
- $(1,1)$ — стол `{1,4}`;
- $(0,2)$ — стол `{4,4}`.

По формуле получается:

$C(2+2-1,2)=C(3,2)=3$

После полного удаления салатов типа `1` в структуре остаётся один тип. Теперь существует только один вариант — взять два салата типа `4`:

$C(1+2-1,2)=C(2,2)=1$

Затем появляется тип `3`, поэтому число присутствующих типов снова становится равным двум. Для трёх салатов ответ равен:

$C(2+3-1,3)=C(4,3)=4$

Этим четырём вариантам соответствуют количества салатов типа `3`, равные $0$, $1$, $2$ или $3$.

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что алгоритм правильно обрабатывает изменения и отвечает на запросы.

### Состояние структуры

После чтения начальных данных `cnt[a]` содержит количество салатов типа $a$. При запросе добавления это количество увеличивается на указанное значение.

При удалении количество уменьшается. По условию нельзя удалить больше салатов, чем имеется, поэтому отрицательного значения не возникает. Если количество становится нулевым, тип удаляется из структуры.

Следовательно, после каждого изменения ключи `cnt` — это в точности типы, присутствующие в холодильнике, а `cnt.size()` или `len(cnt)` равно их числу $m$.

### Соответствие столов решениям уравнения

Зафиксируем запрос `? k`. Для каждого из $m$ присутствующих типов обозначим через $x_i$ количество его салатов на столе. Тогда любой стол задаёт набор неотрицательных чисел, удовлетворяющий равенству:

$x_1+x_2+\ldots+x_m=k$

Обратно, каждый такой набор однозначно определяет мультимножество типов на столе, а значит, один допустимый стол.

Если тип присутствует, его запас составляет не менее одного миллиона салатов. Поскольку $k\le 10^6$, любое значение $x_i$ от $0$ до $k$ допустимо. Поэтому дополнительных верхних ограничений у переменных нет.

Таким образом, между допустимыми столами и неотрицательными решениями указанного уравнения существует взаимно однозначное соответствие.

### Подсчёт решений

По методу шаров и перегородок число неотрицательных решений уравнения с $m$ переменными и суммой $k$ равно $C(m+k-1,k)$. Алгоритм подставляет в эту формулу текущее число ключей структуры, поэтому выводит точное количество различных столов.

Следовательно, все ответы алгоритма корректны.

</details>

<details><summary><b>Сложность</b></summary>

Предподсчёт факториалов и обратных факториалов выполняется один раз за $O(NMAX+\log mod)$ времени и использует $O(NMAX)$ памяти.

В C++ структура `map` содержит не более $d$ ключей:

- добавление, удаление и поиск типа занимают $O(\log d)$;
- запрос ответа после предподсчёта обрабатывается за $O(1)$.

Поэтому один набор данных обрабатывается за $O((n+q)\log d)$ времени и использует $O(n+q)$ памяти в худшем случае для присутствующих типов.

В Python операции со словарём в среднем занимают $O(1)$, поэтому ожидаемое время обработки набора равно $O(n+q)$, а память для структуры — $O(n+q)$ в худшем случае.

Суммы значений $n$ и $q$ по всем наборам не превосходят $200000$, поэтому решение укладывается в ограничения.

</details>

## D. Черепашка чует опасность, двигаясь вниз и вправо

<details><summary><b>Идея</b></summary>

Если бы опасных клеток не было, любой путь из $(1,1)$ в $(n,m)$ состоял бы из:

- $n-1$ перемещения вниз;
- $m-1$ перемещения вправо.

Нужно лишь выбрать, на каких позициях пути будут находиться перемещения вниз. Поэтому общее количество путей равно:

$C(n+m-2,n-1)$

Динамика по всем клеткам доски здесь не подходит: при $n,m\le 10^6$ таблица может содержать до $10^{12}$ клеток. Однако опасных клеток всего две, поэтому можно посчитать пути, проходящие через них, комбинаторно.

Обозначим:

- $A$ — множество путей, проходящих через первую опасную клетку;
- $B$ — множество путей, проходящих через вторую опасную клетку.

Нужно исключить пути из объединения $A\cup B$. По формуле включений-исключений количество безопасных путей равно:

$|All|-|A|-|B|+|A\cap B|$

Путь через одну заданную клетку естественно разбивается на две независимые части: от старта до этой клетки и от неё до финиша. Поэтому число таких путей равно произведению числа способов пройти каждую часть.

Для пересечения $A\cap B$ необходимо посчитать пути, проходящие через обе опасные клетки. Из-за движения только вниз и вправо они могут быть посещены лишь в одном порядке. Расположим их так, чтобы первая клетка имела меньший номер строки, а при равных строках — меньший номер столбца.

#### C++

```cpp
    // отсортируем клетки так, чтобы (r1, c1) шла раньше (r2, c2)
    if (r1 > r2 || (r1 == r2 && c1 > c2)) {
        swap(r1, r2);
        swap(c1, c2);
    }
```

#### Python

```python
    # отсортируем клетки так, чтобы (r1, c1) шла раньше (r2, c2)
    if r1 > r2 or (r1 == r2 and c1 > c2):
        r1, r2 = r2, r1
        c1, c2 = c2, c1
```

После этого остаётся применить включения-исключения, используя формулу для числа монотонных путей между двумя клетками.

</details>

<details><summary><b>Количество путей между двумя клетками</b></summary>

Рассмотрим путь из $(r_1,c_1)$ в $(r_2,c_2)$.

Он существует только в том случае, если $r_1\le r_2$ и $c_1\le c_2$, поскольку черепашка не может двигаться вверх или влево. В решении первый порядок гарантируется перед вызовом функции, а при нарушении второго функция возвращает ноль.

Если путь существует, требуется выполнить:

- $dr=r_2-r_1$ шагов вниз;
- $dc=c_2-c_1$ шагов вправо.

Всего выполняется $dr+dc$ шагов. Выбрав позиции для $dr$ шагов вниз, получаем:

$C(dr+dc,dr)$

#### C++

```cpp
// Количество путей из (r1, c1) в (r2, c2):
int cntWays(int r1, int c1, int r2, int c2) {
    assert(r1 <= r2);
    if (c1 > c2) return 0;
    int dr = r2 - r1, dc = c2 - c1;
    return C(dr+dc, dr);
}
```

#### Python

```python
# Количество путей из (r1, c1) в (r2, c2):
def cntWays(r1, c1, r2, c2):
    assert r1 <= r2
    if c1 > c2:
        return 0
    dr, dc = r2 - r1, c2 - c1
    return C(dr + dc, dr)
```

Возврат нуля при $c_1>c_2$ особенно важен для двух опасных клеток. Если после сортировки по строке первая из них находится правее второй, пройти через обе невозможно: для этого пришлось бы двигаться влево.

</details>

<details><summary><b>Предподсчёт биномиальных коэффициентов</b></summary>

Для каждого набора данных нужно несколько раз вычислить количество путей, то есть биномиальные коэффициенты. Чтобы получать каждый из них за $O(1)$, заранее вычисляются:

- `fact[i]` — значение $i!$ по модулю;
- `ifact[i]` — число, обратное к $i!$ по модулю.

Наибольший верхний аргумент биномиального коэффициента возникает для полного пути и равен $n+m-2$. При $n,m\le 10^6$ он не превосходит $2\cdot 10^6-2$, поэтому размера `NMAX = 2^{21}` достаточно.

Модуль $10^9+7$ является простым. По малой теореме Ферма число, обратное к ненулевому $x$, можно получить как $x^{mod-2}$. В C++ степень вычисляется бинарным алгоритмом.

#### C++

```cpp
// Быстрое возведение в степень:
int binpow(int a, int n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
```

В Python соответствующая операция выполняется встроенной функцией `pow`.

Сначала вычисляются факториалы. Затем находится обратный последний факториал, а остальные обратные факториалы восстанавливаются справа налево.

#### C++

```cpp
// Факториалы и обратные к ним:
const int NMAX = 1 << 21;
int fact[NMAX], ifact[NMAX];
void precalc() {
    fact[0] = 1;
    for (int i = 1; i < NMAX; i++)
        fact[i] = int(fact[i-1] * 1LL * i % mod);
    ifact[NMAX-1] = binpow(fact[NMAX-1], mod-2);
    for (int i = NMAX-2; i >= 0; i--)
        ifact[i] = int((i+1LL) * ifact[i+1] % mod);
}
```


<details><summary><b>Вычисление биномиального коэффициента</b></summary>

После предподсчёта применяется формула:

$C(n,k)=fact[n]\cdot ifact[k]\cdot ifact[n-k]\pmod {mod}$

Если параметры не задают корректный биномиальный коэффициент, функция возвращает ноль.

<details><summary><b>Формула включений-исключений</b></summary>

Сначала учитываются все пути от старта до финиша:

$cntWays(1,1,n,m)$

Число путей через опасную клетку $(r,c)$ равно:

$cntWays(1,1,r,c)\cdot cntWays(r,c,n,m)$

Первая часть выбирается независимо от второй, а их соединение однозначно задаёт полный путь через эту клетку. Такие произведения вычитаются для обеих опасных клеток.

Однако путь, проходящий через обе клетки, был вычтен дважды. Его нужно вернуть один раз. После упорядочивания опасных клеток число таких путей равно:

$cntWays(1,1,r_1,c_1)\cdot cntWays(r_1,c_1,r_2,c_2)\cdot cntWays(r_2,c_2,n,m)$

Если перейти от первой опасной клетки ко второй невозможно, средний множитель равен нулю, и пересечение автоматически не учитывается.

#### C++

```cpp
    // считаем пути по формуле включений-исключений:
    int64_t answ = cntWays(1, 1, n, m);
    answ -= cntWays(1, 1, r1, c1) * 1LL * cntWays(r1, c1, n, m);
    answ -= cntWays(1, 1, r2, c2) * 1LL * cntWays(r2, c2, n, m);
    answ += cntWays(1, 1, r1, c1) * 1LL * cntWays(r1, c1, r2, c2) % mod * cntWays(r2, c2, n, m);
```

#### Python

```python
    # считаем пути по формуле включений-исключений:
    answ = cntWays(1, 1, n, m)
    answ -= cntWays(1, 1, r1, c1) * cntWays(r1, c1, n, m)
    answ -= cntWays(1, 1, r2, c2) * cntWays(r2, c2, n, m)
    answ += cntWays(1, 1, r1, c1) * cntWays(r1, c1, r2, c2) % mod * cntWays(r2, c2, n, m)
```

</details>

<details><summary><b>Пример</b></summary>

Рассмотрим доску $3\times3$ с опасными клетками $(2,2)$ и $(2,3)$.

Без ограничений число путей равно:

$C(4,2)=6$

Через клетку $(2,2)$ проходят:

$C(2,1)\cdot C(2,1)=4$

Через клетку $(2,3)$ проходят:

$C(3,1)\cdot C(1,1)=3$

Некоторые пути вошли в оба подсчёта. Число путей через обе клетки равно:

$C(2,1)\cdot C(1,0)\cdot C(1,1)=2$

По формуле включений-исключений получаем:

$6-4-3+2=1$

Это единственный безопасный путь: дважды вниз, затем дважды вправо.

</details>

<details><summary><b>Ответ</b></summary>

После вычитаний значение `answ` может быть отрицательным. Поэтому сначала берётся остаток по модулю, затем добавляется `mod` и остаток берётся ещё раз. Это приводит результат к диапазону от $0$ до $mod-1$.

#### C++

```cpp
    // выводим ответ:
    cout << (answ % mod + mod) % mod << '\n';
```

#### Python

```python
    # выводим ответ:
    print((answ % mod + mod) % mod)
```

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что алгоритм выводит количество путей, не проходящих через опасные клетки.

### Число монотонных путей

Для перехода из $(r_1,c_1)$ в $(r_2,c_2)$ при $r_1\le r_2$ и $c_1\le c_2$ требуется ровно $r_2-r_1$ шагов вниз и $c_2-c_1$ шагов вправо. Любой порядок этих шагов задаёт ровно один путь, поэтому функция `cntWays` корректно возвращает соответствующий биномиальный коэффициент. Если $c_1>c_2$, такой переход потребовал бы движения влево, поэтому возвращается ноль.

### Пути через одну опасную клетку

Зафиксируем клетку $(r,c)$. Любой путь через неё единственным образом разбивается на путь от $(1,1)$ до $(r,c)$ и путь от $(r,c)$ до $(n,m)$. Обратно, любую пару таких частей можно соединить в полный путь через заданную клетку. Следовательно, произведение значений `cntWays` для двух частей точно равно числу путей через эту клетку.

### Пути через обе опасные клетки

После сортировки первая опасная клетка не ниже второй. Если её столбец также не превосходит столбец второй клетки, путь может посетить их только в порядке:

$(1,1)\rightarrow(r_1,c_1)\rightarrow(r_2,c_2)\rightarrow(n,m)$

Три части выбираются независимо, поэтому их количества перемножаются. Если же $c_1>c_2$, пройти через обе клетки невозможно, и `cntWays(r1,c1,r2,c2)` корректно возвращает ноль.

Таким образом, добавляемое произведение точно равно числу путей, проходящих через обе опасные клетки.

### Применение включений-исключений

Из количества всех путей алгоритм вычитает пути через первую опасную клетку и пути через вторую. Пути, проходящие через обе клетки, при этом вычитаются дважды, поэтому алгоритм добавляет их количество один раз.

В результате каждый путь через хотя бы одну опасную клетку учитывается ноль раз, а каждый путь, не проходящий через них, — ровно один раз. Следовательно, вычисленное значение является искомым количеством безопасных путей.

</details>

<details><summary><b>Сложность</b></summary>

Предподсчёт факториалов и обратных факториалов выполняется один раз за $O(NMAX+\log mod)$ времени и использует $O(NMAX)$ памяти.

Для одного набора данных выполняется постоянное количество вычислений биномиальных коэффициентов, каждое из которых после предподсчёта занимает $O(1)$. Поэтому один тест обрабатывается за $O(1)$ времени и использует $O(1)$ дополнительной памяти.

Общая сложность обработки всех тестов после предподсчёта равна $O(t)$.

</details>

## E. XOR-таблица

<details><summary><b>Идея</b></summary>

XOR вычисляется независимо для каждого бита. Поэтому сначала забудем о числах от $0$ до $2^{60}-1$ и рассмотрим только один фиксированный бит.

Каждая клетка теперь содержит либо $0$, либо $1$. Ограничение на строку означает, что XOR всех битов в этой строке должен быть равен заданному биту. Аналогично задаются ограничения на столбцы.

Сначала выясним, сколько существует бинарных таблиц. Затем заметим, что все $60$ битов можно выбирать независимо, и перемножим количества вариантов.

</details>

<details><summary><b>Решение для одного бита</b></summary>

Обозначим бит в клетке $(i,j)$ через $a_{i,j}$. Ограничение на строку $i$ имеет вид:

$a_{i,1}\oplus a_{i,2}\oplus\ldots\oplus a_{i,m}=x_i$

Ограничение на столбец $j$ записывается аналогично:

$a_{1,j}\oplus a_{2,j}\oplus\ldots\oplus a_{n,j}=y_j$

Изначально ограничений нет, поэтому каждую из $nm$ клеток можно заполнить независимо. Для одного бита существует $2^{nm}$ таблиц.

Осталось понять, как очередное ограничение изменяет это число.

### Каждое ограничение делит число вариантов на два

Пусть добавляется ограничение на строку, которая раньше не была ограничена. Зафиксируем значения всех клеток вне этой строки, а в самой строке — значения всех клеток, кроме одной.

Последний бит строки определяется однозначно: он должен сделать XOR всей строки равным требуемому значению. Значит, из двух возможных значений последней свободной клетки подходит ровно одно.

Следовательно, ровно половина таблиц удовлетворяет новому ограничению. Число вариантов делится на $2$.

Для ограничения на столбец рассуждение полностью аналогично.

Однако это верно лишь до тех пор, пока не заданы ограничения сразу на все $n$ строк и все $m$ столбцов. Последнее из этих $n+m$ ограничений ведёт себя иначе.

### Зависимость между всеми строками и столбцами

Вычислим XOR значений всех строк:

$x_1\oplus x_2\oplus\ldots\oplus x_n$

Если раскрыть XOR каждой строки, каждая клетка таблицы встретится ровно один раз. Поэтому эта величина равна XOR всех клеток таблицы.

То же верно для XOR значений всех столбцов:

$y_1\oplus y_2\oplus\ldots\oplus y_m$

Здесь каждая клетка также встречается ровно один раз. Следовательно, для любой заполненной таблицы обязательно выполняется:

$x_1\oplus x_2\oplus\ldots\oplus x_n=y_1\oplus y_2\oplus\ldots\oplus y_m$

Поэтому последнее ограничение уже не является независимым:

- если указанное в нём значение согласуется с остальными ограничениями, число таблиц не изменяется;
- иначе подходящих таблиц становится ноль.

Итак, если сейчас наложено $s<n+m$ ограничений, то для одного бита число таблиц равно:

$2^{nm-s}$

Если заданы все $n+m$ ограничений, то при согласованных XOR число таблиц равно:

$2^{nm-(n+m-1)}$

В показателе вычитается только $n+m-1$, поскольку последнее условие следует из остальных. При нарушении равенства общих XOR ответ равен нулю.

</details>

<details><summary><b>Почему любые неполные ограничения независимы</b></summary>

Нужно отдельно обосновать, что зависимость не возникает раньше, чем будут ограничены все строки и столбцы.

Рассмотрим некоторый непустой набор ограничений и выполним XOR их левых частей. Чтобы эти ограничения были зависимы, каждая клетка должна встретиться чётное число раз и исчезнуть из итогового XOR.

Клетка $(i,j)$ входит:

- в выбранное ограничение строки $i$, если оно было взято;
- в выбранное ограничение столбца $j$, если оно было взято.

Следовательно, клетка исчезает тогда и только тогда, когда либо выбраны оба соответствующих ограничения, либо не выбрано ни одного.

Если выбрано хотя бы одно ограничение строки, то для исчезновения всех клеток этой строки необходимо выбрать ограничения всех столбцов. Но тогда для исчезновения клеток в этих столбцах требуется выбрать и все строки.

Аналогично, выбор хотя бы одного столбца приводит к необходимости выбрать все столбцы и все строки.

Значит, единственная нетривиальная зависимость использует сразу все $n+m$ ограничений. Поэтому любые $s<n+m$ ограничений независимы и каждое из них действительно делит число подходящих бинарных таблиц ровно на два.

</details>

<details><summary><b>Переход к 60 битам</b></summary>

Теперь вернёмся к исходным значениям $0\le a_{i,j}<2^{60}$.

Каждое число состоит из $60$ битов. Ограничение на XOR строки или столбца распадается на $60$ независимых бинарных ограничений — по одному для каждого разряда.

Изначально каждая из $nm$ клеток может содержать одно из $2^{60}$ значений, поэтому общее количество таблиц равно:

$(2^{60})^{nm}=2^{60nm}$

#### C++

```cpp
    int invPow2 = binpow(binpow(2, 60), mod-2);
    int answ = binpow(2, 60LL * n * m);
```

#### Python

```python
    invPow2 = pow(pow(2, 60, mod), -1, mod)
    answ = pow(2, 60 * n * m, mod)
```

Пока добавленное ограничение независимо, оно задаёт один битовый XOR для каждого из $60$ разрядов. Для каждого бита число вариантов делится на $2$, а для всего числа — на $2^{60}$.

По модулю деление выполняется умножением на обратное число. В решениях `invPow2` — это число, обратное к $2^{60}$ по модулю $10^9+7$.

Если задано $s<n+m$ ограничений, число таблиц равно:

$2^{60(nm-s)}$

После добавления всех ограничений последняя группа из $60$ битовых уравнений не уменьшает число вариантов при согласованности. Поэтому на последнем запросе делить ответ на $2^{60}$ уже не требуется.

</details>

<details><summary><b>Проверка согласованности</b></summary>

Чтобы проверить совместимость полностью заданных ограничений, решения поддерживают:

- `xorRows` — XOR требуемых значений всех уже ограниченных строк;
- `xorCols` — XOR требуемых значений всех уже ограниченных столбцов;
- `usedRows` и `usedCols` — количество ограниченных строк и столбцов.

При добавлении ограничения его значение включается в соответствующий XOR.

#### C++

```cpp
        if (ch == 'r') {
            int k; int64_t x;
            cin >> k >> x;
            usedRows++;
            xorRows ^= x;
        } else {
            assert(ch == 'c');
            int k; int64_t x;
            cin >> k >> x;
            usedCols++;
            xorCols ^= x;
        }
```

#### Python

```python
        if ch[0] == 'r':
            k, x = int(ch[1]), int(ch[2])
            usedRows += 1
            xorRows ^= x
        else:
            assert ch[0] == 'c'
            k, x = int(ch[1]), int(ch[2])
            usedCols += 1
            xorCols ^= x
```

Конкретные номера строк и столбцов для подсчёта не нужны. По условию одно ограничение не накладывается дважды, поэтому достаточно знать число уже использованных строк и столбцов. Значение `k` считывается, но дальше не используется.

Когда ограничены все строки и столбцы, должно выполняться равенство `xorRows == xorCols`. Оно одновременно проверяет согласованность всех $60$ битов: два числа равны тогда и только тогда, когда совпадают все их биты.

</details>

<details><summary><b>Обработка очередного ограничения</b></summary>

После чтения запроса сначала проверяется особый случай: если ограничения уже заданы для всех строк и столбцов, но их общие XOR различаются, решений нет.

Если же общее число добавленных ограничений всё ещё меньше $n+m$, новое условие независимо. Тогда текущее количество таблиц умножается на число, обратное к $2^{60}$.

#### C++

```cpp
        if (usedRows == n && usedCols == m && xorRows != xorCols)
            answ = 0;
        if (usedRows + usedCols < n + m)
            answ = int((answ * 1LL * invPow2) % mod);
        cout << answ << '\n';
```

#### Python

```python
        if usedRows == n and usedCols == m and xorRows != xorCols:
            answ = 0
        if usedRows + usedCols < n + m:
            answ = answ * invPow2 % mod
        print(answ)
```

Когда `usedRows + usedCols == n + m`, добавлено последнее ограничение. Поэтому деления уже нет:

- при совпадении общих XOR прежнее число таблиц остаётся ответом;
- при несовпадении ответ предварительно становится равным нулю.

Поскольку ограничения только добавляются, после получения нулевого ответа подходящие таблицы уже не появятся.

</details>

<details><summary><b>Пример для одного бита</b></summary>

Рассмотрим бинарную таблицу размера $2\times2$:

```text
a b
c d
```

Без ограничений существуют $2^4=16$ заполнений.

Пусть сначала потребовали, чтобы XOR первой строки был равен $0$:

$a\oplus b=0$

Теперь значение `b` однозначно определяется значением `a`, а `c` и `d` остаются свободными. Получается $2^3=8$ таблиц.

Добавим ограничение на первый столбец:

$a\oplus c=0$

Теперь `c` определяется через `a`, поэтому остаётся $2^2=4$ таблицы.

Добавим условие на вторую строку:

$c\oplus d=0$

После него свободно только `a`, а остальные значения определяются через него. Остаётся $2$ таблицы.

Наконец, ограничим второй столбец. Его XOR уже определяется предыдущими тремя равенствами. Действительно,

$(a\oplus b)\oplus(c\oplus d)=(a\oplus c)\oplus(b\oplus d)$

Поэтому последнее условие либо выполняется для обеих оставшихся таблиц, либо противоречит предыдущим и уничтожает все варианты. Оно не может оставить ровно половину таблиц.

Для исходной задачи то же рассуждение независимо применяется к каждому из $60$ битов.

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что после каждого запроса алгоритм выводит точное количество таблиц, удовлетворяющих всем текущим ограничениям.

### Один бит

Для одного бита таблица содержит $nm$ бинарных переменных, поэтому без ограничений существует $2^{nm}$ заполнений.

Пока наложено меньше $n+m$ ограничений, они независимы. Это следует из того, что XOR любого непустого собственного поднабора уравнений строк и столбцов не может уничтожить все переменные: единственная нетривиальная зависимость включает ограничения сразу на все строки и все столбцы.

Каждое новое независимое бинарное уравнение делит число решений на два. Поэтому после $s<n+m$ запросов существует $2^{nm-s}$ бинарных таблиц.

Когда заданы все $n+m$ ограничений, XOR левых частей всех строковых уравнений совпадает с XOR левых частей всех столбцовых уравнений: в обоих случаях получается XOR всех клеток. Следовательно, необходимо равенство XOR правых частей.

Если оно выполняется, последнее уравнение следует из предыдущих, поэтому число решений остаётся равным $2^{nm-(n+m-1)}$. Если равенство нарушено, система несовместна и решений нет.

### Все 60 битов

Ограничения на разные биты независимы. Любой выбор подходящей бинарной таблицы для каждого из $60$ разрядов однозначно образует таблицу чисел от $0$ до $2^{60}-1$, и наоборот.

Поэтому количества решений для отдельных битов перемножаются. Каждое независимое ограничение уменьшает число таблиц в $2^{60}$ раз, что алгоритм реализует умножением на `invPow2`.

Равенство `xorRows == xorCols` эквивалентно совпадению общих XOR во всех $60$ разрядах. Значит, после последнего ограничения алгоритм сохраняет ответ при совместности и заменяет его нулём при противоречии.

Следовательно, после каждого запроса `answ` содержит точное количество допустимых таблиц по модулю $10^9+7$.

</details>

<details><summary><b>Сложность</b></summary>

Для каждого запроса выполняется постоянное количество арифметических операций и операций XOR, поэтому один набор данных обрабатывается за $O(q)$ времени.

Дополнительная память составляет $O(1)$: хранить сами ограничения, номера использованных строк и номера использованных столбцов не требуется.

В начале каждого набора выполняется несколько бинарных возведений в степень. Их время равно $O(\log(nm)+\log mod)$, поэтому полная оценка для одного набора составляет $O(q+\log(nm)+\log mod)$.

С учётом ограничения на сумму значений $q$ решение укладывается в заданные ограничения.

</details>

<details><summary><b>Реализация на C++</b></summary>

#### C++

```cpp
#include <bits/stdc++.h>
#include <cassert>
using namespace std;
const int mod = (int)1e9+7;
// быстрое возведение в степень:
int binpow(int a, int64_t n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
// решение:
void solve() {
    int n, m; cin >> n >> m;
    int q; cin >> q;
    int invPow2 = binpow(binpow(2, 60), mod-2);
    int answ = binpow(2, 60LL * n * m);
    int64_t xorRows = 0, xorCols = 0;
    int usedRows = 0, usedCols = 0;
    while (q --> 0) {
        char ch; cin >> ch;
        if (ch == 'r') {
            int k; int64_t x;
            cin >> k >> x;
            usedRows++;
            xorRows ^= x;
        } else {
            assert(ch == 'c');
            int k; int64_t x;
            cin >> k >> x;
            usedCols++;
            xorCols ^= x;
        }
        if (usedRows == n && usedCols == m && xorRows != xorCols)
            answ = 0;
        if (usedRows + usedCols < n + m)
            answ = int((answ * 1LL * invPow2) % mod);
        cout << answ << '\n';
    }
}
main() {
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details><summary><b>Реализация на Python</b></summary>

#### Python

```python
mod = int(1e9) + 7
# решение:
def solve():
    n, m = map(int, input().split())
    q = int(input())
    invPow2 = pow(pow(2, 60, mod), -1, mod)
    answ = pow(2, 60 * n * m, mod)
    xorRows, xorCols = 0, 0
    usedRows, usedCols = 0, 0
    while q > 0:
        ch = input().split()
        if ch[0] == 'r':
            k, x = int(ch[1]), int(ch[2])
            usedRows += 1
            xorRows ^= x
        else:
            assert ch[0] == 'c'
            k, x = int(ch[1]), int(ch[2])
            usedCols += 1
            xorCols ^= x
        if usedRows == n and usedCols == m and xorRows != xorCols:
            answ = 0
        if usedRows + usedCols < n + m:
            answ = answ * invPow2 % mod
        print(answ)
        q -= 1
tt = int(input())
while tt > 0:
    solve()
    tt -= 1
```
