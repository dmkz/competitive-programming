## Глава 3. Пути по клеточному полю

В предыдущей главе мы научились быстро вычислять сочетания по простому модулю. Теперь применим этот инструмент к одной из самых распространённых комбинаторных моделей — подсчёту путей по прямоугольной сетке.

Раньше подобные задачи можно было решать динамическим программированием: для каждой клетки хранить количество способов добраться до неё. Однако если на поле нет препятствий или имеется только одна закрытая клетка, число маршрутов можно получить напрямую с помощью сочетаний.

В этой главе клетки таблицы нумеруются с единицы. Начальная клетка имеет координаты $(1,1)$, а конечная — $(n,m)$. За один шаг разрешается перейти в соседнюю клетку вниз или вправо.

## 3.1. Все пути без препятствий

Сначала рассмотрим таблицу без препятствий. Требуется пройти из клетки $(1,1)$ в клетку $(n,m)$, двигаясь только вниз и вправо.

Чтобы попасть из первой строки в строку $n$, необходимо сделать ровно $n-1$ шагов вниз. Аналогично, чтобы попасть из первого столбца в столбец $m$, необходимо сделать ровно $m-1$ шагов вправо.

Таким образом, любой маршрут содержит:

- $n-1$ шагов вниз;
- $m-1$ шагов вправо;
- $n+m-2$ шага всего.

Обозначим шаг вниз символом `D`, а шаг вправо — символом `R`. Тогда каждому маршруту соответствует последовательность из $n+m-2$ символов, содержащая ровно $n-1$ символов `D` и $m-1$ символов `R`.

Например, при движении из $(1,1)$ в $(3,4)$ один из маршрутов можно записать так:

```text
R D R R D
```

Эта последовательность однозначно задаёт путь: сначала мы идём вправо, затем вниз, ещё два раза вправо и в конце вниз.

Чтобы построить маршрут, достаточно выбрать $n-1$ позиций, на которых будут стоять шаги `D`. Все остальные позиции автоматически займут шаги `R`. Поэтому число маршрутов равно

$$C_{n+m-2}^{n-1}.$$

Вместо позиций для шагов вниз можно было выбрать $m-1$ позиций для шагов вправо. В этом случае получилось бы

$$C_{n+m-2}^{m-1}.$$

По симметрии сочетаний эти значения равны:

$$C_{n+m-2}^{n-1}=C_{n+m-2}^{m-1}.$$

> [!IMPORTANT]
> Если каждый объект состоит из фиксированного количества элементов двух типов, часто достаточно выбрать позиции для элементов одного из типов. Оставшиеся позиции определятся автоматически.

Ту же задачу можно решить динамическим программированием за $O(nm)$. Формула через сочетание позволяет после предподсчёта факториалов получить ответ за $O(1)$.

Сам предподсчёт факториалов до $n+m$ занимает $O(n+m)$ времени и памяти. Его преимущество становится особенно заметным, если необходимо ответить на много запросов для разных клеток одной сетки.

## 3.2. Путь через заданную клетку

Теперь добавим новое условие: маршрут должен обязательно пройти через клетку $(r,c)$, где $1\le r\le n$ и $1\le c\le m$.

Разделим маршрут в этой клетке на две части:

1. путь из $(1,1)$ в $(r,c)$;
2. путь из $(r,c)$ в $(n,m)$.

Сначала посчитаем количество вариантов для каждой части.

### Путь до клетки $(r,c)$

Чтобы попасть из $(1,1)$ в $(r,c)$, нужно сделать:

- $r-1$ шагов вниз;
- $c-1$ шагов вправо;
- $r+c-2$ шага всего.

Выберем позиции для $r-1$ шагов вниз. Число способов равно

$$C_{r+c-2}^{r-1}.$$

### Путь от клетки $(r,c)$ до финиша

Чтобы попасть из $(r,c)$ в $(n,m)$, нужно сделать:

- $n-r$ шагов вниз;
- $m-c$ шагов вправо;
- $n+m-r-c$ шагов всего.

Выберем позиции для $n-r$ шагов вниз. Получаем

$$C_{n+m-r-c}^{n-r}.$$

Для каждого способа добраться до клетки $(r,c)$ можно независимо выбрать любой способ пройти от неё до финиша. По правилу умножения число маршрутов через заданную клетку равно

$$C_{r+c-2}^{r-1}\cdot C_{n+m-r-c}^{n-r}.$$

Почему здесь можно применить правило умножения? Каждый маршрут через $(r,c)$ однозначно разбивается на два участка. И наоборот, любая пара из пути до $(r,c)$ и пути после $(r,c)$ образует ровно один полный маршрут.

> [!TIP]
> Условие «маршрут проходит через заданную точку» часто позволяет разделить путь на независимые части. Посчитайте количество вариантов для каждой части, а затем перемножьте результаты.

Формула работает и для граничных случаев. Например, если $(r,c)=(1,1)$, первый участок не содержит ни одного шага и существует ровно в одном варианте. Действительно, $C_0^0=1$. Аналогично обрабатывается случай $(r,c)=(n,m)$.

## 3.3. Путь в обход одной клетки

Теперь предположим, что клетка $(r,c)$ закрыта и проходить через неё нельзя.

Сначала посчитаем все маршруты из $(1,1)$ в $(n,m)$ без учёта препятствия:

$$C_{n+m-2}^{n-1}.$$

Среди них есть маршруты, проходящие через закрытую клетку. Их количество мы уже умеем находить:

$$C_{r+c-2}^{r-1}\cdot C_{n+m-r-c}^{n-r}.$$

Все допустимые маршруты — это все маршруты за вычетом маршрутов через закрытую клетку. Поэтому ответ равен

$$C_{n+m-2}^{n-1}-C_{r+c-2}^{r-1}\cdot C_{n+m-r-c}^{n-r}.$$

Обозначим количество всех маршрутов через `allWays`, а количество маршрутов через закрытую клетку — через `throughCell`. Тогда вычисление по модулю выглядит так:

```cpp
(allWays - throughCell + mod) % mod
```

Прибавление `mod` необходимо, чтобы результат вычитания не оказался отрицательным.

Формула корректно работает и в том случае, когда закрыта начальная или конечная клетка. Через каждую из них проходят все маршруты, поэтому после вычитания ответ будет равен нулю.

Программы предполагают, что выполняется условие $n+m<mod$. Это позволяет вычислить все необходимые факториалы и обратные факториалы способом из предыдущей главы.

Полные реализации доступны отдельно для самостоятельного изучения: [C++](examples/example-01.cpp) и [Python3](examples/example-01.py).

<details>
<summary><strong>C++: пути в обход одной закрытой клетки</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
const ll mod = 1000000007;
ll power(ll a, ll exponent) {
	ll answ = 1;
	while (exponent > 0) {
		if (exponent % 2 == 1) answ = answ * a % mod;
		a = a * a % mod;
		exponent /= 2;
	}
	return answ;
}
main() {
	int n, m, r, c; cin >> n >> m >> r >> c;
	int maxN = n + m;
	// Предподсчитываем факториалы, чтобы быстро получать каждое сочетание.
	vector<ll> fact(maxN + 1), invFact(maxN + 1);
	fact[0] = 1;
	for (int i = 1; i <= maxN; i++) fact[i] = fact[i - 1] * i % mod;
	invFact[maxN] = power(fact[maxN], mod - 2);
	for (int i = maxN; i >= 1; i--) invFact[i - 1] = invFact[i] * i % mod;
	auto combination = [&](int all, int chosen) {
		if (chosen < 0 || chosen > all) return 0LL;
		return fact[all] * invFact[chosen] % mod * invFact[all - chosen] % mod;
	};
	// Вычитаем пути через закрытую клетку из числа всех маршрутов.
	ll allWays = combination(n + m - 2, n - 1);
	ll throughCell = combination(r + c - 2, r - 1) * combination(n + m - r - c, n - r) % mod;
	cout << (allWays - throughCell + mod) % mod << '\n';
}
```

</details>

<summary><strong>Python3: пути в обход одной закрытой клетки</strong></summary>

```python
mod = 10 ** 9 + 7
def power(a, exponent):
	answ = 1
	while exponent > 0:
		if exponent % 2 == 1: answ = answ * a % mod
		a = a * a % mod
		exponent //= 2
	return answ
n, m, r, c = map(int, input().split())
maxN = n + m
# Предподсчитываем факториалы, чтобы быстро получать каждое сочетание.
fact = [1] * (maxN + 1)
for i in range(1, maxN + 1): fact[i] = fact[i - 1] * i % mod
invFact = [1] * (maxN + 1)
invFact[maxN] = power(fact[maxN], mod - 2)
for i in range(maxN, 0, -1): invFact[i - 1] = invFact[i] * i % mod
def combination(allCount, chosen):
	if chosen < 0 or chosen > allCount: return 0
	return fact[allCount] * invFact[chosen] % mod * invFact[allCount - chosen] % mod
# Вычитаем пути через закрытую клетку из числа всех маршрутов.
allWays = combination(n + m - 2, n - 1)
throughCell = combination(r + c - 2, r - 1) * combination(n + m - r - c, n - r) % mod
print((allWays - throughCell) % mod)
```

</details>

<details>
<summary><strong>Пример запуска</strong></summary>

```text
Ввод
4 5 2 3

Вывод
17
```

Всего из клетки $(1,1)$ в клетку $(4,5)$ существует $C_7^3=35$ маршрутов.

До закрытой клетки $(2,3)$ можно добраться $C_3^1=3$ способами. От неё до клетки $(4,5)$ можно добраться $C_4^2=6$ способами. Следовательно, через закрытую клетку проходят $3\cdot6=18$ маршрутов.

После их исключения остаётся $35-18=17$ допустимых маршрутов.
