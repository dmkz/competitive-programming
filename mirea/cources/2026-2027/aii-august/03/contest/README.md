# Разбор задач

## A. Подарок на день рождения

<details><summary><b>Идея</b></summary>

Каждый сувенир можно либо положить в коробку, либо не класть. При этом один и тот же сувенир разрешено выбрать не более одного раза.

Для каждой желаемой суммы цен нужно определить:

- минимальный возможный суммарный вес выбранных сувениров;
- максимальный возможный суммарный вес выбранных сувениров.

Перебирать все подмножества сувениров напрямую нельзя: при $n = 100$ их количество равно $2^{100}$.

Однако суммы, о которых спрашивают в запросах, не превосходят $100000$. Это позволяет применить динамическое программирование по суммарной цене — классический рюкзак.

Обычно в задачах о рюкзаке фиксируют вес и максимизируют цену. Здесь ситуация обратная: фиксируется цена, а среди всех наборов с такой ценой нужно найти минимальный и максимальный вес.

</details>

<details><summary><b>Состояние динамики</b></summary>

Пусть мы уже рассмотрели первые `i` сувениров.

Обозначим:

- `dpMin[i][s]` — минимальный суммарный вес набора из первых `i` сувениров, имеющего суммарную цену `s`;
- `dpMax[i][s]` — максимальный суммарный вес такого набора.

Если собрать набор цены `s` из первых `i` сувениров невозможно, будем хранить специальные значения:

- `dpMin[i][s] = INF`;
- `dpMax[i][s] = -INF`.

Здесь `INF` — достаточно большое число. В реализации можно использовать `1 << 60`: оно намного больше любого возможного суммарного веса.
</details>

<details><summary><b>Начальные значения</b></summary>

До рассмотрения сувениров существует ровно один доступный набор: пустой. Его цена равна нулю, и его вес тоже равен нулю. Поэтому:

```cpp
dpMin[0][0] = 0;
dpMax[0][0] = 0;
```

Все остальные суммы на этом этапе недостижимы.

</details>

<details><summary><b>Переходы</b></summary>

Рассмотрим очередной сувенир с ценой `v[i]` и весом `w[i]`. Пусть после его обработки мы хотим получить суммарную цену `s`. Возможны два случая.

### Не брать сувенир

Тогда набор не меняется. Все варианты, которые были доступны после обработки первых `i` сувениров, остаются доступными и после рассмотрения следующего.

```cpp
dpMin[i + 1] = dpMin[i];
dpMax[i + 1] = dpMax[i];
```

```python
dpMin[i + 1] = dpMin[i].copy()
dpMax[i + 1] = dpMax[i].copy()
```

Копирование слоя сразу учитывает все варианты, в которых текущий сувенир не выбран.

### Взять сувенир

Если текущий сувенир выбран и итоговая цена равна $s$, то до его добавления нужно было собрать набор цены $s - v_i$. Тогда его вес увеличивается на `w[i]`. Следовательно, переход для минимального веса выглядит так:

$dpMin[i + 1][s] = \min(dpMin[i + 1][s], dpMin[i][s - v_i] + w_i)$

Аналогично, для максимального веса:

$dpMax[i + 1][s] = \max(dpMax[i + 1][s], dpMax[i][s - v_i] + w_i)$

В коде:

```cpp
for (int s = v[i]; s <= S; s++) {
    setmin(dpMin[i + 1][s], w[i] + dpMin[i][s - v[i]]);
    setmax(dpMax[i + 1][s], w[i] + dpMax[i][s - v[i]]);
}
```

```python
for s in range(v[i], S + 1):
    dpMin[i + 1][s] = min(
        dpMin[i + 1][s],
        w[i] + dpMin[i][s - v[i]]
    )
    dpMax[i + 1][s] = max(
        dpMax[i + 1][s],
        w[i] + dpMax[i][s - v[i]]
    )
```

Важно, что мы переходим из слоя `i` в слой `i + 1`. Поэтому при добавлении текущего сувенира используются только наборы, построенные без него. Значит, один сувенир нельзя взять дважды.

</details>

<details><summary><b>Пример перехода</b></summary>

Пусть уже обработаны некоторые сувениры, и стоимость `5` можно получить с минимальным весом `12` и максимальным весом `20`.

Рассмотрим новый сувенир:

- его цена равна `3`;
- его вес равен `7`.

Тогда, добавив его к набору стоимости `5`, можно получить набор стоимости `8`.

Его минимальный вес будет равен: $12 + 7 = 19$.

Максимальный вес будет равен: $20 + 7 = 27$.

Однако это ещё не обязательно окончательные ответы для стоимости `8`: возможно, существуют другие способы набрать эту же цену. Поэтому новые значения нужно сравнить с уже имеющимися через `min` и `max`.

</details>

<details><summary><b>Ответы на запросы</b></summary>

После обработки всех `n` сувениров в динамике в строке `n` находятся ответы для всех возможных сумм цен.

Для каждого запроса `x`:

- если `dpMin[n][x]` равно `INF`, собрать подарок такой стоимости нельзя, поэтому выводим `-1`;
- иначе выводим `dpMin[n][x]` и `dpMax[n][x]`.

```cpp
if (dpMin[n][x[i]] >= inf)
    cout << "-1\n";
else
    cout << dpMin[n][x[i]] << ' ' << dpMax[n][x[i]] << '\n';
```

```python
if dpMin[n][x[i]] >= inf:
    print(-1)
else:
    print(dpMin[n][x[i]], dpMax[n][x[i]])
```

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что динамика находит правильные минимальные и максимальные веса для каждой стоимости.

Рассмотрим `dpMin[i][s]` и `dpMax[i][s]`. Они должны содержать соответственно минимальный и максимальный вес среди всех наборов из первых `i` сувениров общей стоимости `s`.

### База индукции

При `i = 0` сувениров нет.

Можно собрать только пустой набор, имеющий цену `0` и вес `0`. Поэтому:

$dpMin = dpMax = 0$.

Все положительные стоимости недостижимы. Начальная инициализация корректна.

### Переход индукции

Предположим, что после обработки первых `i` сувениров все значения динамики корректны.

Рассмотрим любой набор из первых `i + 1` сувениров стоимости `s`.

У него есть ровно две возможности:

- текущий сувенир не выбран;
- текущий сувенир выбран.

Если текущий сувенир не выбран, то этот набор полностью состоит из первых `i` сувениров. Такой вариант учитывается копированием предыдущего слоя.

Если текущий сувенир выбран, то после его удаления остаётся набор из первых `i` сувениров стоимости `s - v[i]`. По предположению индукции минимальный и максимальный веса такого набора уже лежат в `dpMin[i][s - v[i]]` и `dpMax[i][s - v[i]]`. После добавления веса `w[i]` получаются все варианты, в которых текущий сувенир выбран.

Таким образом, динамика рассматривает все допустимые наборы стоимости `s` и выбирает среди них минимальный и максимальный вес.

Следовательно, после обработки всех сувениров значения `dpMin[n][s]` и `dpMax[n][s]` содержат правильные ответы.

</details>

<details><summary><b>Сложность</b></summary>

Обозначим через $S$ максимальную сумму среди всех запросов текущего теста: $S = \max x_i$.

Для каждого из `n` сувениров перебираются все стоимости от `0` до `S`. Поэтому время работы равно: $O(nS)$.

В данной реализации хранятся все слои динамики, поэтому память составляет: $O(nS)$.

При $n \leq 100$ и $S \leq 100000$ реализация на C++ укладывается в ограничение памяти.

Суммарный вес может достигать $100 \cdot 10^9 = 10^{11}$, поэтому для весов и значений динамики в C++ необходимо использовать тип `long long`.

</details>

<details><summary><b>Реализация на C++</b></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
void setmin(auto &x, const auto &y) { if (y < x) x = y; }
void setmax(auto &x, const auto &y) { if (y > x) x = y; }
using ll = long long;
const ll inf = 1LL << 60;
void solve() {
    // читаем входные данные:
    int n, q; cin >> n >> q;
    vector<int> w(n), v(n), x(q);
    for (auto &it : w) cin >> it;
    for (auto &it : v) cin >> it;
    for (auto &it : x) cin >> it;
    // считаем максимальную сумму:
    const int S = *max_element(x.begin(), x.end());
    // строим два рюкзака:
    // dpMin[n][s] = минимальный суммарный вес для набора стоимостью s
    // dpMax[n][s] = максимальный суммарный вес для набора стоимостью s
    vector dpMin(n+1, vector(S+1, +inf));
    vector dpMax(n+1, vector(S+1, -inf));
    // инициализация:
    dpMin[0][0] = 0;
    dpMax[0][0] = 0;
    // считаем переходы:
    for (int i = 0; i < n; i++) {
        // копируем предыдущий слой - здесь мы не берём i-й предмет:
        dpMin[i+1] = dpMin[i];
        dpMax[i+1] = dpMax[i];
        // обновляем варианты, если i-й предмет выбран:
        for (int s = v[i]; s <= S; s++) {
            // Сейчас стоимость s, взяли предмет (v[i], w[i]), значит до этого
            // стоимость была s - v[i], и нам нужен мин и макс вес для предыдущего рюкзака
            setmin(dpMin[i+1][s], w[i] + dpMin[i][s-v[i]]);
            setmax(dpMax[i+1][s], w[i] + dpMax[i][s-v[i]]);
        }
    }
    // отвечаем на запросы:
    for (int i = 0; i < q; i++)
        if (dpMin[n][x[i]] >= +inf)
            cout << "-1\n";
        else
            cout << dpMin[n][x[i]] << ' ' << dpMax[n][x[i]] << '\n';
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details><summary><b>Реализация на Python</b></summary>

```python
inf = 1 << 60
def solve():
    # читаем входные данные:
    n, q = map(int, input().split())
    w = list(map(int, input().split()))
    v = list(map(int, input().split()))
    x = list(map(int, input().split()))
    # считаем максимальную сумму:
    S = max(x)
    # строим два рюкзака:
    # dpMin[n][s] = минимальный суммарный вес для набора стоимостью s
    # dpMax[n][s] = максимальный суммарный вес для набора стоимостью s
    dpMin = [[inf] * (S + 1) for _ in range(n + 1)]
    dpMax = [[-inf] * (S + 1) for _ in range(n + 1)]
    # инициализация:
    dpMin[0][0] = 0
    dpMax[0][0] = 0
    # считаем переходы:
    for i in range(n):
        # копируем предыдущий слой - здесь мы не берём i-й предмет:
        dpMin[i + 1] = dpMin[i].copy()
        dpMax[i + 1] = dpMax[i].copy()
        # обновляем варианты, если i-й предмет выбран:
        for s in range(v[i], S + 1):
            # Сейчас стоимость s, взяли предмет (v[i], w[i]), значит до этого
            # стоимость была s - v[i], и нам нужен мин и макс вес для предыдущего рюкзака
            dpMin[i + 1][s] = min(dpMin[i + 1][s], w[i] + dpMin[i][s - v[i]])
            dpMax[i + 1][s] = max(dpMax[i + 1][s], w[i] + dpMax[i][s - v[i]])
    # отвечаем на запросы:
    for i in range(q):
        if dpMin[n][x[i]] >= inf:
            print(-1)
        else:
            print(dpMin[n][x[i]], dpMax[n][x[i]])

tt = int(input())
while tt > 0:
    solve()
    tt -= 1
```

</details>

## B. Осторожная лестница

<details><summary><b>Идея</b></summary>

Студент начинает на первой ступени и должен попасть на последнюю. За один ход он может перейти на следующую ступень или перепрыгнуть через одну, то есть перейти на одну или две ступени вперёд.

На ступени с числом `0` наступать нельзя. Кроме того, среди всех посещённых ступеней не должно быть трёх подряд идущих ступеней с положительными числами.

Нужно не только понять, существует ли допустимый маршрут, но и найти максимальную сумму чисел на посещённых ступенях.

Обычная динамика по номеру ступени должна учитывать не только текущую позицию, но и информацию о последних посещённых ступенях. Действительно, если мы пришли на ступень с положительным числом, важно знать, сколько положительных чисел подряд уже было в конце маршрута.

Будем хранить длину текущей серии положительных чисел. Так как три положительных числа подряд запрещены, возможны только три состояния:

- `0` — последняя посещённая ступень содержит отрицательное число;
- `1` — маршрут заканчивается ровно одним положительным числом;
- `2` — маршрут заканчивается двумя положительными числами подряд.

</details>

<details><summary><b>Состояние динамики</b></summary>

Пусть `dp[i][k]` — максимальная сумма чисел на допустимом маршруте, который заканчивается на ступени `i`, а текущая серия положительных чисел в конце маршрута имеет длину `k`.

Параметр `k` принимает одно из трёх значений:

- `k = 0`, если на ступени `i` записано отрицательное число;
- `k = 1`, если ступень `i` содержит положительное число, а предыдущая посещённая ступень — отрицательная или отсутствует;
- `k = 2`, если ступень `i` и предыдущая посещённая ступень содержат положительные числа.

Если в состояние `dp[i][k]` попасть невозможно, в нём хранится значение `-inf`.

Важно, что серия считается только среди посещённых ступеней. Например, при маршруте `1 → 3 → 5` ступени `1`, `3` и `5` являются тремя подряд идущими посещёнными ступенями, хотя между ними были пропущены другие ступени.

</details>

<details><summary><b>Начальные значения</b></summary>

Маршрут всегда начинается на первой ступени. По условию она доступна, поэтому её число не равно нулю.

Если на первой ступени записано отрицательное число, маршрут состоит из одной ступени и заканчивается серией положительных чисел длины `0`:

#### C++

```cpp
if (a[0] < 0)
    dp[0][0] = a[0];
```

#### Python

```python
if a[0] < 0:
    dp[0][0] = a[0]
```

Если же число положительное, в конце маршрута находится ровно одно положительное число:

#### C++

```cpp
else {
    assert(a[0] > 0);
    dp[0][1] = a[0];
}
```

#### Python

```python
else:
    assert a[0] > 0
    dp[0][1] = a[0]
```

Все остальные состояния остаются недостижимыми.

</details>

<details><summary><b>Переходы</b></summary>

Рассмотрим ступень `i`.

На неё можно прийти только со ступени `i - 1` или со ступени `i - 2`, поскольку студент делает прыжки длины один или два.

Ступени с числом `0` недоступны. Поэтому для них не выполняется ни одна из ветвей перехода: значения `dp[i][k]` остаются равными `-inf`.

### Отрицательное число

Если `a[i] < 0`, то после посещения этой ступени серия положительных чисел обрывается. Независимо от предыдущего состояния новая длина серии равна `0`.

Значит, можно прийти из любого состояния `k` на одной из двух предыдущих ступеней. Переход имеет вид:

$dp[i][0] = \max(dp[i][0], a[i] + dp[i - d][k])$

Здесь $d$ равно `1` или `2`, а $k$ принимает значения `0`, `1` и `2`.

В решении эти два возможных прыжка записаны отдельно:

#### C++

```cpp
if (a[i] < 0) // отрицательное число прерывает серию
    for (int k = 0; k <= 2; k++) {
        // прыжок на 1:
        if (i-1 >= 0) setmax(dp[i][0], a[i] + dp[i-1][k]);
        // прежок на 2:
        if (i-2 >= 0) setmax(dp[i][0], a[i] + dp[i-2][k]);
    }
```

#### Python

```python
if a[i] < 0:  # отрицательное число прерывает серию
    for k in range(3):
        # прыжок на 1:
        if i - 1 >= 0:
            dp[i][0] = max(dp[i][0], a[i] + dp[i - 1][k])
        # прежок на 2:
        if i - 2 >= 0:
            dp[i][0] = max(dp[i][0], a[i] + dp[i - 2][k])
```

### Положительное число

Если `a[i] > 0`, оно продолжает текущую серию положительных чисел.

Чтобы получить серию длины `1`, перед этим маршрут должен был заканчиваться отрицательной ступенью, то есть находиться в состоянии `0`.

Чтобы получить серию длины `2`, предыдущий маршрут должен был заканчиваться ровно одним положительным числом, то есть находиться в состоянии `1`.

Переход имеет вид:

$dp[i][k] = \max(dp[i][k], a[i] + dp[i - d][k - 1])$

Здесь $d$ равно `1` или `2`, а $k$ равно `1` или `2`.

Перехода в состояние `k = 3` нет. Именно поэтому маршрут не может содержать три положительных числа подряд.

В решении:

#### C++

```cpp
else if (a[i] > 0) // положительное число продолжает серию
    for (int k = 1; k <= 2; k++) {
        // прыжок на 1:
        if (i-1 >= 0) setmax(dp[i][k], a[i] + dp[i-1][k-1]);
        // прыжок на 2:
        if (i-2 >= 0) setmax(dp[i][k], a[i] + dp[i-2][k-1]);
    }
```

#### Python

```python
elif a[i] > 0:  # положительное число продолжает серию
    for k in range(1, 3):
        # прыжок на 1:
        if i - 1 >= 0:
            dp[i][k] = max(dp[i][k], a[i] + dp[i - 1][k - 1])
        # прыжок на 2:
        if i - 2 >= 0:
            dp[i][k] = max(dp[i][k], a[i] + dp[i - 2][k - 1])
```

</details>

<details><summary><b>Пример</b></summary>

Рассмотрим ступени со значениями:

```text
2 5 -8 4 3
```

Подходит маршрут `1 → 2 → 3 → 4 → 5`.

На первых двух ступенях находятся положительные числа `2` и `5`, поэтому после второй ступени длина текущей серии равна `2`.

Третья ступень содержит число `-8`. Она прерывает серию положительных чисел, поэтому после неё состояние становится равным `0`.

Затем студент посещает ступени со значениями `4` и `3`. Это ещё одна серия из двух положительных чисел.

Получается маршрут с суммой $2 + 5 - 8 + 4 + 3 = 6$. Он допустим, потому что в нём нет трёх положительных чисел подряд среди посещённых ступеней.

</details>

<details><summary><b>Ответ</b></summary>

После обработки всех ступеней нас интересуют состояния на последней ступени.

Максимальная найденная сумма равна `answ`:

#### C++

```cpp

const ll minPossibleAnswer = n * ll(*min_element(all(a)));
if (answ < minPossibleAnswer) cout << "0\n";
else cout << "1 " << answ << '\n';
```

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что динамика находит максимальную сумму среди маршрутов, которые удовлетворяют ограничению на положительные числа.

Рассмотрим состояние `dp[i][k]`. По определению оно хранит максимальную сумму на допустимом маршруте, который заканчивается на ступени `i`, а длина серии положительных чисел в конце маршрута равна `k`.

### База индукции

Маршрут начинается на первой ступени.

Если `a[0] < 0`, единственный маршрут в начале состоит из первой ступени, имеет сумму `a[0]` и заканчивается серией положительных чисел длины `0`. Поэтому значение `dp[0][0]` инициализируется числом `a[0]`.

Если `a[0] > 0`, единственный маршрут имеет сумму `a[0]` и заканчивается серией положительных чисел длины `1`. Поэтому значение `dp[0][1]` инициализируется числом `a[0]`.

Все остальные состояния недостижимы. Значит, база корректна.

### Переход индукции

Предположим, что значения динамики для всех ступеней с номерами меньше `i` корректны.

Любой маршрут, который приходит на ступень `i`, делает последний прыжок либо со ступени `i - 1`, либо со ступени `i - 2`. Других вариантов по условию нет.

Если `a[i] < 0`, то посещение этой ступени прерывает любую серию положительных чисел. Предыдущий маршрут мог находиться в любом из состояний `0`, `1` и `2`. Динамика перебирает оба возможных предыдущих номера ступени и все три состояния, после чего выбирает наибольшую сумму.

Если `a[i] > 0`, длина серии увеличивается на единицу. В состояние `1` можно перейти только из состояния `0`, а в состояние `2` — только из состояния `1`. Переход из состояния `2` на положительную ступень не рассматривается, поскольку в таком случае в маршруте появились бы три положительных числа подряд.

Таким образом, все допустимые маршруты, приходящие на ступень `i`, учтены переходами динамики. Среди маршрутов с одинаковыми `i` и `k` сохраняется только вариант с наибольшей суммой.

Следовательно, после обработки последней ступени максимум среди состояний `dp[n - 1][0]`, `dp[n - 1][1]` и `dp[n - 1][2]` соответствует максимальной сумме допустимого маршрута.

</details>

<details><summary><b>Сложность</b></summary>

Для каждой ступени рассматриваются не более двух предыдущих ступеней и три возможных состояния динамики.

Поэтому время работы составляет $O(n)$.

В решении хранится по три значения динамики для каждой из `n` ступеней, поэтому память составляет $O(n)$.

Сумма всех значений $n$ по тестам не превосходит $300000$, поэтому решение укладывается в ограничения.

Значения на ступенях могут достигать $10^9$ по модулю, а суммарный ответ — порядка $10^{14}$. Поэтому в C++ необходимо использовать тип `long long`.

</details>

<details><summary><b>Реализация на C++</b></summary>

#### C++

```cpp
#include <bits/stdc++.h>
#include <cassert>
#define all(x) (x).begin(),(x).end()
using namespace std;
using ll = long long;
const ll inf = 1LL << 60;
void setmax(auto &x, const auto &y) { if (x < y) x = y; }
void solve() {
    // читаем данные:
    int n; cin >> n;
    vector<int> a(n);
    for (auto &it : a)
        cin >> it;
    // считаем динамику: dp[i][k] -> максимальная сумма, с которой мы пришли в i-ю ступеньку,
    // где текущая серия взятых положительных чисел равна k.
    vector dp(n, vector(3, -inf));
    // инициализация динамики:
    if (a[0] < 0)
        dp[0][0] = a[0];
    else {
        assert(a[0] > 0);
        dp[0][1] = a[0];
    }
    for (int i = 1; i < n; i++)
        if (a[i] < 0) // отрицательное число прерывает серию
            for (int k = 0; k <= 2; k++) {
                // прыжок на 1:
                if (i-1 >= 0) setmax(dp[i][0], a[i] + dp[i-1][k]);
                // прежок на 2:
                if (i-2 >= 0) setmax(dp[i][0], a[i] + dp[i-2][k]);
            }
        else if (a[i] > 0) // положительное число продолжает серию
            for (int k = 1; k <= 2; k++) {
                // прыжок на 1:
                if (i-1 >= 0) setmax(dp[i][k], a[i] + dp[i-1][k-1]);
                // прыжок на 2:
                if (i-2 >= 0) setmax(dp[i][k], a[i] + dp[i-2][k-1]);
            }
    // выводим ответ:
    ll answ = *max_element(dp[n-1].begin(), dp[n-1].end());
    const ll minPossibleAnswer = n * ll(*min_element(all(a)));
    if (answ < minPossibleAnswer) cout << "0\n";
    else cout << "1 " << answ << '\n';
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

## C. Олимпиадное общежитие!

<details><summary><b>Идея</b></summary>

Нужно разбить всех участников ровно на $k$ комнат. В каждой комнате должно быть от двух до четырёх человек, а вклад комнаты в ответ определяется только её минимальным и максимальным результатами. Если пытаться перебирать составы комнат напрямую, придётся выбирать произвольные подмножества участников, и число таких вариантов слишком велико.

Сначала отсортируем результаты. После этого естественно хочется, чтобы участники с близкими результатами жили вместе: помещение в одну комнату очень слабого и очень сильного участника увеличивает её неудобство, даже если между ними находятся другие результаты.

Главный факт состоит в том, что существует оптимальное разбиение, в котором каждая комната образует непрерывный отрезок отсортированного массива. Действительно, если жители двух комнат в отсортированном порядке перемешаны, можно сохранить размеры комнат, но отдать одной комнате более ранние элементы, а другой — более поздние. Внутренние крайние значения при таком «распутывании» не расходятся дальше, поэтому сумма неудобств не увеличивается. Повторяя это преобразование, получаем разбиение на отрезки.

Значит, после сортировки достаточно последовательно покрыть массив группами длины $2$, $3$ или $4$. Стоимость очередной группы $[l, r]$ сразу известна и равна $a[r] - a[l]$. Остаётся выбрать длины групп так, чтобы групп было ровно $k$ и суммарная стоимость была минимальной.

</details>

<details><summary><b>Как прийти к динамике</b></summary>

После сведения к отрезкам решение строится слева направо. Предположим, уже распределены первые несколько участников в отсортированном порядке. Для продолжения важно знать не конкретный состав уже созданных комнат, а только два факта: сколько первых участников использовано и сколько комнат уже образовано. Все дальнейшие решения зависят именно от этой границы префикса и числа комнат.

Удобно рассматривать последнюю комнату в разбиении некоторого префикса. Её размер может быть только $2$, $3$ или $4$. Если последняя комната занимает элементы с индексами от $j$ до $i$, то до неё независимо и оптимально разбивается префикс из первых $j$ элементов, а стоимость самой комнаты равна $a[i] - a[j]$. Это и приводит к динамике по префиксу и числу комнат.

</details>

<details><summary><b>Состояние динамики</b></summary>

Пусть $dp[i][g]$ — минимальная суммарная неудобность при разбиении первых $i$ участников отсортированного массива ровно на $g$ комнат. Если такое разбиение невозможно, значение состояния считается бесконечным.

Индексы участников в массиве начинаются с нуля, поэтому первые $i$ участников — это элементы с индексами от $0$ до $i - 1$. Такое определение удобно: если последняя комната начинается с индекса $j$, то перед ней остаётся ровно первые $j$ участников, то есть состояние $dp[j][g]$.

</details>

<details><summary><b>Начальные значения</b></summary>

Пустой префикс можно распределить в ноль комнат с нулевой суммарной неудобностью, поэтому $dp[0][0] = 0$. Все остальные состояния изначально недостижимы.

Бесконечность нужна, чтобы переход из невозможного состояния не мог улучшить корректный ответ. В коде для этого используется значение `inf`.

</details>

<details><summary><b>Переходы</b></summary>

Рассмотрим комнату, которая заканчивается на участнике с индексом $i$. Переберём её размер $sz$ от $2$ до $4$. Тогда она начинается в позиции $j = i - sz + 1$, содержит отрезок $[j, i]$ и имеет стоимость $a[i] - a[j]$.

Если до этой комнаты первые $j$ участников были размещены в `wasGroups` комнатах, то после добавления новой комнаты первые $i + 1$ участников размещены в `wasGroups + 1` комнатах:

$dp[i + 1][wasGroups + 1] = \min(dp[i + 1][wasGroups + 1], dp[j][wasGroups] + a[i] - a[j])$.

Перебор всех трёх допустимых размеров последней комнаты рассматривает все возможные варианты её границы. А минимум выбирает наилучшее разбиение среди них.

</details>

<details><summary><b>Пример</b></summary>

В первом наборе после сортировки получаем массив $[1, 3, 10, 12]$. Нужно создать две комнаты. Поскольку всего участников четыре, обе комнаты должны иметь размер два. Возможное разбиение на отрезки — $[1, 3]$ и $[10, 12]$. Их стоимости равны $3 - 1 = 2$ и $12 - 10 = 2$, поэтому суммарный ответ равен $4$.

Динамика получает это значение, когда для последней комнаты $[10, 12]$ выбирается размер $2$: к оптимальному значению $dp[2][1] = 2$ прибавляется стоимость $12 - 10 = 2$.

</details>

<details><summary><b>Ответ</b></summary>

Все $n$ участников должны быть распределены ровно по $k$ комнатам. По определению состояния искомое значение равно $dp[n][k]$.

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что алгоритм выводит минимальную возможную сумму неудобств.

Сначала обоснуем сведение к отрезкам. Рассмотрим участников в порядке неубывания результатов. Если две комнаты перемешаны в этом порядке, перераспределим их жителей, сохранив размеры комнат: более ранние элементы отдадим первой комнате, а более поздние — второй. У крайних значений новых комнат не возникает большего разброса, чем у исходных пересекающихся комнат, поэтому сумма их неудобств не увеличивается. Последовательно устраняя все такие пересечения, получаем оптимальное разбиение, в котором жители каждой комнаты идут подряд в отсортированном массиве.

Теперь докажем корректность динамики. Состояние $dp[i][g]$ означает минимальную стоимость разбиения первых $i$ отсортированных участников ровно на $g$ допустимых комнат. База $dp[0][0] = 0$ корректна: пустой набор не требует комнат и не создаёт неудобства. Другие начальные состояния невозможны, что корректно отражает бесконечность.

Рассмотрим любое допустимое разбиение первых $i + 1$ участников на `wasGroups + 1` комнат. В нём последняя комната является отрезком $[j, i]$ длины $2$, $3$ или $4$. Удалим её. Оставшиеся первые $j$ участников образуют допустимое разбиение на `wasGroups` комнат, стоимость которого не меньше $dp[j][wasGroups]$ по определению состояния. Поэтому стоимость исходного разбиения не меньше значения, получаемого соответствующим переходом.

С другой стороны, каждый переход берёт корректное разбиение первых $j$ участников и добавляет к нему допустимую последнюю комнату размера от $2$ до $4$. Следовательно, он действительно строит допустимое разбиение первых $i + 1$ участников. Перебор размеров $2$, $3$ и $4$ охватывает все возможные последние комнаты, а взятие минимума оставляет лучшую стоимость среди всех допустимых разбиений данного префикса.

По индукции по длине префикса все состояния динамики имеют заявленный смысл. В частности, $dp[n][k]$ является минимальной стоимостью разбиения всех участников ровно на $k$ комнат, то есть искомым ответом.

</details>

<details><summary><b>Сложность</b></summary>

Для каждого из $n$ правых концов последней комнаты перебираются три её возможных размера и до $k$ значений числа уже созданных комнат. Поэтому время работы одного набора данных равно $O(nk)$.

Таблица динамики содержит $(n + 1)(k + 1)$ значений, поэтому используется $O(nk)$ памяти. Ограничение на сумму произведений $nk$ не превосходит $4000000$, поэтому такая сложность соответствует ограничениям.

</details>

<details><summary><b>Реализация на C++</b></summary>

#### C++

```cpp
#include <bits/stdc++.h>
#include <cassert>
#define all(x) (x).begin(),(x).end()
using namespace std;
using ll = long long;
const ll inf = 1LL << 60;
void setmin(auto &x, const auto &y) { if (x > y) x = y; }
void solve() {
    // читаем данные:
    int n, k; cin >> n >> k;
    vector<int> a(n);
    for (auto &it : a)
        cin >> it;
    // сортируем участников по возрастанию их результатов:
    sort(all(a));
    // делим участников на группы
    vector dp(1+n, vector(k+1, +inf));
    dp[0][0] = 0;
    for (int i = 0; i < n; i++) {
        for (int sz = 2; sz <= 4; sz++) {
            int j = i - sz + 1;
            if (j < 0) continue;
            // группа [j, i] стоимостью a[i] - a[j]
            for (int wasGroups = 0; wasGroups < k; wasGroups++)                
                setmin(dp[i+1][wasGroups+1], dp[j][wasGroups] + a[i] - a[j]);
        }
    }
    // выводим ответ:
    cout << dp[n][k] << '\n';
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

## D. Прогулка по городскому парку

<details><summary><b>Идея</b></summary>

Для каждого запроса требуется максимальная сумма по маршруту из клетки $(1, 1)$ в клетку $(n, m)$, который обязан посетить заданную клетку $(r, c)$. На первый взгляд можно было бы отдельно искать лучший маршрут для каждого запроса. Однако запросов может быть до $300000$, а один такой поиск по всей таблице потребовал бы $O(nm)$ времени. В худшем случае это дало бы слишком большую сложность.

Ключевой факт состоит в том, что любой маршрут, проходящий через клетку $(r, c)$, естественно распадается на две части: путь из $(1, 1)$ в $(r, c)$ и путь из $(r, c)$ в $(n, m)$. Ограничения на движения не мешают такому разбиению: до запрошенной клетки маршрут идёт только вправо и вниз, а после неё продолжает идти только вправо и вниз.

Следовательно, для каждого запроса достаточно заранее знать две величины: лучшую сумму на пути от старта до каждой клетки и лучшую сумму на пути от каждой клетки до финиша. Тогда ответ для $(r, c)$ получится сложением этих двух оптимальных значений. Значение самой клетки при этом будет учтено дважды, поэтому его нужно вычесть один раз.

Сначала решения считывают таблицу и все запросы. Запросы хранятся в двух массивах: номера строк и номера столбцов соответственно.

#### C++

```cpp
    vector a(nRows, vector<int>(nCols));
    for (auto &row : a)
        for (auto &it : row)
            cin >> it;
    vector<int> rows(q), cols(q);
    for (auto &it : rows) cin >> it;
    for (auto &it : cols) cin >> it;
```

#### Python

```python
    a = [list(map(int, input().split())) for _ in range(nRows)]
    rows = list(map(int, input().split()))
    cols = list(map(int, input().split()))
```

</details>

<details><summary><b>Как прийти к динамике</b></summary>

Рассмотрим сначала путь из старта в некоторую клетку $(r, c)$. Последним шагом в неё можно прийти ровно из одной из двух клеток: сверху или слева. Значит, если оптимальные ответы для этих предшественников уже известны, оптимальный путь в $(r, c)$ выбирает лучший из них и добавляет впечатление текущей клетки.

Аналогично удобно рассматривать путь из некоторой клетки до финиша. Первый шаг такого пути ведёт либо вниз, либо вправо. Поэтому значение для текущей клетки можно получить по значениям клеток снизу и справа. Чтобы они были вычислены заранее, нужно обходить таблицу от правого нижнего угла к левому верхнему.

Так появляются две независимые динамики. Первая отвечает за лучшие префиксы маршрутов, вторая — за лучшие суффиксы. После их вычисления каждый запрос обрабатывается за $O(1)$.

</details>

<details><summary><b>Состояние динамики</b></summary>

Пусть $dpS[r][c]$ — наибольшее возможное впечатление от маршрута из левой верхней клетки в клетку с индексами $r, c$ включительно.

Пусть $dpF[r][c]$ — наибольшее возможное впечатление от маршрута из клетки $r, c$ в правую нижнюю клетку включительно.

Все элементы таблиц первоначально получают значение $-inf$. Оно обозначает недостижимое состояние и позволяет безопасно брать максимум при переходах. В данной задаче из старта достижима каждая клетка, как и из каждой клетки достижим финиш, но такая инициализация единообразно задаёт динамики на границах.

#### C++

```cpp
    vector dpS(nRows, vector(nCols, -inf));
    vector dpF(nRows, vector(nCols, -inf));
    dpS[0][0] = a[0][0];
    dpF[nRows-1][nCols-1] = a[nRows-1][nCols-1];
```

#### Python

```python
    dpS = [[-inf] * nCols for _ in range(nRows)]
    dpF = [[-inf] * nCols for _ in range(nRows)]
    dpS[0][0] = a[0][0]
    dpF[nRows - 1][nCols - 1] = a[nRows - 1][nCols - 1]
```

</details>

<details><summary><b>Начальные значения</b></summary>

Для прямой динамики базой служит стартовая клетка: маршрут из неё в неё же состоит из одной клетки, поэтому $dpS[0][0] = a[0][0]$.

Для обратной динамики базой служит финишная клетка: маршрут из неё до неё же также состоит только из неё, поэтому $dpF[n-1][m-1] = a[n-1][m-1]$. Остальные значения будут восстановлены переходами.

</details>

<details><summary><b>Переходы</b></summary>

Для $dpS[r][c]$ рассматриваются все возможные последние шаги в клетку $(r, c)$. Если существует клетка сверху, можно продолжить оптимальный маршрут в неё шагом вниз. Если существует клетка слева, можно продолжить оптимальный маршрут в неё шагом вправо. Других способов попасть в текущую клетку нет, поэтому максимум этих вариантов даёт точное значение прямой динамики.

#### C++

```cpp
    for (int r = 0; r < nRows; r++)
        for (int c = 0; c < nCols; c++) {
            if (r > 0) setmax(dpS[r][c], a[r][c] + dpS[r-1][c]);
            if (c > 0) setmax(dpS[r][c], a[r][c] + dpS[r][c-1]);
        }
```

#### Python

```python
    for r in range(nRows):
        for c in range(nCols):
            if r > 0:
                dpS[r][c] = max(dpS[r][c], a[r][c] + dpS[r - 1][c])
            if c > 0:
                dpS[r][c] = max(dpS[r][c], a[r][c] + dpS[r][c - 1])
```

Для $dpF[r][c]$ рассуждение симметрично, только теперь рассматривается первый шаг из клетки $(r, c)$. Он может вести вниз либо вправо. В обходе справа налево и снизу вверх значения для клеток снизу и справа уже известны, поэтому по ним можно найти оптимальную сумму до финиша.

#### C++

```cpp
    for (int r = nRows-1; r >= 0; r--)
        for (int c = nCols-1; c >= 0; c--) {
            if (r + 1 < nRows) setmax(dpF[r][c], a[r][c] + dpF[r+1][c]);
            if (c + 1 < nCols) setmax(dpF[r][c], a[r][c] + dpF[r][c+1]);
        }
```

#### Python

```python
    for r in range(nRows - 1, -1, -1):
        for c in range(nCols - 1, -1, -1):
            if r + 1 < nRows:
                dpF[r][c] = max(dpF[r][c], a[r][c] + dpF[r + 1][c])
            if c + 1 < nCols:
                dpF[r][c] = max(dpF[r][c], a[r][c] + dpF[r][c + 1])
```

</details>

<details><summary><b>Пример</b></summary>

В первом наборе данных рассмотрим запрос для клетки $(2, 2)$ со значением $3$. Лучшая сумма из старта до неё равна $1 + 2 + 3 = 6$: нужно пройти через клетку $(2, 1)$. Лучшая сумма от неё до финиша равна $3 + 6 = 9$. При сложении значение $3$ оказалось посчитано в обеих частях, поэтому ответ равен $6 + 9 - 3 = 12$.

Это соответствует маршруту $(1,1) \rightarrow (2,1) \rightarrow (2,2) \rightarrow (2,3)$.

</details>

<details><summary><b>Ответ</b></summary>

Для запроса в клетке $(r, c)$ прямой и обратный оптимальные пути можно склеить в этой клетке. Их общая сумма равна $dpS[r][c] + dpF[r][c] - a[r][c]$: слагаемое $a[r][c]$ вычитается, потому что оно входит в обе части пути. Индексы запросов переводятся из нумерации с единицы в нумерацию с нуля.

#### C++

```cpp
    for (int i = 0; i < q; i++) {
        const int r = rows[i]-1, c = cols[i]-1;
        ll res = dpS[r][c] + dpF[r][c] - a[r][c];
        cout << res << '\n';
    }
```

#### Python

```python
    for i in range(q):
        r, c = rows[i] - 1, cols[i] - 1
        res = dpS[r][c] + dpF[r][c] - a[r][c]
        print(res)
```

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что алгоритм выводит максимальное возможное впечатление для каждого запроса.

По определению $dpS[r][c]$ должен содержать максимум среди всех маршрутов из старта в клетку $(r, c)$. База корректна: для клетки $(0, 0)$ существует единственный маршрут из одной клетки, и его сумма равна $a[0][0]$. Для любой другой клетки последний шаг допустимого маршрута приходит либо сверху, либо слева. Переход рассматривает оба этих и только эти случая, добавляя к оптимальному значению предшественника значение текущей клетки. Следовательно, по индукции в порядке обхода $dpS[r][c]$ равен оптимальной сумме от старта до $(r, c)$.

Аналогично, $dpF[r][c]$ должен содержать максимум среди всех маршрутов из $(r, c)$ в финиш. База в правой нижней клетке корректна. Первый шаг любого маршрута из другой клетки ведёт либо вниз, либо вправо; других допустимых направлений нет. Переход перебирает оба варианта и присоединяет значение текущей клетки к оптимальному продолжению. Поэтому по индукции в обратном порядке обхода $dpF[r][c]$ равен оптимальной сумме от $(r, c)$ до финиша.

Теперь зафиксируем запрос в клетке $(r, c)$. Любой допустимый маршрут, проходящий через неё, единственным образом делится на часть от старта до $(r, c)$ и часть от $(r, c)$ до финиша. Сумма первой части не превосходит $dpS[r][c]$, а второй — $dpF[r][c]$. При сложении значение запрошенной клетки учитывается дважды, поэтому суммарное значение любого такого маршрута не превосходит $dpS[r][c] + dpF[r][c] - a[r][c]$.

С другой стороны, оптимальный маршрут, задающий $dpS[r][c]$, и оптимальный маршрут, задающий $dpF[r][c]$, можно соединить в клетке $(r, c)$. Получится допустимый маршрут от старта до финиша через запрошенную клетку с суммой $dpS[r][c] + dpF[r][c] - a[r][c]$. Значит, вычисленная величина достижима и одновременно не меньше суммы любого допустимого маршрута. Следовательно, она и есть правильный ответ.

</details>

<details><summary><b>Сложность</b></summary>

Для каждого набора данных каждая из двух динамик один раз обходит все $nm$ клеток, а обработка запросов занимает $O(q)$. Поэтому время работы равно $O(nm + q)$.

Таблица значений и две таблицы динамики занимают $O(nm)$ памяти, а массивы запросов — $O(q)$. Общая память равна $O(nm + q)$. При ограничениях на суммы $nm$ и $q$ по всем наборам эти оценки соответствуют ограничениям.

</details>

#### C++

```cpp
#include <bits/stdc++.h>
#include <cassert>
using namespace std;
using ll = long long;
const ll inf = 1LL << 60;
void setmax(auto &x, const auto &y) { if (x < y) x = y; }
void solve() {
    // читаем все доступные данные:
    int nRows, nCols, q;
    cin >> nRows >> nCols >> q;
    vector a(nRows, vector<int>(nCols));
    for (auto &row : a)
        for (auto &it : row)
            cin >> it;
    vector<int> rows(q), cols(q);
    for (auto &it : rows) cin >> it;
    for (auto &it : cols) cin >> it;
    // считаем две динамики: прямую (1, 1) -> (n, m) и обратную (n, m) -> (1, 1)
    vector dpS(nRows, vector(nCols, -inf));
    vector dpF(nRows, vector(nCols, -inf));
    dpS[0][0] = a[0][0];
    dpF[nRows-1][nCols-1] = a[nRows-1][nCols-1];
    // переходы для прямой динамики:
    for (int r = 0; r < nRows; r++)
        for (int c = 0; c < nCols; c++) {
            if (r > 0) setmax(dpS[r][c], a[r][c] + dpS[r-1][c]);
            if (c > 0) setmax(dpS[r][c], a[r][c] + dpS[r][c-1]);
        }
    // переходы для обратной динамики:
    for (int r = nRows-1; r >= 0; r--)
        for (int c = nCols-1; c >= 0; c--) {
            if (r + 1 < nRows) setmax(dpF[r][c], a[r][c] + dpF[r+1][c]);
            if (c + 1 < nCols) setmax(dpF[r][c], a[r][c] + dpF[r][c+1]);
        }
    // отвечаем на запросы:
    for (int i = 0; i < q; i++) {
        const int r = rows[i]-1, c = cols[i]-1;
        ll res = dpS[r][c] + dpF[r][c] - a[r][c];
        cout << res << '\n';
    }
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

## E. История поздравлений

<details><summary><b>Идея</b></summary>

Требуется после каждого изменения узнать длину наибольшей общей подпоследовательности текущих строк $S$ и $T$. Если после каждой операции заново запускать стандартную динамику для LCS, придётся пересчитывать таблицу размера $|S| \cdot |T|$. При длинах до $1000$ это слишком дорого: число запросов велико, а измениться при этом мог всего один символ.

Сначала заметим главное свойство изменений: они происходят исключительно в конце строк. Поэтому после добавления буквы к $S$ все значения динамики для прежних префиксов $S$ и $T$ остаются правильными. Новыми становятся только значения, соответствующие новому полному префиксу $S$, то есть одна строка таблицы. Аналогично, добавление буквы к $T$ требует вычислить только один новый столбец.

Удаление ещё проще. При удалении последней буквы строка возвращается к некоторому ранее существовавшему префиксу. Значения динамики для него уже были вычислены в тот момент, когда этот префикс был текущей строкой, и после этого не менялись: позднейшие добавления заполняли только строки или столбцы с бо́льшими индексами. Значит, при удалении достаточно убрать букву из текущей строки и взять значение из уже сохранённой клетки таблицы.

Для удобной индексации решения добавляют в начало строк разные служебные символы. Тогда реальные буквы нумеруются с $1$, а строка или столбец с индексом $0$ естественно соответствуют пустому префиксу и содержат нули.

#### C++

```cpp
    string s, t;
    cin >> s >> t;
    s = "$" + s;
    t = "^" + t;
```

#### Python

```python
    s = ["$"] + list(input())
    t = ["^"] + list(input())
```

</details>

<details><summary><b>Как прийти к динамике</b></summary>

Рассмотрим любые префиксы: первые $i$ букв строки $S$ и первые $j$ букв строки $T$. Чтобы понять длину их наибольшей общей подпоследовательности, удобно посмотреть на последние буквы этих префиксов.

Если они совпадают, эту букву можно поставить последней в общей подпоследовательности. До неё остаётся оптимально сопоставить префиксы длины $i - 1$ и $j - 1$.

Если последние буквы различны, одна общая подпоследовательность не может использовать их обе в качестве одного последнего элемента. Следовательно, хотя бы одна из этих букв не используется. Можно либо не учитывать последнюю букву первого префикса, либо не учитывать последнюю букву второго. Так задача сводится к одному из двух меньших префиксных подзадач.

Именно эта зависимость от соседних меньших префиксов позволяет сначала заполнить таблицу для начальных строк, а затем при добавлении символа пересчитывать только новую строку либо новый столбец.

</details>

<details><summary><b>Состояние динамики</b></summary>

Пусть $dp[i][j]$ — длина наибольшей общей подпоследовательности первых $i$ настоящих букв текущей строки $S$ и первых $j$ настоящих букв текущей строки $T$. Иными словами, это ответ для префиксов, оканчивающихся в служебно дополненных строках на позициях $i$ и $j$.

Состояний с недостижимым значением здесь нет: любая пара префиксов имеет общую подпоследовательность, хотя бы пустую. Поэтому таблица создаётся нулевой. Нулевая строка и нулевой столбец — это случаи, когда один из префиксов пуст; их ответ равен $0$.

Начальная таблица вычисляется обычной динамикой по всем парам индексов. Это необходимо сделать один раз для исходных строк каждого набора.

#### C++

```cpp
int dp[1001][1001]; // глобальный массив нужен из-за мультитестов
                    // нельзя выделять массив 1001 * 1001 для каждого теста, так как их 10000
```

#### Python

```python
dp = [[0] * 1001 for _ in range(1001)]  # глобальный массив нужен из-за мультитестов
                                         # нельзя выделять массив 1001 * 1001 для каждого теста, так как их 10000
```

#### C++

```cpp

    for (int i = 1; i < isz(s); i++)
        for (int j = 1; j < isz(t); j++)
            if (s[i] == t[j]) dp[i][j] = 1 + dp[i-1][j-1];
            else dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
```

#### Python

```python
        for j in range(1, len(t)):

```

</details>

<details><summary><b>Переходы</b></summary>

Для клетки $dp[i][j]$ есть два случая.

- Если $S[i] = T[j]$, существует оптимальная общая подпоследовательность, заканчивающаяся этой общей буквой. Её длина равна $1 + dp[i - 1][j - 1]$.
- Иначе последняя буква хотя бы одного из рассматриваемых префиксов не входит в оптимальную подпоследовательность. Поэтому надо выбрать лучшее из $dp[i - 1][j]$ и $dp[i][j - 1]$.

При операции `S+` появляется новая последняя буква $S$, а значит, требуется пройти по всем префиксам $T$ и вычислить строку с новым индексом $i$. Значения сверху и слева к моменту вычисления каждой клетки уже известны: верхняя строка была построена раньше, а предыдущая клетка текущей строки вычислена на предыдущем шаге цикла.

#### C++

```cpp
    // отдельно вынесем функцию вычисления i-й строки: она получается удалением цикла по j
    auto calcIthRow = [&](int i) {
        for (int j = 1; j < isz(t); j++)
            if (s[i] == t[j]) dp[i][j] = 1 + dp[i-1][j-1];
            else dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
    };
```


<details><summary><b>Пример</b></summary>

Рассмотрим первый набор: исходные строки равны `a` и `a`. После `S+ c` получаются `ac` и `a`. Добавленная строка динамики соответствует букве `c`; совпадения с единственной буквой `a` нет, поэтому значение в правой нижней клетке остаётся равным $1$.

После `T+ c` появляется новый столбец для буквы `c`. В правой нижней клетке совпадают последние буквы `c`, поэтому к значению для префиксов `a` и `a`, равному $1$, добавляется единица. Ответ становится равным $2$.

После `S-` текущая строка вновь становится `a`. Никакой пересчёт не требуется: нужная клетка для префиксов `a` и `ac` уже была вычислена до добавления `c` в первую строку. Её значение равно $1$.

</details>

<details><summary><b>Ответ</b></summary>

После каждого запроса текущие строки имеют длины $|S|$ и $|T|$. По определению состояния искомая длина LCS находится в клетке $dp[|S|][|T|]$. В реализации служебные символы занимают позицию $0$, поэтому индекс последней настоящей буквы равен длине контейнера минус $1$.


<details><summary><b>Корректность</b></summary>

Докажем, что алгоритм после каждого запроса выводит длину наибольшей общей подпоследовательности текущих строк.

По определению $dp[i][j]$ должен содержать длину LCS префиксов из первых $i$ букв $S$ и первых $j$ букв $T$. База корректна: если $i = 0$ или $j = 0$, хотя бы один префикс пуст, поэтому общая подпоследовательность может иметь только длину $0$.

Рассмотрим вычисление клетки $dp[i][j]$ при положительных $i$ и $j$. Если $S[i] = T[j]$, можно закончить общую подпоследовательность этой буквой. Всё, что стоит до неё, является общей подпоследовательностью префиксов длины $i - 1$ и $j - 1$, а оптимальная её длина равна $dp[i - 1][j - 1]$. Следовательно, переход $1 + dp[i - 1][j - 1]$ даёт оптимальное значение.

Если $S[i] \ne T[j]$, общая подпоследовательность не может использовать обе эти буквы как один общий последний элемент. Значит, в любом допустимом решении не используется последняя буква первого префикса либо не используется последняя буква второго. В первом случае его длина не превосходит $dp[i - 1][j]$, во втором — $dp[i][j - 1]$. Максимум этих значений достижим соответствующей оптимальной подпоследовательностью, поэтому переход корректен и рассматривает все допустимые случаи.

Следовательно, начальное заполнение вычисляет корректные значения для всех префиксов исходных строк. После `S+` изменяется только префикс, включающий новую последнюю букву $S$, то есть только новая строка. Алгоритм пересчитывает её по уже доказанным корректным переходам, используя старые строки и ранее вычисленные клетки новой строки. Поэтому вся таблица для новых текущих строк остаётся корректной. Тот же аргумент работает для `T+`, когда пересчитывается только новый столбец.

После `S-` или `T-` текущая строка становится прежним префиксом. Его значения в таблице были корректно вычислены раньше и не перезаписывались, поскольку добавления записывают лишь новые строки или столбцы. Значит, после удаления таблица также содержит корректное значение для текущей пары строк.

Наконец, клетка $dp[|S|][|T|]$ по смыслу состояния соответствует полным текущим строкам. Поэтому выводимое из неё значение равно длине их наибольшей общей подпоследовательности. Алгоритм корректен.

</details>

<details><summary><b>Сложность</b></summary>

Для начальных строк одного набора таблица заполняется за $O(|S| \cdot |T|)$ времени. Операция `S+` пересчитывает строку длины $|T|$, поэтому занимает $O(|T|)$; операция `T+` занимает $O(|S|)$. Удаления выполняются за $O(1)$.

Суммарное время начальных заполнений равно $O(u)$, а суммарное время всех добавлений равно $O(w)$. Остальные запросы добавляют $O(q)$, поэтому итоговая оценка — $O(u + w + q)$. По ограничениям это укладывается в заданные пределы.

Таблица $dp$ содержит $1001 \cdot 1001$ целых чисел, поэтому используется $O(1000^2)$ памяти. Она глобальная и переиспользуется между наборами, что не создаёт отдельную таблицу для каждого из них.

</details>

#### C++

```cpp
#include <bits/stdc++.h>
#define isz(x) (int)(x).size()
using namespace std;
int dp[1001][1001]; // глобальный массив нужен из-за мультитестов
                    // нельзя выделять массив 1001 * 1001 для каждого теста, так как их 10000
void solve() {
    // читаем данные:
    string s, t;
    cin >> s >> t;
    s = "$" + s;
    t = "^" + t;
    // инициализируем динамику:
    for (int i = 1; i < isz(s); i++)
        for (int j = 1; j < isz(t); j++)
            if (s[i] == t[j]) dp[i][j] = 1 + dp[i-1][j-1];
            else dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
    // отдельно вынесем функцию вычисления i-й строки: она получается удалением цикла по j
    auto calcIthRow = [&](int i) {
        for (int j = 1; j < isz(t); j++)
            if (s[i] == t[j]) dp[i][j] = 1 + dp[i-1][j-1];
            else dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
    };
    // отдельно вынесем функцию вычисления j-го столбца: она получается удалением цикла по i
    auto calcJthCol = [&](int j) {
        for (int i = 1; i < isz(s); i++)
            if (s[i] == t[j]) dp[i][j] = 1 + dp[i-1][j-1];
            else dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
    };
    // обрабатываем запросы:
    int q; cin >> q;
    while (q --> 0) {
        string query; cin >> query;
        if (query == "S+") {
            // читаем символ, добавляем его в конец строки "s", и вычисляем новую строку ДП:
            char ch; cin >> ch;
            s.push_back(ch);
            calcIthRow(isz(s)-1);
        } else if (query == "T+") {
            // читаем символ, добавляем его в конец строки "t", и вычисляем новый столбец ДП:
            char ch; cin >> ch;
            t.push_back(ch);
            calcJthCol(isz(t)-1);
        } else if (query == "S-") {
            // просто удаляем последний символ строки s
            s.pop_back();
        } else if (query == "T-") {
            // просто удаляем последний символ строки t
            t.pop_back();
        }
        // выводим ответ:
        cout << dp[isz(s)-1][isz(t)-1] << '\n';
    }
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```
