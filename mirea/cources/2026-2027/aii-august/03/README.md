# Многомерное динамическое программирование

## 1. Состояние помнит не только позицию

В прошлой лекции состояние часто задавалось одним индексом: номером ступени, концом префикса или длиной уже построенного ответа. Это не свойство динамики, а только удачный случай. Состояние должно хранить всё, от чего зависят допустимые продолжения.

> [!NOTE]
> **Задача.** Вернёмся к лестнице. На каждой из $n$ $(1 \le n \le 200000)$ ступеней записана награда, некоторые ступени непроходимы. Робот начинает перед первой ступенью, прыгает на одну или две ступени и хочет попасть ровно на последнюю, набрав наибольшую сумму наград. После трёх двойных прыжков подряд робот устанет, поэтому третий двойной прыжок запрещён.

Одного номера ступени уже недостаточно. Из одной и той же ступени можно иметь разные правила на следующий двойной прыжок. Например, после двух подряд двойных прыжков следующий ход обязан быть одинарным, а после одинарного прыжка двойной снова разрешён.

> [!IMPORTANT]
> В состояние динамики входит каждая характеристика прошлого, которая меняет набор допустимых следующих действий.

Перед тем, как показать решение и код, разберём один удобный и излюбленный олимпиадниками способ обновления многомерной динамики.

## 2. Короткая запись обновления

В динамике часто встречается один и тот же переход: вычислить кандидата и оставить его, только если он улучшает текущее значение. Вместо записи `dp[i][j] = max(dp[i][j], candidate)` олимпиадники используют короткий хэлпер.

```cpp
void setmax(auto& x, const auto& y) {
	// Заменяем значение, только если кандидат его улучшает.
	if (x < y) x = y;
}
void setmin(auto& x, const auto& y) {
	// Заменяем значение, только если кандидат его уменьшает.
	if (x > y) x = y;
}
```

`auto` позволяет не писать шаблон или тип состояния. После этого обновление динамики: `setmax(dp[i][j], candidate)`. Аналогично `setmin` оставляет меньшее из двух значений.

В Python число нельзя изменить по ссылке, поэтому передаём изменяемый список, его индекс и кандидата:

```python
def setmax(a, index, value):
	# Заменяем элемент, только если кандидат его улучшает.
	if a[index] < value: a[index] = value
def setmin(a, index, value):
	# Заменяем элемент, только если кандидат его уменьшает.
	if a[index] > value: a[index] = value
```

Для двумерной таблицы передаём строку: `setmax(dp[i], j, candidate)`. Это убирает повторение `dp[i][j]` и сохраняет условие обновления в одном месте.

> [!IMPORTANT]
> Для восстановления ответа в C++ удобно хранить в ячейке пару из значения и перехода. Тогда `setmax(dp[ni][nj], make_pair(candidate, move))` одновременно выбирает лучший результат и сохраняет ход `move`. Сравнение пар лексикографическое, поэтому сначала сравнивается значение.

В Python создание и сравнение кортежей в каждой релаксации заметно замедляет большую динамику. Поэтому, если время работы программы критично, то значение оставляют в `dp`, а переход – в отдельном массиве `parent` и записывают их одним условием:

```python
# Улучшаем значение состояния найденным кандидатом.
if dp[ni][nj] < candidate:
	# Вместе со значением сохраняем переход, который его дал.
	dp[ni][nj] = candidate
	parent[ni][nj] = move
```

Теперь мы можем вернуться к решению задачи...

## 3. Три состояния на каждой ступени

Пусть $dp[i][r]$ – наибольшая сумма наград на пути, закончившемся на ступени $i$, если последние $r$ прыжков были двойными. Здесь $r$ принимает значения $0$, $1$ или $2$. Значение $0$ означает, что последний прыжок был одинарным. Перед лестницей положим $dp[0][0]=0$, остальные состояния недостижимы.

Из достижимого состояния $(i,r)$ есть два вида переходов:

1. Если ступень $i+1$ проходима, одинарный прыжок ведёт в $(i+1,0)$. Серия двойных прыжков обрывается.
2. Если $r<2$ и ступень $i+2$ проходима, двойной прыжок ведёт в $(i+2,r+1)$.

Из $(i,2)$ второго перехода нет. Это и есть место, где правило об усталости попадает в динамику.

<details>
<summary><strong>C++: прыжки робота по лестнице</strong></summary>

```cpp
for (int i = 0; i <= n; i++)
	for (int r = 0; r <= 2; r++) {
		// Из недостижимого состояния нельзя продолжить путь.
		if (dp[i][r] == -inf) continue;
		// Одинарный прыжок сбрасывает длину серии двойных прыжков.
		if (i + 1 <= n && cells[i] == '.')
			setmax(dp[i + 1][0], dp[i][r] + a[i + 1]);
		// После двух двойных прыжков следующий двойной прыжок запрещён.
		if (r < 2 && i + 2 <= n && cells[i + 1] == '.')
			setmax(dp[i + 2][r + 1], dp[i][r] + a[i + 2]);
	}
```

</details>

<details>
<summary><strong>Python3: прыжки робота по лестнице</strong></summary>

```python
for i in range(n + 1):
	for r in range(3):
		# Из недостижимого состояния нельзя продолжить путь.
		if dp[i][r] == -inf: continue
		# Одинарный прыжок сбрасывает длину серии двойных прыжков.
		if i + 1 <= n and cells[i] == '.':
			setmax(dp[i + 1], 0, dp[i][r] + a[i + 1])
		# После двух двойных прыжков следующий двойной прыжок запрещён.
		if r < 2 and i + 2 <= n and cells[i + 1] == '.':
			setmax(dp[i + 2], r + 1, dp[i][r] + a[i + 2])
```

</details>

Как обычно, у нас тут $1$-индексация, поэтому `cells[i]` описывает ступень $i+1$. Ответом будет максимум из трёх состояний на последней ступени. Если все три недостижимы, пути нет.

Полные реализации перехода: [C++](Part-01-State-with-Memory/examples/example-01.cpp) и [Python3](Part-01-State-with-Memory/examples/example-01.py).

## 4. Почему это называют полуторамерной динамикой

Таблица имеет два индекса, но второй пробегает всего три значения. Количество состояний равно $3(n+1)$, а каждое обрабатывается за $O(1)$. Поэтому время работы равно $O(n)$, а память – $O(n)$.

На олимпиадах такую динамику иногда называют **полуторамерной** или **1.5-мерной**. Вторая координата существует, однако её размер – константа и не зависит от $n$.

> [!TIP]
> Дополнительный параметр с постоянным числом значений обычно не меняет асимптотику по основному размеру входа.

Следующая глава рассмотрит двумерную таблицу с двумя большими геометрическими координатами: строкой и столбцом клетки на сетке.

## 5. Путь на прямоугольной сетке

> [!NOTE]
> **Задача.** Дана сетка из $n$ строк и $m$ столбцов $(1 \le n,m \le 1000)$. В некоторых клетках стоять нельзя, а в каждой проходимой клетке записано целое число. Из левой верхней клетки разрешено идти только вниз или вправо. Нужно дойти до правой нижней клетки с наибольшей суммой чисел.

Каждый путь описывается клеткой, в которой он заканчивается. Обозначим через $dp[i][j]$ наибольшую сумму чисел на пути в клетку с координатами $(i,j)$. В эту клетку можно прийти только сверху или слева:

$$
dp[i][j]=a[i][j]+\max(dp[i-1][j],dp[i][j-1]).
$$

Если клетка закрыта или оба её предшественника недостижимы, значение состояния равно $-\infty$. Базой служит верхняя левая клетка, если она проходима.

> [!IMPORTANT]
> Порядок строк сверху вниз и столбцов слева направо корректен, потому что оба предшественника уже обработаны.

## 6. Предыдущая и текущая строки

Для перехода нужны значение из клетки сверху, лежащей в предыдущей строке, и значение из клетки слева в текущей строке. Поэтому всю таблицу хранить не требуется. Пусть `previous[j]` хранит ответ для клетки сверху, а `current[j - 1]` – ответ для клетки слева.

<details>
<summary><strong>C++: идём по сетке к финишу</strong></summary>

```cpp
// previous хранит значения для строки над текущей, а current формируется для текущей строки.
for (int i = 0; i < n; i++) {
	// Обработку новой строки начинаем с недостижимых состояний.
	fill(current.begin(), current.end(), -inf);
	for (int j = 0; j < m; j++) {
		// Через закрытую клетку путь пройти не может.
		if (cells[i][j] == '#') continue;
		// Верхняя левая клетка служит началом любого пути.
		if (i == 0 && j == 0) current[j] = a[i][j];
		else {
			// Выбираем лучший из путей, которые приходят сверху или слева.
			ll best = max(previous[j], j == 0 ? -inf : current[j - 1]);
			// Значение для клетки можно получить только от достижимого предшественника.
			if (best != -inf) current[j] = best + a[i][j];
		}
	}
	// После обработки эта строка станет предыдущей для следующей.
	swap(previous, current);
}
```

</details>

<details>
<summary><strong>Python3: идём по сетке к финишу</strong></summary>

```python
# previous хранит значения для строки над текущей, а current формируется для текущей строки.
previous = [-inf] * m
for i in range(n):
	# Обработку новой строки начинаем с недостижимых состояний.
	current = [-inf] * m
	for j in range(m):
		# Через закрытую клетку путь пройти не может.
		if cells[i][j] == '#': continue
		# Верхняя левая клетка служит началом любого пути.
		if i == 0 and j == 0: current[j] = a[i][j]
		else:
			# Выбираем лучший из путей, которые приходят сверху или слева.
			best = max(previous[j], -inf if j == 0 else current[j - 1])
			# Значение для клетки можно получить только от достижимого предшественника.
			if best != -inf: current[j] = best + a[i][j]
	# После обработки эта строка станет предыдущей для следующей.
	previous = current
```

</details>

Память стала $O(m)$, время осталось $O(nm)$. Полные реализации выводят максимальную сумму или `IMPOSSIBLE`: [C++](Part-02-Grid-and-Diagonals/examples/example-01.cpp) и [Python3](Part-02-Grid-and-Diagonals/examples/example-01.py).

## 7. Порядок по диагоналям

Иногда построчный обход не задаёт корректного порядка. Для ходов вправо и вниз есть другое удобное наблюдение: каждой клетке соответствует **диагональ** с номером $d=i+j$. После любого из этих ходов номер диагонали увеличивается на один.

Переберём диагонали в порядке возрастания их номеров. На диагонали $d$ номер строки $i$ может принимать значения от $\max(0,d-m+1)$ до $\min(n-1,d)$. После выбора строки номер столбца однозначно определяется как $j=d-i$.

<details>
<summary><strong>C++: перебираем клетки по диагоналям</strong></summary>

```cpp
// Номер диагонали i + j задаёт порядок обработки состояний.
for (int d = 0; d <= n + m - 2; d++) {
	// Перебираем только те строки, для которых существует столбец j = d - i.
	int low = max(0, d - m + 1);
	int high = min(n - 1, d);
	for (int i = low; i <= high; i++) {
		// После выбора строки вторая координата определяется номером диагонали.
		int j = d - i;
		// Обрабатываем клетку (i, j), лежащую на диагонали d.
	}
}
```

</details>

<details>
<summary><strong>Python3: перебираем клетки по диагоналям</strong></summary>

```python
# Номер диагонали i + j задаёт порядок обработки состояний.
for d in range(n + m - 1):
	# Перебираем только те строки, для которых существует столбец j = d - i.
	low = max(0, d - m + 1)
	high = min(n - 1, d)
	for i in range(low, high + 1):
		# После выбора строки вторая координата определяется номером диагонали.
		j = d - i
		# Обрабатываем клетку (i, j), лежащую на диагонали d.
```

</details>

> Если каждый переход увеличивает некоторое целое выражение, зависящее от координат на сетке, то это выражение может задать порядок обхода состояний.

## 8. Ход конём на двумерной сетке

> [!NOTE]
> **Задача.** На той же сетке разрешены ходы коня $(+2,+1)$, $(+1,+2)$, $(-1,+2)$ и $(+2,-1)$. Нужно найти путь с наибольшей суммой чисел.

Ход $(-1,+2)$ ведёт в строку, расположенную выше текущей, поэтому при построчном обходе можно обратиться к состоянию, которое ещё не вычислено.

Тем не менее все четыре хода увеличивают $i+j$: на $3$, $3$, $1$ и $1$ соответственно. Поэтому диагональный порядок остаётся корректным. Из каждой обработанной клетки обновим состояния клеток, в которые ведут допустимые ходы коня.

> [!WARNING]
> Важен не привычный построчный порядок, а порядок, в котором каждое состояние читается после всех своих предшественников. Для ходов коня это гарантирует обход по диагоналям.

Полные реализации диагонального обхода: [C++](Part-02-Grid-and-Diagonals/examples/example-02.cpp) и [Python3](Part-02-Grid-and-Diagonals/examples/example-02.py). Они считывают проходимость и значения клеток, а затем находят наибольшую сумму на пути, составленном из ходов коня.

## 9. Задача о рюкзаке

В сеточных задачах обе координаты состояния описывали положение на поле. Теперь одна координата будет означать число уже обработанных предметов, а другая – доступную вместимость. Таблица остаётся двумерной, но её смысл и порядок обновления требуют отдельного разбора.

> [!NOTE]
> **Задача.** Даны $n$ $(1 \le n \le 200)$ предметов. У предмета $i$ есть вес $w_i$ и ценность $v_i$, рюкзак вмещает не более $c$ $(1 \le c \le 10^5)$ единиц веса. Каждый предмет разрешено взять не более одного раза. Нужно найти наибольшую суммарную ценность.

Среди первых $i$ предметов можно выбрать разные наборы, которые помещаются в рюкзак вместимости $x$. Оба параметра важны для дальнейших переходов, поэтому $dp[i][x]$ обозначает наибольшую суммарную ценность набора из первых $i$ предметов с весом, не превосходящим $x$.

> [!NOTE]
> Здесь $x$ – вместимость, а не точный вес набора. В более привычном варианте $dp[i][x]$ хранит наибольшую ценность набора с точным весом $x$.
>
> Тогда в нулевой строке достижим только вес $0$, а окончательный ответ нужно искать как максимум среди всех $x\le c$.
>
> Но здесь мы намеренно храним ответ для веса, не превосходящего $x$, поэтому итог сразу находится в $dp[n][c]$.

**Переход**. Очередной предмет либо не входит в набор, либо входит в него. Если предмет $i$ взят, то до его добавления набор занимал не более $x-w_i$ единиц веса:

$$
dp[i][x]=\max\left(dp[i-1][x],\ dp[i-1][x-w_i]+v_i\right).
$$

Второе слагаемое допустимо только при $w_i\le x$.

**Инициализация**. Пока ни один предмет не рассмотрен, можно выбрать только пустой набор с ценностью $0$. Поэтому $dp[0][x]=0$ для всех $x$.

> [!IMPORTANT]
> В обоих вариантах перехода используется строка $i-1$. Это запрещает положить текущий предмет в рюкзак дважды.

## 10. Два слоя вместо всей таблицы

Чтобы найти только ценность ответа, не нужно хранить все $n+1$ строк. Для обработки очередного предмета достаточно строки `previous`, построенной по уже обработанным предметам. Строку `current` для нового предмета сначала копируем из неё, а затем рассматриваем все подходящие вместимости.

<details>
<summary><strong>C++: собираем ценный рюкзак</strong></summary>

```cpp
// previous[x] хранит наибольшую ценность набора из уже обработанных предметов для вместимости x.
vector<ll> previous(c + 1), current(c + 1);
for (int i = 0; i < n; i++) {
	// Копируем варианты, в которых предмет i не входит в набор.
	current = previous;
	// Если взять предмет i, добавляем его ценность к оптимальному набору вместимости x - w[i].
	for (int x = w[i]; x <= c; x++)
		setmax(current[x], previous[x - w[i]] + v[i]);
	// Полученная строка описывает уже обработанные предметы на следующем шаге.
	swap(previous, current);
}
```

</details>

<details>
<summary><strong>Python3: собираем ценный рюкзак</strong></summary>

```python
# previous[x] хранит наибольшую ценность набора из уже обработанных предметов для вместимости x.
previous = [0] * (c + 1)
for i in range(n):
	# Копируем варианты, в которых предмет i не входит в набор.
	current = previous[:]
	# Если взять предмет i, добавляем его ценность к оптимальному набору вместимости x - w[i].
	for x in range(w[i], c + 1):
		setmax(current, x, previous[x - w[i]] + v[i])
	# Полученная строка описывает уже обработанные предметы на следующем шаге.
	previous = current
```

</details>

Это та же формула, только строка $i-1$ названа `previous`, а строка $i$ – `current`. Память уменьшается с $O(nc)$ до $O(c)$.

Полные реализации двухслойного варианта: [C++](Part-03-Knapsack/examples/example-01.cpp) и [Python3](Part-03-Knapsack/examples/example-01.py).

## 11. Сколько существует точных наборов

> [!NOTE]
> **Задача.** Уберём ценности. Сколькими способами можно выбрать подмножество данных предметов с суммарным весом ровно $x$?

Теперь $ways[i][x]$ хранит количество подмножеств из первых $i$ предметов с точным весом $x$. Переход складывает два непересекающихся случая: предмет $i$ не входит в подмножество или входит в него.

$$
ways[i][x]=ways[i-1][x]+ways[i-1][x-w_i].
$$

Начальное условие здесь другое: пустое подмножество – единственный способ получить вес $0$. Подмножеств с другими весами не существует.

Сначала покажем двухслойный вариант. `previous[x]` хранит количество подмножеств с весом $x$, составленных из уже обработанных предметов, а `current[x]` – после обработки очередного предмета:

<details>
<summary><strong>C++: считаем наборы заданного веса</strong></summary>

```cpp
// previous[x] хранит количество подмножеств с весом x, составленных из уже обработанных предметов.
// Пустое подмножество – единственное подмножество с весом 0.
previous[0] = 1;
for (int i = 0; i < n; i++) {
	// Сначала копируем подмножества, в которые предмет i не входит.
	current = previous;
	// Если взять предмет i, к подмножеству с весом x - w[i] добавляется этот предмет.
	for (int x = w[i]; x <= c; x++)
		current[x] += previous[x - w[i]];
	// Полученная строка описывает уже обработанные предметы на следующем шаге.
	swap(previous, current);
}
```

</details>

<details>
<summary><strong>Python3: считаем наборы заданного веса</strong></summary>

```python
# previous[x] хранит количество подмножеств с весом x, составленных из уже обработанных предметов.
previous = [0] * (c + 1)
# Пустое подмножество – единственное подмножество с весом 0.
previous[0] = 1

	# Сначала копируем подмножества, в которые предмет i не входит.
	current = previous[:]
	# Если взять предмет i, к подмножеству с весом x - w[i] добавляется этот предмет.
	for x in range(w[i], c + 1):
		current[x] += previous[x - w[i]]
	# Полученная строка описывает уже обработанные предметы на следующем шаге.
	previous = current
```

</details>

## 12. Один слой вместо двух

Два слоя можно сжать до одного. При добавлении очередного предмета будем обходить веса **справа налево**. Тогда `ways[x - w]` ещё хранит количество способов до добавления предмета.

```cpp
// ways[x] хранит количество подмножеств с весом x, составленных из уже обработанных предметов.
// Пустое подмножество – единственное подмножество с весом 0.
ways[0] = 1;
// Если взять предмет i, он дополняет подмножество с весом x - w[i] до веса x.
// Обратный обход читает состояние, в котором предмет i ещё не был добавлен.
for (int x = c; x >= w; x--)
	ways[x] += ways[x - w];
```

```python
# ways[x] хранит количество подмножеств с весом x, составленных из уже обработанных предметов.
# Пустое подмножество – единственное подмножество с весом 0.
ways[0] = 1
# Если взять предмет i, он дополняет подмножество с весом x - w[i] до веса x.
# Обратный обход читает состояние, в котором предмет i ещё не был добавлен.
for x in range(c, w - 1, -1):
	ways[x] += ways[x - w]
```

> [!WARNING]
> Если в этом переходе обходить веса слева направо, один предмет можно будет использовать несколько раз. Такой обход соответствует неограниченному рюкзаку, а не выбору подмножества предметов.

Полные реализации односвязного варианта: [C++](Part-03-Knapsack/examples/example-05.cpp) и [Python3](Part-03-Knapsack/examples/example-05.py).

## 13. Как удалить добавленный предмет

> [!NOTE]
> **Задача.** Пусть предметы добавляются в набор, но в любой момент разрешено удалить один из ранее добавленных предметов. Массив `ways` хранит количество подмножеств из активных предметов для каждого точного веса.

Пусть удаляется предмет с весом $w$. При добавлении такого предмета используется формула $new[x]=old[x]+old[x-w]$. Чтобы удалить предмет, выразим старое значение:

$$
old[x]=new[x]-old[x-w].
$$

В правой части используется уже восстановленное значение `old[x-w]`, поэтому при удалении предмета веса обходят **слева направо**. Направление обхода меняется вместе со знаком:

```cpp
// После удаления вычитаем подмножества, в которые входил предмет с весом w.
// При обходе слева направо ways[x - w] уже восстановлен до удаления предмета.
for (int x = w; x <= c; x++)
	ways[x] = (ways[x] - ways[x - w] + mod) % mod;
```

```python
# После удаления вычитаем подмножества, в которые входил предмет с весом w.
# При обходе слева направо ways[x - w] уже восстановлен до удаления предмета.
for x in range(w, c + 1):
	ways[x] = (ways[x] - ways[x - w]) % mod
```

Это не симметричная операция, а обратная. При добавлении предмета мы читали старое состояние и шли справа налево. При удалении читаем уже восстановленное состояние и идём слева направо.

Полные программы поддерживают добавление и удаление предметов. В команде `- id` число `id` обозначает номер более ранней команды добавления. После каждой команды они выводят количество подмножеств из активных предметов с точным весом $c$ по модулю $10^9+7$: [C++](Part-03-Knapsack/examples/example-02.cpp) и [Python3](Part-03-Knapsack/examples/example-02.py).

## 14. Вопрос достижимости и битовый набор

> [!NOTE]
> **Задача.** Для данных весов предметов нужно узнать, достижим ли каждый точный вес, а не число способов его набрать.

Для хранения информации о достижимости каждого веса хватит только одного бита: достижим или нет. Тогда используем bitset. Бит с номером $x$ равен единице, если вес $x$ достижим. Добавление предмета с весом $w$ выражается одной побитовой операцией:

```cpp
// Бит с номером x показывает, достижим ли вес x.
bitset<maxC + 1> possible;
// Пустое подмножество имеет вес 0.
possible[0] = 1;
// Сдвиг берёт предмет i, а | сохраняет варианты без него.
for (int i = 0; i < n; i++)
	possible |= possible << w[i];
```

```python
# Бит с номером x показывает, достижим ли вес x.
# Единственный установленный бит соответствует пустому подмножеству с весом 0.
possible = 1
# Сдвиг берёт предмет i, а | сохраняет варианты без него.
for w in weights:
	possible |= possible << w
```

Сдвиг создаёт варианты, в которых предмет взят, а `|` сохраняет варианты без этого предмета. Правая часть вычисляется до присваивания, поэтому один предмет не используется повторно. Такая запись особенно быстра в C++, когда вместимость заранее ограничена константой `maxC`. В полном C++-примере используется `maxC = 100000`, поэтому входная вместимость не должна превышать $100000$.

> [!CAUTION]
> Битовое множество хранит только информацию о достижимости. По нему нельзя восстановить количество способов и нельзя удалить один предмет: разные подмножества могли установить один и тот же бит.

Полные реализации проверяют достижимость заданного веса: [C++](Part-03-Knapsack/examples/example-06.cpp) и [Python3](Part-03-Knapsack/examples/example-06.py). В Python одно большое целое число служит битовым множеством.

## 15. Восстановление ответа в задаче о рюкзаке

> [!NOTE]
> **Задача.** Вернёмся к исходной задаче о ценности рюкзака. Теперь нужно вывести индексы предметов в одном оптимальном наборе.

Для восстановления состава рюкзака одного слоя недостаточно. После перезаписи ячейки исчезает информация о том, на каком шаге был взят предмет. Сохраним всю таблицу `dp[i][x]` и массив `parent[i][x]` с координатами состояния, из которого получено оптимальное значение.

<details>
<summary><strong>C++: запоминаем выбранные предметы</strong></summary>

```cpp
// Сохраняем все строки и координаты предка для каждого оптимального состояния.
for (int i = 1; i <= n; i++)
	for (int x = 0; x <= c; x++) {
		// Сначала рассматриваем вариант, в котором предмет i не входит в набор.
		dp[i][x] = dp[i - 1][x];
		parent[i][x] = {i - 1, x};
		// Если предмет i улучшает ответ, переходим из состояния с вместимостью x - w[i].
		if (w[i] <= x && dp[i - 1][x - w[i]] + v[i] > dp[i][x]) {
			dp[i][x] = dp[i - 1][x - w[i]] + v[i];
			parent[i][x] = {i - 1, x - w[i]};
		}
	}
```

</details>

<details>
<summary><strong>Python3: запоминаем выбранные предметы</strong></summary>

```python
# Сохраняем все строки и координаты предка для каждого оптимального состояния.
for i in range(1, n + 1):
	for x in range(c + 1):
		# Сначала рассматриваем вариант, в котором предмет i не входит в набор.
		dp[i][x] = dp[i - 1][x]
		parent[i][x] = i - 1, x
		# Если предмет i улучшает ответ, переходим из состояния с вместимостью x - w[i].
		if w[i] <= x and dp[i - 1][x - w[i]] + v[i] > dp[i][x]:
			dp[i][x] = dp[i - 1][x - w[i]] + v[i]
			parent[i][x] = i - 1, x - w[i]
```

</details>

Начинаем обратный обход из состояния `(n,c)` и переходим только в состояние `parent[i][x]`. Если при таком переходе уменьшилась вторая координата, значит, предмет $i$ вошёл в набор, поэтому добавляем его индекс в ответ. Обратный обход заканчивается в нулевой строке.

<details>
<summary><strong>C++: восстанавливаем выбранные предметы</strong></summary>

```cpp
// Идём от оптимального состояния к нулевой строке.
vector<int> answ;
for (int i = n, x = c; i > 0;) {
	auto [prevI, prevX] = parent[i][x];
	// Уменьшение второй координаты означает, что предмет i вошёл в набор.
	if (prevX != x) answ.push_back(i);
	i = prevI;
	x = prevX;
}
// Индексы предметов были найдены в обратном порядке.
reverse(answ.begin(), answ.end());
```

</details>

<details>
<summary><strong>Python3: восстанавливаем выбранные предметы</strong></summary>

```python
# Идём от оптимального состояния к нулевой строке.

i, x = n, c
while i > 0:
	prevI, prevX = parent[i][x]
	# Уменьшение второй координаты означает, что предмет i вошёл в набор.
	if prevX != x: answ.append(i)
	i, x = prevI, prevX
# Индексы предметов были найдены в обратном порядке.
answ.reverse()
```

</details>

## 16. Правильные скобочные последовательности

Правильная скобочная последовательность строится слева направо. Открывающая скобка увеличивает баланс на один, закрывающая уменьшает его на один. Ни в одном префиксе баланс не должен стать отрицательным, а в конце он обязан равняться нулю.

> [!NOTE]
> **Задача.** Дано число пар скобок $n$ $(1 \le n \le 2000)$. Нужно подсчитать количество правильных скобочных последовательностей длины $2n$ по модулю $10^9+7$.

Пусть $dp[pos][balance]$ обозначает количество способов построить префикс из первых `pos` символов с балансом `balance`.

> [!NOTE]
> Баланс – это разность между количеством уже поставленных открывающих и закрывающих скобок. В нём содержится вся информация о префиксе, необходимая для выбора следующего символа.

## 17. Два допустимых продолжения

К префиксу из состояния `(pos, balance)` можно добавить открывающую скобку, если их ещё поставлено меньше $n$. Количество уже поставленных открывающих скобок равно $(pos+balance)/2$. Закрывающую скобку можно добавить только при `balance > 0`, иначе полученный префикс перестанет быть правильным.

В коде удобно ограничить баланс сверху числом $n$. Для каждой длины достаточно хранить одну строку состояний, а следующую строить отдельно:

<details>
<summary><strong>C++: считаем правильные скобочные последовательности</strong></summary>

```cpp
const int mod = 1000000007;
// current[balance] хранит число правильных префиксов текущей длины с данным балансом.
vector<int> current(n + 1), next(n + 1);
// Пустой префикс с нулевым балансом можно получить единственным способом.
current[0] = 1;
// Каждый правильный префикс продолжаем одним допустимым символом.
for (int pos = 0; pos < 2 * n; pos++) {
	// Для новой длины начинаем с недостижимых состояний.
	fill(next.begin(), next.end(), 0);
	for (int balance = 0; balance <= n; balance++) {
		// Из состояния, которому не соответствует ни одного префикса, переходов нет.
		if (current[balance] == 0) continue;
		// Открывающую скобку можно добавить, пока их количество не достигло n.
		if ((pos + balance) / 2 < n)
			next[balance + 1] = (next[balance + 1] + current[balance]) % mod;
		// Закрывающая скобка допустима, только если ранее была открыта парная скобка.
		if (balance > 0)
			next[balance - 1] = (next[balance - 1] + current[balance]) % mod;
	}
	// Префиксы новой длины становятся текущими.
	swap(current, next);
}
```

</details>

<details>
<summary><strong>Python3: считаем правильные скобочные последовательности</strong></summary>

```python
mod = 10 ** 9 + 7
# current[balance] хранит число правильных префиксов текущей длины с данным балансом.
current = [0] * (n + 1)
# Пустой префикс с нулевым балансом можно получить единственным способом.
current[0] = 1
# Каждый правильный префикс продолжаем одним допустимым символом.
for pos in range(2 * n):
	# Для новой длины начинаем с недостижимых состояний.
	next = [0] * (n + 1)
	for balance in range(n + 1):
		# Из состояния, которому не соответствует ни одного префикса, переходов нет.
		if current[balance] == 0: continue
		# Открывающую скобку можно добавить, пока их количество не достигло n.
		if (pos + balance) // 2 < n: next[balance + 1] = (next[balance + 1] + current[balance]) % mod
		# Закрывающая скобка допустима, только если ранее была открыта парная скобка.
		if balance > 0: next[balance - 1] = (next[balance - 1] + current[balance]) % mod
	# Префиксы новой длины становятся текущими.
	current = next
```

</details>

Ответ находится в `current[0]` после построения $2n$ символов. Закрывающая скобка при нулевом балансе запрещена, поэтому в таблицу не попадает ни один неправильный префикс. Алгоритм работает за $O(n^2)$ времени и использует $O(n)$ памяти.

Полные реализации переходов: [C++](Part-04-Balanced-Brackets/examples/example-01.cpp) и [Python3](Part-04-Balanced-Brackets/examples/example-01.py).

> [!IMPORTANT]
> В динамике по балансу проверка `balance > 0` делается до перехода, а не после него. Отрицательное состояние вообще не должно существовать.

## 18. Полная программа

## 19. Наибольшая общая подпоследовательность

> [!NOTE]
> **Задача.** Даны строки $s$ длины $n$ и $t$ длины $m$ $(1 \le n,m \le 2000)$. Подпоследовательность получается удалением некоторых символов без изменения порядка остальных. Нужно найти одну из наибольших общих подпоследовательностей этих строк.

В состоянии удобно хранить два префикса: $dp[i][j]$ – длина наибольшей общей подпоследовательности первых $i$ символов строки $s$ и первых $j$ символов строки $t$. У пустого префикса нет общей непустой подпоследовательности, поэтому нулевая строка и нулевой столбец таблицы равны нулю.

Если последние символы префиксов совпали, этот символ можно добавить к ответу для более коротких префиксов. В противном случае хотя бы один из последних символов не входит в некоторую оптимальную подпоследовательность, поэтому отбросим один из них:

$$
dp[i][j]=
\begin{cases}
dp[i-1][j-1]+1,&s[i-1]=t[j-1],\\
\max(dp[i-1][j],dp[i][j-1]),&s[i-1]\ne t[j-1].
\end{cases}
$$

> [!IMPORTANT]
> Переход в $dp[i-1][j]$ отбрасывает последний символ строки $s$, но оставляет первые $j$ символов строки $t$. Переход в $dp[i][j-1]$ устроен симметрично. Поэтому символы $s[i-1]$ и $t[j-1]$ сравнивают только в диагональном переходе $dp[i-1][j-1]$, где отбрасываются оба последних символа.

## 20. Восстановление ответа

Вместе с `dp[i][j]` запишем в `parent[i][j]` координаты состояния, из которого получено это значение. При равных символах предок лежит на диагонали `(i-1,j-1)`. Иначе выбираем соседа с наибольшим значением и сохраняем его координаты. При равенстве выберем верхнего соседа.

<details>
<summary><strong>C++: ищем общую подпоследовательность</strong></summary>

```cpp
// dp[i][j] — длина LCS первых i символов s и первых j символов t.
for (int i = 1; i <= n; i++)
	for (int j = 1; j <= m; j++) {
		if (s[i - 1] == t[j - 1]) {
			// Совпавшие последние символы добавляют один к ответу для более коротких префиксов.
			dp[i][j] = dp[i - 1][j - 1] + 1;
			parent[i][j] = {i - 1, j - 1};
		} else if (dp[i - 1][j] >= dp[i][j - 1]) {
			// Отбрасываем последний символ строки s и при равенстве выбираем верхнего соседа.
			dp[i][j] = dp[i - 1][j];
			parent[i][j] = {i - 1, j};
		} else {
			// Отбрасываем последний символ строки t.
			dp[i][j] = dp[i][j - 1];
			parent[i][j] = {i, j - 1};
		}
	}
// Восстанавливаем ответ по parent и добавляем символы диагональных переходов.
vector<char> answer;
for (int i = n, j = m; i > 0 && j > 0;) {
	auto [prevI, prevJ] = parent[i][j];
	// Диагональный переход означает, что символ s[i - 1] вошёл в подпоследовательность.
	if (prevI == i - 1 && prevJ == j - 1) answer.push_back(s[i - 1]);
	// Переходим в сохранённое состояние-предок.
	i = prevI;
	j = prevJ;
}
// Символы добавлены с конца подпоследовательности, поэтому разворачиваем их.
reverse(answer.begin(), answer.end());
```

</details>

## 21. Количество строк, не содержащих данную подстроку

> [!NOTE]
> **Задача.** Дано число $n$ $(1 \le n \le 10^5)$ и запрещённая строка $p$ длины $m$ $(1 \le m \le 50)$ из строчных латинских букв. Необходимо посчитать по модулю $10^9+7$ строки длины $n$, в которых строка $p$ не встречается как подстрока.

Будем строить строку слева направо. После добавления очередной буквы важно не всё построенное начало, а только его конец: он может оказаться началом запрещённого шаблона. Для уже построенной строки `s` введём **состояние** $j$ – наибольшую длину суффикса строки `s`, совпадающего с префиксом строки $p$. То есть последние $j$ символов `s` равны первым $j$ символам $p$.

Пусть $p=\text{abab}$. У строки `caba` состояние равно $3$, потому что она оканчивается на `aba` – префикс шаблона длины $3$. Значение $j=0$ означает, что ни один непустой суффикс не совпал с началом $p$. Значение $j=m$ означает, что построенная строка оканчивается на весь шаблон $p$.

> [!IMPORTANT]
> Состояние описывает только конец строки. Оно не показывает, встретился ли шаблон раньше: строка с состоянием $j<m$ может уже содержать $p$. Поэтому в динамике храним только строки, в которых $p$ ещё не встретилась. Если две такие строки имеют одинаковое состояние и к ним дописать одну и ту же букву, новое состояние у них будет одинаковым. Значит, можно хранить количество строк в каждом состоянии.

## 22. Как меняется состояние

Пусть строка находится в безопасном состоянии $j<m$ и к ней добавляют букву `ch`. Если `ch` совпадает со следующим символом шаблона, уже набранный префикс продолжается. Но несовпадение не всегда возвращает состояние в $0$: после новой буквы конец строки может совпасть с более коротким префиксом шаблона.

Например, для $p=\text{abab}$ состояние $3$ означает, что строка оканчивается на `aba`. После добавления `b` этот префикс продолжается до `abab`, поэтому новое состояние равно $4$. После добавления `a` ожидаемый символ не совпал, но строка `abaa` оканчивается на `a` – префикс шаблона длины $1$. Новое состояние равно $1$, а не $0$. После добавления `c` строка `abac` не оканчивается ни на один непустой префикс шаблона, поэтому новое состояние равно $0$.

После добавления буквы нужно найти **наибольший** префикс $p$, совпадающий с новым суффиксом строки. Именно он содержит максимум информации о том, какую часть шаблона можно продолжить следующей буквой. Для поиска достаточно взять префикс $p$ длины $j$, приписать к нему `ch` и найти у полученной строки наибольший суффикс, совпадающий с префиксом $p$.

> [!IMPORTANT]
> Нельзя воспринимать состояние как счётчик подряд совпавших символов: после несовпадения оно не обязано обнуляться. Состояние всегда равно длине наибольшего префикса шаблона, совпадающего с концом строки.

## 23. Зачем делать предподсчёт переходов

В каждом переходе основной динамики нужно выполнить описанный поиск нового состояния для пары `(j, ch)`. Такой поиск перебирает до $m$ длин суффикса и для каждой длины сравнивает до $m$ символов, поэтому работает за $O(m^2)$.

В основной динамике будет $n$ слоёв, $m$ состояний и $26$ букв. Если выполнять поиск в каждом переходе, время составит $O(26nm^3)$. При $n=10^5$ и $m=50$ это уже слишком много.

Но результат поиска не зависит от длины построенной строки. Он определяется только текущим состоянием $j$ и добавляемой буквой `ch`. Таких пар всего $26m$, поэтому каждый переход можно вычислить один раз и сохранить в таблице `nextState`.

> [!IMPORTANT]
> Предподсчёт заменяет $26nm$ дорогих поисков суффикса на $26m$ таких поисков. После него каждый переход основной динамики становится обращением к одной ячейке таблицы.

## 24. Предподсчёт переходов

Для каждой пары `(j, ch)` вычислим `nextState[j][ch]` – состояние после добавления буквы `ch` к строке из состояния $j$.

Функция `findNext` перебирает длину $k$ от $\min(m,j+1)$ до $0$. Для каждого $k$ она проверяет, совпадает ли суффикс длины $k$ у строки, полученной приписыванием `ch` к префиксу $p$ длины $j$, с префиксом $p$ длины $k$. Первое подходящее $k$ и есть новое состояние.

<details>
<summary><strong>C++: что меняется после новой буквы</strong></summary>

```cpp
int findNext(const string& p, int matched, char ch) {
	// В состоянии matched суффикс строки совпадает с префиксом p такой длины.
	string current = p.substr(0, matched) + ch;
	// Среди суффиксов current ищем самый длинный префикс шаблона.
	for (int len = min((int)p.size(), (int)current.size()); len >= 0; len--) {
		bool equal = true;
		// Проверяем, равен ли выбранный суффикс префиксу p той же длины.
		for (int i = 0; i < len; i++)
			if (current[current.size() - len + i] != p[i]) equal = false;
		// Перебор идёт по убыванию, поэтому первое совпадение задаёт новое состояние.
		if (equal) return len;
	}
	return 0;
}
```

</details>

<details>
<summary><strong>Python3: что меняется после новой буквы</strong></summary>

## 25. Динамика по длине

После предподсчёта не нужно снова искать суффикс: в каждом переходе достаточно взять `to = nextState[j][ch]`. Пусть `current[j]` – количество строк длины `length`, которые ещё не содержат $p$ и находятся в состоянии $j$. У пустой строки состояние $0$, поэтому `current[0] = 1`.

Из каждого состояния переберём все $26$ букв. Если `to` меньше $m$, то добавление `ch` создаёт допустимую строку следующей длины и увеличивает `next[to]`. Если `to = m`, добавленная буква завершила шаблон $p$, поэтому этот переход пропускаем.

<details>
<summary><strong>C++: считаем строки без запрещённого шаблона</strong></summary>

```cpp
// current[j] хранит число допустимых строк текущей длины в состоянии j.
current[0] = 1;
for (int length = 0; length < n; length++) {
	// В next собираем строки, которые на один символ длиннее.
	fill(next.begin(), next.end(), 0);
	for (int j = 0; j < m; j++)
		for (int ch = 0; ch < 26; ch++) {
			int to = nextState[j][ch];
			// Переход в m завершил запрещённую подстроку.
			if (to == m) continue;
			next[to] = (next[to] + current[j]) % mod;
		}
	// Следующий слой становится текущим.
	swap(current, next);
}
```

</details>

<details>
<summary><strong>Python3: считаем строки без запрещённого шаблона</strong></summary>

Таблица переходов занимает $O(26m)$ памяти, два слоя динамики – $O(m)$. Время работы равно $O(26nm+26m^3)$, а общая память – $O(26m)$.

## 26. Динамика на подотрезках

> [!NOTE]
> **Задача.** На столе лежит массив из $n$ $(1 \le n \le 2000)$ чисел. Два игрока ходят по очереди, каждый выбирает левый или правый элемент оставшегося отрезка и забирает его себе. Оба играют оптимально. Найти, на сколько очков первый игрок опередит второго.

После нескольких ходов не нужно помнить порядок всех взятых чисел. Достаточно знать оставшийся отрезок $[i,j]$. Пусть $dp[i][j]$ обозначает наибольшую разность «очки текущего игрока минус очки соперника», которую текущий игрок может гарантировать, играя на этом отрезке.

Если взять левое число $a_i$, сопернику достанется отрезок $[i+1,j]$, на котором он сможет обеспечить разность $dp[i+1][j]$ в свою пользу. Поэтому разность для текущего игрока равна $a_i-dp[i+1][j]$. Аналогично получается переход для правого конца:

$$
dp[i][j]=\max\left(a_i-dp[i+1][j],\ a_j-dp[i][j-1]\right).
$$

На отрезке, состоящем из одного числа, игрок забирает это число целиком, поэтому $dp[i][i]=a_i$.

> [!IMPORTANT]
> В `dp[i][j]` хранится не сумма первого игрока, а разность для того игрока, чей ход сейчас. Поэтому значение следующего состояния нужно вычитать.

## 27. Обход состояний в порядке возрастания длины

Переход для отрезка длины `length` читает значения для двух отрезков длины `length - 1`. Поэтому внешний цикл перебирает длины в порядке возрастания, а внутренний – левые границы. Правая граница вычисляется как `j = i + length - 1`.

<details>
<summary><strong>C++: выбираем число с краёв отрезка</strong></summary>

```cpp
// dp[i][j] хранит наибольшую разность для игрока, который ходит на отрезке [i, j].
// На отрезке из одного числа текущий игрок забирает это число целиком.
for (int i = 0; i < n; i++)
	dp[i][i] = a[i];
// Перебираем длины по возрастанию, чтобы меньшие отрезки уже были обработаны.
for (int length = 2; length <= n; length++)
	for (int i = 0; i + length <= n; i++) {
		// Правая граница определяется левой границей и длиной отрезка.
		int j = i + length - 1;
		// После выбора ход переходит к сопернику, который играет на меньшем отрезке.
		dp[i][j] = max(a[i] - dp[i + 1][j], a[j] - dp[i][j - 1]);
	}
```

</details>

```python
# dp[i][j] хранит наибольшую разность для игрока, который ходит на отрезке [i, j].
# На отрезке из одного числа текущий игрок забирает это число целиком.
for i in range(n):
	dp[i][i] = a[i]
# Перебираем длины по возрастанию, чтобы меньшие отрезки уже были обработаны.
for length in range(2, n + 1):
	for i in range(n - length + 1):
		# Правая граница определяется левой границей и длиной отрезка.
		j = i + length - 1
		# После выбора ход переходит к сопернику, который играет на меньшем отрезке.
		dp[i][j] = max(a[i] - dp[i + 1][j], a[j] - dp[i][j - 1])
```

</details>

Когда вычисляется `dp[i][j]`, значения `dp[i+1][j]` и `dp[i][j-1]` уже заполнены для предыдущей длины. Время работы и объём памяти равны $O(n^2)$.

Полные реализации: [C++](Part-07-Interval-Game/examples/example-01.cpp) и [Python3](Part-07-Interval-Game/examples/example-01.py). Они выводят разность очков первого и второго игроков, которую первый игрок может гарантировать при оптимальной игре.

> [!TIP]
> В динамике на подотрезках сначала проверьте, значения для отрезков какой длины читает переход. Это сразу определит направление внешнего цикла.

```text
Вывод
10
```

</details>
