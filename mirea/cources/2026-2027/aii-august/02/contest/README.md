# Разбор задач

## A. Проездные для курьера

<details>
<summary>Текстовый разбор</summary>

Выбирая проездной в текущий день, мы одновременно определяем расходы на несколько последующих дней. Поэтому не будем хранить набор уже купленных проездных. Вместо этого рассмотрим начало дня $i$, который ещё не покрыт проездным, и будем хранить в $dp[i]$ минимальную стоимость проездных, необходимых с этого момента до конца расписания.

Если день $i$ рабочий, в его начале необходимо купить один из трёх проездных. Однодневный переносит нас к началу дня $i+1$, трёхдневный – к началу дня $i+3$, семидневный – к началу дня $i+7$. Поэтому переход имеет вид:

$dp[i]=\min\left(a_i+dp[i+1],\ b_i+dp[i+3],\ c_i+dp[i+7]\right)$.

В выходной день покупать проездной нельзя и не требуется. Мы просто переходим к следующему дню: $dp[i]=dp[i+1]$. Во всех переходах используются состояния с бóльшими индексами, поэтому динамику будем вычислять справа налево.

После последнего дня платить уже не за что. Чтобы не проверять отдельно, выходит ли срок действия проездного за границу расписания, создадим массив из $n+7$ ячеек и запишем нули в $dp[n],dp[n+1],\ldots,dp[n+6]$. Теперь одна и та же формула работает для каждого рабочего дня, включая последние шесть.

В коде дни нумеруются с нуля, поэтому ответом будет $dp[0]$. Один набор входных данных обрабатываем за $O(n)$ времени и $O(n)$ памяти.

</details>

<summary>Решение на C++ (<code>A.cpp</code>)</summary>

```cpp
// Решим задачу динамическим программированием. Так как покупка проездного влияет на
// последующие дни, то удобнее всего рассуждать справа налево. Состояние i - номер дня,
// в котором мы сейчас находимся. Храним в динамике минимальную стоимость добраться из
// начала i-го дня до конца последнего дня. Переходы: покупка проездного
// на k дней даёт переход i -> i+k с заданной стоимостью. Основная формула:
// dp[i] = min(a[i] + dp[i+1], b[i] + dp[i+3], c[i] + dp[i+7]).
// В случае выходного дня мы не можем покупать проездной, поэтому результат переносится:
// dp[i] = dp[i+1]. Для удобства реализации мы выделяем n+7 ячеек вместо n. Дни после n-го
// инициализируем нулями, остальное - бесконечностями.
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
const ll inf = (ll)1e18L;
void solve() {
    // читаем данные
    int n; cin >> n;
    string s; cin >> s;
    vector<int> a(n), b(n), c(n);
    for (int i = 0; i < n; i++)
        cin >> a[i];
    for (int i = 0; i < n; i++)
        cin >> b[i];
    for (int i = 0; i < n; i++)
        cin >> c[i];
    // решаем задачу динамическим программированием справа налево
    vector<ll> dp(n+7, inf);
    // инициализация динамики:
    for (int i = n; i < n+7; i++)
        dp[i] = 0;
    // переходы:
    for (int i = n-1; i >= 0; i--)
        if (s[i] == '#') // выходной
            dp[i] = dp[i+1];
        else // рабочий день
            dp[i] = min({
                a[i] + dp[i+1], // один день
                b[i] + dp[i+3], // три дня
                c[i] + dp[i+7]  // семь дней
            });
    // выводим ответ:
    cout << dp[0] << '\n';
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

<summary>Разбор решения на C++</summary>

Чтобы не проверять срок действия каждого проездного относительно границы расписания, создадим семь дополнительных ячеек:

```cpp
vector<ll> dp(n+7, inf);
for (int i = n; i < n+7; i++)
    dp[i] = 0;
```

Например, при покупке семидневного проездного в предпоследний рабочий день потребуется значение `dp[i+7]`. Такая ячейка существует и равна нулю, поскольку после конца периода дополнительные расходы отсутствуют.

Для рабочего дня запишем три варианта одним вызовом `min`:

```cpp
dp[i] = min({
    a[i] + dp[i+1], // один день
    b[i] + dp[i+3], // три дня
    c[i] + dp[i+7]  // семь дней
});
```

Фигурные скобки формируют список из трёх значений. `min` выбирает среди них наименьшую полную стоимость, а не наименьшую цену проездного: к каждой цене уже прибавлена оптимальная стоимость оставшихся дней.

```python
dp = [inf] * (n + 7)
```

```python
for i in range(n - 1, -1, -1):
```

Первый аргумент задаёт начало обхода, второй в него не входит, а отрицательный третий аргумент уменьшает индекс. В результате последовательно обрабатываем дни $n-1,n-2,\ldots,0$, причём к моменту вычисления $dp[i]$ все состояния справа от $i$ уже известны.

## B. Калибровка приборов

<details>
<summary>Текстовый разбор</summary>

Будем рассматривать первый сеанс в ещё не разбитой части массива. Если он начинается в позиции $i$ и заканчивается в позиции $j$, то после него остаётся независимо разбить суффикс, начинающийся в $j+1$. Такое разбиение естественно считать динамикой справа налево.

Будем хранить в $dp[i]$ минимальную стоимость разбиения суффикса $[i,n-1]$. Пустой суффикс не требует оплаты, поэтому $dp[n]=0$. Для каждого $i$ переберём конец первого сеанса $j$ от $i$ до $n-1$. Стоимость этого сеанса равна $(\max(a[i..j]) - \min(a[i..j]))^2+c$, а для оставшегося суффикса потребуется $dp[j+1]$.

$dp[i]=\min_{j\ge i}\left((\max(a[i..j]) - \min(a[i..j]))^2+c+dp[j+1]\right)$.

Не будем заново искать минимум и максимум для каждого сеанса. Зафиксируем $i$, будем увеличивать $j$ слева направо и поддерживать значения `minA` и `maxA`. После добавления очередного элемента они обновляются за $O(1)$, поэтому вычисление одного состояния занимает $O(n)$, а всё решение – $O(n^2)$.

Для восстановления ответа вместе со стоимостью в $dp[i]$ сохраним конец `j` оптимального первого сеанса. Начнём с $i=0$, добавим сохранённый `j` в ответ и продолжим с $j+1$. В результате получим именно концы сеансов, которые требуется вывести.

Память, необходимая для динамики и восстановления, составляет $O(n)$.

</details>

<details>
<summary>Решение на C++ (<code>B.cpp</code>)</summary>

```cpp
// Нужно разбить массив на группы. Количество групп не ограничено. Снова будем решать справа
// налево, потому что так будет удобнее писать формулы перехода и восстанавливать ответ.
// Пусть dp[i] = минимальная стоимость разбиения суффикса [i, i+1, ..., n] на группы.
// Инициализация: dp[n] = 0 - пустой суффикс получаем бесплатно.
// Переходы: перебираем границы группы, в которую мы включим i-й элемент. Пусть это [i, j].
// Тогда dp[i] = min(cost(i, j) + dp[j+1]), означающая, что мы сформировали группу [i, j], а
// затем продолжили формировать группы, начиная с (j+1)-го элемента.
// cost(i, j) = (max(a[i..j]) - min(a[i..j]))^2 + c. Можно предподсчитать заранее, либо
// считать вместе с динамикой на лету.
// Для восстановления ответа храним пару (значение, индекс последнего элемента).
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
const ll inf = 8e18L;
void solve() {
    // читаем данные
    int n, c; cin >> n >> c;
    vector<int> a(n);
    for (int i = 0; i < n; i++)
        cin >> a[i];
    // решаем задачу справа-налево для удобства
    vector dp(n+1, pair<ll,int>(inf, -1));
    dp[n] = {0, -1};
    for (int i = n - 1; i >= 0; i--) {
        int minA = a[i], maxA = a[i];
        for (int j = i; j < n; j++) {
            // включаем отрезок [i, j] и добавляем к нему dp[j+1]
            if (minA > a[j]) minA = a[j];
            if (maxA < a[j]) maxA = a[j];
            ll currCost = (maxA - minA) * 1LL * (maxA - minA) + c;
            dp[i] = min(dp[i], make_pair(dp[j+1].first + currCost, j));
        }
    }
    // восстанавливаем ответ:
    vector<int> answ;
    for (int i = 0; i < n; i = dp[i].second + 1)
        answ.push_back(dp[i].second);
    // выводим его:
    cout << dp[0].first << '\n';
    cout << answ.size() << '\n';
    for (auto it : answ)
        cout << it + 1 << ' ';
    cout << '\n';
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

<summary>Разбор решения на C++</summary>

В каждой ячейке `dp[i]` будем хранить и стоимость, и конец первой выбранной группы:

```cpp
vector dp(n+1, pair<ll,int>(inf, -1));
dp[n] = {0, -1};
```

Тип пары выводится из начального значения. Сначала пары сравниваются по стоимости, поэтому `min` выбирает оптимальный переход. При равных стоимостях сравниваются вторые элементы, однако любой из полученных концов задаёт корректное оптимальное разбиение.

Разность измерений нужно возводить в квадрат в 64-битном типе:

```cpp
ll currCost = (maxA - minA) * 1LL * (maxA - minA) + c;
```

Разность двух значений типа `int` может достигать порядка $2\cdot10^9$, а её квадрат уже не помещается в `int`. Множитель `1LL` переводит всё произведение в 64-битный тип ещё до умножения.

Ответ восстановим по сохранённым концам групп:

```cpp
for (int i = 0; i < n; i = dp[i].second + 1)
    answ.push_back(dp[i].second);
```

Для суффикса, начинающегося в `i`, поле `dp[i].second` содержит конец его первой группы. Следующий нераспределённый элемент расположен сразу после него, поэтому новое начало равно `dp[i].second + 1`.

</details>

<details>
<summary>Разбор решения на Python3</summary>

В Python каждая ячейка будет содержать кортеж `(стоимость, конец)`:

```python
dp = [(inf, -1)] * (n + 1)
dp[n] = (0, -1)
```

Кортежи сравниваются лексикографически: сначала по стоимости, затем по индексу конца. Поэтому встроенная функция `min` выберет оптимальную стоимость, а при равенстве сохранит один из корректных вариантов восстановления. Повторение списка безопасно: кортежи неизменяемы, и в дальнейшем каждую ячейку мы заменяем новым кортежем.

При расширении правой границы группы будем обновлять её минимум и максимум:

```python
if minA > a[j]: minA = a[j]
if maxA < a[j]: maxA = a[j]
currCost = (maxA - minA) ** 2 + c
```

После обработки позиции `j` переменные `minA` и `maxA` описывают ровно отрезок $[i,j]$. Поэтому стоимость очередного кандидата вычисляется за $O(1)$, а не требует отдельного обхода всего отрезка.

При восстановлении будем сдвигать начало ещё не обработанного суффикса:

```python
while i < n:
    answ.append(dp[i][1])
    i = dp[i][1] + 1
```

Сначала добавим последний индекс текущего сеанса. Затем переменная `i` перейдёт к первому индексу следующего сеанса. Цикл завершится после обработки сеанса, оканчивающегося в $n-1$.

## C. Риск Микото

<details>
<summary>Текстовый разбор</summary>

Уровень риска равен наибольшей опасности среди выполненных заданий. Зафиксируем допустимый уровень `mid` и разрешим выполнять только задания с $d_i\le mid$.

**Монотонность**. Если при таком ограничении удаётся набрать награду не меньше $r$, то при большем `mid` решение сохранится, поскольку доступных заданий станет больше. Следовательно, будем искать ответ бинарным поиском.

Для фиксированного `mid` учтём запрет на пять подряд пропущенных заданий. Если выполненные задания имеют номера $p$ и $q$, между ними разрешается пропустить не более четырёх позиций, то есть $q-p\le5$. Это же условие будем проверять в начале и в конце последовательности. Для этого добавим две фиктивные позиции: $0$ перед всеми заданиями и $n+1$ после них. Их награды и опасности равны нулю.

Будем хранить в $dp[i]$ наибольшую награду допустимой последовательности, последнее выполненное задание которой имеет номер $i$. Недостижимые состояния обозначим $-\infty$. В доступное задание $i$ можно перейти из одного из пяти предыдущих номеров:

$dp[i]=b_i+\max(dp[i-1],dp[i-2],\ldots,dp[i-5])$.

Положим $dp[0]=0$. Тогда последовательность может начаться с любого из первых пяти реальных заданий. Достижимость фиктивной позиции $n+1$ означает, что после последнего выполненного задания осталось не больше четырёх пропусков. Проверка будет истинной тогда и только тогда, когда $dp[n+1]\ge r$.

**Границы поиска.** Значение `low = 0` не подходит: опасности всех реальных заданий и требуемая награда положительны. Значение `high = 10^9+1` служит специальной границей, превосходящей любую опасность. Если набор достижим, при этой границе доступны все задания, поэтому она подходит. Если же и при ней решения нет, в ходе поиска `high` сохранит это значение, а программа выведет `-1`.

В одной проверке для каждой позиции обрабатываем не более пяти переходов, поэтому она работает за $O(n)$. Полная сложность составляет $O(n\log(10^9))$, память – $O(n)$.

</details>

<details>
<summary>Решение на C++ (<code>C.cpp</code>)</summary>

```cpp

// которого мы можем рисковать. Тогда мы будем рассматривать выполнение только тех заданий,
```

## D. Закрытая лестница

<details>
<summary>Текстовый разбор</summary>

В этой задаче бинарный поиск не потребуется: нам нужно сразу посчитать число путей. Будем хранить в $dp[i]$ количество способов попасть на ступеньку $i$. На первой ступеньке мы уже стоим, поэтому $dp[0]=1$. Для закрытой ступеньки значение $dp[i]$ останется равным нулю.

Если ступенька $i$ открыта, на неё можно перейти с любой ступеньки от `left[i]` до `right[i]`. Количество независимых маршрутов складывается, поэтому:

$dp[i]=\sum_{j=left[i]}^{right[i]}dp[j]$.

Прямой подсчёт такой суммы для каждой ступеньки оказался бы слишком медленным, поскольку диапазоны могут быть длинными. Поэтому будем поддерживать префиксные суммы `pref`, где `pref[k]` равна $dp[0]+dp[1]+\ldots+dp[k-1]$. Тогда сумму на отрезке $[l,r]$ вычислим как `pref[r + 1] - pref[l]`.

Все предшественники ступеньки $i$ имеют меньшие номера. Поэтому будем обходить ступеньки слева направо: к моменту вычисления $dp[i]$ нужные значения `dp` и `pref` уже будут известны. Сразу после нахождения $dp[i]$ обновим `pref[i+1]`. Входные границы переведём из нумерации с единицы в нумерацию с нуля, чтобы формула совпадала с индексами массивов.

Все вычисления выполним по модулю $10^9+7$. Один набор входных данных обработаем за $O(n)$ времени и $O(n)$ памяти.

</details>

<details>
<summary>Решение на C++ (<code>D.cpp</code>)</summary>

```cpp
// На ступеньку i мы можем попасть только из ступенек от left[i] до right[i]. Значит, формула
// перехода суммирует независимые способы добраться до них:
// dp[i] = dp[l] + dp[l+1] + ... + dp[r].
// Чтобы вычислять сумму быстро, нам нужно хранить префиксные суммы поверх ответов динамики.
// Теперь считаем dp[i] = pref[r+1] - pref[l], а затем обновляем префиксные суммы вот так:
// pref[i+1] = dp[i] + pref[i]. Работаем с остатками по простому модулю 10^9+7.
#include <bits/stdc++.h>
using namespace std;
const int mod = (int)1e9+7;
void solve() {
    // читаем данные:
    int n; cin >> n;
    string s; cin >> s;
    vector<int> left(n), right(n);
    for (int i = 1; i < n; i++)
        cin >> left[i], left[i]--;
    for (int i = 1; i < n; i++)
        cin >> right[i], right[i]--;
    // считаем динамику и префиксные суммы для неё:
    vector<int> dp(n, 0), pref(n+1);
    dp[0] = 1, pref[1] = 1;
    for (int i = 1; i < n; i++) {
        // количество способов - сумма на отрезке [l, r]:
        if (s[i] == '.')
            dp[i] = (pref[right[i]+1] - pref[left[i]] + mod) % mod;
        // обновляем префиксные суммы:
        pref[i+1] = (pref[i] + dp[i]) % mod;
    }
    cout << dp.back() << "\n";
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

## E. Лавовый коридор Киберляндии

<details>
<summary>Текстовый разбор</summary>

Рассмотрим прыжок с платформы $i$ на более позднюю платформу $j$. По условию прыжок безопасен, если

$y_j-y_i<x_j-x_i$.

Перенесём слагаемые с индексом $i$ в левую часть неравенства, а с индексом $j$ – в правую:

$x_i-y_i<x_j-y_j$.

Для каждой платформы вычислим $a_i=x_i-y_i$. Тогда безопасная последовательность платформ в точности соответствует строго возрастающей подпоследовательности массива $a$: порядок индексов уже совпадает с порядком платформ. Таким образом, задача сводится к поиску НВП – наибольшей возрастающей подпоследовательности.

Квадратичная динамика по всем предыдущим платформам не пройдёт по ограничениям. Поэтому используем стандартную компактную динамику – нахождение НВП за $(n\log(n))$ с восстановлением ответа.

Для каждой длины `len` будем хранить минимальное возможное последнее значение возрастающей подпоследовательности этой длины. Чем меньше её хвост, тем проще продолжить подпоследовательность следующими элементами.

При обработке $a_i$ двоичным поиском найдём первую длину, хвост которой не меньше $a_i$, и заменим этот хвост. Для **строго** возрастающей подпоследовательности нужна именно первая позиция с `>=`: равное значение не увеличивает длину, а улучшает хвост той же длины. Одновременно сохраним индекс предшественника из подпоследовательности на единицу короче.

После обхода максимальная заполненная длина станет длиной ответа. Её последний индекс задаст начало обратного восстановления по массиву `prev`, после чего мы развернём ответ.

Один набор входных данных обработаем за $O(n\log(n))$ времени и $O(n)$ памяти.

</details>

<details>
<summary>Решение на C++ (<code>E.cpp</code>)</summary>

```cpp
// Запишем формальное условие. Мы можем сделать прыжок i --> j, если верно следующее:
// i < j и y[j] - y[i] < x[j] - x[i]. Преобразуем неравенство путём переноса того, что зависит
// от i, налево, а того, что зависит от j, направо. Получим: x[i] - y[i] < x[j] - y[j].
// Обозначим A[i] = x[i] - y[i]. Тогда нужно найти наибольшую возрастающую последовательность
// в массиве A и восстановить её элементы.
#include <bits/stdc++.h>
using namespace std;
const int inf = (int)2e9+100;
using pii = pair<int,int>;
void solve() {
    // читаем данные:
    int n; cin >> n;
    vector<int> x(n), y(n);
    for (int i = 0; i < n; i++)
        cin >> x[i];
    for (int i = 0; i < n; i++)
        cin >> y[i];
    // Формальное условие: y[j] - y[i] < x[j] - x[i] => x[i] - y[i] < x[j] - y[j]
    // Обозначим a[i] = x[i] - y[i]. Тогда для массива "a" нужно найти максимальную
    // возрастающую подпоследовательность и вывести индексы входящих в неё элементов
    vector<int> a(n), prev(n, -1);
    vector<pii> dp(n+1, {inf, inf});
    dp[0] = {-inf, -1};
    for (int i = 0; i < n; i++) {
        auto it = lower_bound(dp.begin(), dp.end(), pii{x[i] - y[i], -inf});
        prev[i] = (it-1)->second;
        *it = {x[i] - y[i], i};
    }
    // находим длину НВП:
    int len = n;
    while (len >= 0 && dp[len].first == inf)
        len--;
    // восстанавливаем индексы входящих в неё элементов:
    vector<int> answ;
    for (int i = dp[len].second; i > -1; i = prev[i])
        answ.push_back(i);
    reverse(answ.begin(), answ.end());
    // выводим ответ:
    cout << len << '\n';
    for (auto it : answ)
        cout << it+1 << ' ';
    cout << '\n';
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

<details>
<summary>Разбор решения на C++</summary>

Каждая ячейка `dp[len]` хранит пару: хвост подпоследовательности и индекс платформы, на которой этот хвост получен:

```cpp
vector<pii> dp(n+1, {inf, inf});
dp[0] = {-inf, -1};
```

Значение `inf` помечает ещё не построенные длины. У нулевой подпоследовательности хвост равен $-\infty$, а индекс равен `-1`, поэтому она сможет стать предшественницей первой реальной платформы.

Позицию для текущего значения найдём и сразу сохраним его предка:

```cpp
auto it = lower_bound(dp.begin(), dp.end(), pii{x[i] - y[i], -inf});
prev[i] = (it-1)->second;
*it = {x[i] - y[i], i};
```

`lower_bound` найдёт первую пару с хвостом не меньше текущего значения. Второй элемент ключа равен `-inf`, поэтому при одинаковом хвосте будет выбрана первая подходящая длина. Предыдущая ячейка содержит индекс конца подпоследовательности на единицу короче, и этот индекс мы запишем в `prev[i]`. Затем текущая платформа улучшит хвост найденной длины.

При обратном проходе будем собирать индексы с конца:

```cpp
for (int i = dp[len].second; i > -1; i = prev[i])
    answ.push_back(i);
reverse(answ.begin(), answ.end());
```

Массив `prev` ведёт к более ранним платформам, поэтому индексы попадут в `answ` в обратном порядке. `reverse` восстановит порядок посещения, а при печати мы прибавим к индексам единицу.

<summary>Решение на Python3 (<code>E.py</code>)</summary>

```python
# Запишем формальное условие. Мы можем сделать прыжок i --> j, если верно следующее:
# i < j и y[j] - y[i] < x[j] - x[i]. Преобразуем неравенство путём переноса того, что зависит
# от i, налево, а того, что зависит от j, направо. Получим: x[i] - y[i] < x[j] - y[j].
# Обозначим A[i] = x[i] - y[i]. Тогда нужно найти наибольшую возрастающую последовательность
# в массиве A и восстановить её элементы.
from bisect import bisect_left
inf = 2 * 10 ** 9 + 100
def solve():
    # читаем данные:
    n = int(input())
    x = list(map(int, input().split()))
    y = list(map(int, input().split()))
    # Формальное условие: y[j] - y[i] < x[j] - x[i] => x[i] - y[i] < x[j] - y[j]
    # Обозначим a[i] = x[i] - y[i]. Тогда для массива "a" нужно найти максимальную
    # возрастающую подпоследовательность и вывести индексы входящих в неё элементов
    a = [0] * n
    prev = [-1] * n
    dp = [(inf, inf)] * (n + 1)
    dp[0] = (-inf, -1)
    for i in range(n):
        a[i] = x[i] - y[i]
        it = bisect_left(dp, (a[i], -inf))
        prev[i] = dp[it - 1][1]
        dp[it] = (a[i], i)
    # находим длину НВП:
    len = n
    while len >= 0 and dp[len][0] == inf:
        len -= 1
    # восстанавливаем индексы входящих в неё элементов:
    answ = []
    i = dp[len][1]
    while i > -1:
        answ.append(i)
        i = prev[i]
    answ.reverse()
    # выводим ответ:
    print(len)
    for it in answ:
        print(it + 1, end=' ')
    print()
tt = int(input())
while tt > 0:
    solve()
    tt -= 1
```

<summary>Разбор решения на Python3</summary>

Python сравнивает кортежи лексикографически, поэтому список пар можно использовать для двоичного поиска:

```python
dp = [(inf, inf)] * (n + 1)
dp[0] = (-inf, -1)
```

Первый элемент пары – минимальный возможный хвост, второй – его индекс. Пока подпоследовательность заданной длины не построена, её хвост равен `inf`. Для нулевой длины создадим искусственный хвост `-inf`, поэтому начало любой НВП получит предка `-1`.

Поиск позиции и обновление длины выполним так:

```python
it = bisect_left(dp, (a[i], -inf))
prev[i] = dp[it - 1][1]
dp[it] = (a[i], i)
```

`bisect_left` вернёт первую позицию, в которой пара не меньше ключа. Ключ `(a[i], -inf)` заставит поиск ориентироваться прежде всего на значение `a[i]`. При равном значении найдётся та же длина, а не следующая, поэтому подпоследовательность останется строго возрастающей. Индекс из предыдущей длины будет сохранён до перезаписи `dp[it]`.

Длину ответа найдём по маркеру недостижимости:

```python
len = n
while len >= 0 and dp[len][0] == inf:
    len -= 1
```

Все ячейки длиннее НВП не изменялись и сохранили хвост `inf`. Первая заполненная ячейка при движении справа налево задаст максимальную длину, с которой начнётся восстановление.
