# Одномерное динамическое программирование

## 1. Что такое динамическое программирование

Динамическое программирование – это способ быстро и ритмично писать олимпиадный код.

Шутка. Это динамичное программирование, а не динамическое.

Динамическое программирование – это способ решить задачу так, чтобы никто не понял, как ты это решил и почему это работает.

Снова шутка. Это жадные алгоритмы и конструктивы.

Ну а теперь серьёзно. В олимпиадных задачах **динамическое программирование** – это способ эффективно организовать перебор вариантов. Мы разбиваем варианты на классы по параметрам, которые важны для продолжения перебора, и для каждого класса храним только нужную сводку о его лучшем представителе.

> [!NOTE]
> Два частичных решения можно положить в один класс, если после них остаются одинаковые допустимые продолжения. Тогда из класса не нужно хранить все варианты: достаточно того, который лучше по цели задачи.

Такое определение звучит слишком абстрактно, поэтому начнём с одной точной задачи. На ней появятся все слова из определения, а уже потом их можно будет переносить на другие ситуации.

## 2. Разбираем пример

Есть лестница с пронумерованными ступенями от $0$ до $n$. Робот начинает на ступени $0$ и за один ход поднимается на одну или на две ступени. Нужно попасть ровно на ступень $n$. Будем называть **маршрутом** последовательность сделанных прыжков.

Например, при $n=4$ есть пять маршрутов:

$$
1+1+1+1,\quad 1+1+2,\quad 1+2+1,\quad 2+1+1,\quad 2+2.
$$

Их можно перечислить рекурсией. Из текущей ступени пробуем прыгнуть на $1$, затем на $2$, и останавливаемся, когда попали на $n$ или перелетели её. Такое дерево перебора корректно, но с ростом $n$ его размер растёт как числа Фибоначчи. Уже на нескольких десятках ступеней обходить все ветви слишком долго.

<details>
<summary><strong>C++: перебор всех маршрутов</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
main() {
	ios::sync_with_stdio(false);
	cin.tie(0);
	// Читаем конечную ступень:
	int n; cin >> n;
	vector<int> path;
	function<void(int)> enumerate = [&](int i) {
		if (i == n) {
			for (auto it : path)
				cout << it << ' ';
			cout << '\n';
			return;
		}
		if (i > n) return;
		// Продолжаем маршрут каждым допустимым прыжком.
		for (int jump : {1, 2}) {
			path.push_back(jump);
			enumerate(i + jump);
			path.pop_back();
		}
	};
	enumerate(0);
}
```

</details>

<details>
<summary><strong>Python3: перебор всех маршрутов</strong></summary>

```python

		path.append(jump)
		enumerate(i + jump, n, path)
		path.pop()
# Читаем конечную ступень:
n = int(input())

```

</details>

Теперь положим на каждую ступень $i>0$ целую награду $a_i$. Она может быть отрицательной: тогда посещение ступени приносит штраф. Робот получает награду каждой посещённой ступени, а среди всех маршрутов нужно выбрать тот, который приносит наибольшую сумму. Задача стала другой, но дерево вариантов осталось тем же: в каждой вершине есть один или два допустимых следующих прыжка.

<details>
<summary><strong>C++: полный перебор с наградами</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
main() {
	ios::sync_with_stdio(false);
	cin.tie(0);
	const ll inf = 1LL << 60;
	// Читаем награды ступеней:
	int n; cin >> n;
	vector<ll> a(n + 1);
	for (int i = 1; i <= n; i++)
		cin >> a[i];
	function<ll(int)> best = [&](int i) {
		if (i == n) return 0LL;
		ll answ = -inf;
		// Перебираем все следующие прыжки без запоминания ответов.
		for (int jump : {1, 2})
			if (i + jump <= n)
				answ = max(answ, a[i + jump] + best(i + jump));
		return answ;
	};
	cout << best(0) << '\n';
}
```

</details>

<details>
<summary><strong>Python3: полный перебор с наградами</strong></summary>

Сам по себе большой перебор ещё не доказывает, что нужна динамика. Иногда задачу решает жадный выбор, сортировка, структура данных или совсем другое наблюдение. Динамика появляется в другой ситуации: разные ветви перебора приводят к **одинаковому положению**, после которого им доступны одни и те же дальнейшие решения.

В лестнице таким положением является текущая ступень. До ступени $i$ можно добраться разными маршрутами, но дальше для всех них разрешены одинаковые прыжки: на $i+1$ и $i+2$. Если один маршрут уже собрал меньше награды, чем другой маршрут на той же ступени, он не сможет стать лучше после одинакового продолжения. Его можно больше не рассматривать.

> [!IMPORTANT]
> <u>Динамика сокращает перебор только тогда, когда частичные варианты можно заменить более коротким описанием без потери возможных продолжений.</u>

Это и есть выигрыш. Наивный алгоритм вновь и вновь исследует одинаковые продолжения из одной ступени. Динамика вычисляет лучший результат для неё один раз и использует его во всех ветвях, которые в эту ступень пришли.

<details>
<summary><strong>C++: итеративная динамика</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
main() {
	ios::sync_with_stdio(false);
	cin.tie(0);
	// Читаем награды ступеней:
	int n; cin >> n;
	vector<ll> a(n + 1);
	for (int i = 1; i <= n; i++)
		cin >> a[i];
	// dp[i] — наибольшая сумма на маршруте до ступени i.
	vector<ll> dp(n + 1);
	if (n >= 1) dp[1] = a[1];
	for (int i = 2; i <= n; i++)
		dp[i] = a[i] + max(dp[i - 1], dp[i - 2]);
	cout << dp[n] << '\n';
}
```

</details>

<details>
<summary><strong>Python3: итеративная динамика</strong></summary>


> [!TIP]
> В олимпиадном коде такой массив обычно называют `dp` – это сокращение от dynamic programming. Длинное имя не заменяет инвариант: перед переходом должно быть ясно, что означает `dp[i]`.

## 3. Частичное решение и состояние

**Частичное решение** – это вариант, который ещё не обязан быть ответом, но уже сделал несколько шагов. В нашей задаче это любой маршрут от ступени $0$ до некоторой ступени $i$. Полный ответ получится только у маршрута, который дошёл до $n$.

У частичного решения есть история: какие именно прыжки были сделаны и какие награды уже собраны. Для продолжения эта история важна не целиком. Набор разрешённых следующих прыжков определяет только текущая ступень $i$. Поэтому все маршруты, закончившиеся на $i$, можно собрать в один класс.

**Состояние** – это короткое описание класса частичных решений, достаточное для продолжения. Здесь состоянием служит номер текущей ступени. В одномерной динамике состояния естественно нумеруются одним индексом $i$, поэтому для них удобно завести массив.

Состояние должно хранить все данные, от которых зависят будущие действия. Представим, что в правила добавили запрет на два прыжка длины $2$ подряд. Одного номера ступени уже недостаточно: после одинаковой ступени разрешённые действия зависят от длины последнего прыжка. Тогда состояние должно включать и ступень, и эту длину. Если их не различать, мы объединим маршруты с разными продолжениями и получим неверный ответ.

> [!CAUTION]
> Слишком грубое состояние склеивает варианты с разными продолжениями и даёт неверный ответ. Слишком подробное состояние сохраняет почти весь перебор и не укладывается в ограничения.

Поэтому подбор состояния – центральная часть решения. Формула обычно получается уже после того, как стало понятно, что именно фиксирует индекс $i$ и какие прошлые данные он обязан помнить.

## 4. Что хранить в состоянии

Не нужно путать состояние с числом, которое записано в массиве. Состояние отвечает на вопрос «где находится робот?», а значение отвечает на вопрос «что известно о маршрутах в это положение?». Для задачи с наградами обозначим через $dp_i$ наибольшую сумму наград среди всех маршрутов, которые заканчиваются на ступени $i$.

Пусть награды на ступенях от $1$ до $5$ равны $[2,-5,7,-4,3]$. Для начала положим $dp_0=0$: робот уже стоит в начале и ещё ничего не получил. Дальше значения получаются такими:

| ступень $i$ | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| награда $a_i$ | – | 2 | $-5$ | 7 | $-4$ | 3 |
| лучшая сумма $dp_i$ | 0 | 2 | $-3$ | 9 | 5 | 12 |

На ступень $3$ выгоднее прийти со ступени $1$: $dp_3=2+7=9$, а путь через ступень $2$ дал бы только $-3+7=4$. На последнюю ступень нужно прыгнуть со ступени $3$, поэтому маршрут $0 \rightarrow 1 \rightarrow 3 \rightarrow 5$ собирает $2+7+3=12$ и пропускает обе штрафные ступени. Маршрут с одними прыжками длины $1$ собрал бы только $2-5+7-4+3=3$. Такая ручная таблица помогает не угадать, а проверить смысл перехода.

Вообще для $i \ge 2$ получаем

$$
dp_i = a_i + \max(dp_{i-1}, dp_{i-2}).
$$

Для первой ступени остаётся отдельная база $dp_1=a_1$. В этой формуле номер $i$ задаёт состояние, а `max` отвечает на вопрос задачи: из всех маршрутов к одной ступени нужен самый выгодный.

Если изменить вопрос о той же лестнице, изменится значение в состоянии:

- для наименьшего числа прыжков $dp_i$ хранит **минимум**;
- для вопроса «можно ли попасть на ступень $i$?» $dp_i$ хранит **достижимость** `true` или `false`;
- для подсчёта всех маршрутов $dp_i$ хранит **число способов**.

Выбор значения определяет операцию в переходе. Лучший из нескольких предшественников выбирают через `max` или `min`. Для достижимости используют логическое «или». Для числа маршрутов складывают количества. Состояния могут остаться теми же, но меняется смысл числа в ячейке и действие, которым объединяются предшественники.

> [!TIP]
> Сначала произнесите вслух полное значение $dp_i$: «это ... среди всех ...». Если фразу нельзя закончить однозначно, переход пока писать рано.

## 5. Пять вопросов перед кодом

У законченной динамики всегда есть ответы на пять вопросов. Проверим их на лестнице, а не на ещё не введённых задачах.

1. **Что означает состояние?** Здесь $dp_i$ – наибольшая сумма наград среди маршрутов, которые закончились на ступени $i$.
2. **Какие последние действия могли привести в него?** Последним действием был прыжок на одну или две ступени, поэтому предшественниками являются $i-1$ и $i-2$.
3. **Где находится база?** На ступени $0$ есть один маршрут без прыжков с суммой $0$. Для первой ступени есть только один предшественник.
4. **В каком порядке считать?** К моменту вычисления $dp_i$ значения $dp_{i-1}$ и $dp_{i-2}$ уже должны быть готовы, поэтому ступени обрабатываются слева направо.
5. **Где лежит ответ?** Нужен лучший маршрут до последней ступени, значит, ответ находится в $dp_n$.

<details>
<summary><strong>После этого остаётся доказательство оптимальности методом математической индукции</strong></summary>

Берём произвольное допустимое частичное решение из состояния $i$ и смотрим на его последнее действие. Оно приводит из одного из перечисленных состояний. По предположению индукции в каждом предшественнике уже хранится правильное значение. Переход выбирает или объединяет эти значения точно так, как требует цель задачи. Значит, новое состояние тоже вычислено верно.

</details>

Такой шаблон не заменяет размышление, но дисциплинирует его. Если не получается ответить хотя бы на один из пяти вопросов, значит, не хватает свойства состояния, пропущен предшественник или выбран неправильный порядок обхода.

Полезно нарисовать состояния точками, а переходы – стрелками. В лестнице из ступени $i$ идут стрелки в $i+1$ и $i+2$. Все они направлены к большему номеру, поэтому циклов нет. Проход слева направо является порядком, в котором перед каждой стрелкой уже посчитана её начальная точка.

## 6. Рекурсия с мемоизацией

Ту же динамику можно записать как рекурсивную функцию. Чтобы найти лучший результат на ступени $i$, естественно рассмотреть последнее действие и рекурсивно спросить ответ для ступеней $i-1$ и $i-2$. Такое рассуждение рождает вызовы в нужном порядке само: функция сначала запросит состояния, от которых зависит, и только затем вычислит текущее.

Без дополнительной обработки рекурсия повторит ту же проблему, что и полный перебор: один и тот же `solve(i)` будет вызван из разных ветвей. **Мемоизация** добавляет к ней кэш. После первого вычисления `solve(i)` сохраняем значение в `dp[i]` и отмечаем `ready[i] = true`. Каждый следующий вызов немедленно возвращает уже готовый ответ.

> [!TIP]
> В более сложной задаче бывает трудно сразу придумать порядок обхода состояний. Начните с естественной рекурсии по последнему действию, затем добавьте мемоизацию. Она превращает повторные вычисления в обращения к кэшу, а явный итеративный обход можно подобрать позже.

<details>
<summary><strong>C++: рекурсия с мемоизацией</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
main() {
	ios::sync_with_stdio(false);
	cin.tie(0);
	// Читаем награды ступеней:
	int n; cin >> n;
	vector<ll> a(n + 1), dp(n + 1);
	vector<bool> ready(n + 1, false);
	for (int i = 1; i <= n; i++)
		cin >> a[i];
	function<ll(int)> solve = [&](int i) {
		if (i == 0) return 0LL;
		if (ready[i]) return dp[i];
		// Кэшируем лучший результат после рекурсивного вычисления предшественников.
		dp[i] = a[i] + solve(i - 1);
		if (i >= 2) dp[i] = max(dp[i], a[i] + solve(i - 2));
		ready[i] = true;
		return dp[i];
	};
	cout << solve(n) << '\n';
}
```

</details>

<details>
<summary><strong>Python3: рекурсия с мемоизацией</strong></summary>

Рекурсивная и итеративная записи используют один и тот же набор состояний и один и тот же переход. Отличается только порядок, в котором программа приходит к состояниям. Для лестницы проход слева направо проще и не расходует стек вызовов. В задачах с более запутанными зависимостями рекурсия с кэшем иногда оказывается естественнее.

## 7. Перекрывающиеся подзадачи и границы состояния

Ещё одно условие применимости – перекрытие подзадач. У ступени $4$ есть разные пути, но каждый из них использует один и тот же лучший результат для ступеней $2$ и $3$. Если разные ветви перебора никогда не приходят в одно состояние, запоминание ничего не экономит.

Практический путь к состоянию часто начинается с медленной рекурсии. В лестнице такая рекурсия получила бы только номер текущей ступени. Если добавить запрет на два длинных прыжка подряд, параметром станет ещё и длина предыдущего прыжка. Для каждого параметра спросите: изменит ли его значение множество допустимых продолжений? Если да, параметр обязан остаться в состоянии.

После такого сокращения полезно проверить два частичных решения с одинаковым предполагаемым состоянием. Попробуйте продолжить их одним и тем же действием. Если одно продолжение разрешено, а другое нет, состояние склеило варианты слишком рано. В лестнице с новым запретом это сразу заметно по двум маршрутам на одинаковой ступени, у которых последние прыжки имеют разную длину.

Наконец, договоритесь об индексации до кода. В этой задаче математическая и программная нумерации могут совпасть: `dp[0]` означает стартовую ступень. Тогда легко выписать первые значения и увидеть, что переход для `dp[1]` отличается от общего случая, а с `dp[2]` уже доступны оба предшественника.

База не берётся из стандартной инициализации массива. Сначала она следует из определения состояния, и лишь затем это значение записывается в программу. Так не возникает случайного нуля там, где по смыслу должна находиться недостижимость или единственный пустой способ.

## 8. Ещё один пример

Лягушка стоит на первой из $n$ $(2 \le n \le 2 \cdot 10^5)$ платформ. Высоты платформ даны массивом $h$. За прыжок с платформы $j$ на $i$ она платит $|h_i-h_j|$ и может прыгать на следующую или через одну платформу. Нужно найти наименьшую стоимость достижения последней платформы.

Здесь класс частичных решений опять задаётся последней платформой. Но маршрут с меньшей уже уплаченной стоимостью всегда не хуже маршрута с большей стоимостью, если они стоят на одной платформе. Поэтому

$$
\text{dp}_i = \min\left(\text{dp}_{i-1} + |h_i-h_{i-1}|,\ \text{dp}_{i-2} + |h_i-h_{i-2}|\right).
$$

Для высот $[10, 30, 40, 20, 20]$ получаем значения $[0, 20, 30, 30, 30]$. В последнюю платформу выгодно прийти не напрямую через четвёртую, а повторить высоту $20$ после неё. Убрать из состояния сумму уже потраченной энергии нельзя: два маршрута в одну платформу с разной стоимостью уже не равноправны.

<details>
<summary><strong>C++: минимальная стоимость прыжков</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
main() {
	ios::sync_with_stdio(false);
	cin.tie(0);
	// Читаем высоты платформ:
	int n; cin >> n;
	vector<ll> h(n);
	for (auto& it : h)
		cin >> it;
	// dp[i] — наименьшая цена, с которой лягушка приходит на i-ю платформу.
	const ll inf = (1LL << 60);
	vector<ll> dp(n, inf);
	dp[0] = 0;
	for (int i = 1; i < n; i++) {
		dp[i] = dp[i - 1] + abs(h[i] - h[i - 1]);
		if (i >= 2)
			dp[i] = min(dp[i], dp[i - 2] + abs(h[i] - h[i - 2]));
	}
	// Последняя ячейка содержит цену пути до последней платформы.
	cout << dp[n - 1] << '\n';
}
```

</details>

<details>
<summary><strong>Python3: минимальная стоимость прыжков</strong></summary>


</details>

## 9. Недостижимые состояния в программе

В базовой модели из первой части каждая ступень доступна. Добавим строку `cells` из символов `.` и `#`: точка обозначает открытую клетку, решётка – закрытую. Награда $a_i$ теперь может быть и положительной, и отрицательной. Это отделяет препятствия от значений и оставляет два разных случая: клетка закрыта и клетка открыта, но до неё нельзя добраться разрешёнными прыжками.

Для открытой, но недостижимой клетки в массиве `dp` нужно хранить не обычную сумму. На бумаге это $-\infty$, а в программе удобно объявить `const ll inf = 1LL << 60;` и записывать недостижимость как `-inf`. Это значение означает «маршрута в эту клетку нет» и не может совпасть с настоящим ответом.

```cpp
const ll inf = 1LL << 60;
vector<ll> dp(n, -inf);
if (cells[i] == '.') {
	ll best = dp[i - 1];
	if (i >= 2) best = max(best, dp[i - 2]);
	if (best != -inf) dp[i] = best + a[i];
}
```

```python
inf = 10 ** 30
dp = [-inf] * n
if cells[i] == '.':
	best = dp[i - 1]
	if i >= 2: best = max(best, dp[i - 2])
	if best != -inf: dp[i] = best + a[i]
```

Проверка `best != -inf` не даёт выдать закрытую или недостижимую клетку за обычное состояние. В задачах, где значения могут быть отрицательными, `inf` должен быть настолько велик, чтобы реальный ответ не совпал с `-inf`.

> [!TIP]
> Ещё надёжнее хранить достижимость отдельным булевым массивом, но в этой задаче это усложнило бы только запись.

> [!WARNING]
> Нельзя инициализировать все значения нулями. Ноль тогда будет одновременно означать «в клетку нельзя попасть» и «лучший маршрут имеет сумму $0$», а переход перестанет различать эти случаи.

На наградах $[2,-3,4,7,-5,5,3]$ и строке `.#...#.` допустимый маршрут $1 \rightarrow 3 \rightarrow 4 \rightarrow 5 \rightarrow 7$ собирает $11$. Клетки $2$ и $6$ закрыты, поэтому переходы через них не рассматриваются. В полном [C++](Part-02-Transition-Variants/examples/example-01.cpp) и [Python3](Part-02-Transition-Variants/examples/example-01.py) примерах используется именно эта договорённость.

<details>
<summary><strong>Пример запуска</strong></summary>

```text
Ввод
7
2 -3 4 7 -5 5 3
.#...#.

Вывод
11
```

</details>

Для поиска только значения ответа достаточно хранить последние два состояния и получить $O(1)$ дополнительной памяти. Полный массив оставлен намеренно: в главе о восстановлении он позволит вернуть сам маршрут, а не только его сумму.

## 10. Подсчёт способов

При подсчёте способов варианты не конкурируют: в ответ нужны все допустимые маршруты. Поэтому вместо выбора лучшего значения складывают количества вариантов из разных групп.

Вернёмся к уже знакомой модели: робот стоит в точке $0$ и за один ход перемещается на $1$ или на $2$. Для данной точки $n$ $(1 \le n \le 10^6)$ нужно найти количество последовательностей прыжков, которые приводят ровно в $n$. Раньше мы выбирали маршрут с наибольшей наградой, а теперь посчитаем все маршруты. Порядок прыжков важен: маршруты $1, 2$ и $2, 1$ различны.

Обозначим через $\text{dp}_i$ число маршрутов в точку $i$. Последним действием был прыжок на $1$ или на $2$, поэтому

$$
\text{dp}_i = \text{dp}_{i-1} + \text{dp}_{i-2}.
$$

Слагаемое с отрицательным индексом просто не добавляют. База $\text{dp}_0 = 1$: существует ровно один способ остаться в начальной точке, не сделав ни одного прыжка. Пустой маршрут нужен не как специальное исключение, а как обычный предшественник первого действия.

> [!IMPORTANT]
> При подсчёте складывают только количества вариантов с взаимоисключающими последними действиями. Иначе один маршрут может попасть в сумму дважды.

## 11. Разбор примера на подсчёт количества путей

Вычислим значения до точки $6$. Начинаем с $\text{dp}_0=1$. Затем получаем $\text{dp}_1=1$, $\text{dp}_2=2$, $\text{dp}_3=3$, $\text{dp}_4=5$, $\text{dp}_5=8$, $\text{dp}_6=13$. Для точки $3$ это маршруты $1+1+1$, $1+2$ и $2+1$. Для точки $6$ восемь маршрутов оканчиваются прыжком на $1$, а пять – прыжком на $2$.

Маршруты в этих двух группах не пересекаются: у каждого есть ровно один последний прыжок. Поэтому сложение не теряет и не дублирует решения. Этот же аргумент заменяет доказательство корректности для большинства динамик на подсчёт путей.

<details>
<summary><strong>C++: подсчёт маршрутов</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
main() {
	ios::sync_with_stdio(false);
	cin.tie(0);
	// Читаем конечную точку:
	int n; cin >> n;
	const int mod = 1000000007;
	// dp[i] — число последовательностей прыжков на 1 и 2 в точку i.
	vector<int> dp(n + 1);
	dp[0] = 1;
	for (int i = 1; i <= n; i++) {
		dp[i] = dp[i - 1];
		if (i >= 2) dp[i] = (dp[i] + dp[i - 2]) % mod;
	}
	// Выводим количество маршрутов в конечную точку.
	cout << dp[n] << '\n';
}
```

</details>

<details>
<summary><strong>Python3: подсчёт маршрутов</strong></summary>


## 12. Почему ответ считают по модулю?

> [!NOTE]
> Здесь мы не будем рассматривать всю модульную арифметику. Только сумму остатков.

Число маршрутов обычно растёт экспоненциально. Уже для небольших $n$ оно не помещается в `long long`, даже если алгоритм выполняет всего один проход. Когда условие требует остаток по модулю $M$, после каждого сложения можно заменить значение на остаток по $M$.

Такое преобразование корректно, потому что остаток от суммы зависит только от остатков слагаемых:

$$
(a+b) \bmod M = ((a \bmod M) + (b \bmod M)) \bmod M.
$$

Если в условии нет модуля, нельзя добавлять его по привычке. Возможно, автор ожидает большое целое число, другой способ представить ответ или доказательство, что ответ помещается в выбранный тип.

> [!WARNING]
> Нулевое значение в динамике подсчёта означает «способов нет». Поэтому база для пустого действия равна $1$, а не $0$.

## 13. Рекуррентная формула не всегда означает динамику

После динамики легко принять за неё любой массив, который вычисляется по соседнему индексу. Это неверно. В динамике несколько частичных решений приходят в одно **состояние**, а в ячейке остаётся нужная сводка: лучший ответ, число способов или достижимость. В **предподсчёте** для каждой позиции значение однозначно задаётся входом, поэтому сравнивать и склеивать варианты не нужно.

> [!IMPORTANT]
> Если в состояние не приходят разные частичные решения, рекуррентная формула сама по себе не делает алгоритм динамическим программированием.

Следующие приёмы – простые линейные предподсчёты: значение в каждой позиции определяется входом и одним уже вычисленным соседом. Они часто встречаются внутри более сложных задач, в том числе рядом с настоящей динамикой, но сами по себе динамикой не являются.

## 14. Префиксные суммы

Пусть **префиксная сумма** $\text{pref}_i$ равна сумме первых $i$ элементов массива, причём $\text{pref}_0=0$. Тогда

$$
\text{pref}_{i+1}=\text{pref}_i+a_i.
$$

Префикс длины $i$ всегда состоит из строго первых $i$ элементов. У него нет другого способа построения и нет *конкурирующих маршрутов*, поэтому это обычное накопление значения. Зато после предподсчёта сумма на полуинтервале $[l,r)$ равна $\text{pref}_r-\text{pref}_l$ за $O(1)$.

```cpp
vector<ll> pref(n + 1);
for (int i = 0; i < n; i++)
	pref[i + 1] = pref[i] + a[i];
```

```python
pref = [0] * (n + 1)
for i in range(n):
	pref[i + 1] = pref[i] + a[i]
```

Префиксные суммы могут быть частью решения с динамикой, но сами не становятся динамикой от сходства с ней.

## 15. Ближайший отличающийся элемент справа

Для позиции $i$ обозначим через $N_i$ первую позицию $j>i$, где $a_j \ne a_i$. Если такой позиции нет, положим $N_i=n+1$. Индексы в этой договорённости начинаются с $1$. При обходе справа налево для $i<n$ получаем

$$
N_n=n+1,\qquad
N_i =
\begin{cases}
N_{i+1}, & a_i=a_{i+1},\\
i+1, & a_i\ne a_{i+1}.
\end{cases}
$$

Ответ определяется единственным соседом справа. В коде массив называется `firstDifferent`, а фиктивной позиции $n+1$ соответствует индекс `n` в нумерации с нуля.

> [!TIP]
> Если нужен первый отличный элемент справа, проходите массив справа налево и переносите уже известную границу текущего блока.

<details>
<summary><strong>C++: ближайшая отличающаяся позиция</strong></summary>

```cpp
// Последнему элементу соответствует фиктивная позиция n + 1.
vector<int> firstDifferent(n);
firstDifferent[n - 1] = n;
for (int i = n - 2; i >= 0; i--) {
    if (a[i] == a[i + 1])
        firstDifferent[i] = firstDifferent[i + 1];
    else
        firstDifferent[i] = i + 1;
}
```

</details>

<details>
<summary><strong>Python3: ближайшая отличающаяся позиция</strong></summary>

```python
# Последнему элементу соответствует фиктивная позиция n + 1.
firstDifferent = [0] * n
firstDifferent[-1] = n
for i in range(n - 2, -1, -1):
    if a[i] == a[i + 1]:
        firstDifferent[i] = firstDifferent[i + 1]
    else:
        firstDifferent[i] = i + 1
```

</details>

Полные [C++](Part-03-Useful-Precomputations/examples/example-01.cpp) и [Python3](Part-03-Useful-Precomputations/examples/example-01.py) программы выводят только ближайшие отличающиеся позиции.

## 16. Длина блока одинаковых значений

Дуальная величина $B_i$ – длина максимального подотрезка из значений $a_i$, который начинается в позиции $i$. Можно вычислить её без хранения $N_i$:

$$
B_n=1,\qquad
B_i =
\begin{cases}
B_{i+1}+1, & a_i=a_{i+1},\\
1, & a_i\ne a_{i+1}.
\end{cases}
$$

В коде этот массив называется `blockLen`. Здесь тоже нет выбора между вариантами: равенство соседей либо продолжает единственный блок, либо начинает новый.

<details>
<summary><strong>C++: длина блока</strong></summary>

```cpp
// Последний элемент образует блок длины один.
vector<int> blockLen(n);
blockLen[n - 1] = 1;
for (int i = n - 2; i >= 0; i--) {
    if (a[i] == a[i + 1]) blockLen[i] = blockLen[i + 1] + 1;
    else blockLen[i] = 1;
}
```

</details>

<details>
<summary><strong>Python3: длина блока</strong></summary>

```python
# Последний элемент образует блок длины один.
blockLen = [0] * n
blockLen[-1] = 1
for i in range(n - 2, -1, -1):
    if a[i] == a[i + 1]: blockLen[i] = blockLen[i + 1] + 1
    else: blockLen[i] = 1
```

</details>

## 17. Возрастающий подотрезок, начинающийся в позиции

Пусть $L_i$ – длина максимального строго возрастающего подотрезка, который начинается в $a_i$. Последний элемент имеет значение $L_n=1$. Для остальных позиций, если $a_i<a_{i+1}$, то $L_i=L_{i+1}+1$; иначе $L_i=1$.

Продолжение отрезка снова *единственное*: можно только проверить соседнюю пару $a_i,a_{i+1}$. В коде массив называется `incLen`, а обход справа налево работает за $O(n)$ времени и использует $O(n)$ памяти.

```cpp
incLen[n - 1] = 1;

    if (a[i] < a[i + 1]) incLen[i] = incLen[i + 1] + 1;
    else incLen[i] = 1;
}
```

</details>

<details>
<summary><strong>Python3: длина возрастающего подотрезка</strong></summary>


</details>

Все три приёма выглядят как рекуррентные формулы, но каждый читает единственное значение из входа или соседней позиции. Название массива не важно: `dp`, `best` и `ways` не заменяют критерий альтернативных частичных решений.

> [!WARNING]
> Не вводите DP только потому, что значение зависит от соседней ячейки. Сначала найдите варианты, которые действительно конкурируют или объединяются в одном состоянии.

## 18. Возрастающая подпоследовательность

Дан массив из $n$ $(1 \le n \le 4000)$ чисел. Нужно найти длину его наибольшей строго возрастающей подпоследовательности. Подпоследовательность сохраняет порядок индексов, но не обязана состоять из соседних элементов. Например, в массиве $[5, 1, 6, 2, 3, 4, 0, 7]$ можно выбрать $[1, 2, 3, 4, 7]$ длины $5$.

## 19. Квадратичная динамика для возрастающей подпоследовательности

> [!NOTE]
> Для подпоследовательности важно различать последний выбранный индекс. Состояние должно знать элемент, с которым будет сравниваться следующий кандидат.

Пусть $\text{dp}_i$ – наибольшая длина строго возрастающей подпоследовательности, которая **заканчивается** элементом $a_i$. Слово «заканчивается» не случайно: оно сразу подсказывает последнее действие. Перед $a_i$ в такой подпоследовательности стоит некоторый элемент $a_j$ с меньшим индексом и меньшим значением.

Для каждого $j<i$ с $a_j<a_i$ можно продолжить лучшую подпоследовательность из состояния $j$:

$$
\text{dp}_i = 1 + \max_{j<i,\ a_j<a_i} \text{dp}_j.
$$

Если подходящего $j$ нет, подпоследовательность состоит только из $a_i$, поэтому база равна $\text{dp}_i=1$. Мы считаем индексы слева направо, и к моменту обработки $i$ известны все допустимые $j$.

> [!IMPORTANT]
> Переход перебирает все индексы, которые могут быть предпоследними в ответе.
>
> Условие $a_j<a_i$ отвечает за строгое возрастание, а условие $j<i$ – за порядок исходного массива.

## 20. Разбор примера

Рассмотрим массив $[5, 1, 6, 2, 3, 4, 0, 7]$. В строке `prev` указан один индекс, который даёт лучшее значение. Прочерк означает, что меньшего подходящего элемента слева нет.

| индекс $i$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| $a_i$ | 5 | 1 | 6 | 2 | 3 | 4 | 0 | 7 |
| `prev[i]` | – | – | 0 | 1 | 3 | 4 | – | 5 |
| `dp[i]` | 1 | 1 | 2 | 2 | 3 | 4 | 1 | 5 |

Например, для $i=5$ предшественник равен $4$: $a_4=3<a_5=4$, поэтому `dp[5] = dp[4] + 1 = 4`. Для последнего элемента выбираем $j=5$ и получаем `dp[7] = dp[5] + 1 = 5`. Если идти по этим предкам от $7$, выйдет подпоследовательность с индексами $[1,3,4,5,7]$ и значениями $[1,2,3,4,7]$.

Ответ не обязан находиться в последней позиции массива. Например, в массиве $[1, 2, 3, 0]$ значения `dp` равны $[1, 2, 3, 1]$, а ответ равен $3$. Поэтому после вычисления всех состояний нужно взять максимум по массиву `dp`.

```cpp
vector<int> dp(n, 1);
for (int i = 0; i < n; i++)
	for (int j = 0; j < i; j++)
		if (a[j] < a[i]) dp[i] = max(dp[i], dp[j] + 1);
```

```python
dp = [1] * n
for i in range(n):
	for j in range(i):
		if a[j] < a[i]: dp[i] = max(dp[i], dp[j] + 1)
```

## 21. Цена прямого перехода

Для каждого $i$ мы перебираем все предыдущие $j$. Поэтому число сравнений равно $O(n^2)$, а память – $O(n)$. При $n \le 4000$ это нормальное решение, особенно если после длины нужно восстановить саму подпоследовательность.

Состояние по последнему индексу достаточно, потому что условие продолжения зависит только от $a_i$. Любая следующая позиция $k$ может продолжить подпоследовательность с концом в $i$ тогда и только тогда, когда $i<k$ и $a_i<a_k$. Более ранние элементы этой подпоследовательности уже проверены между собой и не влияют на следующий выбор. Поэтому из всех подпоследовательностей с одним концом нужно хранить только наибольшую длину.

## 22. Быстрая динамика для возрастающей подпоследовательности

Задачу поиска наибольшей строго возрастающей подпоследовательности часто называют **LIS** – от *Longest Increasing Subsequence*.

Заведём массив `dp` длины $n+1$. Положим `dp[0] = -inf`, а все `dp[1..n] = inf`. Нулевой элемент обозначает пустую подпоследовательность. После обработки префикса `dp[k]` для $k \ne 0$ равно минимальному возможному последнему элементу строго возрастающей подпоследовательности длины $k$. Если такой подпоследовательности ещё нет, в `dp[k]` остаётся `inf`.

Здесь `inf` выбирают строго больше по модулю любого входного значения. Тогда $-inf<a_i<inf$, и сторожа не могут совпасть с настоящим окончанием подпоследовательности.

Например, после префикса $[5, 1, 6, 2, 3, 4]$ начало массива `dp` равно `[-inf, 1, 2, 3, 4]`, а дальше идут `inf`. Значение `dp[1] = 1` заканчивает подпоследовательность длины $1$, а `dp[4] = 4` – длины $4$. Конечные значения для разных длин не обязаны образовывать одну подпоследовательность исходного массива.

## 23. Как обработать очередное число

Массив `dp` не убывает. Для очередного числа $x$ найдём бинарным поиском первую позицию `pos` от $1$ до $n$, где `dp[pos] \ge x`.

Заменяем `dp[pos]` на $x$. Значение `dp[pos]` было не меньше $x$, поэтому новое окончание не хуже прежнего. Позиция всегда найдётся: в конце массива стоят `inf`.

В C++ весь проход выглядит так:

```cpp
const ll inf = 1LL << 60;
vector<ll> dp(n + 1, inf);
dp[0] = -inf;
int answ = 0;
for (int i = 0; i < n; i++) {
	int pos = lower_bound(dp.begin() + 1, dp.end(), a[i]) - dp.begin();
	dp[pos] = a[i];
	answ = max(answ, pos);
}
```

В Python используется стандартная функция `bisect_left` из модуля `bisect`:

```python
from bisect import bisect_left
inf = 10 ** 30
dp = [-inf] + [inf] * n
answ = 0
for i in range(n):
	pos = bisect_left(dp, a[i], 1)
	dp[pos] = a[i]
	answ = max(answ, pos)
```

Одно обновление занимает $O(\log(n))$, весь алгоритм – $O(n \log(n))$.

Обработаем массив $[5, 1, 6, 2, 3, 4, 0, 7]$ слева направо:

| очередное $x$ | начало `dp` после обработки |
| ---: | --- |
| 5 | [-inf, 5, inf, ...] |
| 1 | [-inf, 1, inf, ...] |
| 6 | [-inf, 1, 6, inf, ...] |
| 2 | [-inf, 1, 2, inf, ...] |
| 3 | [-inf, 1, 2, 3, inf, ...] |
| 4 | [-inf, 1, 2, 3, 4, inf, ...] |
| 0 | [-inf, 0, 2, 3, 4, inf, ...] |
| 7 | [-inf, 0, 2, 3, 4, 7, inf, ...] |

После числа $0$ конечные значения $0, 2, 3, 4$ не образуют подпоследовательность исходного массива. Они хранят лучшие окончания отдельно для длин от $1$ до $4$. После $7$ наибольший индекс с конечным значением равен $5$, значит, ответ равен $5$.

## 25. Доказательство корректности решения

Докажем индукцией по длине обработанного префикса инвариант: `dp[0] = -inf`, а для каждого $k \ge 1$ значение `dp[k]` равно `inf` либо минимальному достижимому окончанию строго возрастающей подпоследовательности длины $k$.

До чтения элементов инвариант выполнен. Пустая подпоследовательность имеет длину $0$ и окончание `-inf`, а подпоследовательностей положительной длины ещё нет.

Из инварианта следует, что `dp` не убывает. Для двух соседних достижимых длин возьмём подпоследовательность длины $k+1$ с минимальным окончанием. Её предпоследний элемент меньше окончания, а `dp[k]` не больше предпоследнего элемента. Значит, `dp[k] < dp[k + 1]`. После последней достижимой длины стоят одинаковые `inf`.

Пусть пришло число $x$, а `pos` – первая позиция от $1$ до $n$, где `dp[pos] \ge x`. Она существует из-за хвоста из `inf`. Если `pos = 1`, к пустой подпоследовательности можно приписать $x$. Иначе `dp[pos - 1] < x`, поэтому к достижимой подпоследовательности длины `pos - 1` можно приписать $x$. Значит, после замены `dp[pos] = x` значение в позиции `pos` достижимо.

Для длин меньше `pos` новое число не улучшает ответ: там уже `dp[k] < x`. Для длины `pos` старое значение не меньше $x$, поэтому новое окончание минимально. Для большей длины новое число тоже не создаёт лучшего окончания. Иначе существовала бы новая подпоследовательность длины больше `pos`, оканчивающаяся в $x$. Её первые `pos` элементов лежат до $x$ и образуют подпоследовательность длины `pos` с окончанием меньше $x$, что противоречит выбору `pos`. Старые подпоследовательности остаются допустимыми, поэтому инвариант сохранён.

Следовательно, длина LIS равна наибольшему индексу с `dp[k] < inf`. Когда этот индекс впервые становится достижимым, текущая `pos` равна ему, и программа обновляет `answ`. Достигнутая длина не исчезает при обработке следующих элементов, поэтому в конце `answ` равен ответу.

## 26. Восстановление ответа

Значения в `dp` достаточно, пока задача просит только максимум, минимум или длину, то есть саму величину. Чтобы вывести сам маршрут или подпоследовательность, выбор нужно сохранять прямо во время перехода.

Вернёмся к маршруту с прыжками на одну или две клетки. Если лучшее значение для клетки $i$ получено переходом из клетки $j$, сохраним `parent[i] = j`. Начальная клетка не имеет предшественника, поэтому для неё удобно записать `-1`.

> [!NOTE]
> Восстановление хранит не весь путь, а только последнее действие каждого выбранного состояния. Цепочка последних действий однозначно ведёт от ответа к базе.

## 27. Как пройти путь в обратную сторону

Сначала считаем ту же динамику, что и для значения ответа. Когда новый переход улучшает `dp[i]`, в этот же момент сохраняем индекс предшественника в `parent[i]`.

<details>
<summary><strong>C++: вычисление и восстановление</strong></summary>

```cpp
const ll inf = 1LL << 60;
// dp хранит лучшую сумму, parent — предка выбранного перехода.
vector<ll> dp(n, -inf);
vector<int> parent(n, -1);
if (cells[0] == '.') dp[0] = a[0];
for (int i = 1; i < n; i++) {
	if (cells[i] == '.') {
		// При равенстве оставляем прыжок на одну клетку, как в исходной динамике.
		int prev = i - 1;
		if (i >= 2 && dp[i - 2] > dp[prev]) prev = i - 2;
		if (dp[prev] != -inf) {
			// Значение и выбранное ребро перехода обновляются вместе.
			dp[i] = dp[prev] + a[i];
			parent[i] = prev;
		}
	}
}
// Идём от финала по предкам и возвращаем прямой порядок.
vector<int> path;
if (dp[n - 1] != -inf) {
	for (int i = n - 1; i != -1; i = parent[i])
		path.push_back(i + 1);
	reverse(path.begin(), path.end());
}
```

</details>

<details>
<summary><strong>Python3: вычисление и восстановление</strong></summary>

```python
inf = 10 ** 30
# dp хранит лучшую сумму, parent — предка выбранного перехода.
dp = [-inf] * n
parent = [-1] * n
if cells[0] == '.': dp[0] = a[0]
for i in range(1, n):
	if cells[i] == '.':
		# При равенстве оставляем прыжок на одну клетку, как в исходной динамике.
		prev = i - 1
		if i >= 2 and dp[i - 2] > dp[prev]: prev = i - 2
		if dp[prev] != -inf:
			# Значение и выбранное ребро перехода обновляются вместе.
			dp[i] = dp[prev] + a[i]
			parent[i] = prev
# Идём от финала по предкам и возвращаем прямой порядок.
path = []
if dp[-1] != -inf:
	i = n - 1
	while i != -1:
		path.append(i + 1)
		i = parent[i]
	path.reverse()
```

</details>

После вычисления ответа начинаем с конечного состояния. Добавляем его индекс в `path`, переходим в `parent[i]` и повторяем, пока не попадём в `-1`. Список получается в обратном порядке, поэтому в конце его нужно перевернуть.

В примере с наградами $[2,-3,4,7,-5,5,3]$ и строкой `.#...#.` оптимальный маршрут заканчивается в клетке $7$. В таблице индексы записаны от $1$, как в выводе. В программе `parent` хранит те же индексы от $0$.

| текущая клетка | `parent` текущей клетки | `path` после добавления |
| ---: | ---: | --- |
| 7 | 5 | [7] |
| 5 | 4 | [7, 5] |
| 4 | 3 | [7, 5, 4] |
| 3 | 1 | [7, 5, 4, 3] |
| 1 | -1 | [7, 5, 4, 3, 1] |

После `reverse` получаем маршрут $[1,3,4,5,7]$. `parent[i]` обновляется только вместе с улучшением `dp[i]`, поэтому каждый записанный предок даёт оптимальное значение текущего состояния. В этом маршруте индекс предка меньше текущего, поэтому обратный обход обязательно придёт в базу и не образует цикл.

Полные программы на [C++](Part-06-Restore-Answer/examples/example-01.cpp) и [Python3](Part-06-Restore-Answer/examples/example-01.py) содержат этот переход, читают награды и доступность клеток, а затем выводят оптимальную сумму и восстановленный маршрут.

## 28. Восстановление в LIS

В квадратичной LIS массив `parent` строится так же. Когда `dp[i]` улучшается переходом из $j$, записываем `parent[i]=j`. После вычисления выбираем индекс с максимальным `dp[i]` и идём по предкам назад. В условии $a_j<a_i$ уже зашита гарантия, что восстановленная последовательность строго возрастает.

<details>
<summary><strong>C++: квадратичная LIS с восстановлением</strong></summary>

```cpp
// dp[i] — длина LIS с концом в i, parent[i] — её предшественник.
vector<int> dp(n, 1), parent(n, -1);
int finish = 0;
for (int i = 0; i < n; i++) {
	// Перебираем все допустимые предпоследние элементы.
	for (int j = 0; j < i; j++) {
		if (a[j] < a[i] && dp[j] + 1 > dp[i]) {
			// Запоминаем именно тот переход, который улучшил длину.
			dp[i] = dp[j] + 1;
			parent[i] = j;
		}
	}
	// После всей строки выбираем состояние, из которого начнётся обратный обход.
	if (dp[i] > dp[finish]) finish = i;
}
// Восстанавливаем значения выбранной подпоследовательности.
vector<int> sequence;
for (int i = finish; i != -1; i = parent[i])
	sequence.push_back(a[i]);
reverse(sequence.begin(), sequence.end());
```

</details>

<details>
<summary><strong>Python3: квадратичная LIS с восстановлением</strong></summary>

```python
# dp[i] — длина LIS с концом в i, parent[i] — её предшественник.
dp = [1] * n
parent = [-1] * n
finish = 0
for i in range(n):
	# Перебираем все допустимые предпоследние элементы.
	for j in range(i):
		if a[j] < a[i] and dp[j] + 1 > dp[i]:
			# Запоминаем именно тот переход, который улучшил длину.
			dp[i] = dp[j] + 1
			parent[i] = j
	# После всей строки выбираем состояние, из которого начнётся обратный обход.
	if dp[i] > dp[finish]: finish = i
# Восстанавливаем значения выбранной подпоследовательности.
sequence = []
i = finish

	sequence.append(a[i])
	i = parent[i]

```

</details>

Полные программы на [C++](Part-06-Restore-Answer/examples/example-02.cpp) и [Python3](Part-06-Restore-Answer/examples/example-02.py) реализуют квадратичный переход, а затем выводят длину и одну восстановленную LIS.

В быстрой LIS для восстановления мало одного значения `dp[k]`: нужен ещё индекс элемента, на котором заканчивается эта подпоследовательность. В C++ объединим их в пару `dp[k] = {минимальное окончание, его индекс}`. У пустой подпоследовательности это `dp[0] = {-inf, -1}`.

Например, перед обработкой числа $4$ в позиции $6$ массива $[5,1,6,2,3,4,0,7]$ массив `dp` содержит такие пары. Индексы элементов в таблице начинаются с $1$.

| длина $k$ | `dp[k].first` | `dp[k].second` |
| ---: | ---: | ---: |
| 0 | -inf | -1 |
| 1 | 1 | 2 |
| 2 | 2 | 4 |
| 3 | 3 | 5 |

Для числа $4$ бинарный поиск по первым компонентам даёт `pos = 4`. В `dp[3].second` уже лежит позиция $5$, поэтому в коде с индексами от $0$ записываем `parent[5] = dp[3].second`. Затем заменяем всю пару: `dp[4] = {4, 5}`.

В `lower_bound` передаём пару `{a[i], -1}`. Второй компонент `-1` меньше любого настоящего индекса, поэтому она стоит раньше каждой пары `{a[i], j}` с тем же значением. Значит, поиск найдёт первую длину, у которой окончание не меньше $a_i$, и равные элементы не удлинят строго возрастающую подпоследовательность. После обработки всех элементов `dp[answ].second` указывает на последний элемент одной из наибольших подпоследовательностей.

<details>
<summary><strong>C++: быстрая LIS с восстановлением</strong></summary>

```cpp
const ll inf = 1LL << 60;
// dp[k] хранит минимальное окончание и индекс элемента с этим окончанием.
vector<pair<ll, int>> dp(n + 1, {inf, -1});
vector<int> parent(n, -1);
dp[0] = {-inf, -1};
int answ = 0;
for (int i = 0; i < n; i++) {
	// Пара с индексом -1 идёт раньше всех элементов с таким же значением.
	int pos = lower_bound(dp.begin() + 1, dp.end(), pair<ll, int>{a[i], -1}) - dp.begin();
	// Предыдущая длина уже хранит индекс нужного предшественника.
	parent[i] = dp[pos - 1].second;
	dp[pos] = {a[i], i};
	answ = max(answ, pos);
}
// Начинаем обратный обход с конца подпоследовательности максимальной длины.
vector<ll> sequence;
for (int i = dp[answ].second; i != -1; i = parent[i])
	sequence.push_back(a[i]);
reverse(sequence.begin(), sequence.end());
```

</details>

Полные программы на [C++](Part-06-Restore-Answer/examples/example-03.cpp) и [Python3](Part-06-Restore-Answer/examples/example-03.py) используют быстрый переход и выводят длину и одну восстановленную LIS.

> [!NOTE]
> В Python3 два отдельных списка обычно работают быстрее, чем список кортежей. Поэтому храним окончания в `dp`, их индексы в `last`, а перед заменой `dp[pos]` записываем `parent[i] = last[pos - 1]`.

<details>
<summary><strong>Python3: быстрая LIS с восстановлением</strong></summary>

```python
from bisect import bisect_left
inf = 10 ** 30
# dp[k] — минимальное окончание длины k, last[k] — его индекс в a.
dp = [-inf] + [inf] * n
last = [-1] * (n + 1)
parent = [-1] * n
answ = 0
for i in range(n):
	# Находим длину, для которой a[i] станет новым минимальным окончанием.
	pos = bisect_left(dp, a[i], 1)
	# До обновления last[pos - 1] ещё указывает на настоящего предшественника.
	parent[i] = last[pos - 1]
	dp[pos] = a[i]
	last[pos] = i
	answ = max(answ, pos)
# Начинаем обратный обход с конца подпоследовательности максимальной длины.
sequence = []
i = last[answ]
while i != -1:
	sequence.append(a[i])
	i = parent[i]
sequence.reverse()
```

</details>
