## Глава 4. Массовая факторизация

В олимпиадных задачах редко просят факторизовать всего одно число. Гораздо чаще вам дают массив из $10^5$ элементов, и для каждого из них нужно найти простые делители. 

Если мы будем применять наивный алгоритм факторизации за $O(\sqrt{x})$ к каждому числу, то для $10^5$ чисел порядка $10^9$ программа сделает около $10^5 \cdot 31622 \approx 3 \cdot 10^9$ операций. Это слишком медленно и гарантированно приведёт к вердикту Time Limit Exceeded. Нам нужны более хитрые подходы, которые зависят от ограничений задачи.

## 4.1. Факторизация с помощью списка простых чисел

Предположим, нам нужно факторизовать $10^5$ чисел, каждое из которых не превосходит $10^9$. 

Вспомним, как работает наивная факторизация: мы перебираем все возможные делители $d$ от $2$ до $\sqrt{x}$. Но ведь успешные деления происходят **только на простые числа**! Все составные числа мы пропускаем впустую, тратя на них драгоценные такты процессора.

Корень из $10^9$ — это примерно $31622$. На отрезке от $1$ до $31622$ находится всего $3401$ простое число. Что если мы один раз, до обработки всех запросов, найдём эти простые числа с помощью Решета Эратосфена и сохраним их в массив? Тогда при факторизации каждого конкретного числа $x$ мы будем перебирать не все числа подряд, а **только заранее найденные простые**.

Количество проверок для каждого числа сократится с $31622$ до $3401$. Асимптотика одного запроса улучшится с $O(\sqrt{x})$ до $O(\frac{\sqrt{x}}{\log x})$. Общее время работы для $n$ запросов составит $O(n \cdot \frac{\sqrt{x}}{\log x})$, что легко уложится в ограничения.

<details>
<summary><strong>C++: факторизация по списку простых</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAX_SQRT = 31622;
vector<int> primes;
void solve() {
    int x; cin >> x;
    for (int p : primes) {
        if (p * p > x) break;
        if (x % p == 0) {
            int cnt = 0;
            while (x % p == 0) {
                cnt++;
                x /= p;
            }
            cout << p << "^" << cnt << ' ';
        }
    }
    if (x > 1) cout << x << "^1 ";
    cout << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Предподсчёт простых чисел до корня из максимального X
    vector<bool> isPrime(MAX_SQRT + 1, true);
    for (int i = 2; i <= MAX_SQRT; i++) {
        if (isPrime[i]) {
            primes.push_back(i);
            for (int j = i * i; j <= MAX_SQRT; j += i) isPrime[j] = false;
        }
    }
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

```python
MAX_SQRT = 31622
is_prime = [True] * (MAX_SQRT + 1)
primes = []
for i in range(2, MAX_SQRT + 1):
    if is_prime[i]:
        primes.append(i)
        for j in range(i * i, MAX_SQRT + 1, i):

tt = int(input())
for _ in range(tt):
    x = int(input())
    for p in primes:
        if p * p > x: break
        if x % p == 0:
            cnt = 0
            while x % p == 0:
                cnt += 1
                x //= p
            print(f"{p}^{cnt}", end=' ')
    if x > 1: print(f"{x}^1", end=' ')
    print()
```

</details>

> [!TIP]
> Обратите внимание на условие `p * p > x` внутри цикла. Число $x$ в процессе деления постоянно уменьшается. Нам не нужно перебирать простые числа вплоть до исходного корня, достаточно проверять их до корня из **текущего** значения $x$. Это даёт колоссальный прирост скорости на практике.

## 4.2. Факторизация за логарифм (наименьший простой делитель)

Теперь рассмотрим другую ситуацию. Пусть запросов стало ещё больше — например, $10^6$, но сами числа стали меньше и не превосходят $10^7$. 

В этом случае мы можем позволить себе завести массив размером $10^7$. Идея заключается в том, чтобы слегка модифицировать Решето Эратосфена. Вместо того чтобы хранить логическое значение `true` или `false`, давайте для каждого числа хранить его **наименьший простой делитель** (Smallest Prime Factor). Назовём этот массив `minPrime`.

Изначально заполним массив так, чтобы для каждого числа наименьшим делителем было оно само: `minPrime[i] = i`. 
Затем запустим Решето Эратосфена. Когда мы находим простое число $i$ и начинаем вычёркивать его кратные $j$, мы будем записывать в `minPrime[j]` значение $i$, но **только в том случае**, если там всё ещё лежит само число $j$. Если там уже записано что-то другое, значит, мы нашли делитель раньше, и он меньше текущего.

Что нам даёт массив `minPrime`? Он превращает факторизацию в моментальный процесс! 
Чтобы факторизовать число $x$, мы просто смотрим в `minPrime[x]`. Это гарантированно простое число, на которое $x$ делится. Мы делим $x$ на `minPrime[x]` и повторяем процесс для нового значения $x$, пока оно не превратится в единицу.

Поскольку при каждом делении число уменьшается как минимум вдвое, количество шагов не превышает двоичного логарифма от $x$. Асимптотика одного запроса становится равной $O(\log x)$. Это невероятно быстро!

<details>
<summary><strong>C++: факторизация за логарифм</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAX_X = 10000000;
int minPrime[MAX_X + 1];
void solve() {
    int x; cin >> x;
    while (x > 1) {
        cout << minPrime[x] << ' ';
        x /= minPrime[x];
    }
    cout << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Модифицированное Решето Эратосфена
    for (int i = 2; i <= MAX_X; i++) minPrime[i] = i;
    for (int i = 2; i * i <= MAX_X; i++) {
        if (minPrime[i] == i) {
            for (int j = i * i; j <= MAX_X; j += i) {
                if (minPrime[j] == j) minPrime[j] = i;
            }
        }
    }
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

> [!IMPORTANT]
> Этот метод требует $O(X)$ памяти для хранения массива `minPrime`. В C++ массив типа `int` на $10^7$ элементов займёт около 40 мегабайт, что абсолютно нормально для олимпиад. Однако в Python списки потребляют значительно больше памяти, поэтому при $X > 10^6$ в Python этот метод стоит применять с осторожностью, чтобы не получить Memory Limit Exceeded.

## 4.3. Итоги четвёртой главы

Мы разобрали два мощных метода массовой факторизации. Выбор между ними всегда диктуется ограничениями задачи:
1. Если числа огромные (до $10^{12}$), но запросов мало — используем обычную факторизацию за $O(\sqrt{x})$.
2. Если числа большие (до $10^9$), и запросов много — предподсчитываем простые числа до корня и факторизуем за $O(\frac{\sqrt{x}}{\log x})$.
3. Если числа умеренные (до $10^7$), и запросов очень много — строим массив наименьших простых делителей и факторизуем за $O(\log x)$.

Но что, если нам нужно факторизовать не просто большое число, а число, которое задано в виде факториала? Например, найти степень вхождения двойки в $100!$. Вычислять сам факториал бессмысленно — он не поместится ни в один тип данных. О том, как элегантно решать такие задачи с помощью формулы Лежандра, мы поговорим в пятой главе.
