# Теория чисел в олимпиадных задачах

## Глава 1. Базовые понятия и факторизация

Теория чисел — это один из самых красивых и часто встречающихся разделов в олимпиадном программировании. Задачи на эту тему могут выглядеть как пугающие математические головоломки, но на деле большинство из них сводится к нескольким элегантным и быстрым алгоритмам. 

В этой главе мы начнём с самых основ: поговорим о делимости, простых числах и научимся эффективно раскладывать числа на множители. Постепенно усложняя алгоритмы, мы перейдём от наивных решений за $O(n)$ к быстрым подходам за $O(\sqrt{n})$, которые позволят вашим программам укладываться в жёсткие лимиты времени.

## 1.1. Делители, простые и составные числа

Говорят, что целое число $a$ **делится** на целое число $b$ (где $b \neq 0$), если остаток от деления $a$ на $b$ равен нулю. В этом случае $b$ называют **делителем** числа $a$.

Все натуральные числа, большие единицы, можно разделить на две большие группы:
- **Простые числа** — это числа, которые имеют ровно два различных натуральных делителя: единицу и само себя (например, $2, 3, 5, 7, 11$).
- **Составные числа** — это числа, которые имеют больше двух делителей (например, $4, 6, 8, 9$).

> [!IMPORTANT]
> Единица **не является** ни простым, ни составным числом, так как у неё ровно один натуральный делитель. Двойка — единственное чётное простое число.

## 1.2. Проверка числа на простоту

Самая базовая задача теории чисел — определить, является ли заданное число $n$ простым. 

Наивный подход очевиден: можно просто перебрать все числа от $2$ до $n-1$ и проверить, делится ли $n$ на какое-либо из них. Если делитель найден, число составное. Если цикл завершился, а делителей нет — число простое. Однако такой алгоритм работает за $O(n)$, что слишком медленно для чисел порядка $10^9$.

Давайте оптимизируем этот процесс. Заметим важное свойство: делители числа всегда ходят парами. Если $n$ делится на $d$, то оно делится и на $\frac{n}{d}$. 
Например, для числа $36$ парами делителей будут: $(1, 36)$, $(2, 18)$, $(3, 12)$, $(4, 9)$, $(6, 6)$.

Обратите внимание на последнюю пару. Меньший делитель в паре никогда не превосходит $\sqrt{n}$. Следовательно, если у числа $n$ есть нетривиальный делитель, то хотя бы один такой делитель обязательно найдётся на отрезке от $2$ до $\lfloor\sqrt{n}\rfloor$. 

Это наблюдение позволяет сократить перебор и проверять делители только до корня из $n$. Асимптотика алгоритма улучшается до $O(\sqrt{n})$.

<details>
<summary><strong>C++: проверка на простоту</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;

bool isPrime(int n) {
    if (n < 2) return false;
    for (int i = 2; i * i <= n; i++) {
        if (n % i == 0) return false;
    }
    return true;
}

void solve() {
    int n; cin >> n;
    if (isPrime(n)) cout << "YES" << endl;
    else cout << "NO" << endl;
}

main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details>
<summary><strong>Python3: проверка на простоту</strong></summary>

```python

    if n < 2:
        return False
    i = 2

```

</details>

> [!TIP]
> В коде на C++ мы используем условие `i * i <= n` вместо `i <= sqrt(n)`. Это позволяет избежать работы с вещественными числами и возможных ошибок потери точности.

## 1.3. Степень вхождения простого числа

Пусть $x$ — положительное целое число, а $p$ — простое число. Иногда требуется узнать, **сколько именно раз** можно разделить $x$ на $p$ без остатка. Иными словами, мы ищем максимальное целое $k \ge 0$, для которого $x$ делится на $p^k$. Это число называют степенью вхождения $p$ в $x$ и часто обозначают $v_p(x)$.

Для этого достаточно запустить цикл `while`, который будет делить $x$ на $p$ и увеличивать счётчик до тех пор, пока остаток от деления равен нулю.

<details>
<summary><strong>C++: степень вхождения</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int x, p; cin >> x >> p;
    int cnt = 0;
    while (x % p == 0) {
        cnt++;
        x /= p;
    }
    cout << cnt << endl;
}

main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details>
<summary><strong>Python3: степень вхождения</strong></summary>

```python
x, p = map(int, input().split())
cnt = 0
while x % p == 0:
    cnt += 1
    x //= p
print(cnt)
```

</details>

<details>
<summary><strong>Пример запуска</strong></summary>

```text
Ввод

Вывод

```
Число $24$ делится на $2$ трижды: $24 \to 12 \to 6 \to 3$. На четвёртый раз число $3$ на $2$ нацело уже не делится.
</details>

## 1.4. Поиск всех делителей числа

Что если нам нужно не просто проверить число на простоту, а получить список абсолютно всех его делителей? 

Мы снова можем воспользоваться идеей парных делителей. Перебирая $i$ от $1$ до $\sqrt{n}$, при нахождении делителя $i$ мы можем сразу добавлять в ответ и парный ему делитель $\frac{n}{i}$. Единственный нюанс, который нужно учесть: если $n$ является полным квадратом (например, $36$), то при $i = 6$ парный делитель совпадёт с самим $i$. Чтобы не добавить одно и то же число дважды, нужно добавить простую проверку.

В конце полученный список обычно требуется отсортировать по возрастанию.

<details>
<summary><strong>C++: поиск всех делителей</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n; cin >> n;
    vector<int> divs;
    for (int i = 1; i * i <= n; i++) {
        if (n % i == 0) {
            divs.push_back(i);
            // Добавляем парный делитель, если он отличается от текущего
            if (i * i != n) {
                divs.push_back(n / i);
            }
        }
    }
    sort(divs.begin(), divs.end());
    
    for (int x : divs) cout << x << ' ';
    cout << endl;
}

main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details>
<summary><strong>Python3: поиск всех делителей</strong></summary>

## 1.5. Разложение на простые множители (Факторизация)

Любое натуральное число, большее единицы, можно представить в виде произведения простых чисел. Более того, **основная теорема арифметики** гласит, что такое представление единственно с точностью до порядка следования множителей. 

Например, $360 = 2^3 \cdot 3^2 \cdot 5^1$. Это разложение является своеобразным "ДНК" числа, зная которое, можно легко отвечать на множество вопросов о его свойствах.

Чтобы найти это разложение, будем перебирать возможные делители $d$, начиная с $2$. Если текущее значение $n$ делится на $d$, разделим $n$ на $d$ столько раз, сколько возможно, параллельно подсчитывая степень этого множителя.

Хотя мы перебираем все целые $d$, успешные деления будут происходить только для простых чисел. Действительно, если $d$ составное, у него есть простой делитель $p < d$. К моменту обработки $d$ все множители $p$ уже были полностью удалены из текущего значения $n$, поэтому оно не сможет делиться на $d$.

Цикл продолжается, пока $d^2 \le n$, причём значение $n$ в процессе уменьшается. Если после завершения цикла осталось $n > 1$, то это оставшееся число является простым и входит в разложение в первой степени. Оно не обязательно больше квадратного корня из исходного числа: условие цикла сравнивается с текущим, уже уменьшенным значением $n$.

<details>
<summary><strong>C++: факторизация</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n; cin >> n;
    // Храним пары: {простое число, его степень}
    vector<pair<int, int>> factors;
    
    for (int d = 2; d * d <= n; d++) {
        if (n % d == 0) {
            int cnt = 0;
            while (n % d == 0) {
                cnt++;
                n /= d;
            }
            factors.push_back({d, cnt});
        }
    }
    // Если после всех делений n > 1, то это оставшееся простое число
    if (n > 1) {
        factors.push_back({n, 1});
    }
    
    for (auto p : factors) {
        cout << p.first << "^" << p.second << ' ';
    }
    cout << endl;
}

main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details>
<summary><strong>Python3: факторизация</strong></summary>

## 1.6. Количество делителей числа

Зная разложение числа на простые множители, мы можем мгновенно находить количество всех его делителей, не перебирая их.

Пусть число $n$ разложено на простые: $n = p_1^{a_1} \cdot p_2^{a_2} \cdot \ldots \cdot p_k^{a_k}$.
Любой делитель числа $n$ формируется путём выбора степеней для этих простых чисел. Степень для простого $p_1$ можно выбрать от $0$ до $a_1$ (всего $a_1 + 1$ вариантов). Степень для $p_2$ — от $0$ до $a_2$ (всего $a_2 + 1$ вариантов), и так далее.

По правилу умножения из комбинаторики, общее количество делителей равно произведению количеств вариантов для каждого простого множителя:
$$d(n) = (a_1 + 1) \cdot (a_2 + 1) \cdot \ldots \cdot (a_k + 1)$$

<details>
<summary><strong>C++: количество делителей</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n; cin >> n;
    int cntDivs = 1;
    
    for (int d = 2; d * d <= n; d++) {
        if (n % d == 0) {
            int cnt = 0;
            while (n % d == 0) {
                cnt++;
                n /= d;
            }
            cntDivs *= (cnt + 1);
        }
    }
    if (n > 1) {
        cntDivs *= 2; // Степень оставшегося простого равна 1, значит умножаем на (1 + 1)
    }
    
    cout << cntDivs << endl;
}

main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

Часто в задачах возникает вопрос: а насколько большим может быть количество делителей у числа $n$? 

Хотя мы ищем делители за $O(\sqrt{n})$, само их количество $d(n)$ растёт гораздо медленнее. На практике для диапазонов, встречающихся в олимпиадах, оно оценивается скорее как $O(\sqrt[3]{n})$, а при $n \le 10^{18}$ оказывается ещё меньше. 

Например, на отрезке до $10^{18}$ абсолютным рекордсменом является число $897\,612\,484\,786\,617\,600$. У него всего $103\,680$ делителей. 

> [!NOTE]
> Это знание крайне полезно: если ваш алгоритм сначала находит все делители числа, а затем решает задачу полным перебором по этому списку, то второй этап отработает практически мгновенно, даже если само число огромно.

Числа, у которых делителей больше, чем у любого меньшего положительного целого числа, называются **сверхсоставными числами** (highly composite numbers). Ниже под спойлером приведён список таких чисел, меньших $10^{18}$.

Каждое сверхсоставное число представляется в виде произведения первых подряд идущих простых чисел:
$$n = 2^{a_1} \cdot 3^{a_2} \cdot 5^{a_3} \cdot \ldots \cdot p_k^{a_k},$$
где показатели степеней положительны и не возрастают:
$$a_1 \ge a_2 \ge \ldots \ge a_k \ge 1.$$
Это необходимые свойства сверхсоставных чисел, но не каждое число такого вида обязательно является сверхсоставным.

## 1.7. Сумма всех делителей

Аналогичным образом, опираясь на факторизацию, можно найти сумму всех делителей числа. 

Рассмотрим алгебраическое выражение, составленное из простых множителей числа $n$:
$$(1 + p_1 + p_1^2 + \ldots + p_1^{a_1}) \cdot (1 + p_2 + p_2^2 + \ldots + p_2^{a_2}) \cdot \ldots$$

Если раскрыть скобки в этом произведении, то каждое слагаемое будет представлять собой уникальную комбинацию простых множителей, то есть один из делителей числа $n$. А поскольку мы складываем все эти комбинации, итоговый результат в точности равен сумме всех делителей!

> [!NOTE]
> Сумма делителей может превышать вместимость 32-битного типа, поэтому в C++ для неё обычно используют как минимум `int64_t`.
>
> Однако `int64_t` также не гарантирует отсутствие переполнения при произвольно больших ограничениях: всегда нужно оценивать максимальный возможный ответ, а если требуется остаток по модулю — выполнять умножения с учётом этого модуля.

<details>
<summary><strong>C++: сумма делителей</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n; cin >> n;
    int64_t sumDivs = 1;
    
    for (int d = 2; d * d <= n; d++) {
        if (n % d == 0) {
            int64_t currentSum = 1;
            int64_t currentPower = 1;
            while (n % d == 0) {
                currentPower *= d;
                currentSum += currentPower;
                n /= d;
            }
            sumDivs *= currentSum;
        }
    }
    if (n > 1) {
        sumDivs *= (1 + n);
    }
    
    cout << sumDivs << endl;
}

main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details>

## 1.8. Итоги первой главы

Мы научились работать с делителями и простыми числами за $O(\sqrt{n})$. Факторизация — это мощнейший инструмент, который сводит сложные задачи о делителях к простой комбинаторике и алгебре. 

Однако, что делать, если нам нужно найти общие делители для нескольких чисел? Как быстро вычислять наибольший общий делитель (НОД) и наименьшее общее кратное (НОК), не прибегая к факторизации каждого из них? Об этом, а также о знаменитом алгоритме Евклида, мы поговорим во второй главе.

## Глава 2. Наибольший общий делитель и алгоритм Евклида

В предыдущей главе мы рассматривали числа по отдельности, изучая их внутреннюю структуру через призму простых делителей. Теперь давайте посмотрим, что происходит, когда чисел становится два. 

Во многих задачах требуется найти **наибольший общий делитель (НОД)** двух положительных целых чисел $a$ и $b$ — наибольшее положительное целое число, на которое без остатка делятся и $a$, и $b$. Не менее часто встречается **наименьшее общее кратное (НОК)** — наименьшее положительное целое число, которое делится одновременно и на $a$, и на $b$.

> [!TIP]
> В олимпиадных задачах иногда встречаются и нулевые значения. Для них используют соглашения $\text{НОД}(a, 0) = |a|$ и $\text{НОК}(a, 0) = 0$. В частности, стандартная функция C++ возвращает $\text{НОД}(0, 0) = 0$.

В этой главе мы разберёмся, какой комбинаторный смысл скрывается за этими понятиями, научимся вычислять их за доли секунды и детально разберём знаменитый алгоритм Евклида.

## 2.1. Смысл НОД и НОК через факторизацию

Чтобы по-настоящему понять природу НОД и НОК, давайте взглянем на них через разложение чисел на простые множители. 

Возьмём два числа: $a = 360$ и $b = 252$. Разложим их на простые:
- $360 = 2^3 \cdot 3^2 \cdot 5^1$
- $252 = 2^2 \cdot 3^2 \cdot 7^1$

Любой общий делитель этих чисел должен состоять только из тех простых множителей, которые присутствуют в обоих разложениях. Причём степень каждого простого множителя не может превышать минимальную из двух доступных. 
Следовательно, чтобы получить **НОД**, мы берём пересечение простых множителей в **минимальных степенях**:
$$\text{НОД}(360, 252) = 2^{\min(3, 2)} \cdot 3^{\min(2, 2)} \cdot 5^{\min(1, 0)} \cdot 7^{\min(0, 1)} = 2^2 \cdot 3^2 = 36$$

А что насчёт общего кратного? Оно должно делиться и на $a$, и на $b$, а значит, обязано включать в себя все простые множители обоих чисел в степенях, достаточных для покрытия каждого из них. 
Поэтому для **НОК** мы берём объединение всех простых множителей в **максимальных степенях**:
$$\text{НОК}(360, 252) = 2^{\max(3, 2)} \cdot 3^{\max(2, 2)} \cdot 5^{\max(1, 0)} \cdot 7^{\max(0, 1)} = 2^3 \cdot 3^2 \cdot 5^1 \cdot 7^1 = 2520$$

> [!TIP]
> Из этого свойства вытекает очень полезный трюк. Если в задаче вас просят найти, **на какие общие простые числа** делятся и $a$, и $b$, вам не нужно факторизовать оба числа и искать пересечение. Достаточно найти их НОД и факторизовать только его! При этом помните, что в самом НОД эти простые числа могут быть в степени больше первой (как двойка и тройка в примере выше), но сам набор уникальных простых множителей будет ровно тем, который вы ищете.

## 2.3. Деление с остатком

Несмотря на наличие готовых функций, олимпиаднику жизненно важно понимать, как именно вычисляется НОД под капотом. Существует целый класс задач, где требуется симулировать шаги этого алгоритма, предсказывать их количество или восстанавливать числа по истории шагов.

В основе алгоритма лежит операция **целочисленного деления с остатком**. Любое целое число $a$ можно разделить на целое число $b$ ($b > 0$) и представить в виде:
$$a = b \cdot q + r$$

Давайте зафиксируем терминологию, чтобы говорить на одном языке:
- $a$ — **делимое** (то, что мы делим);
- $b$ — **делитель** (то, на что мы делим);
- $q$ — **неполное частное** (сколько раз $b$ целиком помещается в $a$);
- $r$ — **остаток** (то, что осталось после выделения всех целых частей).

Важнейшее свойство остатка: он всегда неотрицателен и строго меньше делителя, то есть $0 \le r < b$.

Например, разделим $1071$ на $462$:

$1071 = 462 \cdot 2 + 147$

Здесь делимое — $1071$, делитель — $462$, частное — $2$, а остаток — $147$.

## 2.4. Алгоритм Евклида

Алгоритм Евклида — это один из древнейших математических алгоритмов, описанный ещё в III веке до нашей эры. Он позволяет найти НОД двух чисел, не прибегая к их факторизации.

Главная идея алгоритма опирается на следующее наблюдение. Если
$$a = b \cdot q + r,$$
то любой общий делитель $a$ и $b$ делит разность $a - bq = r$. И наоборот, любой общий делитель $b$ и $r$ делит число $bq + r = a$. Значит, у пар $(a, b)$ и $(b, r)$ совпадают все общие делители, поэтому:
$$\text{НОД}(a, b) = \text{НОД}(b, r)$$

Это означает, что мы можем заменить сложную задачу поиска НОД для больших чисел $a$ и $b$ на более простую задачу для чисел $b$ и $r$. И мы можем повторять этот процесс до тех пор, пока остаток не станет равным нулю. Как только остаток обнулился, последнее ненулевое число и есть наш НОД.

Давайте проследим работу алгоритма по шагам для чисел $1071$ и $462$, записывая каждый шаг в виде $a = b \cdot q + r$:

1. $1071 = 462 \cdot 2 + 147$ (заменяем пару $1071$ и $462$ на пару $462$ и $147$)
2. $462 = 147 \cdot 3 + 21$ (заменяем пару $462$ и $147$ на пару $147$ и $21$)
3. $147 = 21 \cdot 7 + 0$ (остаток равен нулю, алгоритм завершён)

Последний ненулевой остаток (или, что то же самое, делитель на последнем шаге) равен $21$. Это и есть $\text{НОД}(1071, 462)$.

## 2.5. Худший случай: числа Фибоначчи

Насколько быстро работает алгоритм Евклида? На каждом шаге мы берём остаток от деления, и числа стремительно уменьшаются. Но какие входные данные заставят алгоритм сделать **максимально возможное** количество шагов?

Чтобы алгоритм работал долго, числа должны уменьшаться как можно медленнее. Это происходит, когда на каждом промежуточном шаге неполное частное $q$ принимает минимально возможное положительное значение, то есть $q = 1$.

Тогда равенство
$$a = b \cdot q + r$$
принимает особенно простой вид:
$$a = b + r$$

Посмотрите внимательно на это равенство. Каждое число оказывается суммой двух следующих чисел, возникающих в алгоритме. Если прочитать последовательность в обратном направлении, получится знакомое правило: каждое следующее число равно сумме двух предыдущих. Именно так устроены **числа Фибоначчи**!

Поэтому соседние числа Фибоначчи являются худшим случаем для алгоритма Евклида. Например, для чисел $55$ и $34$ вычисления выглядят так:

$$55 = 34 \cdot 1 + 21$$
$$34 = 21 \cdot 1 + 13$$
$$21 = 13 \cdot 1 + 8$$
$$13 = 8 \cdot 1 + 5$$
$$8 = 5 \cdot 1 + 3$$
$$5 = 3 \cdot 1 + 2$$
$$3 = 2 \cdot 1 + 1$$
$$2 = 1 \cdot 2 + 0$$

Как видите, почти на каждом шаге неполное частное равно единице, поэтому числа уменьшаются настолько медленно, насколько это возможно. Исключением становится последнее деление, на котором остаток обнуляется.

Однако даже такой худший случай не представляет для нас никакой опасности. Числа Фибоначчи растут экспоненциально, а значит, количество шагов алгоритма увеличивается лишь логарифмически. Поэтому асимптотика алгоритма Евклида составляет:
$$O(\log(\min(a, b)))$$

Даже для чисел порядка $10^{18}$ алгоритму потребуется менее 90 делений с остатком. Иными словами, на практике НОД вычисляется практически мгновенно.

## 2.6. Реализация алгоритма Евклида

Если вам всё же потребовалось написать алгоритм Евклида вручную, это делается буквально в пару строк с помощью цикла `while`. Мы просто продолжаем брать остаток и менять числа местами, пока второе число не превратится в ноль.

<details>
<summary><strong>C++: алгоритм Евклида</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
int gcd(int a, int b) {
    while (b != 0) {
        a %= b;
        swap(a, b);
    }
    return a;
}
void solve() {
    int a, b; cin >> a >> b;
    cout << gcd(a, b) << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details>
<summary><strong>Python3: алгоритм Евклида</strong></summary>

```python
def gcd(a, b):
    while b != 0:
        a, b = b, a % b
    return a

a, b = map(int, input().split())
print(gcd(a, b))
```

</details>

> [!IMPORTANT]
> Для неотрицательных $a$ и положительного $b$ не нужно заранее проверять, какое из чисел больше. Если $a < b$, то $a \bmod b = a$, поэтому после первой итерации числа автоматически поменяются местами. Алгоритм также корректно обрабатывает ноль: $\text{НОД}(a, 0) = a$.

## 2.7. Связь между НОД и НОК

Мы уже выяснили, что НОД — это пересечение простых множителей, а НОК — их объединение. Из этого следует красивая математическая формула, связывающая эти две величины:
$$a \cdot b = \text{НОД}(a, b) \cdot \text{НОК}(a, b)$$

Если перемножить два числа, то каждый простой множитель будет учтён суммарно столько раз, какова сумма его степеней в $a$ и $b$. Но ведь $\min(x, y) + \max(x, y) = x + y$. Поэтому произведение НОД и НОК в точности равно произведению самих чисел.

Из этой формулы мы получаем классический способ вычисления НОК:
$$\text{НОК}(a, b) = \frac{a \cdot b}{\text{НОД}(a, b)}$$

С математической точки зрения формула абсолютно верна. Однако при переносе её в код возникает одна коварная ловушка: порядок вычислений внезапно становится очень важен.

> [!WARNING]
> Если сначала перемножить $a$ и $b$, промежуточный результат может переполниться, даже если сам НОК прекрасно помещается в используемый тип данных.
>
> Поэтому в программе формулу следует записывать так:
> $\text{НОК}(a, b) = \frac{a}{\text{НОД}(a, b)} \cdot b$
>
> Сначала мы делим $a$ на НОД — это деление всегда выполняется нацело, — и только после этого умножаем результат на $b$.

В C++ для вычисления НОК обычно следует использовать `int64_t`, особенно если исходные числа хранятся в типе `int`. Но помните: изменение порядка операций спасает только от **промежуточного переполнения**. Если сам ответ не помещается в `int64_t`, потребуется другой способ его хранения или вычисление по модулю.

Для положительных чисел приведённая формула применяется напрямую. Если же по условию задачи $a = 0$ или $b = 0$, то НОК принимают равным нулю. Этот случай лучше обработать отдельно, чтобы не получить деление на $\text{НОД}(0, 0) = 0$.

<details>
<summary><strong>C++: безопасное вычисление НОК</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
int64_t gcd(int64_t a, int64_t b) {
    while (b != 0) {
        a %= b;
        swap(a, b);
    }
    return a;
}
void solve() {
    int64_t a, b; cin >> a >> b;
    int64_t answ = 0;
    if (a != 0 && b != 0) answ = a / gcd(a, b) * b;
    cout << answ << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

## 2.8. Итоги второй главы

Мы разобрали, как НОД и НОК связаны с простыми числами, и изучили алгоритм Евклида, который находит НОД за логарифмическое время. Понимание шагов алгоритма Евклида и его худшего случая на числах Фибоначчи — это классика, которая регулярно встречается в олимпиадных задачах.

Но что, если нам нужно работать не с одним или двумя числами, а с целым массивом чисел от $1$ до $N$? Факторизовать каждое из них по отдельности за $O(\sqrt{n})$ будет слишком долго. В следующей главе мы познакомимся с Решетом Эратосфена — гениальным алгоритмом, который позволяет находить все простые числа на отрезке и оценивать их количество.

## Глава 3. Решето Эратосфена и распределение простых чисел

До сих пор мы проверяли на простоту и факторизовали числа по одному. Алгоритм за $O(\sqrt{n})$ отлично справляется с единичными запросами. Но что, если задача требует найти **все** простые числа на отрезке от $1$ до $N$, где $N = 10^7$? 

Если проверять каждое число алгоритмом за $O(\sqrt{N})$, общее время работы составит $O(N \sqrt{N})$. Для $10^7$ это около $3 \cdot 10^{10}$ операций, что гарантированно приведёт к превышению лимита времени (Time Limit Exceeded). Нам нужен принципиально иной подход, который позволит обрабатывать весь диапазон чисел сразу.

> [!TIP]
> Оценка $O(N\sqrt{N})$ является удобной верхней границей, но на практике проверка всех чисел работает несколько быстрее. Большинство составных чисел быстро находят маленький делитель и завершают проверку досрочно, а полный перебор до корня требуется в основном для простых чисел.
>
> Поскольку простых чисел до $N$ примерно $\frac{N}{\ln N}$, основной вклад можно грубо оценить как
> $O\left(\frac{N\sqrt{N}}{\log N}\right).$
>
> Тем не менее даже этого ускорения совершенно недостаточно для $N = 10^7$, поэтому Решето Эратосфена всё равно оказывается на несколько порядков быстрее.

## 3.1. Идея Решета Эратосфена

Более двух тысяч лет назад древнегреческий математик Эратосфен придумал гениальный и простой алгоритм. 

Представьте, что мы выписали в ряд все числа от $2$ до $N$. Первое невычеркнутое число — двойка. Оно простое. Пройдёмся по ряду и вычеркнем все числа, кратные двум: $4, 6, 8, 10$ и так далее. 
Следующее невычеркнутое число — тройка. Оно тоже простое. Снова пройдёмся по ряду и вычеркнем все числа, кратные трём: $6, 9, 12, 15 \dots$ (некоторые из них уже были вычеркнуты двойкой, это нормально).
Продолжая этот процесс, мы будем находить очередное невычеркнутое число, объявлять его простым и «просеивать» через него весь оставшийся ряд, удаляя его кратные. В конце невычеркнутыми останутся только простые числа.

> [!TIP]
> Алгоритм можно слегка оптимизировать. Если мы нашли простое число $p$, то вычеркивать его кратные можно начинать сразу с $p^2$. Все меньшие кратные (например, $2p$ или $3p$) уже были вычеркнуты ранее, когда мы обрабатывали двойку и тройку. По этой же причине внешний цикл поиска простых чисел достаточно крутить только до $\sqrt{N}$.

## 3.2. Гармонический ряд и оценка сложности

Давайте разберёмся, сколько именно действий делает этот алгоритм. 
Для двойки мы делаем $\frac{N}{2}$ вычеркиваний. Для тройки — $\frac{N}{3}$. Для пятёрки — $\frac{N}{5}$. 

Если бы мы вычеркивали кратные для **всех** чисел, а не только для простых, количество операций описывалось бы суммой:
$$\frac{N}{1} + \frac{N}{2} + \frac{N}{3} + \frac{N}{4} + \dots + \frac{N}{N}$$

Вынесем $N$ за скобки. Внутри останется сумма дробей $1 + \frac{1}{2} + \frac{1}{3} + \dots + \frac{1}{N}$. Эта сумма называется **гармоническим рядом**. В математике строго доказано, что сумма первых $N$ членов гармонического ряда растёт как натуральный логарифм $N$. 
Таким образом, оценка сверху для количества действий составляет $O(N \log N)$.

Но в Решете Эратосфена мы запускаем внутренний цикл **только для простых чисел**. Сумма обратных величин простых чисел $\frac{1}{2} + \frac{1}{3} + \frac{1}{5} + \frac{1}{7} + \dots$ растёт ещё медленнее — как $\log(\log N)$. 

Поэтому итоговая асимптотика Решета Эратосфена составляет $O(N \log \log N)$. Функция $\log \log N$ растёт настолько медленно, что на практике решето работает почти как линейный алгоритм.

Разумеется, максимальное допустимое значение $N$ зависит не только от времени, но и от памяти, языка программирования и выбранного типа массива. В C++ обычное решето часто применяют для значений порядка $10^7$ – $10^8$, если это допускают ограничения по памяти. В Python уже при заметно меньших значениях основным препятствием могут стать как объём памяти, так и скорость циклов.

## 3.3. Реализация алгоритма

В коде мы будем использовать массив логических значений, где индекс означает само число, а значение `true` или `false` показывает, является ли оно простым. Будем считать, что по условию задачи $N \ge 2$, поэтому индексы $0$ и $1$ гарантированно существуют в массиве.

<details>
<summary><strong>C++: Решето Эратосфена</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
void solve() {
    int n; cin >> n;
    vector<bool> isPrime(n + 1, true);
    isPrime[0] = isPrime[1] = false;
    for (int i = 2; i * i <= n; i++) {
        if (isPrime[i]) {
            for (int j = i * i; j <= n; j += i) {
                isPrime[j] = false;
            }
        }
    }
    for (int i = 2; i <= n; i++) {
        if (isPrime[i]) cout << i << ' ';
    }
    cout << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

## 3.4. Плотность распределения простых чисел

Часто в задачах полезно заранее оценить, сколько простых чисел находится на отрезке от $1$ до $N$. Например, такая оценка позволяет вызвать `reserve` для вектора и заранее выделить память под найденные простые числа.

Количество простых чисел, не превосходящих $N$, обозначают через $\pi(N)$. Знаменитая **теорема о распределении простых чисел** утверждает, что при больших $N$ эта функция ведёт себя асимптотически как:
$$\pi(N) \sim \frac{N}{\ln N}$$

Для практической оценки это обычно записывают в более привычном виде:
$$\pi(N) \approx \frac{N}{\ln N}$$

Например, при $N = 10^6$ формула даёт:
$$\frac{10^6}{\ln 10^6} \approx 72\,382.$$

Точное количество простых чисел на этом отрезке равно $78\,498$. Для предварительной оценки памяти такой точности более чем достаточно.

Из этой теоремы вытекает ещё один удивительный и очень полезный факт. Если среди первых $N$ чисел находится примерно $\frac{N}{\ln N}$ простых, то средний промежуток между соседними простыми числами имеет порядок:
$$\frac{N}{\pi(N)} \approx \ln N$$

Для чисел в районе миллиарда, то есть около $10^9$, натуральный логарифм равен примерно $21$. Поэтому в среднем простое число можно ожидать через пару десятков следующих кандидатов.

> [!IMPORTANT]
> Речь идёт именно о **среднем** расстоянии. Иногда между соседними простыми числами встречаются промежутки, значительно превышающие $\ln N$, поэтому эта оценка не даёт строгой гарантии на количество проверок. Тем не менее для поиска одного ближайшего простого числа в обычных олимпиадных ограничениях такой перебор часто оказывается очень быстрым.

## 3.5. Поиск ближайшего простого числа

Знание о распределении простых чисел позволяет элегантно решать задачу поиска ближайшего простого числа.

Предположим, нам дано большое число $X$, например $10^9$, и требуется найти первое простое число, которое больше или равно $X$. Строить Решето Эратосфена до миллиарда было бы слишком затратно по памяти, особенно ради единственного ответа.

Вместо этого можно проверять числа по очереди: сначала $X$, затем $X+1$, $X+2$ и так далее, пока не встретится простое. Каждая отдельная проверка работает за $O(\sqrt{X})$, а простые числа в этом диапазоне на практике встречаются достаточно часто, поэтому обычно требуется проверить совсем немного кандидатов.

Важно понимать, что оценка через среднее расстояние между простыми числами не является строгой оценкой худшего случая. Поэтому записывать сложность всего поиска как гарантированное $O(\sqrt{X}\log X)$ было бы некорректно. Однако для чисел порядка $10^9$ этот подход обычно выполняет лишь несколько десятков проверок, то есть порядка сотен тысяч или нескольких миллионов простых операций, что вполне подходит для одного запроса.

Аналогичным образом можно найти первое простое число, которое меньше или равно $X$, последовательно уменьшая кандидата. При этом будем считать, что $X \ge 2$: иначе простого числа, не превосходящего $X$, просто не существует.

<details>
<summary><strong>C++: поиск ближайших простых чисел</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
bool checkPrime(int x) {
    if (x < 2) return false;
    for (int i = 2; i * i <= x; i++) {
        if (x % i == 0) return false;
    }
    return true;
}
void solve() {
    int x; cin >> x;
    int p = x;
    while (!checkPrime(p)) p++;
    int q = x;
    while (!checkPrime(q)) q--;
    cout << p << ' ' << q << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

<details>
<summary><strong>Python3: поиск ближайших простых чисел</strong></summary>

> Если нужно найти всего одно простое число рядом с $X$, последовательный перебор с проверкой за $O(\sqrt{X})$ часто оказывается самым простым и практичным решением. Однако обязательно сверяйтесь с ограничениями: для большого количества запросов или для чисел, значительно превосходящих $10^9$, могут потребоваться более быстрый тест простоты или другие методы.

## 3.6. Итоги третьей главы

Мы освоили Решето Эратосфена — незаменимый алгоритм для массового поиска простых чисел за $O(N \log \log N)$. Кроме того, познакомившись с гармоническим рядом и теоремой о распределении простых чисел, мы поняли, почему поиск одного простого числа последовательным перебором часто оказывается быстрым на практике. При этом важно помнить: высокая средняя плотность простых чисел помогает оценить ожидаемое поведение алгоритма, но не ограничивает строго расстояние до следующего простого.

Но что делать, если нам нужно не просто найти простые числа, а **факторизовать** сотни тысяч чисел, каждое из которых может достигать $10^9$? Обычная факторизация каждого числа за $O(\sqrt{X})$ не уложится во время. В четвёртой главе мы объединим идеи Решета Эратосфена и факторизации, чтобы научиться раскладывать числа на множители с невероятной скоростью.

## Глава 4. Массовая факторизация

До сих пор мы учились факторизовать одно число за $O(\sqrt{x})$. Для единичного запроса этого обычно вполне достаточно. Но что произойдёт, если в задаче дан целый массив из $10^5$ элементов и для каждого из них требуется найти простые множители?

В худшем случае обычная факторизация каждого числа порядка $10^9$ потребует около:
$$10^5 \cdot 31622 \approx 3 \cdot 10^9$$
проверок делимости. На практике программа часто завершает перебор раньше, однако рассчитывать только на это нельзя: несколько миллиардов операций почти наверняка не уложатся в стандартный лимит времени.

Следовательно, при большом количестве запросов нам нужен **предподсчёт**. Один раз обработав весь допустимый диапазон, мы сможем заметно ускорить факторизацию каждого отдельного числа. Какой именно метод выбрать, будет зависеть от двух параметров: максимального значения чисел и количества запросов.

## 4.1. Факторизация с помощью списка простых чисел

Предположим, нам нужно факторизовать $10^5$ чисел, каждое из которых не превосходит $10^9$. 

Вспомним, как работает наивная факторизация: мы перебираем все возможные делители $d$ от $2$ до $\sqrt{x}$. Но ведь успешные деления происходят **только на простые числа**! Все составные числа мы пропускаем впустую, тратя на них драгоценные такты процессора.

Корень из $10^9$ — это примерно $31622$. На отрезке от $1$ до $31622$ находится всего $3401$ простое число. Что если мы один раз, до обработки всех запросов, найдём эти простые числа с помощью Решета Эратосфена и сохраним их в массив? Тогда при факторизации каждого конкретного числа $x$ мы будем перебирать не все числа подряд, а **только заранее найденные простые**.

В худшем случае количество проверок для одного числа сократится с $31622$ до $3401$. Согласно теореме о распределении простых чисел, количество простых до $\sqrt{x}$ имеет порядок:
$$\frac{\sqrt{x}}{\log \sqrt{x}} = \frac{2\sqrt{x}}{\log x}.$$

Постоянный множитель в асимптотике опускается, поэтому сложность одного запроса обычно записывают как:
$$O\left(\frac{\sqrt{x}}{\log x}\right).$$

Это почти в десять раз меньше проверок, чем при переборе всех возможных делителей подряд. Кроме того, по мере нахождения множителей текущее значение $x$ уменьшается, благодаря чему цикл нередко завершается ещё раньше.

Однако важно не переоценивать это ускорение. Для $10^5$ простых чисел или произведений двух больших простых множителей программа всё ещё может выполнить около $3{,}4 \cdot 10^8$ операций взятия остатка. Для C++ это уже существенная нагрузка, а для Python такой подход, скорее всего, окажется слишком медленным. Поэтому всегда оценивайте не только максимальное значение $x$, но и количество запросов.

<details>
<summary><strong>C++: факторизация по списку простых</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAX_SQRT = 31622;
vector<int> primes;
void solve() {
    int x; cin >> x;
    for (int p : primes) {
        if (p * p > x) break;
        if (x % p == 0) {
            int cnt = 0;
            while (x % p == 0) {
                cnt++;
                x /= p;
            }
            cout << p << "^" << cnt << ' ';
        }
    }
    if (x > 1) cout << x << "^1 ";
    cout << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Предподсчёт простых чисел до корня из максимального X
    vector<bool> isPrime(MAX_SQRT + 1, true);
    for (int i = 2; i <= MAX_SQRT; i++) {
        if (isPrime[i]) {
            primes.push_back(i);
            for (int j = i * i; j <= MAX_SQRT; j += i) isPrime[j] = false;
        }
    }
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

Однако для простого числа или произведения двух больших простых множителей значение $x$ почти не меняется, и цикл выполнит все проверки.

## 4.2. Факторизация за логарифм (наименьший простой делитель)

Теперь рассмотрим другую ситуацию. Пусть запросов стало ещё больше — например, $10^6$, но сами числа стали меньше и не превосходят $10^7$. 

В этом случае мы можем позволить себе завести массив размером $10^7$. Идея заключается в том, чтобы слегка модифицировать Решето Эратосфена. Вместо того чтобы хранить логическое значение `true` или `false`, давайте для каждого числа хранить его **наименьший простой делитель** (Smallest Prime Factor). Назовём этот массив `minPrime`.

Изначально положим `minPrime[i] = i` для каждого $i \ge 2$. После этого запустим модифицированное Решето Эратосфена.

Если `minPrime[i] == i`, то число $i$ простое: ни один меньший простой делитель не изменил его значение. Теперь пройдём по кратным числа $i$, начиная с $i^2$. Для каждого кратного $j$ запишем `minPrime[j] = i`, но только в том случае, если там всё ещё находится само число $j$.

Почему это работает? Простые числа обрабатываются в порядке возрастания. Следовательно, первый простой делитель, который доберётся до составного числа $j$, и будет его **наименьшим простым делителем**. Все последующие простые уже не должны менять найденное значение.

Что нам даёт массив `minPrime`? Он превращает факторизацию в моментальный процесс! 
Чтобы факторизовать число $x$, мы просто смотрим в `minPrime[x]`. Это гарантированно простое число, на которое $x$ делится. Мы делим $x$ на `minPrime[x]` и повторяем процесс для нового значения $x$, пока оно не превратится в единицу.

Поскольку `minPrime[x]` всегда не меньше двух, после каждого деления число уменьшается как минимум вдвое. Следовательно, количество найденных простых множителей с учётом повторений не превышает $\lfloor \log_2 x \rfloor$.

Таким образом, факторизация одного числа работает за:
$$O(\log x).$$

Сам предподсчёт массива `minPrime` приведённым способом занимает $O(X \log \log X)$ времени и $O(X)$ памяти, зато после него даже огромное количество запросов обрабатывается очень быстро. При этом быстрее количества выведенных множителей программа всё равно работать не сможет: если требуется напечатать всё разложение, время вывода также входит в итоговую сложность.

<details>
<summary><strong>C++: факторизация за логарифм</strong></summary>

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAX_X = 10000000;
int minPrime[MAX_X + 1];
void solve() {
    int x; cin >> x;
    while (x > 1) {
        cout << minPrime[x] << ' ';
        x /= minPrime[x];
    }
    cout << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // Модифицированное Решето Эратосфена
    for (int i = 2; i <= MAX_X; i++) minPrime[i] = i;
    for (int i = 2; i * i <= MAX_X; i++) {
        if (minPrime[i] == i) {
            for (int j = i * i; j <= MAX_X; j += i) {
                if (minPrime[j] == j) minPrime[j] = i;
            }
        }
    }
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

</details>

## 4.3. Итоги четвёртой главы

Мы разобрали два мощных способа ускорить массовую факторизацию. Выбор между ними всегда диктуется одновременно **максимальным значением чисел**, **количеством запросов** и **лимитом памяти**:

1. Если запросов мало, а числа достигают $10^{12}$, обычно достаточно обычной факторизации за $O(\sqrt{x})$. Для одного числа это не более миллиона проверок делимости.

2. Если числа достигают примерно $10^9$ и хранить информацию для каждого из них невозможно, заранее строим список простых до корня. После этого один запрос обрабатывается за $O\left(\frac{\sqrt{x}}{\log x}\right)$ в худшем случае. Такой метод заметно быстрее полного перебора, но при $10^5$ тяжёлых запросов всё ещё может оказаться недостаточно быстрым.

3. Если все числа не превосходят примерно $10^7$ и лимит памяти позволяет создать массив на весь диапазон, строим `minPrime`. Предподсчёт потребует $O(X \log \log X)$ времени и $O(X)$ памяти, зато каждый запрос будет обрабатываться за $O(\log x)$.

Иными словами, универсально лучшего метода не существует. Чем больше памяти мы готовы потратить на предподсчёт, тем быстрее сможем отвечать на последующие запросы.

Но что, если число задано не явно, а в виде факториала? Например, требуется найти степень вхождения двойки в $100!$. Сначала вычислять сам факториал, а затем пытаться его факторизовать совершенно бессмысленно: уже при сравнительно небольших $n$ результат перестаёт помещаться в стандартные целочисленные типы.

К счастью, нужную степень можно вычислить напрямую, даже не зная значения самого факториала. В следующей главе мы выведем формулу Лежандра и научимся решать такие задачи всего за $O(\log_p n)$.

## Глава 5. Степень вхождения простого числа в факториал

В конце прошлой главы мы задались интересным вопросом: что делать, если число задано не явно, а в виде факториала?

Напомним, что факториал числа $n$ обозначается как $n!$ и равен произведению всех натуральных чисел от $1$ до $n$:
$$n! = 1 \cdot 2 \cdot 3 \cdot \ldots \cdot n.$$

Факториалы растут с поразительной скоростью. Например, $20!$ ещё помещается в знаковый 64-битный тип, а вот $21!$ — уже нет. При этом $100!$ состоит из 158 цифр.

Конечно, языки с длинной арифметикой, такие как Python, позволяют хранить и гораздо большие числа. Однако сначала вычислять огромный факториал, а затем пытаться факторизовать его — слишком медленный и совершенно ненужный путь. Как это часто бывает в теории чисел, получить нужную информацию можно, даже не вычисляя само число.

Однако в олимпиадных задачах часто требуется узнать, **сколько раз $n!$ делится на заданное простое число $p$**. Иными словами, мы ищем максимальное целое $k$, для которого $n!$ делится на $p^k$.

Эту величину называют степенью вхождения $p$ в $n!$ и обозначают через $v_p(n!)$. Вычислить её напрямую позволяет элегантная **формула Лежандра**.

## 5.1. Вывод формулы Лежандра

Давайте рассуждать логически. Факториал — это произведение:
$$n! = 1 \cdot 2 \cdot 3 \cdot \ldots \cdot n$$

Каждое число в этом произведении, кратное $p$, добавляет в разложение факториала как минимум один множитель $p$. Сколько таких чисел находится на отрезке от $1$ до $n$? Ровно:
$$\left\lfloor \frac{n}{p} \right\rfloor.$$

Здесь угловые скобки обозначают округление вниз. В программе это обычное целочисленное деление.

Например, если $n = 100$ и $p = 2$, то среди чисел от $1$ до $100$ находится ровно $50$ чётных. Следовательно, на первом шаге мы насчитали $50$ двоек.

Но на этом останавливаться рано. Некоторые числа делятся не только на $p$, но и на $p^2$, а значит, содержат как минимум **два** множителя $p$. Один из них мы уже учли, когда считали все числа, кратные $p$. Поэтому каждое число, кратное $p^2$, должно добавить к ответу ещё один множитель:
$$\left\lfloor \frac{n}{p^2} \right\rfloor.$$

Например, при $p = 2$ числа $4, 8, 12, \ldots$ делятся на $2^2 = 4$, поэтому каждая содержащаяся в них вторая двойка должна быть посчитана отдельно.

По той же причине числа, кратные $p^3$, добавляют ещё по одному множителю $p$ сверх уже учтённых:
$$\left\lfloor \frac{n}{p^3} \right\rfloor.$$

Продолжая рассуждение для следующих степеней $p$, мы приходим к **формуле Лежандра**:
$$v_p(n!) =
\left\lfloor \frac{n}{p} \right\rfloor +
\left\lfloor \frac{n}{p^2} \right\rfloor +
\left\lfloor \frac{n}{p^3} \right\rfloor + \ldots$$

Сумма конечна: как только очередная степень $p^k$ становится больше $n$, все следующие слагаемые обращаются в ноль.

> [!IMPORTANT]
> Формула Лежандра в таком виде применяется именно к **простому** числу $p$. Если вместо простого числа дано составное $m$, подставлять его напрямую в формулу нельзя.
>
> Сначала нужно разложить $m$ на простые множители:
> $$m = p_1^{a_1} \cdot p_2^{a_2} \cdot \ldots \cdot p_k^{a_k}.$$
>
> Затем по формуле Лежандра вычисляются степени всех $p_i$ в $n!$, после чего максимальная степень $m$, делящая $n!$, равна:
> $$\min_{1 \le i \le k}
> \left\lfloor \frac{v_{p_i}(n!)}{a_i} \right\rfloor.$$
>
> Например, чтобы узнать, сколько раз $12 = 2^2 \cdot 3$ входит в $n!$, нужно вычислить $v_2(n!)$ и $v_3(n!)$, а затем взять:
> $$\min\left(\left\lfloor \frac{v_2(n!)}{2} \right\rfloor,\; v_3(n!)\right).$$

## 5.2. Оптимизация вычислений в коде

Самая прямолинейная реализация формулы — последовательно вычислять $p$, $p^2$, $p^3$ и делить $n$ на полученные степени. Однако в олимпиадном программировании такой подход создаёт сразу две лишние проблемы.

Во-первых, очередная степень $p^k$ может переполнить целочисленный тип. Причём переполнение часто происходит именно при попытке вычислить первую степень, которая уже превышает $n$.

Во-вторых, использовать функцию `pow` здесь тоже не стоит: она работает с вещественными числами, поэтому при больших значениях может возникнуть ошибка округления.

К счастью, хранить степени $p$ нам вообще не потребуется. Заметим:
$$\left\lfloor \frac{n}{p^2} \right\rfloor =
\left\lfloor
\frac{\left\lfloor n/p \right\rfloor}{p}
\right\rfloor.$$

Следовательно, вместо увеличения знаменателя можно на каждом шаге **делить само число $n$ на $p$**. После первого деления мы получим $\lfloor n/p \rfloor$, после второго — $\lfloor n/p^2 \rfloor$, после третьего — $\lfloor n/p^3 \rfloor$ и так далее.

В результате алгоритм становится удивительно простым:

1. Делим текущее значение $n$ на $p$.
2. Прибавляем полученное значение к ответу.
3. Повторяем процесс, пока $n$ не превратится в ноль.

На каждом шаге число уменьшается в $p$ раз, поэтому количество итераций равно $O(\log_p n)$. Даже для $n$ порядка $10^{18}$ при $p = 2$ цикл выполнится не более 60 раз, а для больших $p$ — ещё меньше.

<summary><strong>C++: степень вхождения в факториал</strong></summary>

void solve() {

    int64_t answ = 0;
    while (n > 0) {
        n /= p;
        answ += n;
    }
    cout << answ << endl;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}

Давайте проверим вычисления вручную. На каждом шаге используется целочисленное деление:

Следовательно,
$$v_2(100!) = 97.$$

Иными словами, $100!$ делится на $2^{97}$, но уже не делится на $2^{98}$.
</details>

> [!NOTE]
> Классическая задача, которая решается формулой Лежандра: **«Сколькими нулями оканчивается число $n!$?»**
>
> Каждый ноль на конце десятичной записи появляется благодаря одному множителю $10$, а:
> $$10 = 2 \cdot 5.$$
>
> Поэтому количество нулей равно числу пар $(2, 5)$ в разложении факториала:
> $$\min(v_2(n!), v_5(n!)).$$
>
> Однако множителей $2$ в факториале всегда не меньше, чем множителей $5$: числа, кратные двойке, встречаются гораздо чаще. Следовательно:
> $$\min(v_2(n!), v_5(n!)) = v_5(n!).$$
>
> Таким образом, чтобы найти количество нулей в конце $n!$, достаточно применить формулу Лежандра для $p = 5$.
