## A1–A2. Сумма простых чисел

<details><summary><b>Идея</b></summary>

В обеих версиях требуется отвечать на большое количество запросов о сумме простых чисел на отрезке. Проверять каждое число на простоту отдельно для каждого запроса слишком долго: запросов может быть несколько сотен тысяч, а границы отрезков велики.

Основная идея состоит из двух этапов:

1. Один раз определить, какие числа в интересующем диапазоне являются простыми.
2. Построить по найденным простым числам префиксные суммы, после чего отвечать на каждый запрос за $O(1)$.

Однако способ поиска простых чисел различается между версиями.

### Простая версия

Все запросы имеют вид $[2,r]$, причём $r \le 10^6$. Поэтому можно заранее построить обычное решето Эратосфена для всех чисел от $0$ до максимальной возможной границы.

Сначала все числа считаются простыми. Затем для каждого простого $i$ вычёркиваются его кратные, начиная с $i^2$. Начинать раньше не требуется: меньшие кратные уже были вычеркнуты меньшими простыми делителями.

После решета тот же массив превращается в массив префиксных сумм: в позиции $i$ хранится сумма всех простых чисел, не превосходящих $i$.

#### C++

```cpp
    primes.assign(NMAX+1, 1);
    primes[0] = primes[1] = 0;
    for (int i = 2; i * i <= NMAX; i++)
        if (primes[i])
            for (int j = i * i; j <= NMAX; j += i)
                primes[j] = 0;
    // считаем префиксные суммы прямо внутри решета:
    for (int i = 2; i <= NMAX; i++)
        primes[i] = (primes[i] ? i : 0) + primes[i-1];
```

#### Python

```python
    primes = [1] * (NMAX + 1)
    primes[0] = primes[1] = 0
    for i in range(2, int(NMAX ** 0.5) + 1):
        if primes[i]:
            for j in range(i * i, NMAX + 1, i):
                primes[j] = 0
    # считаем префиксные суммы прямо внутри решета:
    for i in range(2, NMAX + 1):
        primes[i] = (i if primes[i] else 0) + primes[i - 1]
```

### Сложная версия

Здесь значения могут достигать $10^{12}$, поэтому создать решето для всех чисел от $1$ до $R$ невозможно. При этом длина общего отрезка $[L,R]$ не превосходит $10^6$. Значит, хранить информацию нужно только для чисел внутри этого короткого отрезка.

Используется решето Эратосфена на отрезке $[L,R]$. Сначала обычным решетом находятся простые числа до величины, превосходящей $\sqrt{10^{12}}=10^6$.

#### C++

```cpp
    vector<bool> isPrime(NMAX+1, 1);
    isPrime[0] = isPrime[1] = 0;
    for (int i = 2; i * i <= NMAX; i++)
        if (isPrime[i])
            for (int j = i * i; j <= NMAX; j += i)
                isPrime[j] = 0;
    // возвращаем результат:
    vector<int> primes;
    for (int i = 2; i <= NMAX; i++)
        if (isPrime[i])
            primes.push_back(i);
```

#### Python

```python
    isPrime = [True] * (NMAX + 1)
    isPrime[0] = isPrime[1] = False
    for i in range(2, int(NMAX ** 0.5) + 1):
        if isPrime[i]:
            for j in range(i * i, NMAX + 1, i):
                isPrime[j] = False
    # возвращаем результат:
    primes = []
    for i in range(2, NMAX + 1):
        if isPrime[i]:
            primes.append(i)
```

После этого создаётся отдельное решето только для $R-L+1$ чисел общего отрезка. Позиция $i$ в нём соответствует числу $L+i$.

Для каждого заранее найденного простого $p$ нужно вычеркнуть его составные кратные внутри $[L,R]$. Первое рассматриваемое кратное определяется так, чтобы одновременно выполнялись два условия:

- оно находится не левее $L$;
- оно не равно самому $p$.

Поэтому множитель начинается с

$\max\left(p,\left\lceil \frac{L}{p}\right\rceil\right)$.

Соответствующее число равно этому множителю, умноженному на $p$. Условие множителя не меньше $p$ означает, что вычёркивание начинается не раньше $p^2$, поэтому само простое число $p$ не будет ошибочно признано составным.

</details>

<details><summary><b>Наблюдения</b></summary>

### Почему достаточно простых чисел до $10^6$

Если число $x \le 10^{12}$ составное, то у него обязательно есть простой делитель, не превосходящий $\sqrt{x}$. Действительно, если представить $x$ как произведение двух нетривиальных множителей, хотя бы один из них не превосходит $\sqrt{x}$ и содержит подходящий простой делитель.

Следовательно, каждое составное число из $[L,R]$ будет вычеркнуто одним из простых чисел до $\sqrt R \le 10^6$. Именно поэтому нет необходимости искать простые делители, превосходящие миллион.

### Почему нужны префиксные суммы

После определения простоты чисел можно каждому числу сопоставить значение:

- само число, если оно простое;
- $0$, если оно составное или равно $0$ либо $1$.

Тогда сумма простых на произвольном отрезке превращается в обычную сумму элементов на отрезке.

В простой версии левая граница всегда равна $2$, поэтому ответ уже находится непосредственно в одной позиции префиксного массива.

В сложной версии для префиксного массива используется стандартное определение: `sums[k]` содержит сумму первых $k$ значений общего отрезка. Число $x$ соответствует индексу $x-L$, поэтому сумма на включительном отрезке $[l,r]$ равна

$S[r+1-L]-S[l-L]$.

</details>

<details><summary><b>Создание и инициализация данных</b></summary>

### Простая версия

Массив `primes` первоначально используется как решето: единица обозначает потенциально простое число, а ноль — составное. Числа $0$ и $1$ сразу отмечаются как непростые.

Тип элементов в реализации на C++ — `int64_t`, поскольку после построения префиксных сумм значения уже не помещаются в обычный 32-битный тип `int`.

#### C++

```cpp
const int NMAX = 1 << 20;
vector<int64_t> primes;
void precalc() {
    // строим решето Эратосфена за O(n log(log(n))):
    primes.assign(NMAX+1, 1);
    primes[0] = primes[1] = 0;
```

#### Python

```python
NMAX = 1 << 20
primes = []
def precalc():
    # строим решето Эратосфена за O(n log(log(n))):
    global primes
    primes = [1] * (NMAX + 1)
    primes[0] = primes[1] = 0
```

### Сложная версия

Для общего отрезка создаётся булев массив длины $R-L+1$. Изначально все его элементы считаются простыми. Затем отдельно исключаются $0$ и $1$, если они попали в рассматриваемый диапазон.

#### C++

```cpp
    // вычеркиваем числа на отрезке [L, R], которые делятся на простые:
    vector<bool> isPrime(R-L+1, 1);
    // вычеркнем 0 и 1:
    if (0 >= L) isPrime[0-L] = 0;
    if (1 >= L) isPrime[1-L] = 0;
```

#### Python

```python
# вычёркиваем числа на отрезке [L, R], которые делятся на простые:
isPrime = [True] * (R - L + 1)
# вычеркнем 0 и 1:
if 0 >= L:
    isPrime[0 - L] = False
if 1 >= L:
    isPrime[1 - L] = False
```

После решета на отрезке $[L, R]$ строится массив префиксных сумм. В него добавляется $L+i$, если соответствующее число простое, и $0$ в противном случае.

#### C++

```cpp
    // строим префиксные суммы:
    vector<ll> sums = {0};
    for (int i = 0; i < isz(isPrime); i++)
        sums.push_back(sums.back() + (isPrime[i] ? L + i : 0));
```

#### Python

```python
# строим префиксные суммы:
sums = [0]
for i in range(len(isPrime)):
    sums.append(sums[-1] + (L + i if isPrime[i] else 0))
```

</details>

<details><summary><b>Основные переходы</b></summary>

В простой версии основное вычёркивание выполняется обычным решетом. Если число $i$ осталось простым, все числа $i^2,i^2+i,i^2+2i,\ldots$ являются составными и отмечаются нулями.

Затем при движении слева направо текущая префиксная сумма получается из предыдущей. Если $i$ простое, к ней добавляется $i$, иначе добавляется $0$.

#### C++

```cpp
    for (int i = 2; i * i <= NMAX; i++)
        if (primes[i])
            for (int j = i * i; j <= NMAX; j += i)
                primes[j] = 0;
    // считаем префиксные суммы прямо внутри решета:
    for (int i = 2; i <= NMAX; i++)
        primes[i] = (primes[i] ? i : 0) + primes[i-1];
```

#### Python

```python
    for i in range(2, int(NMAX ** 0.5) + 1):
        if primes[i]:
            for j in range(i * i, NMAX + 1, i):
                primes[j] = 0
    # считаем префиксные суммы прямо внутри решета:
    for i in range(2, NMAX + 1):
        primes[i] = (i if primes[i] else 0) + primes[i - 1]
```

В сложной версии для каждого простого $p$ вычисляется диапазон множителей. Нижняя граница выбирается как максимум между $p$ и первым множителем, дающим число не меньше $L$. Верхняя граница равна $\lfloor R/p\rfloor$.

Таким образом, перебираются в точности кратные $p$, принадлежащие отрезку $[L,R]$ и не меньшие $p^2$. Каждое такое число отмечается составным в позиции `i * p - L`.

#### C++

```cpp
    for (int p : primes) {
        // очень важно начать вычёркивать с 2 * p, то есть случайно не вычеркнуть само p.
        // оптимально начать p^2 и до конца с шагом p, но можно и с 2 * p:
        const ll low = max<ll>(p, (L + p - 1) / p);
        const ll high = R / p;
        for (ll i = low; i <= high; i++)
            isPrime[i * p - L] = 0;
    }
```

#### Python

```python
for p in primes:
    # очень важно начать вычёркивать с 2 * p, то есть случайно не вычеркнуть само p.
    # оптимально начать с p^2 и до конца с шагом p, но можно и с 2 * p:
    low = max(p, (L + p - 1) // p)
    high = R // p
    for i in range(low, high + 1):
        isPrime[i * p - L] = False
```

</details>

<details><summary><b>Пример</b></summary>

В простой версии для запроса $r=10$ решето оставит простыми числа $2$, $3$, $5$ и $7$. После построения префиксных сумм в позиции $10$ будет записано

$2+3+5+7=17$.

Поэтому ответ можно получить одним обращением к массиву.

В сложной версии рассмотрим общий отрезок $[47,53]$. Для каждого простого делителя сегментированное решето вычеркнет его кратные:

- $48$ делится на $2$;
- $49$ делится на $7$;
- $50$ делится на $2$ и $5$;
- $51$ делится на $3$;
- $52$ делится на $2$.

Числа $47$ и $53$ не будут вычеркнуты, поэтому останутся простыми. Тогда для запроса $[47,49]$ ответ равен $47$, а для запроса $[48,52]$ — $0$.

</details>

<details><summary><b>Ответ</b></summary>

### Простая версия

После предподсчёта `primes[rr]` уже содержит сумму всех простых чисел от $2$ до `rr`, поэтому каждый запрос обрабатывается непосредственным обращением к массиву.

#### C++

```cpp
    // отвечаем на них:
    for (auto rr : r)
        cout << primes[rr] << ' ';
    cout << '\n';
```

#### Python

```python
    # отвечаем на них:
    print(*[primes[rr] for rr in r])
```

### Сложная версия

Для запроса $[l_i,r_i]$ из суммы первых $r_i+1-L$ элементов общего отрезка вычитается сумма первых $l_i-L$ элементов. В результате остаётся сумма значений, соответствующих ровно числам от $l_i$ до $r_i$ включительно.

#### C++

```cpp
    // отвечаем на них:
    for (int i = 0; i < q; i++)
        cout << sums[right[i]+1 - L] - sums[left[i] - L] << ' ';
    cout << '\n';
```

#### Python

```python
# отвечаем на них:
print(*[sums[right[i] + 1 - L] - sums[left[i] - L] for i in range(q)])
```

</details>

<details><summary><b>Корректность</b></summary>

### Простая версия

Докажем, что алгоритм правильно отвечает на каждый запрос.

Сначала рассмотрим решето. Числа $0$ и $1$ сразу отмечаются непростыми. Если число $i$ осталось простым, алгоритм вычёркивает все его кратные начиная с $i^2$, поэтому вычёркиваются только составные числа.

С другой стороны, пусть $x$ — составное число. У него существует простой делитель $p \le \sqrt{x}$. Когда алгоритм обрабатывает $p$, число $x$ является кратным $p$ и не меньше $p^2$, поэтому оно будет вычеркнуто. Значит, после решета отмеченными остаются в точности простые числа.

Далее массив обрабатывается слева направо. После обработки позиции $i$ значение `primes[i]` равно предыдущей префиксной сумме плюс $i$, если $i$ простое, и плюс $0$ иначе. Следовательно, `primes[i]` содержит сумму всех простых чисел от $2$ до $i$.

Таким образом, для запроса с правой границей $r$ значение `primes[r]` является требуемой суммой.

### Сложная версия

Докажем сначала корректность сегментированного решета.

Алгоритм вычёркивает число только тогда, когда оно представлено как $i \cdot p$, где $p$ — простое, а $i \ge p$. Поэтому вычёркиваемое число не меньше $p^2$ и имеет два нетривиальных множителя. Следовательно, ни одно простое число не будет вычеркнуто.

Теперь рассмотрим любое составное число $x$ из $[L,R]$. У него есть простой делитель $p \le \sqrt{x} \le 10^6$. Этот простой присутствует в заранее построенном списке. Число $x$ можно представить как $x=i \cdot p$, причём $i \ge p$, если $p$ выбран как наименьший простой делитель. Кроме того, поскольку $x \in [L,R]$, множитель $i$ попадает между вычисленными границами `low` и `high`. Поэтому $x$ обязательно будет вычеркнуто.

Числа $0$ и $1$ отдельно отмечаются непростыми. Значит, после сегментированного решета `isPrime[i]` истинно тогда и только тогда, когда число $L+i$ простое.

При построении префиксных сумм для каждой позиции добавляется само число $L+i$, если оно простое, и ноль иначе. Поэтому `sums[k]` равна сумме простых среди первых $k$ чисел общего отрезка.

Для запроса $[l,r]$ выражение `sums[r+1-L] - sums[l-L]` удаляет вклад всех чисел, расположенных левее $l$, и оставляет вклад чисел от $l$ до $r$ включительно. Поскольку составные числа имеют нулевой вклад, полученное значение равно сумме всех простых чисел на запрошенном отрезке.

</details>

<details><summary><b>Сложность</b></summary>

### Простая версия

Пусть $N=2^{20}$.

Обычное решето Эратосфена работает за $O(N\log\log N)$, а построение префиксных сумм — за $O(N)$. Каждый из $q$ запросов обрабатывается за $O(1)$.

Итоговая временная сложность составляет $O(N\log\log N+q)$, память — $O(N+q)$.

Поскольку $N$ имеет порядок $10^6$, а $q \le 2\cdot 10^5$, эти оценки соответствуют ограничениям.

### Сложная версия

Обозначим длину общего отрезка через $M=R-L+1$, где $M\le 10^6$, а границу обычного решета — через $N=2^{20}$.

Поиск простых до $N$ занимает $O(N\log\log N)$. Сегментированное решето обрабатывает кратные простых внутри короткого отрезка; его стандартная оценка составляет $O(M\log\log R)$ с дополнительным перебором найденных простых. Построение префиксных сумм занимает $O(M)$, ответы на запросы — $O(q)$.

Итоговая временная сложность составляет $O(N\log\log N+M\log\log R+q)$, память — $O(N+M+q)$.

Значения $N$ и $M$ имеют порядок $10^6$, а $q\le 3\cdot 10^5$, поэтому алгоритм укладывается в заданные ограничения.

</details>

<details><summary><b>Реализация на C++</b></summary>

### A1. Простая версия

#### C++

```cpp
#include <bits/stdc++.h>
using namespace std;
// предподсчёт суммы всех простых Решетом Эратосфена
const int NMAX = 1 << 20;
vector<int64_t> primes;
void precalc() {
    // строим решето Эратосфена за O(n log(log(n))):
    primes.assign(NMAX+1, 1);
    primes[0] = primes[1] = 0;
    for (int i = 2; i * i <= NMAX; i++)
        if (primes[i])
            for (int j = i * i; j <= NMAX; j += i)
                primes[j] = 0;
    // считаем префиксные суммы прямо внутри решета:
    for (int i = 2; i <= NMAX; i++)
        primes[i] = (primes[i] ? i : 0) + primes[i-1];
}
void solve() {
    // читаем запросы:
    int q; cin >> q;
    vector<int> r(q);
    for (auto &it : r) cin >> it;
    // отвечаем на них:
    for (auto rr : r)
        cout << primes[rr] << ' ';
    cout << '\n';
}
main() {
    precalc(); // вызываем предподсчёт один раз
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt = 1; //cin >> tt;
    while (tt --> 0) solve();
}
```

### A2. Сложная версия

#### C++

```cpp
#include <bits/stdc++.h>
#define isz(x) (int)(x).size()
using namespace std;
using ll = long long;
// функция находит список всех простых чисел <= NMAX:
vector<int> findPrimeNumbers(int NMAX) {
    // строим решето Эратосфена за O(n log(log(n))):
    vector<bool> isPrime(NMAX+1, 1);
    isPrime[0] = isPrime[1] = 0;
    for (int i = 2; i * i <= NMAX; i++)
        if (isPrime[i])
            for (int j = i * i; j <= NMAX; j += i)
                isPrime[j] = 0;
    // возвращаем результат:
    vector<int> primes;
    for (int i = 2; i <= NMAX; i++)
        if (isPrime[i])
            primes.push_back(i);
    return primes;
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    // читаем входные данные
    int q; ll L, R;
    cin >> q >> L >> R;
    // находим простые до миллиона:
    auto primes = findPrimeNumbers(1 << 20);
    // вычеркиваем числа на отрезке [L, R], которые делятся на простые:
    vector<bool> isPrime(R-L+1, 1);
    // вычеркнем 0 и 1:
    if (0 >= L) isPrime[0-L] = 0;
    if (1 >= L) isPrime[1-L] = 0;
    // вычеркнем все остальные составные числа на отрезке [L, R]:
    for (int p : primes) {
        // очень важно начать вычёркивать с 2 * p, то есть случайно не вычеркнуть само p.
        // оптимально начать p^2 и до конца с шагом p, но можно и с 2 * p:
        const ll low = max<ll>(p, (L + p - 1) / p);
        const ll high = R / p;
        for (ll i = low; i <= high; i++)
            isPrime[i * p - L] = 0;
    }
    // строим префиксные суммы:
    vector<ll> sums = {0};
    for (int i = 0; i < isz(isPrime); i++)
        sums.push_back(sums.back() + (isPrime[i] ? L + i : 0));
    // читаем запросы:
    vector<ll> left(q), right(q);
    for (auto &it : left) cin >> it;
    for (auto &it : right) cin >> it;
    // отвечаем на них:
    for (int i = 0; i < q; i++)
        cout << sums[right[i]+1 - L] - sums[left[i] - L] << ' ';
    cout << '\n';
}
```

## B1–B2. Битва умов

<details><summary><b>Идея</b></summary>

Сначала переформулируем действия игроков. Для каждого простого числа, которое делит и $n$, и $m$, необходимо полностью удалить из обоих чисел все степени этого простого. При этом простые делители, присутствующие только в одном из чисел, удалять нельзя.

Напрямую строить два разложения на простые множители не требуется. Все общие простые делители двух чисел содержатся в их наибольшем общем делителе:

$g=\gcd(n,m)$.

Более того, множество простых делителей $g$ в точности совпадает с множеством простых чисел, присутствующих в обоих списках игроков. Поэтому задача сводится к следующему:

1. Найти исходный НОД чисел.
2. Удалить из $n$ и $m$ все простые множители, входящие в этот НОД.
3. Сравнить оставшиеся значения.

В простой и сложной версиях используется одно и то же наблюдение, но способы удаления общих простых множителей различаются.

### Простая версия

Поскольку $n,m\le 10^9$, можно разложить $g$ на различные простые множители перебором возможных делителей до $\sqrt g$. После нахождения простого делителя все его вхождения из $g$ удаляются. Благодаря этому каждый общий простой делитель добавляется в список ровно один раз.

#### C++

```cpp
    // находим их НОД: он содержит все общие простые делители
    int g = gcd(n, m);
    // раскладываем их НОД на простые множители:
    vector<int> p;
    for (int i = 2; i * i <= g; i++)
        if (g % i == 0) {
            p.push_back(i);
            do { g /= i; } while (g % i == 0);
        }
    if (g > 1)
        p.push_back(g);
```

#### Python

```python
    # находим их НОД: он содержит все общие простые делители
    g = gcd(n, m)
    # раскладываем их НОД на простые множители:
    p = []
    i = 2
    while i * i <= g:
        if g % i == 0:
            p.append(i)
            while g % i == 0:
                g //= i
        i += 1
    if g > 1:
        p.append(g)
```

После этого каждый найденный простой множитель полностью удаляется из обоих исходных чисел.

### Сложная версия

При ограничении $n,m\le 10^{18}$ перебор делителей до квадратного корня уже слишком медленный. Поэтому в сложной версии факторизация вообще не выполняется.

Зафиксируем исходное значение $g=\gcd(n,m)$. Оно содержит все простые числа, которые по правилам игры необходимо удалить.

Рассмотрим $\gcd(n,g)$. В него входят те множители из $g$, которые всё ещё присутствуют в текущем $n$. Если этот НОД больше единицы, на него можно разделить $n$, удалив сразу несколько степеней общих простых делителей. После деления вычислим НОД ещё раз. Процесс продолжается, пока он не станет равен единице.

Аналогично обрабатывается $m$. Важно, что значение $g$ остаётся исходным: оно задаёт множество простых делителей, которые разрешено удалять.

#### C++

```cpp
    // находим их НОД: он содержит все общие простые делители
    ll g = gcd(n, m);
    // рассмотрим НОД как пересечение множества делителей. сокращаем наши числа так:
    // пока пересечение простых делителей не пусто, делим на это пересечение
    // таким образом, факторизация здесь не нужна
    for (ll common; (common = gcd(n, g)) > 1; n /= common);
    for (ll common; (common = gcd(m, g)) > 1; m /= common);
```

#### Python

```python
    # находим их НОД: он содержит все общие простые делители

    # рассмотрим НОД как пересечение множества делителей. Сокращаем наши числа так:
    # пока пересечение простых делителей не пусто, делим на это пересечение
    # таким образом, факторизация здесь не нужна
    while True:
        common = gcd(n, g)
        if common <= 1:
            break
        n //= common
    while True:
        common = gcd(m, g)
        if common <= 1:
            break
        m //= common
```

<details><summary><b>Наблюдения</b></summary>

### Общие простые делители находятся в НОД

Пусть простое число $p$ присутствует в обоих списках. Тогда $p$ делит как $n$, так и $m$, а значит, делит и $\gcd(n,m)$.

Обратно, если простое число $p$ делит $\gcd(n,m)$, то оно делит оба исходных числа. Следовательно, оно присутствует в обоих списках.

Таким образом, простые делители исходного НОД — это в точности те простые числа, по которым должны выполняться деления.

### Степени простых множителей могут различаться

Недостаточно один раз разделить оба числа на их НОД. Например, для $n=12$ и $m=18$ имеем $\gcd(12,18)=6$. После одного деления получились бы $2$ и $3$, хотя по правилам необходимо удалить все степени общих простых чисел $2$ и $3$. Правильный результат — $1$ и $1$.

Именно поэтому в простой версии каждый найденный простой делитель удаляется в цикле, а в сложной версии НОД с фиксированным $g$ вычисляется повторно.

### Почему повторные НОД заменяют факторизацию

Пусть некоторый простой делитель $p$ входит в исходный $g$ и всё ещё делит текущее число $n$. Тогда $p$ делит $\gcd(n,g)$, поэтому очередная итерация обязательно удалит хотя бы один множитель $p$.

Если же простой делитель не входит в $g$, он не может входить и в $\gcd(n,g)$. Следовательно, такой множитель никогда не будет удалён. Это в точности соответствует правилам игры.

</details>

<details><summary><b>Удаление общих простых множителей</b></summary>

### Простая версия

После факторизации НОД список `p` содержит все различные общие простые делители. Для каждого из них выполняется деление $n$ и $m$ до тех пор, пока соответствующее число продолжает делиться на этот простой множитель.

```cpp
    }
```

Цикл завершается, когда НОД становится равен единице. В этот момент в числе уже не осталось ни одного простого делителя исходного $g$.

<details><summary><b>Пример</b></summary>

Рассмотрим числа $n=20$ и $m=18$.

Их разложения имеют вид:

- $20=2^2\cdot 5$;
- $18=2\cdot 3^2$.

Единственный общий простой делитель — $2$. Это также единственный простой делитель числа

$\gcd(20,18)=2$.

По правилам игры все степени двойки удаляются из обоих чисел:

- из $20$ удаляется $2^2$, поэтому остаётся $5$;
- из $18$ удаляется $2$, поэтому остаётся $9$.

Так как $5<9$, побеждает Миша.

Теперь рассмотрим $n=12$ и $m=18$. Исходный НОД равен $6$, его простые делители — $2$ и $3$. После полного удаления обоих простых множителей из каждого числа получаются $1$ и $1$, поэтому побеждает дружба.

В сложной версии тот же результат получается без факторизации. Для $n=12$ и $g=6$ сначала вычисляется $\gcd(12,6)=6$, после чего $n$ становится равным $2$. Затем $\gcd(2,6)=2$, и после деления остаётся $1$. Следующий НОД равен единице, поэтому обработка заканчивается.

</details>

<details><summary><b>Корректность</b></summary>

Докажем корректность алгоритмов обеих версий.

### Общая лемма о НОД

Обозначим исходные числа через $n_0$ и $m_0$, а их НОД — через $g$.

Простое число $p$ является общим простым делителем $n_0$ и $m_0$ тогда и только тогда, когда $p$ делит $g$.

Действительно, если $p$ делит оба числа, то он входит в их НОД. Если же $p$ делит НОД, он по определению делит оба исходных числа.

Следовательно, множество простых делителей $g$ в точности совпадает с множеством простых чисел, по которым игроки должны выполнять деления.

### Корректность простой версии

Факторизация перебирает возможные делители $i$. Если $i$ делит текущее значение $g$, то он добавляется в список, после чего все его степени удаляются из $g$. Поэтому один и тот же простой множитель не добавляется несколько раз.

После завершения перебора, если оставшееся значение $g$ больше единицы, оно само является простым и также добавляется в список. Таким образом, список `p` содержит все различные простые делители исходного НОД и не содержит никаких других чисел.

Для каждого $p$ из списка алгоритм делит $n$ и $m$ на $p$, пока это возможно. Значит, из обоих чисел полностью удаляется степень каждого общего простого делителя.

При этом ни один простой множитель, отсутствующий в исходном НОД, не обрабатывается. Поэтому простые делители, принадлежащие только одному из исходных чисел, сохраняются.

Следовательно, после циклов переменные `n` и `m` совпадают с числами, которые останутся у игроков после всех действий по условию.

### Корректность сложной версии

Рассмотрим обработку числа $n$. Значение $g$ остаётся равным исходному НОД.

На каждой итерации вычисляется `common = gcd(n, g)`. Все простые делители `common` входят в $g$, следовательно, они являются общими простыми делителями исходных чисел. Поэтому деление $n$ на `common` удаляет только те множители, которые разрешено удалять по условию.

Теперь докажем, что будут удалены все необходимые множители. Предположим, что после завершения цикла в $n$ остался некоторый простой делитель $p$, входящий в $g$. Тогда $p$ делит и $n$, и $g$, поэтому $\gcd(n,g)\ge p>1$. Но цикл завершается только при $\gcd(n,g)=1$. Получили противоречие.

Значит, после завершения цикла из $n$ удалены все степени всех простых делителей $g$ и не удалены никакие другие простые множители. Аналогичное доказательство верно для $m$.

Таким образом, в обеих версиях итоговые значения `n` и `m` в точности соответствуют результату описанных в условии делений. Их непосредственное сравнение правильно определяет победителя, а при равенстве правильно выводится `Friendship`.

</details>

<details><summary><b>Сложность</b></summary>

### Простая версия

Пусть $g=\gcd(n,m)$. Перебор возможных делителей при факторизации занимает $O(\sqrt g)$ времени в худшем случае.

Каждое деление уменьшает соответствующее число как минимум в два раза, поэтому суммарное количество делений при удалении множителей составляет $O(\log n+\log m)$.

Итоговая временная сложность одного набора данных:

$O(\sqrt g+\log n+\log m)$.

При $n,m\le 10^9$ и $t\le 100$ это соответствует ограничениям.

Список различных простых делителей содержит $O(\log g)$ элементов, поэтому дополнительная память составляет $O(\log g)$.

### Сложная версия

Алгоритм Евклида вычисляет НОД за $O(\log \max(n,m))$.

Каждая успешная итерация делит текущее число как минимум на $2$, поэтому для одного числа выполняется не более $O(\log n)$ итераций. На каждой итерации вычисляется НОД за логарифмическое время.

Временная сложность одного набора данных составляет

$O(\log^2\max(n,m))$.

Дополнительная память равна $O(1)$.

При $n,m\le 10^{18}$ количество итераций невелико, поэтому алгоритм подходит для $t\le 10000$.

</details>

## C1. Стек на количество делителей (простая версия)

<details><summary><b>Идея</b></summary>

Текущее число может очень быстро стать огромным, поэтому хранить его значение и после каждого запроса напрямую находить все делители невозможно. Вместо самого числа достаточно поддерживать его разложение на простые множители.

Поскольку каждое добавляемое число $p$ гарантированно простое, текущий результат можно представить в виде

$N = \prod p^{e_p}$,

где $e_p$ — количество ещё не отменённых умножений на простое число $p$.

Для числа с таким разложением количество положительных делителей равно

$D(N) = \prod (e_p + 1)$.

Действительно, в делитель можно независимо включить каждое простое $p$ в степени от $0$ до $e_p$, то есть выбрать один из $e_p+1$ вариантов.

Таким образом, хранить текущее число не требуется. Достаточно знать:

- сколько раз встречается каждое простое число;
- текущее произведение $\prod(e_p+1)$;
- порядок активных операций умножения, чтобы запрос `-` мог отменить последнюю из них.

Последнее требование в точности соответствует стеку: операция `+ p` кладёт $p$ на вершину, а операция `-` извлекает последний добавленный простой множитель.

Ответ требуется вычислять по модулю простого числа $998244353$. При изменении одной степени изменяется только один множитель формулы количества делителей, поэтому всё произведение можно обновлять делением на старый множитель и умножением на новый.

Для модульного деления решения используют обратный элемент. Поскольку все множители имеют вид $e_p+1$ и не превосходят $q+1<998244353$, они не равны нулю по модулю и обратный элемент всегда существует.

#### C++

```cpp
// операции по простому модулю:
const int mod = 998244353;
// умножение:
int mulmod(int a, int b) { 
    return int(a * 1LL * b % mod);
}
// возведение в степень:
int binpow(int a, int64_t n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
// обратный:
int invmod(int b) {
    return binpow(b, mod-2);
}
// деление:
int divmod(int a, int b) {
    return mulmod(a, invmod(b));
}
```

<details><summary><b>Переходы</b></summary>

Рассмотрим запрос `+ p`. Пусть до него простое число $p$ имело степень `prev`. Тогда его вклад в количество делителей был равен `prev + 1`.

После умножения степень увеличивается на единицу, поэтому новый вклад равен `prev + 2`. Все остальные простые множители остаются без изменений. Значит, новый ответ получается так:

$answ \leftarrow answ \div (prev+1) \cdot (prev+2)$.

Кроме того, число $p$ помещается в стек, чтобы это умножение можно было отменить в будущем.

#### C++

```cpp
            answ = divmod(answ, prev+1); // делим на то, что было
            answ = mulmod(answ, prev+2); // умножаем на то, что стало
```

Пусть до отмены его степень была равна `prev`. Его старый вклад в количество делителей равен `prev + 1`. После уменьшения степени на единицу новый вклад становится равен `prev`. Следовательно,

$answ \leftarrow answ \div (prev+1) \cdot prev$.

Если `prev` был равен единице, после отмены степень становится нулевой, а новый множитель формулы количества делителей равен единице, что также правильно обрабатывается этой формулой.

<details><summary><b>Пример</b></summary>

Рассмотрим первые четыре запроса из примера.

После запроса `+ 2` имеем число $2^1$. Количество делителей равно $1+1=2$.

После второго запроса `+ 2` степень двойки увеличивается с $1$ до $2$. Её вклад меняется с $2$ на $3$, поэтому количество делителей становится $3$.

После запроса `+ 3` разложение имеет вид $2^2\cdot3^1$. Количество делителей равно

$(2+1)(1+1)=3\cdot2=6$.

Затем запрос `-` отменяет именно последнее умножение, то есть умножение на $3$. Степень тройки уменьшается с $1$ до $0$, её вклад меняется с $2$ на $1$, и ответ снова становится равен $3$.

Важно, что запрос отмены не выбирает произвольный простой множитель. Он всегда удаляет последнее активное умножение, поэтому для его обработки естественно используется стек.

<details><summary><b>Корректность</b></summary>

Докажем, что после каждого запроса алгоритм выводит правильное количество положительных делителей текущего числа.

Будем поддерживать следующий инвариант:

1. `cnt[p]` равен числу ещё не отменённых умножений на простое число $p$, то есть степени $p$ в разложении текущего числа.
2. Стек `st` содержит все ещё не отменённые умножения в порядке их выполнения.
3. `answ` равен $\prod_p(cnt[p]+1)$ по модулю $998244353$.

Изначально текущее число равно $1$. Активных умножений нет, поэтому стек пуст и все степени равны нулю. У числа $1$ ровно один положительный делитель, а `answ` инициализирован единицей. Следовательно, инвариант выполнен до обработки запросов.

Рассмотрим запрос `+ p`. Алгоритм добавляет $p$ в стек и увеличивает `cnt[p]` на единицу. Поэтому первые два пункта инварианта сохраняются. Если старая степень была равна `prev`, старый множитель в формуле количества делителей был равен `prev + 1`, а новый равен `prev + 2`. Алгоритм делит `answ` на старый множитель и умножает на новый, не изменяя вклады остальных простых чисел. Значит, третий пункт также сохраняется.

Рассмотрим запрос `-`. По условию нужно отменить последнее ещё не отменённое умножение. Оно находится на вершине стека, поэтому алгоритм извлекает именно нужное простое число $p$. Затем `cnt[p]` уменьшается на единицу, следовательно, первые два пункта инварианта сохраняются. Если старая степень равнялась `prev`, вклад числа $p$ меняется с `prev + 1` на `prev`. Именно такую замену выполняет алгоритм в `answ`, поэтому третий пункт тоже остаётся верным.

Таким образом, по индукции инвариант выполняется после каждого запроса. По формуле количества делителей значение $\prod_p(cnt[p]+1)$ является количеством положительных делителей текущего числа. Следовательно, каждое выведенное значение `answ` корректно.

</details>

<details><summary><b>Сложность</b></summary>

В реализации на C++ степени простых чисел хранятся в `map`, поэтому обращение к `cnt[p]` занимает $O(\log q)$. Одно модульное деление использует бинарное возведение в степень и работает за $O(\log mod)$. Таким образом, обработка одного запроса занимает $O(\log q+\log mod)$, а одного набора запросов — $O(q(\log q+\log mod))$.

В реализации на Python словарь обеспечивает ожидаемое время $O(1)$ для обращения к степени простого числа, а вычисление обратного элемента занимает $O(\log mod)$. Ожидаемое время обработки набора равно $O(q\log mod)$.

Стек и таблица степеней содержат не более $q$ элементов, поэтому обе реализации используют $O(q)$ дополнительной памяти.

Суммарное количество запросов по всем наборам не превосходит $300000$.

</details>

## C2. Стек на количество делителей (сложная версия)

<details><summary><b>Идея</b></summary>

Текущее число после нескольких умножений может быть слишком большим, поэтому хранить его явно и находить его делители напрямую невозможно. Однако само значение числа нам и не требуется: количество делителей полностью определяется его разложением на простые множители.

Пусть текущее число имеет вид

$N=\prod p^{e_p}$,

где $e_p$ — степень простого числа $p$. Тогда количество его положительных делителей равно

$D(N)=\prod(e_p+1)$.

Действительно, для каждого простого $p$ в делитель можно независимо включить любую степень от $0$ до $e_p$, то есть существует $e_p+1$ вариантов.

В простой версии каждый запрос добавлял ровно один простой множитель. Теперь число $x$ может быть составным. Если

$x=p_1^{k_1}p_2^{k_2}\ldots p_m^{k_m}$,

то после умножения на $x$ степень каждого $p_i$ увеличивается на $k_i$. Следовательно, сначала необходимо быстро факторизовать каждое добавляемое число.

Поскольку все значения $x$ не превосходят $10^7$, можно заранее построить решето минимальных простых делителей. После этого факторизация выполняется последовательным делением числа на найденные простые множители.

В реализации на C++ массив `minDiv` хранит минимальный простой делитель для каждого числа. Сначала решето отмечает составные числа, а затем для каждого простого числа в массив записывается оно само.

#### C++

```cpp
// предподсчёт минимальных простых делителей:
const int NMAX = 1024 * 10000;
int minDiv[NMAX+1];
void precalc() {
    // сначала запускаем решето, чтобы отметить все составные числа:
    for (int i = 2; i * i <= NMAX; i++)
        if (!minDiv[i])
            for (int j = i * i; j <= NMAX; j += i)
                if (!minDiv[j])
                    minDiv[j] = i;
    // теперь отметим все простые числа - они делятся сами на себя:
    for (int i = 2; i <= NMAX; i++)
        if (!minDiv[i]) minDiv[i] = i;
}
```

В реализации на Python решето организовано иначе с учётом требований по времени и памяти PyPy3-64. Чётные числа не хранятся в массиве: минимальные делители запоминаются только для нечётных чисел. Индексом нечётного числа $x$ служит `x // 2`. Кроме того, нулевое значение оставляется у простых чисел, поэтому отдельный проход для их заполнения не нужен.

#### Python

```python
# предподсчёт минимальных простых делителей:
NMAX = 10 ** 7
minDiv = [0] * (NMAX // 2 + 1)
def precalc():
    # отдельно храним минимальные делители только нечётных чисел:
    i = 3
    while i * i <= NMAX:
        if not minDiv[i // 2]:
            for j in range(i * i, NMAX + 1, 2 * i):
                if not minDiv[j // 2]:
                    minDiv[j // 2] = i
        i += 2
```

После факторизации изменяются только степени простых чисел, входящих в $x$. Пусть степень некоторого простого $p$ до запроса была равна `prev`, а в разложении $x$ оно встречается $k$ раз. Тогда вклад этого простого в количество делителей изменяется:

- старый вклад равен `prev + 1`;
- новый вклад равен `prev + k + 1`.

Поэтому весь ответ можно обновить, разделив его на старый вклад и умножив на новый:

$answ\leftarrow answ\div(prev+1)\cdot(prev+k+1)$.

Все действия выполняются по модулю $998244353$. Для деления используется обратный элемент. В C++ он вычисляется бинарным возведением в степень по малой теореме Ферма, а в Python уже найденные обратные элементы дополнительно кэшируются.

#### C++

```cpp
// операции по простому модулю:
const int mod = 998244353;
// умножение:
int mulmod(int a, int b) { 
    return int(a * 1LL * b % mod);
}
// возведение в степень:
int binpow(int a, int64_t n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
// обратный:
int invmod(int b) {
    return binpow(b, mod-2);
}
// деление:
int divmod(int a, int b) {
    return mulmod(a, invmod(b));
}
```

#### Python

```python
# операции по простому модулю:

invs = {1: 1}

def mulmod(a, b):
    return a * b % mod
# обратный:
def invmod(b):

    if result is None:
        result = pow(b, -1, mod)
        invs[b] = result
    return result
# деление:

```

<details><summary><b>Факторизация чисел</b></summary>

В C++ факторизация выполняется непосредственно при обработке запроса. Пока $x>1$, из решета берётся его минимальный простой делитель, после чего $x$ делится на него. Если один простой множитель входит в число несколько раз, он будет извлечён соответствующее количество раз.

Например, для $x=12$ последовательность извлечённых множителей будет равна $2,2,3$. Каждое извлечение увеличивает соответствующую степень на единицу.

#### C++

```cpp
            while (x > 1) {
                // извлекаем минимальный простой делитель и сокращаем на него:
                int p = minDiv[x];
                x /= p;
                // обновляем степень этого делителя:
                int prev = cnt[p]++;
                answ = divmod(answ, prev+1); // делим на то, что было
                answ = mulmod(answ, prev+2); // умножаем на то, что стало
            }
```

В Python одинаковые простые множители объединяются в группы. Функция `factor(x)` возвращает пары `(p, k)`, где $k$ — степень простого $p$ в разложении $x$.

Делитель $2$ извлекается отдельно, поскольку решето хранит сведения только о нечётных числах. Затем обрабатывается оставшаяся нечётная часть. Если для неё в решете записан ноль, текущее число является простым и становится последним множителем факторизации.

#### Python

```python
def factor(x):
    result = []
    # отдельно извлекаем простой делитель 2:
    k = 0
    while x % 2 == 0:
        x //= 2
        k += 1
    if k:
        result.append((2, k))
    # извлекаем остальные простые делители:
    while x > 1:
        p = minDiv[x // 2]
        if not p:
            result.append((x, 1))
            break
        k = 0
        while x % p == 0:
            x //= p
            k += 1
        result.append((p, k))
    return result
```

Так, для $12=2^2\cdot3$ функция вернёт пары `(2, 2)` и `(3, 1)`. Благодаря группировке вклад каждого различного простого числа в ответ изменяется только один раз.

- стек активных операций умножения.

Изначально текущее число равно $1$. Оно не содержит простых множителей и имеет ровно один положительный делитель. Поэтому таблица степеней и стек пусты, а ответ равен единице.

Содержимое стека в реализациях различается.

В C++ в стек помещается исходное число $x$. При отмене оно снова факторизуется с помощью того же решета, после чего внесённые им изменения выполняются в обратную сторону.

В Python факторизация числа сохраняется сразу вместе со значением ответа до умножения. Поэтому при отмене не требуется повторно факторизовать число или выполнять модульное деление: достаточно восстановить старый ответ и уменьшить степени простых множителей.

Оба варианта стека соответствуют условию, поскольку запрос `-` всегда отменяет последнее ещё не отменённое умножение.

<details><summary><b>Переходы</b></summary>

При запросе `+ x` нужно разложить $x$ на простые множители и увеличить их степени в текущем числе.

В C++ исходное значение $x$ сначала помещается в стек. Затем простые множители извлекаются по одному. Если до очередного извлечения степень $p$ была равна `prev`, после него она становится равна `prev + 1`. Поэтому множитель `prev + 1` в формуле количества делителей заменяется на `prev + 2`.

#### C++

```cpp

            int x; cin >> x;

                int prev = cnt[p]++;
                answ = divmod(answ, prev+1); // делим на то, что было
                answ = mulmod(answ, prev+2); // умножаем на то, что стало
            }
```

В Python сначала вычисляется сгруппированная факторизация. В стек сохраняются ответ до умножения и полученный список пар `(p, k)`. Для каждой пары степень простого числа увеличивается сразу на $k$, поэтому старый вклад `prev + 1` заменяется на `prev + k + 1`.

#### Python

```python
        if t == '+':
            # умножение на новое число: обновляем все простые, которые в него входят
            x = int(s[1])
            primeDivisors = factor(x)

                prev = cnt.get(p, 0)
                cnt[p] = prev + k
                answ = divmod(answ, prev + 1) # делим на то, что было
                answ = mulmod(answ, prev + k + 1) # умножаем на то, что стало
```

Теперь рассмотрим отмену.

В C++ со стека извлекается последнее добавленное число $x$. Оно снова раскладывается на простые множители. При удалении одного множителя $p$ его степень уменьшается с `prev` до `prev - 1`, поэтому вклад в количество делителей меняется с `prev + 1` на `prev`.

#### C++

```cpp
        } else {
            // отмена операции: делаем то же самое, но в обратном порядке
            int x = st.top();
            st.pop();

                // извлекаем минимальный простой делитель и сокращаем на него:

                x /= p;

```

В Python стек уже содержит ответ, который был перед отменяемым умножением. Поэтому этот ответ восстанавливается напрямую. После этого остаётся уменьшить степени всех простых чисел из сохранённой факторизации, чтобы таблица `cnt` снова соответствовала текущему произведению.

#### Python

```python

            for p, k in primeDivisors:
                cnt[p] -= k
```

<details><summary><b>Корректность</b></summary>

Докажем, что после каждого запроса алгоритм выводит количество положительных делителей текущего числа.

Будем поддерживать следующие утверждения:

1. Для каждого простого числа $p$ значение `cnt[p]` равно степени $p$ в разложении текущего числа.
2. Стек содержит данные обо всех ещё не отменённых умножениях в порядке их выполнения.
3. Значение `answ` равно $\prod_p(cnt[p]+1)$ по модулю $998244353$.

Изначально текущее число равно $1$. Его разложение не содержит простых множителей, стек пуст, а количество делителей равно единице. Следовательно, все утверждения выполняются до первого запроса.

Рассмотрим запрос `+ x`. Решето минимальных простых делителей позволяет полностью разложить $x$ на простые множители. Поэтому каждый показатель из разложения $x$ прибавляется к степени соответствующего простого числа в `cnt`.

В C++ одинаковый простой множитель обрабатывается по одному вхождению. Если его текущая степень равна `prev`, после одного такого шага она становится равна `prev + 1`. Старый вклад в формулу количества делителей равен `prev + 1`, а новый — `prev + 2`. Алгоритм заменяет ровно эти множители.

В Python все $k$ одинаковых вхождений обрабатываются одной группой. Степень изменяется с `prev` на `prev + k`, поэтому старый вклад `prev + 1` заменяется на `prev + k + 1`. Это даёт тот же результат, что и последовательная обработка каждого вхождения.

Все остальные степени остаются неизменными. Значит, после запроса `+ x` таблица степеней соответствует новому числу, а `answ` соответствует формуле количества его делителей. Информация о запросе помещается на вершину стека, поэтому первые два утверждения также сохраняются.

Теперь рассмотрим запрос `-`. По условию требуется отменить последнее ещё не отменённое умножение. Благодаря порядку элементов в стеке обе реализации извлекают данные именно об этой операции.

В C++ сохранённое число снова полностью факторизуется. Для каждого его простого множителя степень уменьшается на единицу. Если старая степень равна `prev`, её вклад меняется с `prev + 1` на `prev`, и алгоритм выполняет именно такую замену в `answ`. После обработки всех множителей удаляется полный вклад отменяемого числа.

В Python вместе с факторизацией был сохранён ответ до умножения. Поэтому извлечённое значение `answ` сразу равно количеству делителей числа, существовавшего перед отменяемым запросом. Степени каждого простого множителя уменьшаются на сохранённое значение $k$, после чего `cnt` также возвращается к прежнему состоянию.

Таким образом, после отмены все три утверждения продолжают выполняться.

По индукции после каждого запроса

$answ=\prod_p(cnt[p]+1)$.

По формуле количества делителей это значение является количеством положительных делителей текущего числа. Следовательно, алгоритм всегда выводит правильный ответ.

</details>

<details><summary><b>Сложность</b></summary>

Обозначим через $N$ границу решета, а через $\Omega(x)$ — количество простых множителей числа $x$ с учётом повторений. Также обозначим через $\omega(x)$ количество различных простых множителей.

Предподсчёт минимальных простых делителей работает за $O(N\log\log N)$.

В реализации на C++ каждое добавляемое число факторизуется за $O(\Omega(x))$. При отмене оно факторизуется ещё раз. Для каждого извлечённого множителя выполняется обращение к `map` за $O(\log q)$ и модульное деление за $O(\log mod)$. Поэтому суммарное время обработки запросов имеет оценку

$O\left(\sum\Omega(x)(\log q+\log mod)\right)$,

не считая предподсчёта решета.

Массив решета C++ занимает $O(N)$ памяти, а стек и таблица степеней — $O(q)$.

В Python факторизация одного добавляемого числа занимает $O(\Omega(x))$, но обновление ответа выполняется только для $\omega(x)$ групп различных простых множителей. При отмене сохранённый ответ восстанавливается без модульных делений и повторной факторизации. Обратные элементы кэшируются, поэтому бинарное возведение в степень выполняется только при первом запросе конкретного знаменателя.

Если $U$ — количество различных значений, для которых потребовался обратный элемент, суммарное ожидаемое время обработки запросов равно

$O\left(\sum\Omega(x)+\sum\omega(x)+U\log mod\right)$.

Ожидаемая оценка связана с использованием словаря.

Python хранит минимальные делители только нечётных чисел, поэтому длина массива решета равна примерно $N/2$. Дополнительно используются стек с сохранёнными факторизациями, словарь степеней и кэш обратных элементов. Общая асимптотическая память равна $O(N+q)$, так как при ограничении $x\leq10^7$ число различных простых множителей одного запроса ограничено константой.

Указанные для реализации на PyPy3-64 значения составляют 1296 мс и 135288 КБ, что укладывается в ограничения 2 секунды и 256 мегабайт. Сумма значений $q$ по всем наборам не превосходит $300000$.

</details>

<details><summary><b>Реализация на C++</b></summary>

#### C++

```cpp

using namespace std;
// операции по простому модулю:
const int mod = 998244353;
// умножение:
int mulmod(int a, int b) { 
    return int(a * 1LL * b % mod);
}
// возведение в степень:
int binpow(int a, int64_t n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = int(r * 1LL * a % mod);
        a = int(a * 1LL * a % mod);
        n >>= 1;
    }
    return r;
}
// обратный:
int invmod(int b) {
    return binpow(b, mod-2);
}
// деление:
int divmod(int a, int b) {
    return mulmod(a, invmod(b));
}
// предподсчёт минимальных простых делителей:
const int NMAX = 1024 * 10000;
int minDiv[NMAX+1];
void precalc() {
    // сначала запускаем решето, чтобы отметить все составные числа:
    for (int i = 2; i * i <= NMAX; i++)
        if (!minDiv[i])
            for (int j = i * i; j <= NMAX; j += i)
                if (!minDiv[j])
                    minDiv[j] = i;
    // теперь отметим все простые числа - они делятся сами на себя:
    for (int i = 2; i <= NMAX; i++)
        if (!minDiv[i]) minDiv[i] = i;
}
// решение задачи:
void solve() {
    int q; cin >> q;
    stack<int> st; // стек запросов в порядке обработки
    map<int, int> cnt; // количество каждого простого числа
    int answ = 1; // текущее количество делителей
    while (q --> 0) {
        char t; cin >> t;
        if (t == '+') {
            // умножение на новое число: обновляем все простые, которые в него входят
            int x; cin >> x;
            st.push(x); // закидываем число x в стек
            while (x > 1) {
                // извлекаем минимальный простой делитель и сокращаем на него:
                int p = minDiv[x];
                x /= p;
                // обновляем степень этого делителя:
                int prev = cnt[p]++;
                answ = divmod(answ, prev+1); // делим на то, что было
                answ = mulmod(answ, prev+2); // умножаем на то, что стало
            }
        } else {
            // отмена операции: делаем то же самое, но в обратном порядке
            int x = st.top();
            st.pop();
            while (x > 1) {
                // извлекаем минимальный простой делитель и сокращаем на него:
                int p = minDiv[x];
                x /= p;
                // обновляем степень этого делителя:
                int prev = cnt[p]--;
                answ = divmod(answ, prev+1); // делим на то, что было
                answ = mulmod(answ, prev);   // умножаем на то, что стало
            }
        }
        // выводим ответ:
        cout << answ << ' ';
    }
    cout << '\n';
}
main() {

    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

## D. Наибольший НОД

<details><summary><b>Идея</b></summary>

Нужно выбрать два элемента с различными индексами и максимизировать их НОД. Прямой подход — перебрать все пары и вычислить НОД каждой — требует $O(n^2\log A)$ времени. При $n$ до $100000$ пар может быть около $5\cdot10^9$, поэтому такой перебор не укладывается в ограничения.

Посмотрим на задачу с другой стороны. Число $d$ является НОД некоторой пары только в том случае, если оно делит оба элемента этой пары. Значит, вместо перебора пар можно для каждого возможного делителя посчитать, сколько элементов массива на него делятся.

Если некоторый делитель $d$ встречается хотя бы у двух элементов, то можно выбрать эти два элемента, и их НОД будет кратен $d$, а значит, не меньше $d$. Поэтому ответом является максимальный делитель, который встречается хотя бы у двух элементов массива.

Иначе говоря, нужно найти максимальное $d$, для которого выполняется

$|\{i:d\mid a_i\}|\geq2$.

Значения элементов достигают $10^9$, поэтому завести массив счётчиков для всех возможных делителей нельзя. Вместо этого для каждого элемента массива генерируются только его собственные делители, а их количества хранятся в хеш-таблице.

Чтобы получить все делители числа, сначала раскладываем его на простые множители. Для быстрой факторизации заранее находятся все простые числа до $\sqrt{10^9}$. Если после перебора этих простых остался множитель больше единицы, он сам является простым.

#### C++

```cpp
// предподсчёт всех простых чисел до корня из 10^9:
const int NMAX = (int)sqrt(1e9+100);
vector<int> primes;
void precalc() {
    // для разнообразия найдём все простые числа без решета Эратосфена: при проверке
    // очередного числа проверяем делится ли оно на уже найденные. Если не делится -> простое
    primes = {2,3,5,7};
    for (int x = 8; x <= NMAX; x++) {
        bool isPrime = true;
        for (int p : primes) {
            if (p * p > x) break;
            if (x % p == 0) {
                isPrime = false;
                break;
            }
        }
        if (isPrime) primes.push_back(x);
    }
}
```

<details><summary><b>Факторизация числа</b></summary>

Чтобы восстановить все делители числа, удобно сначала представить его в виде

$x=p_1^{k_1}p_2^{k_2}\ldots p_m^{k_m}$.

Достаточно перебирать заранее найденные простые числа, пока $p^2\leq x$. Если очередное простое $p$ делит текущее значение $x$, число делится на $p$ до тех пор, пока это возможно. Количество таких делений и есть степень $p$ в факторизации.

Условие продолжения проверяется для текущего, уже уменьшенного значения $x$. Если после перебора осталось $x>1$, этот остаток является простым. Действительно, если бы у него было хотя бы два нетривиальных множителя, меньший из них не превосходил бы квадратного корня и был бы найден раньше.

#### C++

```cpp
// функция для факторизации заданного числа: находит список простых делителей числа
auto factor(int x) {
    vector<pair<int,int>> result; // пары (простое, его степень)
    for (int p : primes) {
        if (p * p > x) break; // факторизуем до корня. после корня делаем break
        if (x % p == 0) {
            result.push_back({p, 0});
            // делим пока делится
            do {
                x /= p;
                result.back().second++;
            } while (x % p == 0);
        }
    }
    // могло остаться простое больше корня:
    if (x > 1) result.push_back({x, 1});
    return result;
}
```

#### Python

```python

    # могло остаться простое больше корня:

    return result
```

<details><summary><b>Получение всех делителей</b></summary>

Пусть факторизация числа уже известна:

$x=p_1^{k_1}p_2^{k_2}\ldots p_m^{k_m}$.

Любой делитель $x$ имеет вид

$d=p_1^{e_1}p_2^{e_2}\ldots p_m^{e_m}$,

где для каждого $i$ независимо выбирается $0\leq e_i\leq k_i$.

Это позволяет строить список делителей постепенно. Изначально в нём находится только $1$. Пусть уже обработаны несколько простых множителей и в `curr` содержатся все делители, которые можно из них составить. Для следующего простого $p$ со степенью $k$ каждый старый делитель нужно:

- оставить без изменения, что соответствует степени $p^0$;
- умножить на $p$;
- умножить на $p^2$;
- и так далее до $p^k$.

Старые делители уже присутствуют в `curr`, поэтому достаточно добавить варианты со степенями от $1$ до $k$. Важно запомнить старый размер массива до добавлений: только первые `prevSize` элементов являются делителями, построенными без нового простого множителя.

#### C++

```cpp
// функция для восстановления всех делителей, зная факторизацию:
auto divisors(const auto &primeDivisors) {
    vector<int> curr = {1};
    for (auto [p, k] : primeDivisors) {
        // у нас k+1 вариантов: взять p^i в делитель, 0 <= i <= k
        const int prevSize = (int)curr.size();
        // полуинтервал [0, prevSize-1) содержит все делители до рассмотрения p^k
        // мы должны умножить на p^i каждый из них, где 0 <= i <= k
        int mult = 1;
        for (int i = 1; i <= k; i++) {
            mult *= p;
            for (int j = 0; j < prevSize; j++)
                curr.push_back(curr[j] * mult);
        }
    }
    return curr;
}
```

#### Python

```python
# функция для восстановления всех делителей, зная факторизацию:
def divisors(primeDivisors):
    curr = [1]
    for p, k in primeDivisors:
        # у нас k+1 вариантов: взять p^i в делитель, 0 <= i <= k
        prevSize = len(curr)
        # полуинтервал [0, prevSize) содержит все делители до рассмотрения p^k
        # мы должны умножить на p^i каждый из них, где 0 <= i <= k
        mult = 1
        for i in range(1, k + 1):
            mult *= p
            for j in range(prevSize):
                curr.append(curr[j] * mult)
    return curr
```

Каждый делитель появляется ровно один раз, поскольку ему соответствует единственный набор степеней $(e_1,e_2,\ldots,e_m)$.

<details><summary><b>Подсчёт встречаемости делителей</b></summary>

Для каждого элемента массива выполняются два действия:

1. число раскладывается на простые множители;
2. по факторизации генерируются все его положительные делители.

После этого для каждого полученного делителя $d$ увеличивается `cnt[d]`. Таким образом, после обработки всего массива значение `cnt[d]` равно количеству элементов, делящихся на $d$.

Подсчёт ведётся именно по элементам массива, а не по различным значениям. Поэтому если одинаковое число встречается на двух разных позициях, все его делители будут учтены дважды. Это соответствует требованию выбирать элементы с различными индексами.

В C++ используется `unordered_map`. Обычный `map` добавил бы логарифмический множитель к каждому обновлению и, как отмечено в предоставленном решении, не укладывается в ограничение времени.

#### C++

```cpp
    // факторизуем каждое число и для каждого делителя считаем сколько чисел оно делит:
    unordered_map<int, int> cnt; // обычный map<int,int> даёт TLE
    for (auto ai : a)
        for (auto d : divisors(factor(ai)))
            cnt[d]++;
```

#### Python

```python

    cnt = {} # обычный словарь даёт TLE

        for d in divisors(factor(ai)):
```

<details><summary><b>Ответ</b></summary>

После подсчёта остаётся перебрать все встретившиеся делители. Если `cnt[d] > 1`, делитель $d$ входит хотя бы в два элемента массива, то есть существует допустимая пара элементов, оба числа которой делятся на $d$.

Среди всех таких значений выбирается максимальное.

Делитель $1$ присутствует у каждого положительного целого числа. Поскольку $n\geq2$, он всегда встречается хотя бы дважды, поэтому ответ существует и начальное значение `answ = 1` корректно.

#### C++

```cpp
    // находим максимальное число, которое делит два элемента массива:
    int answ = 1;
    for (const auto &[d,k] : cnt)
        if (k > 1)
            answ = max(answ, d);
    cout << answ << '\n';
```

#### Python

```python
    # находим максимальное число, которое делит два элемента массива:
    answ = 1
    for d, k in cnt.items():
        if k > 1:
```

<details><summary><b>Пример</b></summary>

Рассмотрим массив

$[12,18,24,30]$.

Некоторые делители этих чисел встречаются следующим образом:

- $12$ делит числа $12$ и $24$;
- $6$ делит все четыре числа;
- $9$ делит только $18$;
- $15$ делит только $30$;
- $18$ делит только $18$;
- $24$ делит только $24$;
- $30$ делит только $30$.

Максимальный делитель, встречающийся хотя бы у двух элементов, равен $12$. Например,

$\gcd(12,24)=12$.

Хотя делитель $6$ встречается чаще, количество подходящих элементов не требуется максимизировать. Важно максимизировать само значение общего делителя.

Для массива из различных простых чисел $[7,11,13,17,19]$ ни один делитель больше единицы не встречается дважды. Делитель $1$ есть у каждого элемента, поэтому ответ равен $1$.

</details>

<details><summary><b>Корректность</b></summary>

Докажем, что алгоритм находит максимальный возможный НОД двух элементов с различными индексами.

**Лемма 1.** Функция факторизации возвращает полное разложение заданного числа на простые множители.

Перебираются все простые числа $p$, пока $p^2$ не станет больше текущего остатка. Каждый найденный простой делитель извлекается полностью, а количество делений записывается как его степень. Если после этого остаётся число больше единицы, оно является простым: составное число имело бы простой делитель, не превосходящий его квадратного корня, и этот делитель был бы найден раньше. Следовательно, факторизация полна.

**Лемма 2.** По полученной факторизации алгоритм генерирует каждый положительный делитель числа ровно один раз.

Для каждого простого $p_i$ со степенью $k_i$ независимо выбирается степень от $0$ до $k_i$. При обработке очередного простого алгоритм умножает каждый ранее построенный делитель на все допустимые положительные степени этого простого, а вариант со степенью $0$ уже находится в массиве. Поэтому рассматриваются все допустимые наборы степеней. Разным наборам соответствует разное разложение делителя, следовательно, повторов нет.

**Лемма 3.** После обработки массива `cnt[d]` равно количеству элементов массива, делящихся на $d$.

По лемме 2 для каждого элемента генерируются все и только его положительные делители, причём каждый ровно один раз. Для каждого из них счётчик увеличивается на единицу. Поэтому каждый элемент даёт ровно один вклад в `cnt[d]` тогда и только тогда, когда он делится на $d$.

**Лемма 4.** Для НОД любой допустимой пары его значение будет рассмотрено алгоритмом как кандидат.

Пусть выбраны элементы $a_i$ и $a_j$, а их НОД равен $g$. По определению НОД число $g$ делит оба элемента. По лемме 3 получаем `cnt[g] >= 2`, поэтому алгоритм рассматривает $g$ как кандидата и выбирает ответ не меньше него.

**Лемма 5.** Для каждого рассмотренного кандидата существует пара элементов, НОД которой не меньше этого кандидата.

Если `cnt[d] >= 2`, по лемме 3 существуют два элемента с различными индексами, которые делятся на $d$. Их НОД также делится на $d$, поэтому он не меньше $d$.

**Теорема.** Значение `answ`, найденное алгоритмом, равно максимальному НОД пары элементов массива.

Пусть оптимальная пара имеет НОД $g$. По лемме 4 алгоритм рассматривает $g$, поэтому `answ` не меньше оптимального значения. С другой стороны, для выбранного алгоритмом значения `answ` по лемме 5 существует пара с НОД не меньше `answ`. Следовательно, алгоритм не может получить значение больше оптимального. Значит, найденный ответ в точности равен максимальному возможному НОД.

</details>

<details><summary><b>Сложность</b></summary>

Обозначим:

- $A=10^9$ — максимальное значение элемента;
- $P$ — количество простых чисел до $\sqrt A$;
- $\tau(x)$ — количество положительных делителей числа $x$;
- $U$ — количество различных делителей, встретившихся хотя бы у одного элемента массива.

Предподсчёт проверяет числа до $\sqrt A$ на делимость уже найденными простыми. Его время можно записать как

$O\left(\sum_{x=2}^{\sqrt A}\pi(\sqrt x)\right)$,

где $\pi(y)$ — количество простых чисел, не превосходящих $y$. Память для списка простых составляет $O(P)$.

В худшем случае факторизация одного элемента перебирает все простые числа до его квадратного корня, то есть требует $O(P)$ проверок. Генерация его делителей занимает $O(\tau(a_i))$ времени и памяти для временного вектора.

Обновления `unordered_map` работают за ожидаемое $O(1)$, поэтому суммарное ожидаемое время обработки одного набора данных равно

$O\left(nP+\sum_{i=1}^{n}\tau(a_i)+U\right)$.

Дополнительная память равна

$O(P+U+\max_i\tau(a_i))$,

не считая входного массива.

Сумма $n$ по всем наборам не превосходит $100000$. Предоставленная реализация на C++ укладывается в ограничения. Алгоритмически аналогичная реализация на PyPy3-64 работает 5437 мс и получает TLE при ограничении в 2 секунды, что согласуется с отдельным предупреждением в условии.

</details>

```cpp
#include <bits/stdc++.h>
using namespace std;
// предподсчёт всех простых чисел до корня из 10^9:
const int NMAX = (int)sqrt(1e9+100);
vector<int> primes;
void precalc() {
    // для разнообразия найдём все простые числа без решета Эратосфена: при проверке
    // очередного числа проверяем делится ли оно на уже найденные. Если не делится -> простое
    primes = {2,3,5,7};
    for (int x = 8; x <= NMAX; x++) {
        bool isPrime = true;
        for (int p : primes) {
            if (p * p > x) break;
            if (x % p == 0) {
                isPrime = false;
                break;
            }
        }
        if (isPrime) primes.push_back(x);
    }
}
// функция для факторизации заданного числа: находит список простых делителей числа
auto factor(int x) {
    vector<pair<int,int>> result; // пары (простое, его степень)
    for (int p : primes) {
        if (p * p > x) break; // факторизуем до корня. после корня делаем break
        if (x % p == 0) {
            result.push_back({p, 0});
            // делим пока делится
            do {
                x /= p;
                result.back().second++;
            } while (x % p == 0);
        }
    }
    // могло остаться простое больше корня:
    if (x > 1) result.push_back({x, 1});
    return result;
}
// функция для восстановления всех делителей, зная факторизацию:
auto divisors(const auto &primeDivisors) {
    vector<int> curr = {1};
    for (auto [p, k] : primeDivisors) {
        // у нас k+1 вариантов: взять p^i в делитель, 0 <= i <= k
        const int prevSize = (int)curr.size();
        // полуинтервал [0, prevSize-1) содержит все делители до рассмотрения p^k
        // мы должны умножить на p^i каждый из них, где 0 <= i <= k
        int mult = 1;
        for (int i = 1; i <= k; i++) {
            mult *= p;
            for (int j = 0; j < prevSize; j++)
                curr.push_back(curr[j] * mult);
        }
    }
    return curr;
}
void solve() {
    // читаем данные:
    int n; cin >> n;
    vector<int> a(n);
    for (auto &it : a) cin >> it;
    // факторизуем каждое число и для каждого делителя считаем сколько чисел оно делит:
    unordered_map<int, int> cnt; // обычный map<int,int> даёт TLE
    for (auto ai : a)
        for (auto d : divisors(factor(ai)))
            cnt[d]++;
    // находим максимальное число, которое делит два элемента массива:
    int answ = 1;
    for (const auto &[d,k] : cnt)
        if (k > 1)
            answ = max(answ, d);
    cout << answ << '\n';
}
main() {
    precalc(); // предподсчитываем все простые числа один раз
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

## E. Биномиалов Нод Факториалович

<details><summary><b>Идея</b></summary>

В условии требуется найти сумму положительных делителей числа

$\gcd\left(\binom{n}{k},\binom{m}{r}\right)$.

Здесь $\binom{n}{k}$ — количество способов выбрать $k$ элементов из множества из $n$ элементов. Именно такая запись будет использоваться далее.

Напрямую вычислять биномиальные коэффициенты не следует. Даже при $n\leq500000$ число $\binom{n}{k}$ может содержать огромное количество цифр. При этом для вычисления НОД и суммы его делителей сами значения биномиальных коэффициентов не нужны: достаточно знать их разложения на простые множители.

Пусть для простого числа $p$ показатель его степени в числе $x$ обозначается через $v_p(x)$. Тогда

$v_p(\gcd(x,y))=\min(v_p(x),v_p(y))$.

Следовательно, для каждого простого $p$ достаточно определить его степени в обоих биномиальных коэффициентах и взять минимум.

Биномиальный коэффициент выражается через факториалы:

$\binom{n}{k}=\dfrac{n!}{k!(n-k)!}$.

Поэтому его показатель по простому числу $p$ равен

$v_p\left(\binom{n}{k}\right)=v_p(n!)-v_p(k!)-v_p((n-k)!)$.

Аналогично,

$v_p\left(\binom{m}{r}\right)=v_p(m!)-v_p(r!)-v_p((m-r)!)$.

Осталось научиться быстро считать степень простого числа в факториале. Для этого используется формула Лежандра:

$v_p(s!)=\left\lfloor\dfrac{s}{p}\right\rfloor+\left\lfloor\dfrac{s}{p^2}\right\rfloor+\left\lfloor\dfrac{s}{p^3}\right\rfloor+\ldots$

Сумма конечна, поскольку при достаточно большой степени $p^i>s$ очередное слагаемое становится нулевым.

Все возможные простые делители биномиальных коэффициентов не превосходят соответственно $n$ и $m$. Поэтому достаточно найти решетом Эратосфена все простые числа до $\max(n,m)$.

#### C++

```cpp
// функция находит список всех простых чисел <= NMAX:
vector<int> findPrimeNumbers(int NMAX) {
    if (NMAX < 2) NMAX = 2; // передан слишком маленький NMAX
    // строим решето Эратосфена за O(n log(log(n))):
    vector<bool> isPrime(NMAX+1, 1);
    isPrime[0] = isPrime[1] = 0;
    for (int i = 2; i * i <= NMAX; i++)
        if (isPrime[i])
            for (int j = i * i; j <= NMAX; j += i)
                isPrime[j] = 0;
    // возвращаем результат:
    vector<int> primes;
    for (int i = 2; i <= NMAX; i++)
        if (isPrime[i])
            primes.push_back(i);
    return primes;
}
```

#### Python

```python
# функция находит список всех простых чисел <= NMAX:
def findPrimeNumbers(NMAX):
```

<details><summary><b>Степень простого числа в факториале</b></summary>

Чтобы понять формулу Лежандра, сначала посчитаем числа от $1$ до $n$, которые дают хотя бы один множитель $p$. Таких чисел $\lfloor n/p\rfloor$.

Однако числа, делящиеся на $p^2$, содержат ещё один множитель $p$. Их количество равно $\lfloor n/p^2\rfloor$. Числа, делящиеся на $p^3$, дают ещё один множитель, и так далее. Складывая эти количества, получаем полную степень $p$ в $n!$.

В реализации не требуется явно вычислять степени $p^2,p^3,\ldots$. На каждой итерации значение $n$ делится на $p$, а полученное частное прибавляется к ответу:

#### C++

```cpp
// формула Лежандра считает, сколько раз n! делится на простое p
int64_t Legendre(int n, int p) {
    int64_t result = 0;
    while (n > 0) {
        n /= p;
        result += n;
    }
    return result;
}
```

#### Python

```python
# формула Лежандра считает, сколько раз n! делится на простое p
def Legendre(n, p):
    result = 0
    while n > 0:
        n //= p
        result += n
    return result
```

<details><summary><b>Как получить сумму делителей</b></summary>

Пусть после вычисления степеней НОД имеет разложение

$g=\prod p^{e_p}$.

Каждый положительный делитель $g$ содержит простое число $p$ в одной из степеней от $0$ до $e_p$. Поэтому сумма вариантов для одного простого множителя равна

$1+p+p^2+\ldots+p^{e_p}$.

Выбор степеней разных простых чисел независим. При раскрытии произведения

$\prod_p(1+p+p^2+\ldots+p^{e_p})$

будет получен каждый положительный делитель $g$ ровно один раз. Следовательно, сумма делителей равна

$\sigma(g)=\prod_p(1+p+p^2+\ldots+p^{e_p})$.

Сумма геометрической прогрессии вычисляется по формуле

$1+p+\ldots+p^e=\dfrac{p^{e+1}-1}{p-1}$.

Все вычисления выполняются по модулю $998244353$. Деление заменяется умножением на обратный элемент к $p-1$. Поскольку $p\leq500000<998244353$, значение $p-1$ не равно нулю по модулю, поэтому обратный элемент существует.

Для $e=0$ сумма равна единице. Этот случай обрабатывается отдельно.

#### C++

```cpp
// модульная арифметика:
const int mod = 998244353;
int sub(int a, int b) {
    return (a - b + mod) % mod;
}
int add(int a, int b) {
    return (a + b) % mod;
}
int mul(int a, int b) {
    return int(a * 1LL * b % mod);
}
// быстрое возведение в степень:
int binpow(int a, int64_t n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = mul(r, a);
        a = mul(a, a);
        n >>= 1;
    }
    return r;
}
// сумма геометрической прогрессии:
int geom(int a, int64_t n) {
// 1 + a + ... + a^n = (a^{n+1} - 1) / (a - 1)
    if (n == 0) return 1;
    int p = sub(binpow(a, n+1), 1);
    int q = binpow(sub(a, 1), mod-2);
    return mul(p, q);
}
```

<details><summary><b>Переход к алгоритму</b></summary>

Теперь все части решения можно соединить.

Сначала строится список простых чисел до $\max(n,m)$. Затем для каждого простого $p$ вычисляются:

- `countInN` — степень $p$ в $\binom{n}{k}$;
- `countInM` — степень $p$ в $\binom{m}{r}$.

Используя представление биномиального коэффициента через факториалы, получаем:

$countInN=v_p(n!)-v_p(k!)-v_p((n-k)!)$,

$countInM=v_p(m!)-v_p(r!)-v_p((m-r)!)$.

Степень $p$ в НОД равна минимуму этих двух значений:

$e_p=\min(countInN,countInM)$.

После этого текущий ответ умножается на сумму

$1+p+p^2+\ldots+p^{e_p}$.

#### C++

```cpp
    // находим простые числа до max(n, m):
    auto primes = findPrimeNumbers(max(n,m));
    // раскладываем каждый из факториалов на простые множители по формуле Лежандра
    int answ = 1;
    for (int p : primes) {
        // считаем степень вхождения p в число C(n,k) = n!/k!/(n-k)!:
        auto countInN = Legendre(n, p);
        countInN -= Legendre(k, p);
        countInN -= Legendre(n-k, p);
        // считаем степень вхождения p в число C(m,r) = m!/r!/(m-r)!:
        auto countInM = Legendre(m, p);
        countInM -= Legendre(r, p);
        countInM -= Legendre(m-r, p);
        // обновляем сумму делителей:
        answ = mul(answ, geom(p, min(countInN, countInM)));
    }
```

<details><summary><b>Пример</b></summary>

Рассмотрим первый набор:

$n=4$, $m=5$, $k=2$, $r=2$.

Биномиальные коэффициенты равны

$\binom{4}{2}=6=2\cdot3$,

$\binom{5}{2}=10=2\cdot5$.

Для простого числа $2$ степени в обоих коэффициентах равны единице, поэтому в НОД оно входит в степени

$\min(1,1)=1$.

Для простого $3$ степени равны соответственно $1$ и $0$, поэтому минимум равен нулю. Аналогично простой множитель $5$ не входит в первый коэффициент и также не попадает в НОД.

Таким образом,

$\gcd\left(\binom{4}{2},\binom{5}{2}\right)=2$.

Сумма его делителей равна

$1+2=3$.

Рассмотрим также третий набор:

$n=6$, $m=10$, $k=3$, $r=2$.

Получаем

$\binom{6}{3}=20=2^2\cdot5$,

$\binom{10}{2}=45=3^2\cdot5$.

Минимальная степень простого $5$ равна единице, а минимальные степени остальных простых равны нулю. Поэтому НОД равен $5$, а сумма его делителей равна

$1+5=6$.

<details><summary><b>Корректность</b></summary>

Докажем, что алгоритм выводит сумму всех положительных делителей числа $\gcd\left(\binom{n}{k},\binom{m}{r}\right)$.

**Лемма 1.** Функция `Legendre(s, p)` возвращает степень простого числа $p$ в разложении $s!$.

Среди чисел от $1$ до $s$ ровно $\lfloor s/p\rfloor$ чисел содержат хотя бы один множитель $p$. Среди них $\lfloor s/p^2\rfloor$ содержат дополнительный множитель $p$, $\lfloor s/p^3\rfloor$ — ещё один, и так далее. Поэтому полная степень равна

$v_p(s!)=\sum_{i\geq1}\left\lfloor\dfrac{s}{p^i}\right\rfloor$.

Функция последовательно делит $s$ на $p$ и складывает полученные частные, то есть вычисляет именно эту сумму.

**Лемма 2.** Значение `countInN` равно степени $p$ в $\binom{n}{k}$, а `countInM` — степени $p$ в $\binom{m}{r}$.

Используем равенство

$\binom{n}{k}=\dfrac{n!}{k!(n-k)!}$.

При умножении показатели простого складываются, а при точном делении вычитаются. Поэтому

$v_p\left(\binom{n}{k}\right)=v_p(n!)-v_p(k!)-v_p((n-k)!)$.

По лемме 1 каждое слагаемое правильно вычисляется функцией `Legendre`, следовательно, `countInN` имеет требуемый смысл. Для `countInM` доказательство аналогично.

**Лемма 3.** Значение `min(countInN, countInM)` равно степени $p$ в НОД двух биномиальных коэффициентов.

Пусть степени $p$ в двух числах равны $a$ и $b$. Общий делитель может содержать $p$ не более чем в степени $a$ и не более чем в степени $b$. Наибольшая допустимая степень равна $\min(a,b)$, и именно она входит в НОД. По лемме 2 значения $a$ и $b$ правильно представлены переменными `countInN` и `countInM`.

**Лемма 4.** Для простого $p$ со степенью $e$ в НОД значение `geom(p, e)` равно сумме всех возможных степеней $p$ в делителях НОД.

В любой делитель можно включить $p$ в степени от $0$ до $e$. Сумма соответствующих множителей равна

$1+p+p^2+\ldots+p^e$.

Именно эту геометрическую прогрессию вычисляет функция `geom`.

**Лемма 5.** После обработки всех простых чисел `answ` равен сумме всех положительных делителей НОД.

Пусть разложение НОД имеет вид

$g=\prod p^{e_p}$.

Каждый его делитель однозначно задаётся независимым выбором степени каждого простого $p$ от $0$ до $e_p$. Поэтому при раскрытии произведения

$\prod_p(1+p+\ldots+p^{e_p})$

каждый положительный делитель появляется ровно один раз. По леммам 3 и 4 алгоритм умножает именно такие суммы для правильных степеней всех простых чисел.

**Теорема.** Алгоритм выводит требуемый ответ.

Решето перечисляет все простые числа, которые могут входить в биномиальные коэффициенты. Для каждого из них по леммам 1–3 алгоритм правильно определяет степень в НОД. По леммам 4 и 5 произведение, накопленное в `answ`, равно сумме всех положительных делителей этого НОД. Все операции выполняются по модулю $998244353$, следовательно, выводится требуемый остаток.

</details>

<details><summary><b>Сложность</b></summary>

Обозначим $N=\max(n,m)$.

Решето Эратосфена для одного набора данных работает за $O(N\log\log N)$ времени и использует $O(N)$ памяти.

Для одного простого $p$ функция `Legendre(s, p)` выполняет $O(\log_p s)$ итераций. Для каждого простого она вызывается шесть раз: для $n$, $k$, $n-k$, $m$, $r$ и $m-r$.

Кроме того, если простое входит в НОД с положительной степенью, функция `geom` выполняет два модульных возведения в степень за $O(\log mod)$.

Поэтому время обработки одного набора можно оценить как

$O\left(N\log\log N+\sum_{p\leq N}\log_p N+\pi(N)\log mod\right)$,

где $\pi(N)$ — количество простых чисел, не превосходящих $N$. Более грубая оценка имеет вид $O(N\log\log N+\pi(N)(\log N+\log mod))$.

Память составляет $O(N)$ на решето и список простых чисел.

По условию сумма значений $n$ по всем наборам не превосходит $500000$, как и сумма значений $m$. Следовательно, сумма значений $\max(n,m)$ не превосходит $1000000$, что ограничивает суммарный объём построенных решёт.

</details>

```cpp
#include <bits/stdc++.h>
using namespace std;
// модульная арифметика:
const int mod = 998244353;
int sub(int a, int b) {
    return (a - b + mod) % mod;
}
int add(int a, int b) {
    return (a + b) % mod;
}
int mul(int a, int b) {
    return int(a * 1LL * b % mod);
}
// быстрое возведение в степень:
int binpow(int a, int64_t n) {
    int r = 1;
    while (n > 0) {
        if (n % 2 == 1)
            r = mul(r, a);
        a = mul(a, a);
        n >>= 1;
    }
    return r;
}
// сумма геометрической прогрессии:
int geom(int a, int64_t n) {
// 1 + a + ... + a^n = (a^{n+1} - 1) / (a - 1)
    if (n == 0) return 1;
    int p = sub(binpow(a, n+1), 1);
    int q = binpow(sub(a, 1), mod-2);
    return mul(p, q);
}
// функция находит список всех простых чисел <= NMAX:
vector<int> findPrimeNumbers(int NMAX) {
    if (NMAX < 2) NMAX = 2; // передан слишком маленький NMAX
    // строим решето Эратосфена за O(n log(log(n))):
    vector<bool> isPrime(NMAX+1, 1);
    isPrime[0] = isPrime[1] = 0;
    for (int i = 2; i * i <= NMAX; i++)
        if (isPrime[i])
            for (int j = i * i; j <= NMAX; j += i)
                isPrime[j] = 0;
    // возвращаем результат:
    vector<int> primes;
    for (int i = 2; i <= NMAX; i++)
        if (isPrime[i])
            primes.push_back(i);
    return primes;
}
// формула Лежандра считает, сколько раз n! делится на простое p
int64_t Legendre(int n, int p) {
    int64_t result = 0;
    while (n > 0) {
        n /= p;
        result += n;
    }
    return result;
}
// решение задачи:
void solve() {
    // читаем входные данные
    int n, m, k, r;
    cin >> n >> m >> k >> r;
    // находим простые числа до max(n, m):
    auto primes = findPrimeNumbers(max(n,m));
    // раскладываем каждый из факториалов на простые множители по формуле Лежандра
    int answ = 1;
    for (int p : primes) {
        // считаем степень вхождения p в число C(n,k) = n!/k!/(n-k)!:
        auto countInN = Legendre(n, p);
        countInN -= Legendre(k, p);
        countInN -= Legendre(n-k, p);
        // считаем степень вхождения p в число C(m,r) = m!/r!/(m-r)!:
        auto countInM = Legendre(m, p);
        countInM -= Legendre(r, p);
        countInM -= Legendre(m-r, p);
        // обновляем сумму делителей:
        answ = mul(answ, geom(p, min(countInN, countInM)));
    }
    cout << answ << '\n';
}
main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int tt; cin >> tt;
    while (tt --> 0) solve();
}
```

```python
# модульная арифметика:
mod = 998244353
def sub(a, b):
    return (a - b) % mod
def add(a, b):
    return (a + b) % mod
def mul(a, b):
    return a * b % mod
# сумма геометрической прогрессии:
def geom(a, n):
    # 1 + a + ... + a^n = (a^{n+1} - 1) / (a - 1)
    if n == 0:
        return 1
    p = sub(pow(a, n + 1, mod), 1)
    q = pow(sub(a, 1), -1, mod)
    return mul(p, q)
# функция находит список всех простых чисел <= NMAX:
def findPrimeNumbers(NMAX):
    if (NMAX < 2): NMAX = 2; # передан слишком маленький NMAX
    # строим решето Эратосфена за O(n log(log(n))):
    isPrime = [True] * (NMAX + 1)
    isPrime[0] = isPrime[1] = False
    for i in range(2, int(NMAX ** 0.5) + 1):
        if isPrime[i]:
            for j in range(i * i, NMAX + 1, i):
                isPrime[j] = False
    # возвращаем результат:
    primes = []
    for i in range(2, NMAX + 1):
        if isPrime[i]:
            primes.append(i)
    return primes
# формула Лежандра считает, сколько раз n! делится на простое p
def Legendre(n, p):
    result = 0
    while n > 0:
        n //= p
        result += n
    return result
# решение задачи:
def solve():
    # читаем входные данные
    n, m, k, r = map(int, input().split())
    # находим простые числа до max(n, m):
    primes = findPrimeNumbers(max(n, m))

        countInN = Legendre(n, p)
        countInN -= Legendre(k, p)

        countInM = Legendre(m, p)
        countInM -= Legendre(r, p)
        countInM -= Legendre(m - r, p)

        answ = mul(answ, geom(p, min(countInN, countInM)))
```
