## A. Журнал турникета

<details><summary><b>Постановка задачи</b></summary>

Дан журнал из $n$ записей, расположенных в порядке неубывания времени. Каждая запись содержит время, имя сотрудника и направление прохода: `IN` или `OUT`. Записи с одинаковым временем обрабатываются в том порядке, в котором они даны.

В начале суток все сотрудники находятся снаружи. Записи трактуются по следующим правилам:

- `IN` для сотрудника снаружи означает вход;
- повторный `IN` для сотрудника внутри ничего не меняет;
- `OUT` для сотрудника внутри означает выход;
- `OUT` для сотрудника снаружи означает, что он вошёл сразу после своей предыдущей записи, а теперь вышел;
- если перед таким `OUT` предыдущей записи не было, сотрудник считается находившимся внутри с начала суток;
- в момент `24:00:00` все оставшиеся внутри сотрудники выходят.

Для каждого встречающегося в журнале сотрудника требуется определить суммарное время, проведённое в лаборатории. Результаты нужно вывести в лексикографическом порядке имён, записав время в формате `HH:MM:SS`. Для полных суток используется запись `24:00:00`.

</details>

<details><summary><b>Основная идея</b></summary>

Записи нельзя просто разбить на пары `IN`–`OUT`: повторный вход игнорируется, а выход сотрудника, уже находящегося снаружи, сам создаёт новый промежуток пребывания. Поэтому для каждого имени будем хранить **текущее состояние** и связанное с ним время.

Если последняя значимая запись имеет тип `IN`, сохранённое время обозначает начало текущего пребывания. Если она имеет тип `OUT`, сотрудник находится снаружи, а сохранённое время потребуется при следующем `OUT`: по условию сотрудник вошёл сразу после этой записи.

Каждый `OUT` завершает некоторый промежуток пребывания:

- от начала суток, если записей сотрудника ещё не было;
- от сохранённого времени — во всех остальных случаях.

Повторный `IN` не меняет состояние. Обычный `IN` запоминает начало нового пребывания. После обработки журнала для всех сотрудников, оставшихся внутри, добавляется время до конца суток.

В C++ упорядоченные словари дают время работы $O(n\log(m))$, где $m$ — число различных сотрудников. В Python обработка записей занимает в среднем $O(n)$, а сортировка ответов — $O(m\log(m))$. Память в обеих реализациях равна $O(m)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Главная трудность состоит в том, что надпись на записи **не всегда напрямую описывает изменение состояния**. Например, два последовательных `IN` не означают два входа, а `OUT` для сотрудника снаружи восстанавливает пропущенный вход. Следовательно, искать ближайшие пары `IN` и `OUT` без учёта предыдущего состояния нельзя.

Сначала переведём время в количество секунд от начала суток. Тогда продолжительность пребывания между моментами $l$ и $r$ равна $r-l$, а конец суток имеет значение $24\cdot60\cdot60$.

Для каждого сотрудника будем поддерживать два значения:

- последнее известное состояние — `IN` или `OUT`;
- время, от которого следует отсчитывать следующий завершённый промежуток.

Смысл сохранённого времени зависит от состояния:

- при `IN` это начало текущего пребывания;
- при `OUT` это время предыдущего выхода, сразу после которого сотрудник мог снова пройти внутрь без регистрации.

Теперь разберём поступающую запись.

**Запись `IN`.** Если сотрудник уже находится внутри, произошло двойное прикладывание пропуска. Такая запись ничего не меняет, в том числе не сдвигает начало текущего пребывания.

Если сотрудник находится снаружи либо встречается впервые, он входит в указанный момент. Будем хранить состояние `IN` и время этой записи.

**Запись `OUT`.** Здесь всегда заканчивается некоторый промежуток нахождения внутри.

Если сотрудник встречается впервые, по правилам он находился в лаборатории с начала суток. Поэтому к ответу прибавляется время от $00:00:00$ до текущей записи, то есть $t$ секунд.

Если сведения о сотруднике уже есть, к ответу прибавляется $t-p$, где $p$ — сохранённое время:

- при состоянии `IN` значение $p$ является временем обычного входа;
- при состоянии `OUT` сотрудник считается вошедшим сразу после предыдущего выхода, записанного в момент $p$.

После этого сотрудник находится снаружи, поэтому сохраняются состояние `OUT` и текущее время.

Особое внимание требуется записям с одинаковым временем. Они обрабатываются последовательно, как предписывает условие. Если между входом и выходом прошло ноль секунд, к ответу добавляется ноль; состояние при этом всё равно изменяется корректно.

Когда журнал закончился, некоторые сотрудники могут оставаться внутри. Для каждого из них к ответу прибавляется промежуток от сохранённого момента входа до конца суток: $24\cdot60\cdot60-p$.

**Почему алгоритм корректен.** Рассмотрим записи одного сотрудника в порядке их появления. После каждой обработанной записи выполняется следующий инвариант:

- сохранённое состояние совпадает с положением сотрудника после этой записи;
- при `IN` сохранённое время является началом ещё не учтённого пребывания;
- при `OUT` все завершённые промежутки уже добавлены к ответу, а сохранённое время совпадает с моментом последней записи сотрудника.

Обычный `IN` открывает новый промежуток, повторный `IN` сохраняет уже открытый. Любой `OUT` закрывает текущий или восстановленный по правилам промежуток и полностью добавляет его длительность к ответу. Значит, каждый завершённый промежуток учитывается один раз. Незавершённые промежутки закрываются в конце суток, поэтому итоговая сумма содержит всё время, проведённое сотрудником внутри.

В C++ используются `map`, поэтому каждая операция с сотрудником требует $O(\log(m))$, а имена при выводе уже расположены лексикографически. Время работы равно $O(n\log(m))$, память — $O(m)$.

В Python словари работают в среднем за $O(1)$ на операцию, поэтому обработка журнала занимает $O(n)$. Для вывода пары сортируются по имени за $O(m\log(m))$. Память равна $O(m)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
using namespace std;
// функция для перевода из строки формата "HH:MM:SS" в секунды:
int time2sec(const auto &s) {
    int hh, mm, ss;
    int code = sscanf(s.c_str(), "%d:%d:%d", &hh, &mm, &ss);
    assert(code == 3);
    return ss + 60 * (mm + hh * 60);
}
// функция для перевода из секунд в строку формата "HH:MM:SS":
string sec2time(int ss) {
    int hh = ss / 3600;
    int mm = ss / 60 % 60;
    ss %= 60;
    char buf[101];
    sprintf(buf, "%02d:%02d:%02d", hh, mm, ss);
    return buf;
}
// решение задачи:
void solve() {
    int q; cin >> q;
    // храним для каждого чувака его последнее известное состояние (вышел/вошёл, время в секундах):
    map<string, pair<string,int>> cache;
    // а здесь храним ответ в секундах для каждого:
    map<string, int> answ;
    while (q --> 0) {
        string sTime, sName, sType;
        cin >> sTime >> sName >> sType;
        int sec = time2sec(sTime);
        // смотрим, что делал человек до этого, и обновляем ответ и его состояние
        if (sType == "OUT") {
            auto it = cache.find(sName);
            if (it == cache.end())
                // не было, но ушёл
                answ[sName] += sec;
            else
                answ[sName] += sec - it->second.second;
            cache[sName] = {"OUT", sec};
        } else if (sType == "IN") {
            auto it = cache.find(sName);
            if (it != cache.end() && it->second.first == "IN") {
                // ничего не делаем, он повторно приложил пропуск
            } else
                cache[sName] = {"IN", sec};
        }
    }
    // все те, кто до сих пор внутри, должны выйти: обновляем для них ответ:
    for (const auto &[name, val] : cache)
        if (val.first == "IN")
            answ[name] += 24*60*60 - val.second;
    // выводим ответ:
    for (const auto &[name, sec] : answ)
        cout << name << ' ' << sec2time(sec) << '\n';
}
int32_t main() {
    cin.tie(0)->sync_with_stdio(0);
    int tt = 1; //cin >> tt;
    while (tt --> 0) solve();
    return 0;
}
```

```python
from collections import defaultdict
# функция для перевода из строки формата "HH:MM:SS" в секунды:
def time2sec(s):
    hh, mm, ss = map(int, s.split(":"))
    return ss + 60 * (mm + hh * 60)
# функция для перевода из секунд в строку формата "HH:MM:SS":
def sec2time(ss):
    hh = ss // 3600
    mm = ss // 60 % 60
    ss %= 60
    return f"{hh:02d}:{mm:02d}:{ss:02d}"
# решение задачи:
def solve():
    q = int(input())
    # храним для каждого чувака его последнее известное состояние (вышел/вошёл, время в секундах):
    cache = {}
    # а здесь храним ответ в секундах для каждого:
    answ = defaultdict(int)
    while q > 0:
        q -= 1
        sTime, sName, sType = input().split()
        sec = time2sec(sTime)
        # смотрим, что делал человек до этого, и обновляем ответ и его состояние
        if sType == "OUT":
            if sName not in cache:
                # не было, но ушёл
                answ[sName] += sec
            else:
                answ[sName] += sec - cache[sName][1]
            cache[sName] = ("OUT", sec)
        elif sType == "IN":
            if sName in cache and cache[sName][0] == "IN":
                # ничего не делаем, он повторно приложил пропуск
                pass
            else:
                cache[sName] = ("IN", sec)
    # все те, кто до сих пор внутри, должны выйти: обновляем для них ответ:
    for name, val in cache.items():
        if val[0] == "IN":
            answ[name] += 24*60*60 - val[1]
    # выводим ответ:
    for name, sec in sorted(answ.items()):
        print(name, sec2time(sec))
solve()
```

## B. Огни карусели

<details><summary><b>Постановка задачи</b></summary>

По кругу расположены $n$ фонарей с номерами от $0$ до $n-1$. Изначально все они выключены, а указатель находится у фонаря $0$.

На шаге $i$ указатель сдвигается на $i$ позиций по часовой стрелке, после чего состояние текущего фонаря меняется на противоположное.

Для каждого набора данных требуется определить, сколько фонарей включено после $k$ шагов. Значение $k$ может достигать $10^{18}$, количество фонарей — $10^6$, а сумма $n$ по всем наборам данных не превосходит $10^6$.

</details>

<details><summary><b>Основная идея</b></summary>

Напрямую выполнить все $k$ шагов нельзя: их число может быть огромным. Поэтому посмотрим не только на положение указателя, но и на остаток номера шага по модулю $n$.

Пара

- текущая позиция указателя;
- номер выполненного шага по модулю $n$

полностью определяет дальнейшее движение. Как только такая пара повторяется, начинается новый проход по той же последовательности фонарей.

Период находится не позднее чем через $2n+1$ шагов. При этом **два полных периода можно удалить**: каждый фонарь за них переключается чётное число раз, а потому возвращается в прежнее состояние.

После удаления максимально возможного чётного числа периодов остаётся не более $2P-1$ шагов, где $P \le 2n$. Их уже можно выполнить напрямую.

Поиск периода и итоговая симуляция рассматривают $O(n)$ состояний. Бинарный поиск внутри отсортированных списков требует $O(n\log n)$ сравнений; вставка в середину списка может сдвигать элементы, поэтому грубая верхняя оценка для данной реализации — $O(n^2)$, но она, похоже, не достигается. Память — $O(n)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Главная трудность возникает из-за ограничения на $k$: даже линейная по числу шагов симуляция здесь невозможна. Значит, нам потребуется найти повторяющуюся часть движения и отбросить циклы, которые не влияют на конечные состояния фонарей.

Пусть после шага $i$ указатель находится в позиции $p_i$. За первые $i$ шагов он суммарно проходит

$\dfrac{i(i+1)}{2}$

позиций, поэтому

$p_i=\dfrac{i(i+1)}{2}\bmod n$.

Однако одного положения указателя недостаточно, чтобы определить продолжение. Из одной и той же позиции следующий сдвиг может иметь разную длину. Вместе с позицией будем учитывать остаток $i\bmod n`.

Состояние после шага $i$ задаётся парой

$(p_i,\ i\bmod n)$.

Если эта пара встретилась вновь, то совпадают и положение указателя, и остаток номера шага. Следующий сдвиг в обоих случаях имеет один остаток по модулю $n$, поэтому новые состояния также совпадут. Следовательно, дальнейшая последовательность посещаемых фонарей повторяется.

**Почему период находится быстро?** Рассмотрим состояние после шага $2n+1$. Остаток номера шага равен

$(2n+1)\bmod n=1\bmod n$.

Позиция указателя равна

$p_{2n+1}=(2n+1)(n+1)\bmod n=1\bmod n$.

Это то же состояние, что и после первого шага. Значит, повтор обязательно обнаружится не позднее шага $2n+1$, а длина периода не превосходит $2n$.

Осталось понять, почему при первом повторении длину периода можно получить как $i-1$. Переход между состояниями обратим: зная новую позицию и остаток номера шага, можно восстановить предыдущее состояние. Поэтому у последовательности нет непериодического начала. Если бы первое повторившееся состояние возникло не на первом шаге, то совпали бы и его предшественники, а повтор обнаружился бы раньше. Значит, при первом совпадении текущее состояние совпадает с состоянием после шага $1$.

Для поиска повторения будем хранить для каждой позиции отсортированный список остатков номеров шагов, с которыми указатель уже оказывался в этой позиции. Таким образом, наличие пары проверяется бинарным поиском.

Пусть найден период длины $P$. Один период переключает некоторый набор фонарей, причём один фонарь может встретиться в нём несколько раз. Следующий период посещает фонари в той же последовательности. Поэтому за два периода каждый фонарь переключается вдвое больше раз, то есть чётное число раз. После этих $2P$ шагов состояния всех фонарей совпадают с состояниями до них.

Следовательно, из $k$ можно вычесть любое число, кратное $2P$. Будем удалять максимально возможное количество таких шагов:

$k\bmod 2P$.

После этого останется меньше $2P$, а значит, не более $4n-1$ шагов. Повторная симуляция начинается с исходного положения и выключенных фонарей. При каждом посещении состояние соответствующего фонаря меняется, после чего остаётся подсчитать включённые элементы.

Если повтор не успел встретиться до шага $k$, сокращать количество шагов не требуется. В таком случае $k$ само по себе мало: период в любом случае обнаружился бы не позднее чем через $2n+1$ шагов.

**Корректность алгоритма** следует из трёх свойств:

1. Пара из позиции и остатка номера шага полностью определяет дальнейшую последовательность позиций.
2. Первое повторение этой пары замыкает период, начинающийся с первого шага.
3. Два одинаковых периода переключают каждый фонарь чётное число раз, поэтому их удаление не меняет итоговую конфигурацию.

Таким образом, сокращённая симуляция даёт те же состояния фонарей, что и исходные $k$ шагов.

В памяти хранится не более $O(n)$ состояний. Поиск периода и повторная симуляция выполняют $O(n)$ итераций. Бинарные поиски дают $O(n\log n)$ сравнений. Поскольку элементы вставляются в середину массивов, формальная грубая оценка времени для реализации — $O(n^2)$, хотя списки распределены по позициям и на рассматриваемых данных остаются короткими. Память — $O(n)$.

</details>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
#define all(x) (x).begin(),(x).end()
using namespace std;
using ll = long long;
// решение задачи:
void solve() {
    int n; ll k; cin >> n >> k;
    // найдём период. для этого храним пары (позиция, шаг % n). они задают последовательность переходов
    // при попытке хранить пары в set<pair<int,int>> получил Time Limit Exceeded.
    // поэтому храним вектор отсортированных векторов.
    vector cache(n, vector<int>{});
    int pos = 0, i, period = -1;
    for (i = 1; i <= k; i++) {
        // делаем переход:
        (pos += i) %= n;
        // мы уже были тут? смотрим сохранённые шаги и обновляем их
        auto it = lower_bound(all(cache[pos]), i%n);
        if (it != cache[pos].end() && *it == i % n) {
            period = i-1;
            break;
        }
        cache[pos].insert(it, i%n);
    }
    // нашли период, теперь эмулируем заново, но из k вычитаем чётное число периодов
    if (period != -1 && k >= 2 * period)
        k -= (k / (2 * period)) * 2 * period;
    vector<char> a(n, false);
    pos = 0;
    for (i = 1; i <= k; i++) {
        (pos += i) %= n;
        a[pos] ^= 1;
    }
    // считаем и выводим ответ:
    int answ{};
    for (i = 0; i < n; i++)
        answ += a[i];
    cout << answ << '\n';
}
int32_t main() {
    cin.tie(0)->sync_with_stdio(0);
    int tt = 1; cin >> tt;
    while (tt --> 0) solve();
    return 0;
}
```

<details><summary><b>Код на Python</b></summary>

```python
from bisect import bisect_left
# решение задачи:
def solve():
    n, k = map(int, input().split())
    # найдём период. для этого храним пары (позиция, шаг % n). они задают последовательность переходов
    # при попытке хранить пары в set получил Time Limit Exceeded.
    # поэтому храним список отсортированных списков.
    cache = [[] for _ in range(n)]
    pos, i, period = 0, 1, -1
    while i <= k:
        # делаем переход:
        pos = (pos + i) % n
        # мы уже были тут? смотрим сохранённые шаги и обновляем их
        it = bisect_left(cache[pos], i % n)
        if it != len(cache[pos]) and cache[pos][it] == i % n:
            period = i-1
            break
        cache[pos].insert(it, i % n)
        i += 1
    # нашли период, теперь эмулируем заново, но из k вычитаем чётное число периодов
    if period != -1 and k >= 2 * period:
        k -= k // (2 * period) * 2 * period
    a = [False] * n
    pos, i = 0, 1
    while i <= k:
        pos = (pos + i) % n
        a[pos] ^= True
        i += 1
    # считаем и выводим ответ:
    answ = 0
    for i in range(n):
        answ += a[i]
    print(answ)
tt = int(input())
while tt > 0:
    tt -= 1
    solve()
```

После сдвига `pos` содержит положение указателя на шаге `i`. В списке `cache[pos]` бинарным поиском проверяется наличие остатка `i%n`.

Если остаток уже встречался, повторилась вся пара состояний. Первое такое совпадение возвращает последовательность к состоянию после первого шага, поэтому длина периода равна `i-1`.

Если пары ещё не было, остаток вставляется в найденную позицию. Благодаря этому внутренний вектор остаётся отсортированным, и следующие проверки также можно проводить через `lower_bound`.

```cpp
if (period != -1 && k >= 2 * period)
    k -= (k / (2 * period)) * 2 * period;
```

Количество удаляемых шагов кратно удвоенному периоду. За два одинаковых прохода каждый фонарь переключается чётное число раз, поэтому его состояние не меняется.

Выражение `(k / (2 * period)) * 2 * period` обозначает максимальное кратное `2 * period`, не превосходящее `k`. После вычитания остаётся `k % (2 * period)` шагов.

```cpp
vector<char> a(n, false);
pos = 0;
for (i = 1; i <= k; i++) {
    (pos += i) %= n;
    a[pos] ^= 1;
}
```

После сокращения числа шагов симуляция запускается заново. `a[pos]` хранит текущее состояние фонаря, а операция `^= 1` меняет ноль на единицу и единицу на ноль.

Тип `char` здесь используется как компактный контейнер для значений $0$ и $1$.

Симуляция начинается заново, поскольку сокращённое число шагов представляет начальный фрагмент периодической последовательности.

В Python булевы значения участвуют в арифметике как числа: `False` соответствует нулю, а `True` — единице. Поэтому сумма элементов массива равна количеству включённых фонарей.

## C. Сломанное табло

<details><summary><b>Постановка задачи</b></summary>

Дано основание системы счисления $b$, отсортированное множество допустимых цифр $d$ и положительное число $n$, записанное в системе счисления с основанием $b$ без ведущих нулей.

Табло может показать число, если его запись:

- не содержит ведущих нулей;
- состоит только из цифр, принадлежащих $d$.

Требуется найти **наименьшее число, не меньшее $n$**, которое можно показать на табло. Ответ нужно вывести в системе счисления с основанием $b$. Если подходящего положительного числа не существует, следует вывести `-1`.

</details>

<details><summary><b>Основная идея</b></summary>

Для записей одинаковой длины порядок чисел совпадает с **лексикографическим порядком строк**. Поэтому искомую запись будем строить слева направо, стараясь в каждом разряде поставить наименьшую допустимую цифру, не меньшую соответствующей цифры $n$.

Возможны три случая:

- найдена такая же цифра — переходим к следующему разряду;
- найдена большая цифра — ответ уже превосходит $n$, поэтому оставшийся суффикс можно заполнить минимальной допустимой цифрой;
- подходящей цифры нет — увеличиваем ближайший предыдущий разряд, который ещё можно увеличить, а весь суффикс заменяем минимальными цифрами.

Предварительно проверим, существует ли подходящее число той же длины. Если даже запись из максимальной допустимой цифры меньше $n$, придётся строить минимальную допустимую запись длины $|n|+1$.

Для одного набора данных время работы равно $O(|n|\log |d|)$, а память — $O(|n|)$. Поскольку $|d|\leqslant 10$, фактически алгоритм работает за линейное время относительно длины $n$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Перебирать числа начиная с $n$ нельзя: между исходным числом и ближайшей подходящей записью может находиться слишком много значений. Вместо самих чисел будем работать с их цифрами.

Сначала заметим важное свойство. Если две записи в одной системе счисления имеют одинаковую длину и не содержат ведущих нулей, то больше та из них, у которой больше первая различающаяся цифра. Иными словами, **числовой порядок совпадает с лексикографическим**. Основание системы счисления в дальнейших рассуждениях уже не влияет на сравнение строк.

Обозначим длину $n$ через $L$, а максимальную допустимую цифру — через $d_{\max}$. Наибольшая запись длины $L$, которую вообще может составить табло, имеет вид

$d_{\max}d_{\max}\ldots d_{\max}$.

Если даже она меньше $n$, то подходящего числа длины $L$ не существует. Любая корректная запись большей длины превосходит $n$, поэтому достаточно построить **минимальную допустимую запись длины $L+1$**:

- если минимальная цифра из $d$ ненулевая, заполняем ею все разряды;
- если минимальная цифра — ноль, первой ставим следующую цифру из $d$, то есть минимальную ненулевую, а остальные позиции заполняем нулями;
- если разрешён только ноль, положительное число без ведущих нулей составить невозможно, поэтому ответ равен `-1`.

Теперь рассмотрим основной случай: подходящая запись длины $L$ существует.

Будем строить её слева направо. Пока построенный префикс совпадает с префиксом $n$, в текущую позицию нельзя поставить цифру меньше соответствующей цифры $n$: тогда вся запись окажется меньше $n$, независимо от оставшихся разрядов. Поэтому среди допустимых цифр ищем минимальную цифру, которая не меньше текущей цифры $n$.

Если найдена **та же цифра**, префиксы по-прежнему совпадают и нужно рассмотреть следующий разряд.

Если найдена **большая цифра**, построенная запись уже гарантированно больше $n$. Чтобы получить минимальный ответ с таким префиксом, все оставшиеся позиции следует оставить равными минимальной допустимой цифре.

Остаётся случай, когда все допустимые цифры меньше текущей цифры $n$. Продолжить построение с прежним префиксом невозможно. Значит, потребуется увеличить один из предыдущих разрядов.

Выбирать будем самый правый предыдущий разряд, который ещё допускает увеличение. Изменение более правой позиции влияет на число меньше, чем изменение любой позиции слева от неё. Если некоторый разряд уже содержит максимальную допустимую цифру, увеличить его нельзя, поэтому отступаем ещё на одну позицию. Найдя подходящий разряд, заменяем его **минимальной допустимой цифрой, большей текущей**, а весь следующий суффикс заполняем минимальной цифрой из $d$.

Такой разряд обязательно существует. Иначе все предыдущие цифры были бы максимальными, а текущая цифра $n$ превосходила бы максимальную допустимую. Тогда $n$ оказалось бы больше строки из $L$ максимальных цифр, однако этот случай был исключён предварительной проверкой.

Докажем минимальность полученной записи.

Пока выбираются цифры, совпадающие с $n$, другой допустимый ответ не может иметь в этих позициях меньшие цифры: он стал бы меньше $n$. Если в некоторой позиции сразу находится допустимая цифра, большая цифры $n$, выбирается наименьшая из таких цифр, а суффикс заполняется минимальными значениями. Следовательно, меньшего допустимого ответа с тем же префиксом нет.

При откате увеличивается самый правый разряд, который можно увеличить. Любое увеличение более левого разряда даст большее число. В выбранной позиции ставится наименьшая возможная большая цифра, а суффикс снова становится минимальным. Значит, и в этом случае получается наименьшая допустимая запись, превосходящая $n$.

На каждой позиции выполняется двоичный поиск по строке $d$. Во время отката каждая уже просмотренная позиция проходится не более одного дополнительного раза. Поэтому **время работы** равно $O(L\log |d|)$, а дополнительная память для ответа — $O(L)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
using namespace std;
using ll = long long;
// решение задачи:
void solve() {
    int b; string d, n;
    cin >> b >> d >> n;
    // если n состоит целиком из > максимальных цифр, то ответ имеет длину |n|+1
    if (n > string(n.size(), d.back())) {
        string answ(n.size() + 1, d.front());
        if (d.front() == '0') {
            if (d.size() > 1)
                answ.front() = d[1];
            else
                answ = "-1";
        }
        cout << answ << '\n';
        return;
    }
    // иначе ответ имеет такую же длину, строим его слева-направо
```

Такой выбор сохраняет возможность получить ответ не меньше $n$ и при этом минимизирует текущий разряд.
