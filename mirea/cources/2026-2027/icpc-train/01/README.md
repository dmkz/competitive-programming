## A. Кофейный автомат

<details><summary><b>Постановка задачи</b></summary>

В автомате хранятся монеты достоинством $1$, $2$, $5$, $10$, $20$ и $50$ рублей. Для каждого достоинства известно начальное количество монет.

Покупатели обслуживаются **строго по очереди**. Каждый покупатель выбирает напиток стоимостью $p$ рублей и опускает некоторое количество монет каждого достоинства.

- Если внесённая сумма меньше $p$, покупка отклоняется, а содержимое автомата не меняется.
- Иначе внесённые монеты сначала попадают в автомат, после чего тот пытается выдать сдачу.
- Сдача выдаётся жадно: сначала используется максимально возможное количество монет по $50$ рублей, затем по $20$, $10$, $5$, $2$ и $1$ рублю.
- Если таким способом не удаётся набрать точную сумму сдачи, покупка отклоняется, внесённые монеты возвращаются, а состояние автомата полностью восстанавливается.
- При успешной покупке использованные для сдачи монеты удаляются из автомата, а остальные внесённые монеты остаются в нём.

Для каждого покупателя требуется вывести `REFUSED`, если покупка отклонена. Иначе нужно вывести количество монет каждого достоинства в выданной сдаче — **в порядке возрастания номиналов**.

</details>

<details><summary><b>Основная идея</b></summary>

Способ выдачи сдачи полностью определён условием: автомат не ищет произвольный набор монет, а обязан брать номиналы **от большего к меньшему**, каждый раз выдавая максимально возможное количество.

Поэтому для каждого покупателя достаточно напрямую смоделировать работу автомата:

1. Вычислим внесённую сумму.
2. Если её недостаточно, сразу отклоним покупку.
3. Иначе сохраним прежнее состояние автомата и добавим внесённые монеты.
4. Пройдём по номиналам от $50$ до $1$ рубля, выдавая для каждого номинала столько монет, сколько позволяют запас и оставшаяся сдача.
5. Если после этого останется ненулевая сумма, восстановим сохранённое состояние. Иначе оставим получившееся состояние автомата.

Номиналов всего шесть, поэтому обработка одного покупателя занимает $O(6)$, а всех покупателей — $O(q)$. Дополнительная память равна $O(6)$, то есть фактически константна.

</details>

<details><summary><b>Детальный разбор</b></summary>

Главная особенность задачи заключается в том, что автомат выдаёт сдачу не любым подходящим набором монет. Например, он может взять крупную монету, из-за которой оставшуюся сумму уже не удастся набрать, хотя при другом выборе сдача существовала бы. Однако такой другой выбор рассматривать нельзя: порядок и количество выдаваемых монет однозначно заданы условием.

Следовательно, перебирать сочетания монет или решать задачу о размене не требуется. Нужно лишь **точно воспроизвести предписанный жадный процесс**.

Пусть покупатель внёс $u_i$ монет номинала $d_i$. Общая внесённая сумма равна

$s=\sum_{i=1}^{6}u_i d_i$.

Если $s<p$, покупатель не может оплатить напиток. Автомат не принимает его монеты, поэтому состояние остаётся прежним.

Теперь рассмотрим случай $s\ge p$. Сдача равна $r=s-p$. Важно, что внесённые монеты могут сразу попасть в сдачу, поэтому перед её выдачей будем добавлять все $u_i$ к запасам автомата.

Однако покупка ещё может завершиться отказом. Чтобы в таком случае не восстанавливать состояние сложными обратными действиями, заранее сохраним копию количества монет каждого достоинства. Тогда неудачную попытку достаточно отменить одним присваиванием.

Для очередного номинала $d_i$ автомат ограничен двумя величинами:

- в нём находится только $c_i$ таких монет;
- для сдачи нельзя выдать больше $\lfloor r/d_i\rfloor$ монет, иначе их стоимость превысит оставшуюся сумму.

Поэтому число выдаваемых монет однозначно равно

$g_i=\min(c_i,\lfloor r/d_i\rfloor)$.

После этого уменьшим остаток сдачи на $g_i d_i$, а количество монет данного номинала в автомате — на $g_i$. Номиналы будем рассматривать в порядке $50$, $20$, $10$, $5$, $2$, $1$, как и требует условие.

После обработки всех шести номиналов возможны два случая:

- **остаток равен нулю** — сдача набрана полностью, покупка успешна, а текущее состояние автомата уже учитывает и принятые, и выданные монеты;
- **остаток положителен** — жадный процесс не смог выдать точную сдачу, поэтому восстановим состояние, сохранённое до добавления монет покупателя.

Корректность такого моделирования докажем по номиналам. Перед обработкой каждого номинала текущий остаток равен той части сдачи, которую автомат ещё должен выдать, а запасы в массиве совпадают с фактическим содержимым автомата после уже выданных более крупных монет. Формула для $g_i$ выбирает в точности максимальное допустимое количество монет текущего номинала. Значит, после шага состояние снова совпадает с действиями автомата. По индукции это верно для всех шести номиналов.

Если в конце остаток равен нулю, записанный набор монет является именно той сдачей, которую обязан выдать автомат. Если остаток ненулевой, условие требует отклонить покупку, а восстановление сохранённого состояния возвращает содержимое автомата к состоянию перед приходом покупателя. Таким образом, каждый покупатель обрабатывается правильно, а значит, правильными остаются и состояния для всех следующих покупателей.

Для одного покупателя выполняется несколько проходов по шести номиналам, поэтому время работы составляет $O(6q)=O(q)$. Используются массивы фиксированного размера, следовательно, дополнительная память равна $O(6)=O(1)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
using namespace std;
using ll = long long;
void solve() {
    // читаем изначальные количества монет:
    vector<ll> c(6);
    for (auto &it : c) cin >> it;
    const vector<ll> d = {1,2,5,10,20,50};
    // читаем и отвечаем на запросы:
    int q; cin >> q;
    while (q --> 0) {
        // читаем i-й запрос:
        int p; vector<ll> u(6);
        cin >> p;
        for (auto &it : u) cin >> it;
        // считаем сумму. если суммы не хватает, то покупатель сразу уходит:
        ll s = 0;
        for (int i = 0; i < 6; i++)
            s += d[i] * u[i];
        if (s < p) {
            cout << "REFUSED\n";
            continue;
        }
        // сначала монеты попадают в автомат:
        vector<ll> saved = c;
        for (int i = 0; i < 6; i++)
            c[i] += u[i];
        // теперь мы должны выдать сдачу:
        ll r = s - p;
        vector<ll> answ(6);
        for (int i = 5; i >= 0; i--) {
            // выдаём максимальное количество монет, которое можем:
            ll cntI = std::min(c[i], r / d[i]);
            r -= d[i] * cntI;
            c[i] -= cntI;
            answ[i] = cntI;
        }
        if (r != 0) {
            // не получилось -> откатываем:
            c = saved;
            cout << "REFUSED\n";
            continue;
        }
        // тут всё получилось, выводим ответ:
        for (auto it : answ)
            cout << it << ' ';
        cout << '\n';
    }
}
int32_t main() {
    cin.tie(0)->sync_with_stdio(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
    return 0;
}
```

</details>

```python
def solve():
    # читаем изначальные количества монет:
    c = list(map(int,input().split()))
```

<details><summary><b>Разбор сложных фрагментов кода на C++</b></summary>

```cpp
        ll s = 0;
        for (int i = 0; i < 6; i++)
            s += d[i] * u[i];
```

Количество монет в автомате может накапливаться на протяжении многих покупок, поэтому для сумм и количеств используется `long long`. Значение `s` содержит полную сумму, внесённую текущим покупателем.

```cpp
        vector<ll> saved = c;
        for (int i = 0; i < 6; i++)
            c[i] += u[i];
```

`saved` хранит состояние автомата **до попытки покупки**. Внесённые монеты сразу добавляются в `c`, поскольку по условию они уже доступны при выдаче сдачи.

```cpp
        ll r = s - p;
        vector<ll> answ(6);
        for (int i = 5; i >= 0; i--) {
            // выдаём максимальное количество монет, которое можем:
            ll cntI = std::min(c[i], r / d[i]);
            r -= d[i] * cntI;
            c[i] -= cntI;
            answ[i] = cntI;
        }
```

Вектор `d` упорядочен по возрастанию, поэтому обратный проход соответствует требуемому порядку: от $50$ рублей к $1$ рублю.

Выражение `r / d[i]` задаёт максимальное количество монет, которое не превышает оставшуюся сдачу, а `c[i]` ограничивает его фактическими запасами автомата. После выбора `cntI` одновременно уменьшаются и остаток сдачи, и количество монет данного номинала.

```cpp
        if (r != 0) {
            // не получилось -> откатываем:
            c = saved;
            cout << "REFUSED\n";
            continue;
        }
```

Положительный остаток после обработки всех номиналов означает, что автомат не смог выдать точную сдачу установленным способом. Присваивание `c = saved` отменяет как добавление внесённых монет, так и все монеты, которые автомат пытался выдать.

```cpp
        for (auto it : answ)
            cout << it << ' ';
```

Хотя сдача вычисляется от крупных номиналов к мелким, результат хранится по исходным индексам. Поэтому обычный проход по `answ` выводит количества в требуемом порядке: $1$, $2$, $5$, $10$, $20$, $50$.

</details>

```python

```

Расширенная распаковка отделяет первое число строки — стоимость напитка `p`. Остальные шесть чисел образуют список `u` с количествами внесённых монет.

Метод `copy()` создаёт отдельный список с прежним состоянием автомата. Простое присваивание `saved = c` здесь не подошло бы: обе переменные ссылались бы на один список, и последующие изменения `c` затронули бы сохранённое состояние.

Монеты покупателя добавляются до выдачи сдачи, поэтому автомат может вернуть в качестве сдачи даже только что внесённую монету.

```python
        r = s - p
        answ = [0] * 6

            answ[i] = cntI
```

`range(5,-1,-1)` перебирает индексы $5,4,\ldots,0$, то есть номиналы от $50$ до $1$ рубля.

Целочисленное деление `r // d[i]` показывает, сколько монет текущего номинала помещается в оставшуюся сдачу. Функция `min` дополнительно учитывает доступное количество таких монет. Выбранное значение записывается в `answ` по исходному индексу, чтобы затем вывести ответ в порядке возрастания номиналов.

```python
        if r != 0:
            # не получилось -> откатываем:
            c = saved
            print("REFUSED")
            continue
```

Если остаток не обнулился, точную сдачу выдать не удалось. Переменная `saved` по-прежнему ссылается на отдельную неизменённую копию прежнего списка, поэтому присваивание полностью восстанавливает состояние автомата.

```python
        print(*answ)
```

Оператор `*` распаковывает список: его шесть элементов выводятся как отдельные числа через пробел. Порядок элементов соответствует номиналам $1$, $2$, $5$, $10$, $20$, $50$.

## B. Делимость на последнюю цифру

<details><summary><b>Постановка задачи</b></summary>

Натуральное число называется **удачным**, если его последняя десятичная цифра отлична от нуля и число делится на эту цифру.

Дано $t$ отрезков $[l,r]$, где $1 \le l \le r \le 10^{18}$. Для каждого отрезка требуется найти количество удачных чисел $x$, удовлетворяющих неравенству $l \le x \le r$.

</details>

<details><summary><b>Основная идея</b></summary>

Перебирать числа на отрезке нельзя: его длина достигает $10^{18}$. Вместо этого зафиксируем последнюю цифру $d$ числа. Тогда любое подходящее по последней цифре число имеет вид $x=d+10m$.

Условие делимости $x$ на $d$ сводится к делимости $10m$ на $d$. Если $g=\text{НОД}(d,10)$, то $m$ должно делиться на $d/g$. Следовательно, все удачные числа с последней цифрой $d$ образуют арифметическую прогрессию:

$x=d+10k\cdot \dfrac{d}{\text{НОД}(d,10)}$, где $k \ge 0$.

Для каждой из девяти ненулевых цифр посчитаем количество членов этой прогрессии, не превосходящих заданную границу. Пусть $F(R)$ — количество удачных чисел от $1$ до $R$. Тогда ответ для отрезка равен $F(r)-F(l-1)$.

На один запрос требуется $O(9)=O(1)$ времени и $O(1)$ дополнительной памяти. Общая сложность составляет $O(t)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Прямой перебор всех чисел от $l$ до $r$ не подходит: даже один отрезок может содержать порядка $10^{18}$ чисел. Значит, нужно считать подходящие числа сразу группами.

Сначала заметим, что условие задачи связано только с **последней цифрой** числа. Зафиксируем её и обозначим через $d$, где $1 \le d \le 9$. Все числа с такой последней цифрой представляются в виде

$x=d+10m$,

где $m$ — целое неотрицательное число, образованное остальными цифрами десятичной записи.

Число $x$ удачно тогда и только тогда, когда оно делится на $d$. Подставим найденное представление:

$d \mid d+10m$.

Первое слагаемое уже делится на $d$, поэтому условие равносильно следующему:

$d \mid 10m$.

Обозначим $g=\text{НОД}(d,10)$ и представим $d=ga$, $10=gb$. После сокращения получаем $a \mid bm$. При этом $\text{НОД}(a,b)=1$, а значит, множитель $a$ обязан целиком содержаться в $m$. Иными словами,

$m$ делится на $\dfrac{d}{\text{НОД}(d,10)}$.

Обозначим это значение через $s_d$:

$s_d=\dfrac{d}{\text{НОД}(d,10)}$.

Тогда $m=ks_d$ для некоторого целого $k \ge 0$, а все удачные числа с последней цифрой $d$ имеют вид

$x=d+10ks_d$.

Таким образом, для каждой цифры возникает арифметическая прогрессия. Осталось посчитать, сколько её членов не превосходят границу $R$:

$d+10ks_d \le R$.

Если $R<d$, подходящих чисел с такой последней цифрой нет. Иначе

$k \le \left\lfloor\dfrac{R-d}{10s_d}\right\rfloor$.

Допустимые значения начинаются с нуля, поэтому количество подходящих значений $k$ равно

$\left\lfloor\dfrac{R-d}{10s_d}\right\rfloor+1$.

Просуммируем это количество по всем $d$ от $1$ до $9$. Так получим функцию $F(R)$ — число удачных чисел, не превосходящих $R$.

Теперь любой запрос на отрезке восстанавливается стандартной разностью префиксов:

$\text{answer}(l,r)=F(r)-F(l-1)$.

**Почему подсчёт корректен?**

- Каждое построенное число заканчивается цифрой $d$, поскольку отличается от неё на число, кратное $10$.
- Оно делится на $d$, так как выбранное значение $m=ks_d$ гарантирует делимость $10m$ на $d$.
- Любое удачное число имеет некоторую единственную последнюю цифру $d$ от $1$ до $9$. Из условия $d \mid 10m$ следует, что $m$ делится на $s_d$, поэтому такое число обязательно встретится в соответствующей прогрессии.
- Число не может попасть в две разные группы, поскольку его последняя цифра определяется однозначно.

Следовательно, перебор девяти прогрессий учитывает все удачные числа и не создаёт повторов.

Для каждого запроса выполняется девять итераций, поэтому временная сложность равна $O(9t)=O(t)$, а дополнительная память — $O(1)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
using namespace std;
using ll = long long;
ll solve(ll r) {
    // число x можно представить в виде: x = d + 10*(other_digits)
```

## C. Общая фотография

<details><summary><b>Постановка задачи</b></summary>

Даны неотрицательные числа $a$, $b$, $c$ и число $k$, где $n=a+b+c \ge 1$ и $0 \le k<n$.

Требуется построить строку длины $n$, содержащую:

- $a$ букв `A`;
- $b$ букв `B`;
- $c$ букв `C`;
- $k$ соседних пар одинаковых букв.

Если такая строка существует, нужно вывести `YES` и **любой** подходящий вариант. Если составить строку невозможно, следует вывести `NO`.

</details>

<details><summary><b>Основная идея</b></summary>

Разобьём строку на **серии одинаковых букв**. Серия длины $\ell$ содержит $\ell-1$ пар одинаковых соседних символов. Если всего серий $g$, то количество таких пар равно

$k=\sum_i(\ell_i-1)=n-g$.

Следовательно, требуется получить $g=n-k$ серий.

Сначала будем строить строку с **максимальным количеством серий**, то есть по возможности чередовать буквы. Если самой частой буквы $m=\max(a,b,c)$, а остальных букв в сумме $q=n-m$, максимальное число серий равно

$g_{\max}=\min(n,2q+1)$.

После построения максимального разбиения будем уменьшать число серий по одной: удалять крайнюю серию и прибавлять её длину к другой серии той же буквы. Процесс продолжается, пока не останется требуемое количество серий либо дальнейшее объединение станет невозможным.

Асимптотика по времени **$O(n)$**, дополнительная память — **$O(n)$**.

</details>

<details><summary><b>Детальный разбор</b></summary>

Главная трудность состоит в том, что условие задано через соседние позиции. Если расставлять символы по одному и отслеживать количество совпавших пар, возникает слишком много вариантов. Вместо отдельных позиций рассмотрим **максимальные непрерывные серии одинаковых букв**.

Пусть длины серий равны $\ell_1,\ell_2,\ldots,\ell_g$. Внутри серии длины $\ell_i$ находятся $\ell_i-1$ одинаковых соседних пар, а между соседними сериями буквы различаются. Поэтому общее количество совпавших пар равно

$k=\sum_i(\ell_i-1)=\sum_i\ell_i-g=n-g$.

Отсюда сразу получаем необходимое количество серий:

$g=n-k$.

Теперь задача сводится к построению строки из заданного числа серий.

Сначала заметим, сколько серий вообще можно получить. Пусть буква с максимальной частотой встречается $m$ раз, а две остальные — суммарно $q=n-m$ раз.

Если $m \le q$, все символы можно расставить по одному, чередуя буквы. В таком случае каждая серия состоит из одного символа, поэтому число серий равно $n$.

Если $m>q$, части самой частой буквы приходится разделять остальными буквами. Из $q$ разделителей можно получить не более $q+1$ частей этой буквы:

`X ... X ... X ... X`

Вместе с сериями остальных букв получится не более $2q+1$ серий. Следовательно,

$g_{\max}=\min(n,2q+1)$.

Чтобы достичь этого максимума, отделим от самой частой буквы начальную серию длины

$\delta=m-q$,

если это число положительно. После этого самой частой буквы останется $q$ экземпляров — столько же, сколько всех остальных букв вместе. Оставшиеся символы уже можно чередовать, помещая каждый в отдельную серию.

Для такого чередования будем каждый раз выбирать самую многочисленную букву, отличную от буквы последней серии. После выделения начальной серии количества сбалансированы, поэтому очередной допустимый символ находится, пока символы не закончатся. В результате:

- начальная серия имеет длину $\delta$, если она потребовалась;
- каждая следующая серия состоит из одного символа;
- число полученных серий максимально.

Если серий оказалось меньше, чем $g=n-k$, ответа не существует: увеличить их количество уже нельзя.

Остаётся научиться уменьшать число серий. Пусть крайняя серия имеет букву `X`. Если в строке существует ещё одна серия `X`, крайнюю серию можно удалить, а её длину прибавить к любой оставшейся серии `X`. Количество каждой буквы сохраняется, а общее число серий уменьшается на единицу.

При этом соседние серии по-прежнему имеют разные буквы:

- удаляется только крайняя серия, поэтому две внутренние серии не становятся соседями;
- у выбранной внутренней серии меняется длина, но не буква.

Может оказаться, что буква последней серии больше нигде не встречается. Тогда посмотрим на другой конец последовательности, развернув список серий.

Почему хотя бы один конец подходит, пока объединение ещё возможно? В последовательности используются только три буквы. Если буквы обеих крайних серий встречаются по одному разу, все внутренние серии могут состоять только из третьей буквы. Однако две соседние серии не могут иметь одинаковую букву, поэтому внутренних серий в таком случае не больше одной. Значит, каждая используемая буква уже представлена единственной серией, и дальнейшее уменьшение их количества действительно невозможно.

Итак, пока число серий превышает количество различных присутствующих букв, одна из крайних букв обязательно встречается ещё где-либо. Разворачивая последовательность при необходимости, будем удалять подходящую крайнюю серию и объединять её с другой серией той же буквы. Каждая операция уменьшает число серий на единицу, поэтому будут получены все допустимые значения от $g_{\max}$ до минимально возможного числа серий.

Если процесс остановился раньше значения $g=n-k$, требуемая строка не существует. Иначе после объединений остаётся нужное число серий, а значит, количество одинаковых соседних пар равно

$n-g=n-(n-k)=k$.

При построении и объединении создаётся и удаляется не более $O(n)$ серий. Сортируется массив всего из трёх элементов, поэтому каждая такая сортировка занимает постоянное время. Развороты списка также не меняют итоговую оценку: после выбора подходящего конца повторный разворот до достижения минимального числа серий не требуется. Таким образом, время работы составляет **$O(n)$**, а список серий и итоговая строка занимают **$O(n)$** памяти.

</details>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
#define all(x) (x).begin(),(x).end()
#define isz(x) (int)(x).size()
using namespace std;
using ll = long long;
void solve() {
    int a, b, c, k;
    cin >> a >> b >> c >> k;
    int n = a + b + c;
    // нужно определить, можно ли, чередуя группы из одинаковых букв с длинами len[i], получить:
    // sum(len[i]-1) = k => n - nGroups = k => nGroups = n - k. То есть, мы знаем количество групп.
    int nGroups = n - k;
    // попробуем сначала получить максимальное количество групп, затем объединить некоторые группы в одну
    // первую группу нам нужно построить аналитически: берём букву с максимальным количеством
    vector<pair<int,char>> rem{{a,'A'},{b,'B'},{c,'C'}};
    sort(rem.begin(), rem.end(), greater<>());
    int mx = rem[0].first;
    int sum = rem[1].first + rem[2].first;
    // чтобы суметь разделить, нам нужно сделать mx <= sum
    vector<pair<int,char>> answ;
    if (int delta = mx - sum; delta > 0) {
        answ.emplace_back(delta, rem[0].second);
        rem[0].first -= delta;
    }
    // теперь первая группа построена. для каждой следующей группы отделяем один символ
    // с максимальным количеством и ставим группу с одним элементом:
    while (true) {
        sort(rem.begin(), rem.end(), greater<>());
        bool was = false;
        for (auto &[cnt, letter] : rem)
            if (cnt > 0 && (answ.empty() || answ.back().second != letter)) {
                answ.emplace_back(1, letter);
                cnt--;
                was = true;
                break;
            }
        if (!was) break;
    }
    if (isz(answ) < nGroups) {
        cout << "NO\n";
        return;
    }
    // теперь нужно уменьшать количество групп, объединяя похожие. сохраняем номера групп для каждой буквы
    reverse(all(answ));
    map<char, vector<int>> ids;
    for (int i = 0; const auto &[cnt, letter] : answ) {
        ids[letter].push_back(i);
        i++;
    }
    // объединяем группы, отделяя последнюю и сливая её с любой другой группой той же буквы
    while (isz(answ) > nGroups) {
        // берём последнюю группу и сливаем её
        if (ids[answ.back().second].size() == 1) {
            // но если не можем слить, смотрим с другого конца
            reverse(all(answ));
            ids.clear();
            for (int i = 0; const auto &[cnt, letter] : answ)
                ids[letter].push_back(i++);
        }
        auto [lastCnt, lastLetter] = answ.back();
        answ.pop_back();
        ids[lastLetter].pop_back();
        if (ids[lastLetter].size()) {
            int i = ids[lastLetter].front();
            answ[i].first += lastCnt;
        } else {
            cout << "NO\n";
            return;
        }
```

## D. Дуэль за десертом

<details><summary><b>Постановка задачи</b></summary>

На двух тарелках лежат $a$ и $b$ пирожных, где $0 \le a,b \le 200$ и $a+b \ge 1$. Два игрока ходят по очереди. За один ход разрешается:

- съесть любое положительное количество пирожных с одной тарелки;
- съесть с обеих тарелок по $s^2$ пирожных для некоторого целого $s \ge 1$.

Побеждает игрок, съевший последнее пирожное.

Нужно сыграть с жюри $t$ партий. Перед каждой партией разрешается выбрать, кто ходит первым. Требуется **гарантированно выиграть каждую партию**, независимо от действий соперника.

Задача интерактивная: после каждого хода необходимо переводить строку и сбрасывать буфер вывода. Если получена пара `-1 -1`, программа должна немедленно завершиться.

</details>

<details><summary><b>Основная идея</b></summary>

Каждая позиция полностью определяется количеством пирожных на двух тарелках — парой $(a,b)$. Любой ход уменьшает сумму $a+b$, поэтому результат позиции зависит только от уже рассмотренных позиций с меньшей суммой.

Позиция является **выигрышной**, если существует ход в проигрышную позицию. Если такого хода нет, позиция проигрышная. Вместе с признаком выигрышности будем хранить конкретный победный ход.

Все позиции с $0 \le a,b \le 200$ заранее вычислим в порядке возрастания $a+b$. Если начальная позиция проигрышная, выберем второй ход; иначе начнём первыми и сразу переведём игру в проигрышную позицию. После каждого ответа жюри снова будем возвращать игру в проигрышное состояние.

При максимальном количестве пирожных $M=200$ предвычисление работает за $O(M^3)$ и использует $O(M^2)$ памяти. Ответный ход во время взаимодействия находится за $O(1)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Пытаться подобрать стратегию непосредственно во время партии рискованно: возможные ходы имеют разный вид, а жюри вправе отвечать в зависимости от наших действий. Вместо анализа отдельных партий заметим, что количество возможных состояний невелико: на каждой тарелке лежит не более $200$ пирожных.

**Состоянием игры** назовём пару $(a,b)$. Из неё существуют три вида переходов:

- $(a,b) \to (a-x,b)$ для любого $1 \le x \le a$;
- $(a,b) \to (a,b-y)$ для любого $1 \le y \le b$;
- $(a,b) \to (a-s^2,b-s^2)$, если $s^2 \le \min(a,b)$.

Каждый переход уменьшает сумму пирожных. Следовательно, игра не может продолжаться бесконечно, а при разборе позиции $(a,b)$ результаты всех состояний, в которые разрешено перейти, уже можно знать, если обрабатывать позиции по возрастанию $a+b$.

Начнём с позиции $(0,0)$. Игрок, которому в ней нужно ходить, уже не может сделать ход: предыдущий игрок съел последние пирожные. Поэтому $(0,0)$ — **проигрышная позиция**.

Для любой другой пары $(a,b)$ возможны два случая:

- если существует допустимый переход в проигрышную позицию, текущая позиция выигрышная: достаточно сделать этот переход;
- если каждый допустимый ход ведёт в выигрышную позицию, текущая позиция проигрышная: какой бы ход ни был выбран, соперник получит состояние, из которого умеет победить.

Для выигрышной позиции нам нужен не только её тип, но и конкретный ход. Поэтому в таблице будем хранить пару $(x,y)$, которую следует сыграть. Пара $(0,0)$ служит обозначением проигрышного состояния. Такое обозначение однозначно, поскольку ход, не съедающий ни одного пирожного, запрещён.

Чтобы определить состояние $(a,b)$, переберём все допустимые действия:

1. все количества пирожных, которые можно снять с первой тарелки;
2. все количества, которые можно снять со второй тарелки;
3. все квадраты $s^2$, которые можно одновременно снять с обеих тарелок.

Если хотя бы один переход ведёт в состояние, отмеченное парой $(0,0)$, сохраним соответствующий ход. Если ни одного такого перехода нет, в таблице останется $(0,0)$.

**Корректность предвычисления** следует по индукции по сумме $a+b$. База $(0,0)$ определена верно. Рассмотрим позицию с положительной суммой и предположим, что все состояния с меньшей суммой классифицированы правильно. Перебор охватывает каждый допустимый ход из текущей позиции. Если найден переход в проигрышное состояние, игрок может выбрать его и победить. Если такого перехода нет, любой ход отдаёт сопернику выигрышную позицию, а значит, текущая позиция проигрышная. Таким образом, таблица верно определяет тип каждой позиции и хранит допустимый победный ход для каждого выигрышного состояния.

Осталось превратить эту классификацию в стратегию взаимодействия.

- Если начальная позиция проигрышная, будем ходить вторыми.
- Если она выигрышная, выберем первый ход из таблицы и передадим жюри проигрышную позицию.
- После каждого хода жюри состояние становится выигрышным. Действительно, из проигрышной позиции не существует перехода в другую проигрышную позицию. Поэтому в таблице обязательно найдётся ответ, снова переводящий игру в проигрышное состояние.

После каждого хода количество пирожных уменьшается, так что партия неизбежно заканчивается. Жюри не может своим ходом опустошить обе тарелки: это означало бы переход из проигрышной позиции в проигрышную позицию $(0,0)$, а такого перехода по определению нет. Значит, последние пирожные съедим мы.

Всего существует $O(M^2)$ состояний. Для каждого из них перебирается $O(M)$ действий с одной тарелки и $O(\sqrt M)$ совместных ходов, поэтому время предвычисления равно $O(M^3)$, а память — $O(M^2)$. Во время партии каждый ответ извлекается из таблицы за $O(1)$.

</details>

```cpp
for (int x = 1; x * x <= std::min(a, b); x++)
    if (int xx = x*x; table[a-xx][b-xx] == lose) {
        step = {xx, xx};
        break;
    }
```

Здесь `x` обозначает сторону квадрата, а `xx` — количество пирожных, снимаемых с каждой тарелки. Условие `x * x <= std::min(a, b)` гарантирует, что на обеих тарелках достаточно пирожных.

```cpp
if (table[a][b] == lose) {
    cout << "Second" << endl;
} else {
    cout << "First" << endl;
    auto [x,y] = table[a][b];
    cout << x << ' ' << y << endl;
    a -= x, b -= y;
}
```

Из проигрышной начальной позиции выбирается второй ход. Если позиция выигрышная, из таблицы извлекается переход в проигрышное состояние, после чего локальные значения `a` и `b` уменьшаются. Они всегда отражают текущее положение в партии.

`endl` не только переводит строку, но и сбрасывает буфер вывода, что необходимо для интерактивного протокола.

```cpp
while (a+b>0) {
    // ход жюри:
    int x, y; cin >> x >> y;
    a -= x, b -= y;
    // наш ход:
    tie(x,y) = table[a][b];
    cout << x << ' ' << y << endl;
    a -= x, b -= y;
}
```

Перед ходом жюри позиция проигрышна. После его допустимого действия получается выигрышное состояние, поэтому `table[a][b]` содержит ответный ход. Функция `tie` записывает обе координаты сохранённой пары в уже существующие переменные `x` и `y`.

После нашего ответа игра снова находится в проигрышной позиции. Цикл заканчивается, когда обе тарелки опустели в результате нашего хода.

</details>

<details><summary><b>Разбор сложных фрагментов кода на Python</b></summary>

```python
lose = (0,0)
table = [[lose for b in range(201)] for a in range(201)]
```

Кортеж `(0,0)` служит отметкой проигрышной позиции. Такой ход запрещён правилами, поэтому ненулевая пара всегда однозначно обозначает сохранённый победный переход.

Внешнее списковое включение создаёт отдельную строку таблицы для каждого значения `a`. Заполнение одним и тем же кортежем безопасно, поскольку кортежи неизменяемы.

```python

    for a in range(201):

        if 0 <= b <= 200:
            step = lose
```

Состояния перебираются по сумме координат. Все допустимые ходы ведут к меньшей сумме, поэтому необходимые значения таблицы к этому моменту уже найдены. Проверка границ отбрасывает пары, для которых вычисленное значение `b` не попадает в допустимый диапазон.

```python

    if table[a-x][b] == lose:
        step = (x,0)
        break
# ход 2. берём со второй тарелки
```

Два цикла перебирают все ходы, затрагивающие одну тарелку. Если новое состояние проигрышно, соответствующая пара сохраняется в `step`.

Второй цикл может заменить переход, найденный первым. Оба варианта подходят: каждый сохранённый ход передаёт сопернику проигрышную позицию.

```python

    xx = x*x
    if table[a-xx][b-xx] == lose:
        step = (xx,xx)
        break
    x += 1
```

Переменная `x` перебирает положительные целые числа, а `xx` содержит их квадраты. С обеих тарелок снимается именно `xx` пирожных. Ограничение цикла не позволяет снять больше пирожных, чем есть хотя бы на одной из тарелок.

```python
if table[a][b] == lose:
```

Если начальное состояние проигрышно, выбирается игра вторым номером. В противном случае из таблицы берётся победный первый ход.

Параметр `flush=True` немедленно отправляет каждую строку интерактору. Без сброса буфера жюри могло бы не получить ответ и не передать следующий ход.

```python

    x, y = map(int,input().split())
    a -= x; b -= y
    # наш ход:

```

Значения `a` и `b` постоянно поддерживают текущее состояние партии. После хода жюри из таблицы извлекается ответ, возвращающий игру в проигрышную позицию. После собственного хода координаты также уменьшаются; когда их сумма становится нулевой, партия завершена нашей победой.

## E. Отчёт об отключениях

<details><summary><b>Постановка задачи</b></summary>

Дан неориентированный граф из $n$ районов и $m$ кабелей. Кабели могут соединять район с самим собой; кроме того, между одной парой районов может проходить несколько кабелей.

В $k$ попарно различных районах находятся электростанции. Район получает электричество, если по исправным кабелям из него можно добраться хотя бы до одной электростанции.

Изначально исправны все кабели. Затем $q$ попарно различных кабелей выходят из строя в заданном порядке. Требуется после каждой аварии вывести количество районов, которые всё ещё получают электричество.

</details>

<details><summary><b>Основная идея</b></summary>

Поддерживать компоненты связности при удалении рёбер сложно: после удаления одного кабеля компонента может распасться на несколько частей. Зато **добавление рёбер** легко обрабатывается системой непересекающихся множеств.

Поэтому будем рассматривать аварии **в обратном порядке**. Сначала оставим только те кабели, которые не выходили из строя. Это состояние города после всех аварий. Затем будем возвращать сломанные кабели, двигаясь от последней аварии к первой.

Для каждой компоненты связности будем хранить:

- её размер;
- наличие в ней хотя бы одной электростанции.

Также будем поддерживать сумму размеров всех компонент с электростанциями — это и есть количество районов с электричеством.

Время работы — $O((n+m)\alpha(n))$, память — $O(n+m)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Главная трудность задачи связана с тем, что кабели **удаляются**. Если удалённый кабель был единственным путём между двумя частями компоненты, она распадается. Обычная система непересекающихся множеств не умеет находить новые компоненты после такого разрыва.

Однако порядок запросов известен заранее. Посмотрим на процесс с конца: удаление кабеля превращается в его добавление. При добавлении ребра возможны только два случая:

- его концы уже принадлежат одной компоненте — связность не меняется;
- его концы находятся в разных компонентах — эти компоненты объединяются.

Оба случая естественно обрабатываются системой непересекающихся множеств.

Обозначим через $G_i$ состояние графа после первых $i$ аварий. Тогда:

- $G_q$ содержит только кабели, которые не ломались;
- если в $G_i$ вернуть кабель, сломавшийся во время $i$-й аварии, получится $G_{i-1}$.

Значит, начнём с $G_q$, а затем будем восстанавливать кабели в порядке $e_q,e_{q-1},\ldots,e_1$.

Осталось научиться быстро определять количество районов с электричеством. В пределах одной компоненты связности возможны два варианта:

- если в компоненте есть электростанция, электричество получают все её районы;
- если электростанции нет, ни один район этой компоненты электричество не получает.

Следовательно, для каждой компоненты достаточно знать **размер** и **наличие электростанции**. Будем поддерживать величину $\text{answ}$, равную сумме размеров всех компонент, содержащих электростанцию.

При объединении компонент сначала удалим из $\text{answ}$ их прежние вклады. После объединения компоненту считаем подключённой к электричеству, если электростанция находилась хотя бы в одной из двух частей. Затем добавим размер новой компоненты, если она получает электричество.

Такое обновление правильно работает во всех сочетаниях:

- две компоненты без электростанций не влияют на ответ;
- при объединении подключённой и неподключённой компонент к ответу добавляются районы второй компоненты;
- при объединении двух подключённых компонент их районы не должны учитываться повторно, поэтому сначала вычитаются оба прежних вклада, а затем один раз добавляется размер объединённой компоненты.

Сначала отметим все кабели, перечисленные среди аварий. Все остальные кабели присутствуют в $G_q$, поэтому добавим их в структуру данных.

Далее для $i$ от $q$ до $1$ поддерживается следующий инвариант: **перед восстановлением кабеля $e_i$ структура описывает граф $G_i$**. Поэтому текущее значение $\text{answ}$ является ответом после $i$-й аварии. Запишем его, вернём кабель $e_i$ и получим состояние $G_{i-1}$. Ответы записываются с конца, поэтому перед выводом их порядок разворачивается.

Петля, соединяющая район с самим собой, не меняет компоненту: оба её конца имеют одного представителя. Несколько кабелей между одной парой районов также не создают проблем — добавление очередного такого кабеля может оказаться объединением уже связанных вершин и тогда ничего не изменит.

Каждый кабель обрабатывается не более одного раза, а каждая операция системы непересекающихся множеств с эвристикой объединения по размеру и сжатием путей работает за амортизированное $O(\alpha(n))$. Поэтому время работы равно $O((n+m)\alpha(n))$, так как $q\le m$. Для хранения рёбер, запросов и структуры данных требуется $O(n+m)$ памяти.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
using namespace std;
// структура данных "система непересекающихся множеств": в каждом поддереве храним размер, представителя,
// а также флаг: есть ли электростанция в данном поддереве или нет. Ответ на задачу будем поддерживать
// и обновлять после каждого запроса.
struct DSU {
    vector<int> par, sz, enabled;
    int answ{};
    DSU(int n) : par(n+1), sz(n+1, 1), enabled(n+1, false)
    {
        for (int i = 1; i <= n; i++)
            par[i] = i;
    }
    int getPar(int u) {
        return (u == par[u] ? u : (par[u] = getPar(par[u])));
    }
    // размещение электростанции:
    void enable(int i) {
        i = getPar(i);
        enabled[i] = true;
        answ += sz[i];
    }
    // проведение ребра и обновление ответа:
    void connect(int u, int v) {
        u = getPar(u), v = getPar(v);
        if (u == v) return;
        if (sz[u] < sz[v]) swap(u, v);
        if (enabled[u]) answ -= sz[u];
        if (enabled[v]) answ -= sz[v];
        sz[u] += sz[v];
        par[v] = u;
        enabled[u] |= enabled[v];
        if (enabled[u]) answ += sz[u];
    }
};
void solve() {
    // чтение всех данных:
    int n, m, k; cin >> n >> m >> k;
    vector<int> p(k);
    for (auto &it : p) cin >> it;
    vector<pair<int,int>> edges(m);
    for (auto &[u, v] : edges)
        cin >> u >> v;
    int q; cin >> q;
    vector<int> queries(q), usedEdges(m);
    for (auto &it : queries) {
        cin >> it, it--;
        usedEdges[it] = 1;
    }
    // вместо удалений будем рассматривать запросы с конца в начало и добавлять рёбра в граф
    // используем структуру данных "система непересекающихся множеств", которая поддерживает
    // все операции, касающиеся добавления рёбер.
    DSU dsu(n);
    // устанавливаем электростанции:
    for (int i : p)
        dsu.enable(i);
    // проводим рёбра, которые никогда не будут удалены:
    for (int i = 0; i < m; i++)
        if (!usedEdges[i]) {
            auto [u, v] = edges[i];
            dsu.connect(u, v);
        }
    // теперь добавляем рёбра с конца в начало:
    vector<int> answ;
    for (int i = q-1; i >= 0; i--) {
        answ.push_back(dsu.answ);
        int id = queries[i];
        auto [u, v] = edges[id];
        dsu.connect(u, v);
    }
    // выводим ответ:
    for (int i = q-1; i >= 0; i--)
        cout << answ[i] << ' ';
    cout << '\n';
}
int32_t main() {
    cin.tie(0)->sync_with_stdio(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
    return 0;
}
```

```python
        self.answ = 0
```

Функция находит представителя компоненты и одновременно выполняет **сжатие путей**. После рекурсивного поиска вершина `u` начинает ссылаться непосредственно на корень, благодаря чему последующие обращения работают быстрее.

Флаг `enabled` хранится только для представителя компоненты. Электростанции отмечаются до добавления кабелей, поэтому каждая из них сначала образует отдельную компоненту размера один. После этого информация о наличии станции переносится при объединениях.

```cpp

    if (u == v) return;
    if (sz[u] < sz[v]) swap(u, v);
```

После поиска представителей проверяется, принадлежат ли вершины разным компонентам. Если да, меньшая компонента присоединяется к большей.

Перед слиянием из `answ` вычитаются прежние вклады обеих компонент. Флаг новой компоненты вычисляется операцией логического «или»: электричество в ней есть, если электростанция находилась хотя бы в одной части. После этого размер объединённой компоненты добавляется в ответ один раз.

Ответы накапливались от последней аварии к первой. Обратный проход восстанавливает требуемый хронологический порядок.

<details><summary><b>Разбор сложных фрагментов кода на Python</b></summary>

```python
def getPar(self,u):
    if u != self.par[u]:
        self.par[u] = self.getPar(self.par[u])
    return self.par[u]
```

Метод рекурсивно находит представителя компоненты. Присваивание результата в `self.par[u]` выполняет **сжатие путей**: после поиска вершина ссылается непосредственно на корень своей компоненты.

```python
def enable(self,i):
    i = self.getPar(i)
    self.enabled[i] = True
    self.answ += self.sz[i]
```

Признак наличия электростанции хранится у представителя компоненты. На момент вызова `enable` кабели ещё не добавлены, поэтому район с электростанцией является отдельной компонентой. Его размер сразу включается в число районов с электричеством.

```python
def connect(self,u,v):
    u, v = self.getPar(u), self.getPar(v)
    if u == v: return
    if self.sz[u] < self.sz[v]: u, v = v, u
    if self.enabled[u]: self.answ -= self.sz[u]
    if self.enabled[v]: self.answ -= self.sz[v]
    self.sz[u] += self.sz[v]
    self.par[v] = u
    self.enabled[u] |= self.enabled[v]
    if self.enabled[u]: self.answ += self.sz[u]
```

Если представители совпадают, добавленный кабель не меняет связность. Иначе меньшая компонента присоединяется к большей.

До объединения из `self.answ` удаляются вклады подключённых компонент. После слияния флаг `self.enabled[u]` показывает, находилась ли электростанция хотя бы в одной из них. Если да, полный размер новой компоненты возвращается в ответ.

```python
usedEdges = [0] * m
for i in range(q):
    queries[i] -= 1
    usedEdges[queries[i]] = 1
```

Индексы кабелей переводятся из нумерации от единицы к нумерации от нуля. Одновременно отмечаются все кабели, участвующие в авариях: в начальном состоянии обратного процесса они должны отсутствовать.

```python
for i in range(m):
    if not usedEdges[i]:
        u, v = edges[i]
        dsu.connect(u,v)
```

Добавляются все кабели, которые не выходили из строя. После этого структура описывает граф, оставшийся после всех аварий.

```python
answ = []
for i in range(q-1,-1,-1):
    answ.append(dsu.answ)
    id = queries[i]
    u, v = edges[id]
    dsu.connect(u,v)
```

Индекс `i` движется от последней аварии к первой. Перед добавлением кабеля текущее значение `dsu.answ` соответствует состоянию сразу после его поломки. Затем кабель восстанавливается, и структура переходит к предыдущему состоянию города.

```python

```

Срез `answ[::-1]` разворачивает накопленные ответы, чтобы вывести их в исходном порядке аварий.

## F. Фестиваль огней

<details><summary><b>Постановка задачи</b></summary>

В ряд расположены $n$ фонарей с номерами от $1$ до $n$. Расстояние между фонарями с номерами $i$ и $j$ равно $|i-j|$.

Требуется выбрать множество из **$k$ фонарей** так, чтобы среди выбранных не было пары, расстояние между элементами которой равно $d$.

Для каждого набора входных данных нужно найти количество подходящих множеств по модулю $10^9+7$.

Ограничения: $1 \le n \le 2000$, $0 \le k \le n$, $1 \le d \le 10^9$. Сумма $n$ по всем наборам не превосходит $2000$.

</details>

<details><summary><b>Основная идея</b></summary>

Два фонаря конфликтуют лишь тогда, когда их номера отличаются на $d$. Поэтому фонари с разными остатками при делении на $d$ **никак не влияют друг на друга**.

Внутри одного класса остатков номера идут с шагом $d$. Запрещено выбирать два соседних элемента такой последовательности, то есть каждый класс превращается в путь. Для пути длины $s$ динамикой посчитаем количество способов выбрать $t$ вершин без соседних выбранных.

После этого объединим независимые классы второй динамикой: будем распределять требуемые $k$ фонарей между группами и перемножать количества способов.

Если $d \ge n$, конфликтующих пар вообще нет, поэтому ответ равен $\binom{n}{k}$.

**Время работы:** $O(nk)$ на набор данных.  
**Память:** $O(nk)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Перебирать все множества из $k$ фонарей нельзя: их число равно $\binom{n}{k}$ и может быть огромным. Значит, нужно воспользоваться тем, что запрещены не произвольные пары, а только пары с разностью индексов $d$.

Сначала заметим: если фонари $i$ и $j$ образуют запрещённую пару, то $j=i+d$. Следовательно, их номера имеют одинаковый остаток при делении на $d$.

Разделим все фонари на группы:

- в первую попадут $1,1+d,1+2d,\ldots$;
- во вторую — $2,2+d,2+2d,\ldots$;
- и так далее.

**Между разными группами конфликтов нет.** Внутри одной группы конфликтуют соседние элементы последовательности, поскольку разность их номеров равна $d$. Элементы, между которыми в группе есть хотя бы один другой фонарь, отличаются не менее чем на $2d$ и выбирать их вместе разрешено.

Таким образом, каждая группа представляет собой путь, в котором нельзя выбирать соседние вершины.

Если $d \ge n$, максимальное расстояние между фонарями равно $n-1<d$. Ограничение ничего не запрещает, поэтому подходят все множества размера $k$, а их количество равно $\binom{n}{k}$.

Теперь рассмотрим случай $d<n$. Нам потребуется узнать, сколькими способами можно выбрать $t$ несоседних элементов из последовательности длины $i$.

Будем хранить два состояния:

- $\text{dp}[i][t][0]$ — число способов выбрать $t$ элементов среди первых $i$, если элемент $i$ не выбран;
- $\text{dp}[i][t][1]$ — число способов выбрать $t$ элементов среди первых $i$, если элемент $i$ выбран.

Для пустой последовательности существует один способ ничего не выбрать:

$\text{dp}[0][0][0]=1$.

Если элемент $i$ не выбирается, предыдущий элемент мог быть как выбран, так и не выбран:

$\text{dp}[i][t][0]=\text{dp}[i-1][t][0]+\text{dp}[i-1][t][1]$.

Если элемент $i$ выбирается, элемент $i-1$ обязан остаться невыбранным:

$\text{dp}[i][t+1][1]=\text{dp}[i-1][t][0]$.

Обе формулы рассматривают все допустимые варианты и не создают запрещённых соседних пар. Значит, для группы размера $s$ количество способов выбрать $t$ фонарей равно

$\text{ways}(s,t)=\text{dp}[s][t][0]+\text{dp}[s][t][1]$.

Остаётся соединить ответы независимых групп. Пусть $\text{combined}[i][j]$ обозначает число способов выбрать $j$ фонарей среди первых $i$ групп.

Изначально групп ещё нет, поэтому

$\text{combined}[0][0]=1$.

Рассмотрим следующую группу размера $s$. Если из неё берётся $\text{take}$ фонарей, а в предыдущих группах уже выбрано $\text{prev}$ фонарей, то к значению $\text{combined}[i+1][\text{prev}+\text{take}]$ прибавляется

$\text{combined}[i][\text{prev}]\cdot\text{ways}(s,\text{take})$.

Группы независимы, поэтому количества способов перемножаются. Перебор всех значений $\text{take}$ рассматривает каждое возможное распределение выбранных фонарей между группами. При этом любое допустимое множество однозначно разбивается на подмножества внутри классов остатков, так что ни один вариант не теряется и не учитывается повторно.

Размеры групп различаются не более чем на единицу. Если $n=qd+r$, то первые $r$ групп имеют размер $q+1$, а остальные — $q$.

После обработки всех $d$ групп ответ находится в $\text{combined}[d][k]$.

Первая динамика требует $O(nk)$ операций. Для группы размера $s$ объединение занимает $O(k\min(k,s))$ времени. Сумма размеров всех групп равна $n$, поэтому суммарное время объединения также укладывается в $O(nk)$. Объём памяти равен $O(nk)$.

</details>

Индекс `2*t` обозначает состояние, в котором выбрано $t$ элементов, а последний не выбран. В него ведут оба состояния предыдущей длины.

При выборе нового элемента количество выбранных увеличивается до $t+1$, а последний элемент получает состояние `1`. Его индекс равен $2(t+1)+1=2t+3$. Такой переход разрешён лишь из индекса `2*t`, соответствующего невыбранному предыдущему элементу.

```python
combined = [array('i', [0])*(k+1) for _ in range(d+1)]
combined[0][0] = 1
for i in range(d):
    gsize = n//d+(i < n%d)
```

`combined[i][j]` хранит число способов выбрать $j$ фонарей из первых $i$ групп. Логическое выражение `i < n%d` в Python имеет числовое значение `0` или `1`. Поэтому при делении $n$ элементов на $d$ групп первые `n%d` групп получают размер `n//d+1`, остальные — `n//d`.

```python
for take in range(min(k, gsize)+1):
    ways = (dp[gsize][2*take]+dp[gsize][2*take+1])%mod
    for prev in range(k-take+1):
        combined[i+1][prev+take] = add(combined[i+1][prev+take], mul(combined[i][prev], ways))
```

Для выбранного значения `take` складываются состояния, в которых последний элемент группы не взят или взят. Затем группа присоединяется к уже обработанным: число способов для независимых частей перемножается, а количества выбранных фонарей складываются.

Граница `range(k-take+1)` означает, что `prev` принимает значения до `k-take` включительно, поэтому индекс `prev+take` не выходит за пределы массива.
