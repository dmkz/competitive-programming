## A. Кофейный автомат

<details><summary><b>Постановка задачи</b></summary>

В автомате хранятся монеты достоинством $1$, $2$, $5$, $10$, $20$ и $50$ рублей. Для каждого достоинства известно начальное количество монет.

Покупатели обслуживаются **строго по очереди**. Каждый покупатель выбирает напиток стоимостью $p$ рублей и опускает некоторое количество монет каждого достоинства.

- Если внесённая сумма меньше $p$, покупка отклоняется, а содержимое автомата не меняется.
- Иначе внесённые монеты сначала попадают в автомат, после чего тот пытается выдать сдачу.
- Сдача выдаётся жадно: сначала используется максимально возможное количество монет по $50$ рублей, затем по $20$, $10$, $5$, $2$ и $1$ рублю.
- Если таким способом не удаётся набрать точную сумму сдачи, покупка отклоняется, внесённые монеты возвращаются, а состояние автомата полностью восстанавливается.
- При успешной покупке использованные для сдачи монеты удаляются из автомата, а остальные внесённые монеты остаются в нём.

Для каждого покупателя требуется вывести `REFUSED`, если покупка отклонена. Иначе нужно вывести количество монет каждого достоинства в выданной сдаче — **в порядке возрастания номиналов**.

</details>

<details><summary><b>Основная идея</b></summary>

Способ выдачи сдачи полностью определён условием: автомат не ищет произвольный набор монет, а обязан брать номиналы **от большего к меньшему**, каждый раз выдавая максимально возможное количество.

Поэтому для каждого покупателя достаточно напрямую смоделировать работу автомата:

1. Вычислим внесённую сумму.
2. Если её недостаточно, сразу отклоним покупку.
3. Иначе сохраним прежнее состояние автомата и добавим внесённые монеты.
4. Пройдём по номиналам от $50$ до $1$ рубля, выдавая для каждого номинала столько монет, сколько позволяют запас и оставшаяся сдача.
5. Если после этого останется ненулевая сумма, восстановим сохранённое состояние. Иначе оставим получившееся состояние автомата.

Номиналов всего шесть, поэтому обработка одного покупателя занимает $O(6)$, а всех покупателей — $O(q)$. Дополнительная память равна $O(6)$, то есть фактически константна.

</details>

<details><summary><b>Детальный разбор</b></summary>

Главная особенность задачи заключается в том, что автомат выдаёт сдачу не любым подходящим набором монет. Например, он может взять крупную монету, из-за которой оставшуюся сумму уже не удастся набрать, хотя при другом выборе сдача существовала бы. Однако такой другой выбор рассматривать нельзя: порядок и количество выдаваемых монет однозначно заданы условием.

Следовательно, перебирать сочетания монет или решать задачу о размене не требуется. Нужно лишь **точно воспроизвести предписанный жадный процесс**.

Пусть покупатель внёс $u_i$ монет номинала $d_i$. Общая внесённая сумма равна

$s=\sum_{i=1}^{6}u_i d_i$.

Если $s<p$, покупатель не может оплатить напиток. Автомат не принимает его монеты, поэтому состояние остаётся прежним.

Теперь рассмотрим случай $s\ge p$. Сдача равна $r=s-p$. Важно, что внесённые монеты могут сразу попасть в сдачу, поэтому перед её выдачей будем добавлять все $u_i$ к запасам автомата.

Однако покупка ещё может завершиться отказом. Чтобы в таком случае не восстанавливать состояние сложными обратными действиями, заранее сохраним копию количества монет каждого достоинства. Тогда неудачную попытку достаточно отменить одним присваиванием.

Для очередного номинала $d_i$ автомат ограничен двумя величинами:

- в нём находится только $c_i$ таких монет;
- для сдачи нельзя выдать больше $\lfloor r/d_i\rfloor$ монет, иначе их стоимость превысит оставшуюся сумму.

Поэтому число выдаваемых монет однозначно равно

$g_i=\min(c_i,\lfloor r/d_i\rfloor)$.

После этого уменьшим остаток сдачи на $g_i d_i$, а количество монет данного номинала в автомате — на $g_i$. Номиналы будем рассматривать в порядке $50$, $20$, $10$, $5$, $2$, $1$, как и требует условие.

После обработки всех шести номиналов возможны два случая:

- **остаток равен нулю** — сдача набрана полностью, покупка успешна, а текущее состояние автомата уже учитывает и принятые, и выданные монеты;
- **остаток положителен** — жадный процесс не смог выдать точную сдачу, поэтому восстановим состояние, сохранённое до добавления монет покупателя.

Корректность такого моделирования докажем по номиналам. Перед обработкой каждого номинала текущий остаток равен той части сдачи, которую автомат ещё должен выдать, а запасы в массиве совпадают с фактическим содержимым автомата после уже выданных более крупных монет. Формула для $g_i$ выбирает в точности максимальное допустимое количество монет текущего номинала. Значит, после шага состояние снова совпадает с действиями автомата. По индукции это верно для всех шести номиналов.

Если в конце остаток равен нулю, записанный набор монет является именно той сдачей, которую обязан выдать автомат. Если остаток ненулевой, условие требует отклонить покупку, а восстановление сохранённого состояния возвращает содержимое автомата к состоянию перед приходом покупателя. Таким образом, каждый покупатель обрабатывается правильно, а значит, правильными остаются и состояния для всех следующих покупателей.

Для одного покупателя выполняется несколько проходов по шести номиналам, поэтому время работы составляет $O(6q)=O(q)$. Используются массивы фиксированного размера, следовательно, дополнительная память равна $O(6)=O(1)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
using namespace std;
using ll = long long;
void solve() {
    // читаем изначальные количества монет:
    vector<ll> c(6);
    for (auto &it : c) cin >> it;
    const vector<ll> d = {1,2,5,10,20,50};
    // читаем и отвечаем на запросы:
    int q; cin >> q;
    while (q --> 0) {
        // читаем i-й запрос:
        int p; vector<ll> u(6);
        cin >> p;
        for (auto &it : u) cin >> it;
        // считаем сумму. если суммы не хватает, то покупатель сразу уходит:
        ll s = 0;
        for (int i = 0; i < 6; i++)
            s += d[i] * u[i];
        if (s < p) {
            cout << "REFUSED\n";
            continue;
        }
        // сначала монеты попадают в автомат:
        vector<ll> saved = c;
        for (int i = 0; i < 6; i++)
            c[i] += u[i];
        // теперь мы должны выдать сдачу:
        ll r = s - p;
        vector<ll> answ(6);
        for (int i = 5; i >= 0; i--) {
            // выдаём максимальное количество монет, которое можем:
            ll cntI = std::min(c[i], r / d[i]);
            r -= d[i] * cntI;
            c[i] -= cntI;
            answ[i] = cntI;
        }
        if (r != 0) {
            // не получилось -> откатываем:
            c = saved;
            cout << "REFUSED\n";
            continue;
        }
        // тут всё получилось, выводим ответ:
        for (auto it : answ)
            cout << it << ' ';
        cout << '\n';
    }
}
int32_t main() {
    cin.tie(0)->sync_with_stdio(0);
    int tt = 1; // cin >> tt;
    while (tt --> 0) solve();
    return 0;
}
```

</details>

```python
def solve():
    # читаем изначальные количества монет:
    c = list(map(int,input().split()))

    q = int(input())

solve()
```

<details><summary><b>Разбор сложных фрагментов кода на C++</b></summary>

```cpp
        ll s = 0;
        for (int i = 0; i < 6; i++)
            s += d[i] * u[i];
```

Количество монет в автомате может накапливаться на протяжении многих покупок, поэтому для сумм и количеств используется `long long`. Значение `s` содержит полную сумму, внесённую текущим покупателем.

```cpp
        vector<ll> saved = c;
        for (int i = 0; i < 6; i++)
            c[i] += u[i];
```

`saved` хранит состояние автомата **до попытки покупки**. Внесённые монеты сразу добавляются в `c`, поскольку по условию они уже доступны при выдаче сдачи.

```cpp
        ll r = s - p;
        vector<ll> answ(6);
        for (int i = 5; i >= 0; i--) {
            // выдаём максимальное количество монет, которое можем:
            ll cntI = std::min(c[i], r / d[i]);
            r -= d[i] * cntI;
            c[i] -= cntI;
            answ[i] = cntI;
        }
```

Вектор `d` упорядочен по возрастанию, поэтому обратный проход соответствует требуемому порядку: от $50$ рублей к $1$ рублю.

Выражение `r / d[i]` задаёт максимальное количество монет, которое не превышает оставшуюся сдачу, а `c[i]` ограничивает его фактическими запасами автомата. После выбора `cntI` одновременно уменьшаются и остаток сдачи, и количество монет данного номинала.

```cpp
        if (r != 0) {
            // не получилось -> откатываем:
            c = saved;
            cout << "REFUSED\n";
            continue;
        }
```

Положительный остаток после обработки всех номиналов означает, что автомат не смог выдать точную сдачу установленным способом. Присваивание `c = saved` отменяет как добавление внесённых монет, так и все монеты, которые автомат пытался выдать.

```cpp
        for (auto it : answ)
            cout << it << ' ';
```

Хотя сдача вычисляется от крупных номиналов к мелким, результат хранится по исходным индексам. Поэтому обычный проход по `answ` выводит количества в требуемом порядке: $1$, $2$, $5$, $10$, $20$, $50$.

</details>

<details><summary><b>Разбор сложных фрагментов кода на Python</b></summary>

```python

```

Расширенная распаковка отделяет первое число строки — стоимость напитка `p`. Остальные шесть чисел образуют список `u` с количествами внесённых монет.


Метод `copy()` создаёт отдельный список с прежним состоянием автомата. Простое присваивание `saved = c` здесь не подошло бы: обе переменные ссылались бы на один список, и последующие изменения `c` затронули бы сохранённое состояние.

Монеты покупателя добавляются до выдачи сдачи, поэтому автомат может вернуть в качестве сдачи даже только что внесённую монету.

```python
        r = s - p
        answ = [0] * 6
        for i in range(5,-1,-1):

            cntI = min(c[i], r // d[i])
            r -= d[i] * cntI
            c[i] -= cntI
            answ[i] = cntI
```

`range(5,-1,-1)` перебирает индексы $5,4,\ldots,0$, то есть номиналы от $50$ до $1$ рубля.

Целочисленное деление `r // d[i]` показывает, сколько монет текущего номинала помещается в оставшуюся сдачу. Функция `min` дополнительно учитывает доступное количество таких монет. Выбранное значение записывается в `answ` по исходному индексу, чтобы затем вывести ответ в порядке возрастания номиналов.

```python
        if r != 0:
            # не получилось -> откатываем:
            c = saved
            print("REFUSED")
            continue
```

Если остаток не обнулился, точную сдачу выдать не удалось. Переменная `saved` по-прежнему ссылается на отдельную неизменённую копию прежнего списка, поэтому присваивание полностью восстанавливает состояние автомата.

```python
        print(*answ)
```

Оператор `*` распаковывает список: его шесть элементов выводятся как отдельные числа через пробел. Порядок элементов соответствует номиналам $1$, $2$, $5$, $10$, $20$, $50$.

## B. Делимость на последнюю цифру

<details><summary><b>Постановка задачи</b></summary>

Натуральное число называется **удачным**, если его последняя десятичная цифра отлична от нуля и число делится на эту цифру.

Дано $t$ отрезков $[l,r]$, где $1 \le l \le r \le 10^{18}$. Для каждого отрезка требуется найти количество удачных чисел $x$, удовлетворяющих неравенству $l \le x \le r$.

</details>

<details><summary><b>Основная идея</b></summary>

Перебирать числа на отрезке нельзя: его длина достигает $10^{18}$. Вместо этого зафиксируем последнюю цифру $d$ числа. Тогда любое подходящее по последней цифре число имеет вид $x=d+10m$.

Условие делимости $x$ на $d$ сводится к делимости $10m$ на $d$. Если $g=\text{НОД}(d,10)$, то $m$ должно делиться на $d/g$. Следовательно, все удачные числа с последней цифрой $d$ образуют арифметическую прогрессию:

$x=d+10k\cdot \dfrac{d}{\text{НОД}(d,10)}$, где $k \ge 0$.

Для каждой из девяти ненулевых цифр посчитаем количество членов этой прогрессии, не превосходящих заданную границу. Пусть $F(R)$ — количество удачных чисел от $1$ до $R$. Тогда ответ для отрезка равен $F(r)-F(l-1)$.

На один запрос требуется $O(9)=O(1)$ времени и $O(1)$ дополнительной памяти. Общая сложность составляет $O(t)$.

</details>

<details><summary><b>Детальный разбор</b></summary>

Прямой перебор всех чисел от $l$ до $r$ не подходит: даже один отрезок может содержать порядка $10^{18}$ чисел. Значит, нужно считать подходящие числа сразу группами.

Сначала заметим, что условие задачи связано только с **последней цифрой** числа. Зафиксируем её и обозначим через $d$, где $1 \le d \le 9$. Все числа с такой последней цифрой представляются в виде

$x=d+10m$,

где $m$ — целое неотрицательное число, образованное остальными цифрами десятичной записи.

Число $x$ удачно тогда и только тогда, когда оно делится на $d$. Подставим найденное представление:

$d \mid d+10m$.

Первое слагаемое уже делится на $d$, поэтому условие равносильно следующему:

$d \mid 10m$.

Обозначим $g=\text{НОД}(d,10)$ и представим $d=ga$, $10=gb$. После сокращения получаем $a \mid bm$. При этом $\text{НОД}(a,b)=1$, а значит, множитель $a$ обязан целиком содержаться в $m$. Иными словами,

$m$ делится на $\dfrac{d}{\text{НОД}(d,10)}$.

Обозначим это значение через $s_d$:

$s_d=\dfrac{d}{\text{НОД}(d,10)}$.

Тогда $m=ks_d$ для некоторого целого $k \ge 0$, а все удачные числа с последней цифрой $d$ имеют вид

$x=d+10ks_d$.

Таким образом, для каждой цифры возникает арифметическая прогрессия. Осталось посчитать, сколько её членов не превосходят границу $R$:

$d+10ks_d \le R$.

Если $R<d$, подходящих чисел с такой последней цифрой нет. Иначе

$k \le \left\lfloor\dfrac{R-d}{10s_d}\right\rfloor$.

Допустимые значения начинаются с нуля, поэтому количество подходящих значений $k$ равно

$\left\lfloor\dfrac{R-d}{10s_d}\right\rfloor+1$.

Просуммируем это количество по всем $d$ от $1$ до $9$. Так получим функцию $F(R)$ — число удачных чисел, не превосходящих $R$.

Теперь любой запрос на отрезке восстанавливается стандартной разностью префиксов:

$\text{answer}(l,r)=F(r)-F(l-1)$.

**Почему подсчёт корректен?**

- Каждое построенное число заканчивается цифрой $d$, поскольку отличается от неё на число, кратное $10$.
- Оно делится на $d$, так как выбранное значение $m=ks_d$ гарантирует делимость $10m$ на $d$.
- Любое удачное число имеет некоторую единственную последнюю цифру $d$ от $1$ до $9$. Из условия $d \mid 10m$ следует, что $m$ делится на $s_d$, поэтому такое число обязательно встретится в соответствующей прогрессии.
- Число не может попасть в две разные группы, поскольку его последняя цифра определяется однозначно.

Следовательно, перебор девяти прогрессий учитывает все удачные числа и не создаёт повторов.

Для каждого запроса выполняется девять итераций, поэтому временная сложность равна $O(9t)=O(t)$, а дополнительная память — $O(1)$.

</details>

<details><summary><b>Код на C++</b></summary>

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
using namespace std;
using ll = long long;
ll solve(ll r) {
    // число x можно представить в виде: x = d + 10*(other_digits)
```
